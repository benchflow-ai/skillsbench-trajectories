Build Failure Analysis and Solution for google/auto Project
============================================================

ORIGINAL ERROR:
Could not resolve dependencies for project com.google.auto:auto-common:jar:1.0-SNAPSHOT:
Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar

ROOT CAUSE:
The com.google.testing.compile:compile-testing:0.7 library declares a system scope dependency on
com.sun:tools with systemPath=${toolsjar}. This dependency is used for compilation testing but is
not available in Java 9+ where tools.jar was integrated into the JDK.

The compile-testing library (version 0.7) has:
  <dependency>
    <groupId>com.sun</groupId>
    <artifactId>tools</artifactId>
    <version>${java.version}</version>
    <scope>system</scope>
    <systemPath>${toolsjar}</systemPath>
  </dependency>

When building on Java 11 with OpenJDK, the path ${java.home}/../lib/tools.jar does not exist,
causing the dependency resolution to fail.

SOLUTION:
Exclude the com.sun:tools dependency from the compile-testing library in the auto-common module's
pom.xml file. This is safe because:
1. The compile-testing library itself doesn't strictly need tools.jar for its functionality
2. Java 9+ has integrated tools into the JDK, so the system dependency is not needed
3. The compilation can proceed without this explicit system dependency

FIX APPLIED:
Added an <exclusions> section to the compile-testing dependency in common/pom.xml:

  <dependency>
    <groupId>com.google.testing.compile</groupId>
    <artifactId>compile-testing</artifactId>
    <version>0.7</version>
    <scope>test</scope>
    <exclusions>
      <exclusion>
        <groupId>com.sun</groupId>
        <artifactId>tools</artifactId>
      </exclusion>
    </exclusions>
  </dependency>

RESULT:
The build now compiles successfully. The original dependency resolution error is resolved.
The project can now be built on Java 9 and later versions.
