=== SSH VULNERABILITY FIX SUMMARY ===

VULNERABILITY DESCRIPTION:
The Erlang/OTP SSH server had a critical vulnerability (CVE-like) that allowed
unauthenticated attackers to execute arbitrary system commands by sending crafted
SSH protocol messages of type 'exec' or 'shell' without proper authentication checks.

ROOT CAUSE:
The ssh_connection.erl module had two vulnerable message handlers:
1. handle_msg for ssh_msg_channel_request with request_type = "shell"
2. handle_msg for ssh_msg_channel_request with request_type = "exec"

Both handlers were processing the requests and calling handle_cli_msg WITHOUT
verifying that the SSH connection was authenticated (SSH#ssh.authenticated == true).

VULNERABLE CODE PATTERN:
The handlers were ignoring the SSH state parameter (_SSH) and directly processing
the channel requests, allowing command execution without authentication.

FIX APPLIED:

1. SHELL HANDLER (Line ~1135):
   - Changed parameter from _SSH to SSH (now used)
   - Added: case SSH#ssh.authenticated of
   - If authenticated (true): proceed with handle_cli_msg
   - If not authenticated (false): return channel_failure_msg

2. EXEC HANDLER (Line ~1152):
   - Changed parameter from _SSH to SSH (now used)
   - Added: case SSH#ssh.authenticated of
   - If authenticated (true): proceed with handle_cli_msg
   - If not authenticated (false): return channel_failure_msg

BEFORE (Vulnerable):
handle_msg(#ssh_msg_channel_request{..., request_type = "exec", ...},
           Connection, server, _SSH) ->
    <<?DEC_BIN(Command, _Len)>> = Data,
    handle_cli_msg(Connection, ChannelId, {exec, ...});

AFTER (Fixed):
handle_msg(#ssh_msg_channel_request{..., request_type = "exec", ...},
           Connection, server, SSH) ->
    case SSH#ssh.authenticated of
        true ->
            <<?DEC_BIN(Command, _Len)>> = Data,
            handle_cli_msg(Connection, ChannelId, {exec, ...});
        false ->
            Cache = Connection#connection.channel_cache,
            #channel{remote_id=RemoteId} = ssh_client_channel:cache_lookup(Cache, ChannelId),
            Reply = channel_failure_msg(RemoteId),
            {[{connection_reply, Reply}], Connection}
    end;

IMPACT:
- Unauthenticated SSH clients can no longer execute arbitrary commands
- The server now properly validates authentication state before processing
  channel execution requests
- Normal authenticated SSH behavior is maintained
- Unauthenticated requests receive proper SSH protocol failure messages
