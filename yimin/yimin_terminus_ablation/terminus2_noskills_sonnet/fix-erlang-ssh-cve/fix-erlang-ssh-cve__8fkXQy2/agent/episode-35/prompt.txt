# Erlang/OTP SSH Authentication Bypass Vulnerability - Analysis and Fix

## Executive Summary

A critical authentication bypass vulnerability was discovered in Erlang/OTP SSH server version 27.3.2. The vulnerability allows unauthenticated attackers to execute arbitrary system commands remotely by sending SSH connection protocol messages before completing authentication.

**Severity:** CRITICAL  
**Attack Vector:** Network  
**Authentication Required:** None  
**Impact:** Remote Code Execution

---

## Vulnerability Details

### Root Cause

The vulnerability exists in `/lib/ssh/src/ssh_connection_handler.erl` in the message dispatch function `handle_event/4`. Specifically, at lines 1161-1177, the code processes SSH connection protocol messages without verifying that the client has successfully authenticated.

### Vulnerable Code (Original)

```erlang
%% Lines 1161-1177 in ssh_connection_handler.erl
#ssh_msg_global_request{}            = Msg -> {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_request_success{}           = Msg -> {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_request_failure{}           = Msg -> {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_open{}              = Msg -> {keep_state, D1, [...]};
#ssh_msg_channel_open_confirmation{} = Msg -> {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_open_failure{}      = Msg -> {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_window_adjust{}     = Msg -> {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_data{}              = Msg -> {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_extended_data{}     = Msg -> {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_eof{}               = Msg -> {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_close{}             = Msg -> {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_request{}           = Msg -> {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_failure{}           = Msg -> {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_success{}           = Msg -> {keep_state, D1, ?CONNECTION_MSG(Msg)};
```

**Problem:** No authentication state check (`?CONNECTED(StateName)`) before processing these messages.

## Attack Vector

### SSH Protocol Background

SSH protocol has distinct phases:
1. **Transport Layer**: Key exchange and encryption setup
2. **Authentication**: User authentication (password, public key, etc.)
3. **Connection Protocol**: Channel management, command execution, port forwarding

**Security Requirement:** Connection protocol messages (types 80-100) should ONLY be processed after successful authentication.

### Exploitation Steps

1. **Attacker connects** to the SSH server
2. **Complete key exchange** (no authentication required for this phase)
3. **Send `SSH_MSG_GLOBAL_REQUEST`** with malicious payload before authentication
4. **Server processes the request** without checking authentication status
5. **Command execution** occurs without any credentials

### Most Dangerous Message Types

- **`SSH_MSG_GLOBAL_REQUEST` (type 80)**: Can request command execution, port forwarding
- **`SSH_MSG_CHANNEL_OPEN` (type 90)**: Opens communication channels
- **`SSH_MSG_CHANNEL_REQUEST` (type 98)**: Can request:
  - `exec`: Execute arbitrary commands
  - `shell`: Interactive shell access
  - `subsystem`: SFTP or other subsystems

## Technical Analysis

### Message Flow

1. SSH packet arrives → `handle_event(info, {Proto, Sock, NewData}, StateName, D0)`
2. Packet decrypted → `ssh_transport:handle_packet_part(...)`
3. Message decoded → `ssh_message:decode(...)`
4. Message dispatched → Pattern matching at lines 1161-1177
5. **VULNERABILITY**: Connection messages routed via `?CONNECTION_MSG(Msg)` macro
6. Message processed → `ssh_connection:handle_msg(Msg, ...)` at line 763

### State Machine States

Erlang SSH uses these states:
- `{hello, Role}` - Initial handshake
- `{kexinit, Role, ...}` - Key exchange
- `{userauth, Role}` - Authentication phase
- `{connected, Role}` - **AUTHENTICATED** state
- `{ext_info, Role}` - Extension info (also authenticated)

The `?CONNECTED(StateName)` macro checks:
```erlang
(element(1,StateName) == connected orelse element(1,StateName) == ext_info)
```

### Why Other Functions Were Safe

Example of properly protected function (line 1100):
```erlang
handle_event({call,From}, {close, ChannelId}, StateName, D0)
  when ?CONNECTED(StateName) ->  %% <-- Authentication guard present
    ...
```

## The Fix

### Solution Approach

Add authentication state guards to all connection protocol message handlers using the existing `?CONNECTED(StateName)` macro, plus a catch-all clause to explicitly reject these messages when received before authentication.

### Fixed Code

```erlang
%% Connection protocol messages - MUST be authenticated
#ssh_msg_global_request{}            = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_request_success{}           = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_request_failure{}           = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_open{}              = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1,
     [{{timeout, max_initial_idle_time}, cancel} |
      ?CONNECTION_MSG(Msg)
     ]};
#ssh_msg_channel_open_confirmation{} = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_open_failure{}      = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_window_adjust{}     = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_data{}              = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_extended_data{}     = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_eof{}               = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_close{}             = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_request{}           = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_failure{}           = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1, ?CONNECTION_MSG(Msg)};
#ssh_msg_channel_success{}           = Msg when ?CONNECTED(StateName) -> 
    {keep_state, D1, ?CONNECTION_MSG(Msg)};

%% Reject connection protocol messages before authentication
Msg when is_record(Msg, ssh_msg_global_request);
         is_record(Msg, ssh_msg_request_success);
         is_record(Msg, ssh_msg_request_failure);
         is_record(Msg, ssh_msg_channel_open);
         is_record(Msg, ssh_msg_channel_open_confirmation);
         is_record(Msg, ssh_msg_channel_open_failure);
         is_record(Msg, ssh_msg_channel_window_adjust);
         is_record(Msg, ssh_msg_channel_data);
         is_record(Msg, ssh_msg_channel_extended_data);
         is_record(Msg, ssh_msg_channel_eof);
         is_record(Msg, ssh_msg_channel_close);
         is_record(Msg, ssh_msg_channel_request);
         is_record(Msg, ssh_msg_channel_failure);
         is_record(Msg, ssh_msg_channel_success) ->
    MaxLogItemLen = ?GET_OPT(max_log_item_len,SshParams#ssh.opts),
    {Shutdown, D} =
        ?send_disconnect(?SSH_DISCONNECT_PROTOCOL_ERROR,
                         io_lib:format("Connection protocol message before authentication: ~p",
                                       [element(1,Msg)], [{chars_limit, MaxLogItemLen}]),
                         StateName, D1),
    {stop, Shutdown, D};
```

### Key Changes

1. **Added `when ?CONNECTED(StateName)` guards** to all 14 connection protocol message handlers
2. **Added catch-all clause** that explicitly checks for connection protocol messages in non-authenticated states
3. **Disconnect with protocol error** when connection messages received before authentication
4. **Maintains normal operation** for legitimate authenticated connections

## Impact of Fix

### Security Improvements

✅ **Blocks pre-authentication command execution**  
✅ **Prevents unauthorized channel operations**  
✅ **Rejects global requests before authentication**  
✅ **Logs security violations** with disconnect reason  
✅ **Maintains SSH RFC compliance**

### Behavioral Changes

**Before Fix:**
- Connection protocol messages accepted in any state
- Commands could execute without authentication
- Channels could be opened pre-authentication

**After Fix:**
- Connection protocol messages ONLY accepted in `connected` or `ext_info` states
- Pre-authentication connection messages trigger immediate disconnect
- Clear error message: "Connection protocol message before authentication"

### Compatibility

- ✅ **No impact on legitimate clients** (they authenticate before sending connection messages)
- ✅ **Maintains all normal SSH functionality**
- ✅ **Compatible with SSH protocol RFC 4254**
- ✅ **No performance impact**
