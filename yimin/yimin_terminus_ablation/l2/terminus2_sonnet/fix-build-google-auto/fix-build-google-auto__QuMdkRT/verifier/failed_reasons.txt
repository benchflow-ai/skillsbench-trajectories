BUILD FAILURE ANALYSIS
======================

Repository: /home/travis/build/failed/google/auto
Java Version: OpenJDK 11.0.27

Error:
------
Failed to execute goal on project auto-common: Could not resolve dependencies for project com.google.auto:auto-common:jar:1.0-SNAPSHOT: Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar

Root Cause:
-----------
The auto-common module uses compile-testing version 0.7 as a test dependency. This version of compile-testing has a system-scoped dependency on com.sun:tools (tools.jar) which was removed in Java 9+. The tools.jar file was part of the JDK in Java 8 and earlier, but starting with Java 9, the classes were integrated into the JDK modules.

The compile-testing-0.7.pom contains:
<dependency>
  <groupId>com.sun</groupId>
  <artifactId>tools</artifactId>
  <version>${java.version}</version>
  <scope>system</scope>
  <systemPath>${toolsjar}</systemPath>
</dependency>

Where ${toolsjar} is set to ${java.home}/../lib/tools.jar via profiles, which doesn't exist in Java 11.

Solution:
---------
Upgrade compile-testing from version 0.7 to version 0.9 or later, which has proper support for Java 9+ and doesn't require tools.jar as a system dependency.

Files to modify:
- common/pom.xml: Update compile-testing version from 0.7 to 0.9

Second Issue Found:
-------------------
After fixing the compile-testing dependency issue, a new compilation error appeared in the auto-factory module:

Error:
cannot find symbol: class Generated, location: package javax.annotation

Root Cause:
In Java 9+, the javax.annotation.Generated class was moved from javax.annotation to javax.annotation.processing.Generated. The code was using the old import path which doesn't exist in Java 9+.

Affected Files:
- factory/src/main/java/com/google/auto/factory/processor/FactoryWriter.java
- value/src/main/java/com/google/auto/value/processor/AutoValueProcessor.java
- value/src/main/java/com/google/auto/value/processor/AutoAnnotationProcessor.java

Solution:
Changed all imports from 'import javax.annotation.Generated;' to 'import javax.annotation.processing.Generated;' in the affected processor files.
