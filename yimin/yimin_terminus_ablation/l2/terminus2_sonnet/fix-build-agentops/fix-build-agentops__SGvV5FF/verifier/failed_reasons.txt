ANALYSIS OF BUILD FAILURE
=========================

Repository: AgentOps-AI/agentops
Test Failure: tests/test_events.py::TestEvents::test_record_timestamp

ROOT CAUSE:
-----------
The test is failing because the end_timestamp of an ActionEvent is not being updated when agentops.record() is called.

DETAILED ANALYSIS:
------------------
1. In agentops/event.py, the Event class defines both init_timestamp and end_timestamp with default_factory=get_ISO_time
2. This means both timestamps are set to the same time when the event is instantiated
3. The test creates an ActionEvent, sleeps 0.15 seconds, then calls agentops.record(event)
4. The test expects init_timestamp != end_timestamp after recording
5. However, in agentops/client.py, the record() method checks for an active session first
6. If there's no session, it logs a warning and returns early WITHOUT updating end_timestamp
7. The timestamp update code is after the session check, so it never executes

THE BUG:
--------
The end_timestamp should be set to None initially (not get_ISO_time()), and should only be set when:
- The event is recorded, OR
- The event ends

Currently, both timestamps are set to the same value at creation time, which is incorrect.

FIX STRATEGY:
-------------
1. Change end_timestamp in Event class to default to None instead of get_ISO_time()
2. Update the record() function to set end_timestamp before checking for session (or handle the case where there's no session)
3. This ensures end_timestamp is always updated when record() is called

FILES TO MODIFY:
----------------
1. agentops/event.py - Change end_timestamp default
2. agentops/client.py - Update timestamp before session check or handle no-session case
