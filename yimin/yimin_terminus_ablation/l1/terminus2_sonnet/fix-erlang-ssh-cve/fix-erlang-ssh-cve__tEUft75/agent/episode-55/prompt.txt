=== ERLANG/OTP SSH VULNERABILITY ANALYSIS AND FIX ===

VULNERABILITY TYPE: Authentication Bypass - Remote Command Execution

ATTACK VECTOR:
- SSH Message Type: SSH_MSG_CHANNEL_REQUEST (message type 98)
- Specifically: Channel requests with request_type="exec" 
- These messages were processed BEFORE user authentication completed

ROOT CAUSE:
In ssh_connection_handler.erl, the handle_event function (around line 1135) 
processes incoming SSH messages in ANY state, including before authentication.

At line 1175 (original), ssh_msg_channel_request messages were dispatched 
without checking if StateName was {connected,_}. This allowed attackers to:
1. Connect to SSH server
2. Send SSH_MSG_CHANNEL_REQUEST with "exec" type
3. Execute arbitrary commands WITHOUT providing credentials

FIX IMPLEMENTED:
1. Added "when ?CONNECTED(StateName)" guards to all channel message patterns
   (lines 1164-1177)
2. Added explicit rejection clauses for channel messages in non-connected states
   (lines 1180-1195)
3. These clauses send SSH_DISCONNECT_PROTOCOL_ERROR and close the connection

RESULT:
- Authenticated users: Normal SSH behavior maintained
- Unauthenticated attackers: Channel requests are rejected with disconnect
- The server no longer executes commands from unauthenticated SSH messages

- /app/workspace/otp_src_27.3.2/lib/ssh/src/ssh_connection_handler.erl
