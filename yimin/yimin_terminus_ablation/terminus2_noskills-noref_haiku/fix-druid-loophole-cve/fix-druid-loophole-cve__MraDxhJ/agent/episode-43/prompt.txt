# Apache Druid 0.20.0 RCE Vulnerability Patch

## Vulnerability Description

Apache Druid version 0.20.0 contains a critical Remote Code Execution (RCE) vulnerability in the sampler endpoint (`/druid/indexer/v1/sampler`). Authenticated attackers can execute arbitrary code on the server through malicious JavaScript payloads.

### Root Cause

The vulnerability exploits an empty key (`""`) in the filter configuration JSON that can bypass JavaScript security settings. The issue is that JavaScript validation was performed only at execution time (lazy evaluation) rather than at deserialization time, allowing malicious JavaScript filters to be instantiated even when JavaScript was disabled.

### Attack Vector

```http
POST /druid/indexer/v1/sampler HTTP/1.1
Content-Type: application/json

{
  "type": "index",
  "spec": {
    "dataSchema": {
      "transformSpec": {
        "filter": {
          "type": "javascript",
          "function": "function(){java.lang.Runtime.getRuntime().exec('malicious_command');}",
          "": {
            "enabled": true
          }
        }
      }
    }
  }
}
```

The empty key `""` allows the attacker to bypass the `enabled` flag validation.

## Solution

The patch adds validation to all JavaScript-related classes to ensure that JavaScript is enabled **during deserialization** (in the `@JsonCreator` constructor), not just at execution time. This prevents malicious JavaScript objects from being instantiated in the first place.

## Files Modified

1. **processing/src/main/java/org/apache/druid/query/filter/JavaScriptDimFilter.java**
   - Added validation in `@JsonCreator` constructor
   - Prevents JavaScript filters from being deserialized when JavaScript is disabled

2. **processing/src/main/java/org/apache/druid/query/extraction/JavaScriptExtractionFn.java**
   - Added validation in `@JsonCreator` constructor
   - Prevents JavaScript extraction functions from being deserialized when JavaScript is disabled

3. **processing/src/main/java/org/apache/druid/query/aggregation/JavaScriptAggregatorFactory.java**
   - Added validation in `@JsonCreator` constructor
   - Prevents JavaScript aggregators from being deserialized when JavaScript is disabled

4. **processing/src/main/java/org/apache/druid/query/aggregation/post/JavaScriptPostAggregator.java**
   - Added validation in `@JsonCreator` constructor
   - Prevents JavaScript post-aggregators from being deserialized when JavaScript is disabled

## Changes Summary

Each modified file now includes the following validation in its `@JsonCreator` constructor:

```java
Preconditions.checkState(config != null && config.isEnabled(), "JavaScript is disabled");
```

This ensures that:
- JavaScript configuration is validated early during deserialization
- Malicious payloads are rejected immediately
- The empty key bypass no longer works
- All JavaScript features are protected (filters, extraction functions, aggregators, post-aggregators)
