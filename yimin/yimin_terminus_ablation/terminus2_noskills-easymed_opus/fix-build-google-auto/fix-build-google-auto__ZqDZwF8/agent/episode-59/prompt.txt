# Build Failure Analysis for google/auto

## Root Cause
The build fails due to Java version incompatibility. The project uses `compile-testing` library
(versions 0.6, 0.7, 0.8) which has a transitive dependency on `com.sun:tools:jar`.

In Java 8 and earlier, `tools.jar` existed at `${java.home}/../lib/tools.jar` and contained
the `javax.annotation.processing` and `javax.lang.model` APIs needed for annotation processing.

In Java 9+, these APIs were moved into the JDK modules and `tools.jar` no longer exists.
The build is running on Java 11 (OpenJDK), causing the dependency resolution to fail.

## Error Message
```
Could not find artifact com.sun:tools:jar:11.0.27 at specified path 
/usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
```

## Affected Modules
1. common/pom.xml - uses compile-testing:0.7
2. service/pom.xml - uses compile-testing:0.6  
3. factory/pom.xml - uses compile-testing:0.8
4. value/pom.xml - uses compile-testing:0.6

## Solution
Upgrade `compile-testing` to version 0.15 or later, which removed the tools.jar dependency
and is compatible with Java 9+. Version 0.15 uses the standard JDK APIs instead.

The fix requires updating the compile-testing version in all four module pom.xml files:
- common/pom.xml: 0.7 -> 0.15
- service/pom.xml: 0.6 -> 0.15
- factory/pom.xml: 0.8 -> 0.15
- value/pom.xml: 0.6 -> 0.15

Additionally, truth library should be updated to a compatible version (0.36+).

## Additional Issue: Truth Library Compatibility

The compile-testing 0.15 requires a newer version of the truth library.
The old versions (0.23, 0.24, 0.25) are incompatible with compile-testing 0.15
because of API changes in truth (Subject.Factory class was refactored).

The fix also requires updating truth to version 0.36 or later in:
- common/pom.xml: 0.25 -> 0.36
- service/pom.xml: 0.24 -> 0.36  
- factory/pom.xml: 0.25 -> 0.36
- value/pom.xml: 0.25 -> 0.36
