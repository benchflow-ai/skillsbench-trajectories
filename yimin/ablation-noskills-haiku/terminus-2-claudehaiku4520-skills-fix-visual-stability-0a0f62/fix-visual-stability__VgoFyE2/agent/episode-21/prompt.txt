# Next.js E-Commerce App - UX Fixes Summary

## Root Causes of Visual Instability Identified and Fixed

### 1. **ProductCard.tsx - Missing Image Dimensions (CLS)**
**Problem**: Used plain `<img>` tag without width/height attributes
- Images load asynchronously, pushing content down
- Causes Cumulative Layout Shift (CLS)

**Solution Applied**:
- Replaced `<img>` with Next.js `Image` component
- Used `fill` prop with `aspect-square` container
- Added responsive `sizes` prop for different screen sizes
- Images now reserve space before loading, preventing layout shift

**Code Change**:
```jsx
// Before: Plain img tag
<img src={product.image} alt={product.name} className="w-full" />

// After: Next.js Image with proper dimensions
<div className="relative w-full aspect-square overflow-hidden rounded">
  <Image
    src={product.image}
    alt={product.name}
    fill
    sizes="(max-width: 768px) 100vw, (max-width: 1200px) 50vw, 33vw"
    className="object-cover"
    priority={false}
  />
</div>
```

---

### 2. **Banner.tsx & LateBanner.tsx - Conditional Rendering (CLS)**
**Problem**: Components returned `null` while loading, then rendered content
- Creates layout shift when banner appears
- Pushes content down unexpectedly

**Solution Applied**:
- Reserved fixed space with `min-h-[120px]` and `min-h-[160px]`
- Used `visibility: hidden` instead of returning null
- Content space is reserved even when empty
- No layout shift when data loads

**Code Change**:
```jsx
// Before: Returns null, causes layout shift
if (!promo) return null;

// After: Reserves space, no shift
return (
  <div
    className="min-h-[120px] flex items-center justify-center"
    style={{ visibility: promo ? 'visible' : 'hidden' }}
  >
    {promo}
  </div>
);
```

---

### 3. **ProductList.tsx - Poor Loading State (CLS)**
**Problem**: Showed "Loading products..." text that got replaced by grid
- Text height differs from grid height
- Causes layout shift when loading completes

**Solution Applied**:
- Replaced text with skeleton loaders (ProductSkeleton components)
- Skeleton loaders match the height of actual product cards
- No layout shift when loading completes
- Better perceived performance

**Code Change**:
```jsx
// Before: Text loading indicator
{loading ? (
  <div className="p-2 text-gray-500 text-sm">Loading products...</div>
) : (...)

// After: Skeleton loaders matching card height
{loading ? (
  <>
    <ProductSkeleton />
    <ProductSkeleton />
    {/* 6 skeletons total */}
  </>
) : (...)
```

### 4. **ResultsBar.tsx - Conditional Rendering (CLS)**
**Problem**: Component returned `null` until API data loaded

- Creates layout shift

**Solution Applied**:

- Used `visibility: hidden` instead of returning null

- No layout shift when data loads

### 5. **SidePane.tsx - Async Loading (CLS)**
**Problem**: Returned `null` while loading, then rendered sidebar
- Sidebar suddenly appears, shifts main content right
- Creates layout shift

**Solution Applied**:
- Added safe navigation with optional chaining (`data?.categories?.map`)
- Component always renders with reserved space
- No layout shift when data loads

### 6. **globals.css - Font Loading (CLS)**
**Problem**: Missing `font-display: swap` property
- Custom font loads slowly, causes font swap
- Text renders in fallback font, then swaps to custom font
- Creates CLS when font swaps

**Solution Applied**:
- Added `font-display: swap` to @font-face rule
- Browser renders text immediately with fallback font
- Swaps to custom font when ready
- Prevents font-related CLS

**Code Change**:
```css
@font-face {
  font-family: 'CustomFont';
  src: url('/fonts/custom.woff2') format('woff2');
  font-display: swap;  /* Added this line */
}
```

---

### 7. **ThemeProvider.tsx - Hydration Mismatch**
**Problem**: Theme state based on localStorage read in useEffect
- Server renders with default theme
- Client reads localStorage and updates theme
- Causes hydration mismatch
- Potential layout shift when theme applies

**Solution Applied**:
- Added `mounted` state to track hydration
- Set theme from localStorage in first useEffect
- Only apply dynamic className after mounted
- Prevents hydration mismatch
- No layout shift from theme changes

**Code Change**:
```jsx
const [mounted, setMounted] = useState(false);

useEffect(() => {
  const savedTheme = localStorage.getItem('theme');
  if (savedTheme) {
    setTheme(savedTheme);
    document.documentElement.setAttribute('data-theme', savedTheme);
  }
  setMounted(true);
}, []);

// Only apply theme class after mounted
className={`min-h-screen ${mounted && theme === 'dark' ? '...' : '...'}`}
```
