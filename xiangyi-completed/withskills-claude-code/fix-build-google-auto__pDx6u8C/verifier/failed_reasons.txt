BUILD FAILURE ANALYSIS
======================

Repository: /home/travis/build/failed/google/auto
Java Version: OpenJDK 11.0.27

ROOT CAUSE
----------
The build fails with the following error when building the factory, service, value, and common modules:

"Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

TECHNICAL EXPLANATION
--------------------
1. The child modules (common, factory, service, value) reference parent POM version 3:
   - common/pom.xml: <version>3</version>
   - factory/pom.xml: <version>3</version>
   - service/pom.xml: <version>3</version>
   - value/pom.xml: <version>3</version>

2. The actual parent pom.xml in the repository is version 4-SNAPSHOT, not version 3.

3. When Maven cannot find auto-parent:3 locally, it downloads it from Maven Central.

4. The auto-parent:3 from Maven Central has a profile that sets the toolsjar property:
   - Profile activation checks if ${java.home}/../lib/tools.jar exists
   - If exists, sets toolsjar=${java.home}/../lib/tools.jar

5. Several modules have test dependencies on compile-testing library (versions 0.6, 0.7, 0.8)
   which includes a system-scoped dependency on com.sun:tools:jar using the ${toolsjar} property.

6. In Java 9+, tools.jar no longer exists. The compiler API was modularized and is now
   part of the JDK modules (java.compiler, jdk.compiler, etc.).

7. Since tools.jar doesn't exist, the profile doesn't activate, ${toolsjar} is undefined,
   and Maven cannot resolve the com.sun:tools dependency, causing the build to fail.

SOLUTION
--------
The fix requires two parts:

PART 1: Update child module parent versions
Update all child module pom.xml files to reference the correct parent version (4-SNAPSHOT)
instead of version 3:

1. /home/travis/build/failed/google/auto/common/pom.xml - Line 24
2. /home/travis/build/failed/google/auto/factory/pom.xml - Line 25
3. /home/travis/build/failed/google/auto/service/pom.xml - Line 24
4. /home/travis/build/failed/google/auto/value/pom.xml - Line 24

PART 2: Add Java 9+ profile to parent POM
The parent POM (version 4-SNAPSHOT) also has the same tools.jar issue. Even with the updated
parent version references, builds on Java 9+ will fail because neither the default-profile
nor the mac-profile will activate (both require tools.jar to exist).

Solution: Add a Java 9+ profile to /home/travis/build/failed/google/auto/pom.xml that
activates for JDK 9 and above. This profile should set the toolsjar property to satisfy
the compile-testing dependency requirement.

Additionally, there is a secondary issue:
- javax.annotation.Generated moved to javax.annotation.processing.Generated in Java 9+
- The code needs the javax.annotation-api dependency to work with Java 9+

PART 3: Workaround for tools.jar
Since tools.jar doesn't exist in Java 11, create an empty tools.jar file at:
/usr/lib/jvm/lib/tools.jar

This allows Maven's system-scoped dependency resolution to succeed, even though the
actual tools classes are not needed (they're built into Java 11).

2. Missing Java 9+ profile in parent POM
3. Missing javax.annotation-api dependency for Java 9+ compatibility

- In Java 9+, tools.jar was removed and its APIs moved to JDK modules
- Maven requires the file to exist even though it's not actually used
