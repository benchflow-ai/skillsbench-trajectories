# UltraJSON (ujson) Library - Important Functions for Fuzzing

## Overview
UltraJSON is a fast JSON encoder and decoder written in C with Python bindings. It's an excellent fuzzing target due to its C implementation and parsing of untrusted input.

## Important Files for Fuzzing
1. src/ujson/python/ujson.c - Main Python bindings
2. src/ujson/python/JSONtoObj.c - JSON parsing (decode)
3. src/ujson/python/objToJSON.c - JSON encoding (dumps)
4. tests/fuzz.py - Existing fuzz testing infrastructure

## Selected Functions Under Test (FUTs)

### 1. ujson.loads (C extension)
- **Why this target**: JSON parsing from string - critical security boundary
- **Input surface**: String/bytes input - arbitrary JSON data
- **Boundary considerations**: C parsing code, memory management, buffer handling
- **Complexity**: Medium - straightforward JSON parsing but in C

**Callable contract**:
- Required imports: `import ujson`
- Input: `s: str | bytes` (JSON string)
- Returns: Python object (dict, list, str, int, float, bool, None)
- Raises: `ujson.JSONDecodeError` on invalid JSON

**Input model**:
- Primary payload type: str/bytes (JSON data)
- Edge classes: Deeply nested objects, large numbers, unicode escapes, malformed JSON, truncated input

### 2. ujson.dumps (C extension)
- **Why this target**: JSON encoding - also security-relevant
- **Input surface**: Python objects (dicts, lists, primitives)
- **Boundary considerations**: Object serialization in C

**Callable contract**:
- Required imports: `import ujson`
- Input: Python object, optional flags (indent, ensure_ascii, etc.)
- Returns: `str` (JSON string)
- Raises: Various exceptions on non-serializable objects

### 3. ujson.decode (alias for loads)
- Same as loads

### 4. ujson.encode (alias for dumps)
- Same as dumps

## Recommended Fuzzing Approach
1. **Primary focus: ujson.loads()** - highest security impact, parses untrusted input
2. Use atheris/LibFuzzer for coverage-guided fuzzing
3. Compile ujson with sanitizers (ASAN, UBSAN) for memory error detection
4. Use both string and bytes input
5. Secondary: ujson.dumps() with random Python objects

## Oracles
- Must-hold: No crashes, no memory corruption, no buffer overflows
- Acceptable exceptions: JSONDecodeError, ValueError, TypeError, OverflowError
- Suspicious exceptions: MemoryError (could indicate buffer issues), SegmentationFault

## Notes
- This is a C extension - memory safety bugs are possible
- Existing tests/fuzz.py provides good reference for fuzzing approach
- Consider building with debug flags: CFLAGS='-DDEBUG -fsanitize=address'
