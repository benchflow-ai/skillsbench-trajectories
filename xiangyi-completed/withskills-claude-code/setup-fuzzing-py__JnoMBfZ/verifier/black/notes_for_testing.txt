# Black Library - Important Functions for Fuzzing

## Overview
Black is an uncompromising Python code formatter. It parses Python source code and reformats it according to a strict style.

## Important Files for Fuzzing
1. src/black/__init__.py - Contains format_str(), format_file_contents() main formatting entry points
2. src/black/parsing.py - Contains lib2to3_parse() and parse_ast() for Python source parsing
3. src/blib2to3/pgen2/driver.py - Low-level parser driver
4. src/blib2to3/pgen2/tokenize.py - Python tokenizer

## Selected Functions Under Test (FUTs)

### 1. format_str (src/black/__init__.py:1177)
- **Why this target**: Main entry point for formatting Python source code strings
- **Input surface**: String input (src_contents) - arbitrary Python source code
- **Boundary considerations**: Parses Python with lib2to3, transforms AST, regenerates code
- **Complexity**: Very high - full parsing pipeline, AST transformation, line splitting

**Callable contract**:
- Required imports: `from black import format_str, Mode`
- Input: `src_contents: str`, `mode: Mode`
- Returns: `str` (formatted code)
- Raises: Various exceptions on invalid input

**Input model**:
- Primary payload type: str (Python source code)
- Edge classes: Invalid syntax, edge Python syntax, deeply nested structures, unicode, long lines

### 2. lib2to3_parse (src/black/parsing.py:55)
- **Why this target**: Core Python source parsing function
- **Input surface**: String input (src_txt) - Python source code
- **Boundary considerations**: Uses lib2to3 grammar-based parsing

**Callable contract**:
- Required imports: `from black.parsing import lib2to3_parse`
- Input: `src_txt: str`
- Returns: `Node` (parse tree)
- Raises: `InvalidInput` on parse failure

### 3. parse_ast (src/black/parsing.py:137)
- **Why this target**: Python AST parsing for safety checks
- **Input surface**: String input (src) - Python source code

**Callable contract**:
- Required imports: `from black.parsing import parse_ast`
- Input: `src: str`
- Returns: `ast.AST`
- Raises: `SyntaxError` on invalid code

## Recommended Fuzzing Approach
1. Focus on `format_str()` as primary target - comprehensive formatting pipeline
2. Use `Mode()` with default settings for simplicity
3. Use atheris/LibFuzzer for coverage-guided fuzzing
4. Accept common exceptions as expected: SyntaxError, InvalidInput, NothingChanged
5. Target crashes, hangs, assertion failures

## Oracles
- Must-hold: No crashes, no hangs, no memory corruption
- Acceptable exceptions: SyntaxError, InvalidInput, NothingChanged, TokenError
- Suspicious exceptions: AttributeError, KeyError, RecursionError, AssertionError (except AST safety)
