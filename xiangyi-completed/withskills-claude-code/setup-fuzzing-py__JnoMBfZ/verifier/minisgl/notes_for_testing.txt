# MiniSGL Library - Important Functions for Fuzzing

## Overview
MiniSGL appears to be an inference engine framework for LLM serving. It contains core data structures for handling requests, batches, sampling, and scheduling.

## Important Files for Fuzzing
1. python/minisgl/core.py - Core data structures (SamplingParams, Req, Batch, Context)
2. python/minisgl/tokenizer/ - Tokenizer implementations
3. python/minisgl/scheduler/ - Request scheduling
4. python/minisgl/engine/ - Engine implementation

## Selected Functions Under Test (FUTs)

### 1. SamplingParams (python/minisgl/core.py:15)
- **Why this target**: Core data class for sampling parameters
- **Input surface**: Float and int parameters (temperature, top_k, top_p, max_tokens)
- **Boundary considerations**: Edge values for sampling parameters

**Callable contract**:
- Required imports: `from minisgl.core import SamplingParams`
- Input: `temperature: float`, `top_k: int`, `top_p: float`, etc.
- Returns: SamplingParams object

**Input model**:
- Primary payload type: numeric values (float, int)
- Edge classes: Negative values, extreme values, NaN, Inf

### 2. Req (python/minisgl/core.py:28)
- **Why this target**: Request data structure for inference
- **Input surface**: torch.Tensor (input_ids), various int parameters
- **Boundary considerations**: Validates indices and lengths

Note: This library has dependencies on torch and potentially CUDA, making fuzzing more complex.
It may require mocking or specific hardware.

## Recommended Fuzzing Approach
1. Focus on SamplingParams validation as simpler target
2. Use property-based testing with numeric edge cases
3. Mock torch dependencies if needed
4. This library may be less suitable for traditional LibFuzzer fuzzing due to torch dependency

## Oracles
- Must-hold: No crashes, proper assertion handling
- Acceptable exceptions: AssertionError (for invalid inputs), ValueError
- Suspicious exceptions: AttributeError, RuntimeError
