UJSON LIBRARY - FUZZING TARGET NOTES
===================================

PRIMARY TARGETS FOR FUZZING:

1. JSON_DecodeObject() [C extension]
   File: /app/ujson/src/ujson/lib/ultrajsondec.c (lines 790-834)
   Input: Raw JSON buffer, buffer size, decoder configuration
   Why: Main JSON parser entry point with recursive descent parsing
   Tests: Deeply nested structures, malformed JSON, unicode edge cases
   Crashes: Stack exhaustion, buffer overflow, integer overflow

2. decode_string() [C extension]
   File: /app/ujson/src/ujson/lib/ultrajsondec.c (lines 362-587)
   Input: JSON string content with escape sequences
   Why: Complex escape sequence and UTF-8 validation
   Tests: Escape sequences, surrogate pairs, overlong UTF-8
   Crashes: Integer overflow in buffer reallocation, UTF-8 validation errors

3. decode_numeric() [C extension]
   File: /app/ujson/src/ujson/lib/ultrajsondec.c (lines 91-247)
   Input: Numeric literals (integers, floats, special values)
   Why: Integer overflow detection with multiple type transitions
   Tests: Boundary values, NaN/Infinity, overflow limits
   Crashes: Integer multiplication overflow, type promotion edge cases

4. encode() [C extension]
   File: /app/ujson/src/ujson/lib/ultrajsonenc.c (lines 665-852)
   Input: Python objects with various types (dict, list, custom)
   Why: Recursive encoding with depth enforcement
   Tests: Deeply nested objects, circular references, custom iterators
   Crashes: Stack exhaustion, buffer overflow, iterator state corruption

5. JSONToObj() [Python C API]
   File: /app/ujson/src/ujson/python/JSONtoObj.c (lines 163-286)
   Input: str, bytes, bytearray, or objects with buffer protocol
   Why: Python wrapper handling multiple input types
   Tests: Various input types, encoding edge cases, buffer protocol
   Crashes: Memory management issues, PyPy compatibility

SECURITY WARNINGS:
- Library in maintenance-only mode (per README.md)
- C implementation with manual memory management
- Complex string/escape processing with multiple code paths
- Known vulnerability: integer overflow in buffer calculations

ATTACK SURFACES:
- JSON string parsing (escape sequences, unicode, surrogate pairs)
- Numeric parsing (overflow detection, NaN/Infinity)
- Recursive object/array encoding (depth, circular refs)
- Python buffer protocol (memory management)
- UTF-8 validation (overlong sequences)

FUZZING STRATEGY:
- Generate malformed JSON with incomplete structures
- Create deeply nested arrays/objects (exceed 1024 limit)
- Test all escape sequence variations
- Unicode surrogate pairs and overlong UTF-8
- Large numeric values at overflow boundaries
- Custom Python objects with special iteration

TEST CORPUS IDEAS:
- Valid JSON from test suite
- Malformed JSON (unclosed braces, missing commas)
- Deep nesting (1024+ levels)
- All escape sequences (\", \\, \/, \b, \f, \n, \r, \t)
- Unicode escapes with surrogate pairs
- Numeric edge cases (max int, float precision limits)
- Circular reference objects
- Custom Python types with __json__ methods

POTENTIAL VULN CLASSES:
- Stack exhaustion (deep nesting)
- Memory exhaustion (large escape buffers)
- Buffer overflow (UTF-8, surrogate pairs)
- Integer overflow (buffer sizes)
- Use-after-free (escape buffer realloc)
