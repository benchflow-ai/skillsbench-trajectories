MINISGL LIBRARY - FUZZING TARGET NOTES
=====================================

PRIMARY TARGETS FOR FUZZING:

1. TokenizeManager.tokenize()
   File: /app/minisgl/python/minisgl/tokenizer/tokenize.py (lines 16-33)
   Input: List[TokenizeMsg] with text (str or List[Dict[str,str]])
   Why: Critical entry point converting raw text to token IDs for inference
   Tests: Various text types, chat templates, Unicode edge cases
   Crashes: Chat template injection, unbounded text handling

2. DetokenizeManager.detokenize()
   File: /app/minisgl/python/minisgl/tokenizer/detokenize.py (lines 74-115)
   Input: List[DetokenizeMsg] with uid, token ID, finished flag
   Why: State-dependent decoding with incremental streaming and offset tracking
   Tests: State corruption, uid ordering, Unicode replacement handling
   Crashes: State dict corruption, malformed token sequences

3. serialize_type() + deserialize_type()
   File: /app/minisgl/python/minisgl/message/utils.py (lines 20-69)
   Input: Dict with __type__ field and nested values
   Why: Recursive object instantiation without validation
   Tests: Type confusion, malformed class names, circular references
   Crashes: Missing class errors, signature validation failures

4. Sampler.prepare() + sample_impl()
   File: /app/minisgl/python/minisgl/engine/sample.py (lines 24-68)
   Input: SamplingParams (temperature, top_k, top_p), logits tensor
   Why: Numerical processing with weak parameter validation
   Tests: NaN, Infinity, negative values, out-of-bounds ranges
   Crashes: Numerical instability, tensor operation failures

5. load_hf_weight() + _merge_state_dict()
   File: /app/minisgl/python/minisgl/models/weight.py (lines 52-99)
   Input: Model path string, state dict with arbitrary keys
   Why: File system access and tensor manipulation with minimal validation
   Tests: Corrupted files, missing keys, dimension mismatches
   Crashes: KeyError on missing weights, tensor concatenation failures

ATTACK SURFACES:
- Tokenization (unbounded text, chat template injection)
- Deserialization (type confusion, unsafe instantiation)
- Sampling parameters (numerical edge cases, NaN/Inf)
- Weight loading (file system, tensor operations)
- State management (uid handling, streaming state)

FUZZING STRATEGY:
- Generate arbitrary strings/JSON for tokenization
- Inject malicious __type__ values in deserialization
- Create extreme parameter combinations (NaN, Inf, negatives)
- Send overlapping uid values and out-of-order messages
- Corrupt safetensors files and provide missing keys

TEST CORPUS IDEAS:
- Valid prompts from test suite
- Malformed JSON and chat templates
- Extreme sampling parameters
- Unicode text variations
- Model files with missing/corrupted weights
- Large/deeply nested structures
