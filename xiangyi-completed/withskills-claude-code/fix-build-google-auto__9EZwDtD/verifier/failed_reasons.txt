# Build Error Analysis for google/auto Project

## Build Errors Identified

### Issue 1: tools.jar Dependency Not Found in Java 11 (FIXED)
- **Error**: Could not resolve dependencies for project com.google.auto:auto-common:jar:1.0-SNAPSHOT: Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
- **Root Cause**:
  - The compile-testing v0.7/v0.6/v0.8 libraries declare a system-scoped dependency on com.sun:tools
  - In Java 7-10, tools.jar was available in the JDK
  - In Java 11+, tools.jar was removed and its classes were merged into main JDK modules
- **Solution**: Exclude the com.sun:tools dependency from compile-testing in all modules
- **Files Modified**:
  - /home/travis/build/failed/google/auto/pom.xml (removed problematic profiles)
  - /home/travis/build/failed/google/auto/common/pom.xml (added exclusion)
  - /home/travis/build/failed/google/auto/factory/pom.xml (added exclusion)
  - /home/travis/build/failed/google/auto/service/pom.xml (added exclusion)
  - /home/travis/build/failed/google/auto/value/pom.xml (added exclusion)
- **Status**: FIXED - auto-common module now compiles successfully

### Issue 2: Missing javax.annotation.Generated Class (NEW)
- **Error**: /auto-factory/src/main/java/com/google/auto/factory/processor/FactoryWriter.java:[39,24] cannot find symbol - class Generated in package javax.annotation
- **Root Cause**:
  - The javax.annotation.Generated annotation was part of tools.jar in Java 7-10
  - In Java 11+, this annotation is not available by default
  - The @Generated annotation is now part of the javax.annotation-api module
- **Solution**: Add javax.annotation-api dependency to affected modules (factory, value, service)
- **Files to Modify**:
  - /home/travis/build/failed/google/auto/factory/pom.xml
  - /home/travis/build/failed/google/auto/service/pom.xml
  - /home/travis/build/failed/google/auto/value/pom.xml

## Technical Details

The google/auto project was designed for Java 7 (see .travis.yml configuration). It relied on tools.jar which was part of the JDK. In Java 11, Oracle removed tools.jar and distributed its contents through standard Maven repositories as javax.annotation-api.

## Patches Created

### Patch 1: Remove problematic profiles from parent POM (patch_1.diff)
- **File**: pom.xml (parent)
- **Change**: Removed the "default-profile" and "mac-profile" profiles that attempt to locate tools.jar
- **Reason**: These profiles are no longer needed for Java 9+ and cause the build to fail when tools.jar doesn't exist

### Patch 2: Exclude tools.jar from compile-testing dependency (patch_2.diff)
- **Files**: common/pom.xml, factory/pom.xml, service/pom.xml, value/pom.xml
- **Change**: Added `<exclusion>` for com.sun:tools in compile-testing dependencies
- **Reason**: The compile-testing library v0.6/v0.7/v0.8 declares a system-scoped dependency on tools.jar which doesn't exist in Java 11

### Patch 3: Add javax.annotation-api dependency (patch_3.diff)
- **Files**: factory/pom.xml, service/pom.xml, value/pom.xml
- **Change**: Added dependency on javax.annotation-api v1.3.2
- **Reason**: The javax.annotation.Generated class, which was part of tools.jar in Java 7-10, is now provided by the javax.annotation-api module

### Additional Changes:
- **Updated parent versions**: Changed all module pom.xml files to reference auto-parent v4-SNAPSHOT instead of v3 to use the updated parent with the removed profiles
