IPYTHON FUZZING ANALYSIS - NOTES FOR TESTING

## IMPORTANT FUNCTIONS FOR FUZZING

### Top 5 Targets - CRITICAL to HIGH Priority:

1. **split_user_input()** - Core input line splitting (CRITICAL)
   - File: IPython/core/splitinput.py:43-68
   - Entry point for ALL user input in prefilter pipeline
   - Complex regex pattern matching with special characters
   - Returns 4-tuple: (whitespace_prefix, escape_char, function_name, rest_of_line)

   Regex Pattern:
   ```
   line_split = re.compile(r"""
     ^(\s*)               # whitespace
     ([,;/%]|!!?|\?\??)?  # escape chars: , ; / % ! !! ? ??
     \s*(%{0,2}[\w\.\*]*) # function name with optional %
     (.*?$|$)             # rest of line
   """, re.VERBOSE)
   ```

   Key Edge Cases:
   - No match fallback to split(None, 1)
   - Very long input strings (>1MB)
   - Regex catastrophic backtracking potential
   - Unicode function names (你好, 😀)
   - Mixed escape characters (?, ??, !!, etc.)
   - Only whitespace/escape chars (no function name)
   - Null bytes and control characters

   Fuzzing Focus: Malformed escapes, long repeating patterns, Unicode edge cases

2. **arg_split()** - Shell-like argument splitting (CRITICAL)
   - File: IPython/utils/_process_common.py:185-220
   - Processes command-line arguments for all magics
   - Uses shlex with error handling
   - `strict=True`: raises ValueError, `strict=False`: partial parse

   Key Implementation:
   ```python
   lex = shlex.shlex(s, posix=posix)
   lex.whitespace_split = True
   lex.commenters = ''  # Disabled
   ```

   Edge Cases:
   - Unmatched quotes (', ", """)
   - Escape sequences (\n, \t, \\)
   - Very long argument lists
   - Null bytes and control characters
   - Triple quoted strings
   - Backslash edge cases (\\ vs \n)
   - Comments disabled but # in input

   Known Issues: shlex has edge cases with complex escape sequences
   Fuzzing Focus: Quote matching, escape handling, backslash sequences

3. **TransformerManager.transform_cell()** - Input transformation (CRITICAL)
   - File: IPython/core/inputtransformer2.py:635-644
   - Orchestrates entire transformation pipeline for code
   - Applies: cleanup, line, and token transformers
   - Loop limit: TRANSFORM_LOOP_LIMIT = 50

   Pipeline Steps:
   1. Ensure trailing newline
   2. Apply cleanup_transforms (leading_empty_lines, indents, prompts)
   3. Apply line_transforms (cell_magic)
   4. Apply token_transforms (MagicAssign, SystemAssign, EscapedCommand, HelpEnd)

   Edge Cases:
   - Infinite transformation loops (test loop limit)
   - Cell magic without blank line at end
   - Deeply nested parentheses/brackets
   - Magic assignments with complex expressions
   - System commands with special characters
   - Very large cells (>100MB)
   - Binary data in cell magic body
   - Token explosion scenarios

   Fuzzing Focus: Loop limit bypasses, token explosion, nested structures

4. **parse_argstring()** - Magic argument parsing (HIGH)
   - File: IPython/core/magic_arguments.py:164-170, 195-198
   - Parses arguments for @magic_arguments decorated functions
   - Uses argparse with custom MagicArgumentParser
   - Validates argument names with NAME_RE regex

   Key Features:
   ```python
   NAME_RE = re.compile(r"[a-zA-Z][a-zA-Z0-9_-]*$")
   ```
   - Supports abbreviated options if unique
   - Partial parsing mode available
   - Help request handling (--help, -h)

   Used By: %run, %timeit, %debug, %load, %paste, and many others

   Edge Cases:
   - Very long option names and values
   - Invalid option formats (---, ----opt)
   - Type coercion attacks
   - Argument names shadowing builtins
   - Arguments that look like filenames
   - Null bytes in arguments
   - Multiline argument values

   Fuzzing Focus: Argparse injection, NAME_RE ReDoS, type coercion

5. **prefilter_line()** - Main prefiltering function (HIGH)
   - File: IPython/core/prefilter.py:263-305
   - Applied to every line of user input
   - Applies transformers and finds/executes handlers
   - Handler types: MagicHandler, ShellEscapeHandler, AliasHandler, AutoCallHandler

   Flow:
   1. Check if line is empty (early return)
   2. Apply transform_line() via all transformers
   3. Create LineInfo object
   4. Find handler via checkers
   5. Call handler.handle() and return result

   Edge Cases:
   - Very long lines (>100MB)
   - Only whitespace/special chars
   - Unicode function names
   - Mixed handler triggers
   - Continuation lines with unusual whitespace
   - Binary data in line

   Global State: self.shell._last_input_line = line (information leak potential)

   Fuzzing Focus: Handler selection, LineInfo creation, transformer composition

## FUZZING STRATEGY

### Recommended Input Categories:
1. Empty and whitespace variations
2. Very long strings (megabytes)
3. Unicode and special characters
4. Escape sequence combinations
5. Handler trigger patterns
6. Format string injection patterns
7. Mixed valid/invalid components

### Priority by FUT:
1. split_user_input() - 40% resources (entry point)
2. arg_split() - 30% resources (critical for magics)
3. transform_cell() - 15% resources (code generation)
4. parse_argstring() - 10% resources (magic args)
5. prefilter_line() - 5% resources (integration)

### Expected High-Value Findings:
- ReDoS in regex patterns
- Infinite loops in transformation pipeline
- Argument injection vulnerabilities
- Handler confusion/bypass attacks
- Memory exhaustion via large inputs
- Unicode handling edge cases
