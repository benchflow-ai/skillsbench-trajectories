## IMPORTANT FUNCTIONS FOR FUZZING

### Top 5 Targets - CRITICAL to HIGH Priority:

1. **lib2to3_parse()** - Core parser (CRITICAL)
   - File: src/black/parsing.py:55
   - Signature: lib2to3_parse(src_txt: str, target_versions: Collection[TargetVersion] = ()) -> Node
   - Foundation for entire formatting pipeline
   - Parses Python code using modified lib2to3 grammar
   - Handles: all Python syntax, f-strings, pattern matching (3.10+)

   Key Features:
   - Grammar selection based on target_versions
   - Supports Python 3.6 through 3.12+
   - Returns AST Node or raises exception
   - Error recovery mechanisms

   Edge Cases:
   - Parser crashes with malformed syntax
   - DoS via deeply nested structures
   - Unicode/encoding issues
   - F-string edge cases
   - Type annotations with complex syntax
   - Pattern matching (match/case) validation
   - Walrus operator edge cases
   - Invalid UTF-8 sequences
   - Very long single tokens (identifiers, strings)

   Fuzzing Focus:
   - Deeply nested parentheses: (((((...))))
   - Invalid syntax variations
   - Grammar conflicts between Python versions
   - Target version edge cases
   - Extreme input sizes

   Crashes Here Impact: Everything downstream depends on this

2. **format_str()** - End-to-end formatter (CRITICAL)
   - File: src/black/format_str function in __init__.py:1177
   - Signature: format_str(src_contents: str, *, mode: Mode, lines: Collection[tuple[int, int]] = ()) -> str
   - Primary public API for formatting
   - Exercises entire formatting pipeline
   - Entry point for most Black usage

   Mode Configuration Parameters:
   - target_versions: Set of Python versions
   - line_length: Line length limit
   - string_normalization: Normalize quotes
   - is_pyi: Treat as type stub
   - magic_trailing_comma: Preserve trailing commas
   - experimental_string_processing: Experimental mode
   - preview: Preview features enabled

   Key Operations:
   1. Parse input with lib2to3_parse()
   2. Transform AST if needed
   3. Generate formatted lines
   4. Render output

   Edge Cases:
   - Very long lines (>10000 characters)
   - Nested structures with long content
   - String escaping edge cases
   - Unicode in code
   - Format twice stability (idempotence)
   - Partial line ranges (lines parameter)
   - Mode combinations causing conflicts
   - Large files (>100MB)
   - Memory exhaustion with deeply nested code

   Fuzzing Focus:
   - All Mode parameter combinations
   - Format stability: format(format(code)) == format(code)
   - Partial range formatting
   - Very long input files
   - Edge cases in transformation

   Oracle: Idempotence - formatting twice should produce identical output

3. **iter_fexpr_spans()** - F-string expression extraction (HIGH)
   - File: src/black/trans.py:1309
   - Signature: iter_fexpr_spans(s: str) -> Iterator[tuple[int, int]]
   - Extracts expression positions within f-string content
   - Unique to Black - complex brace matching
   - Critical for f-string formatting

   Key Logic:
   - Iterate through f-string content
   - Track brace nesting depth
   - Identify expression boundaries
   - Handle quote nesting
   - Return (start, end) tuples

   Edge Cases:
   - Nested braces: {{ {{{var}}} }}
   - Mixed quotes within expressions: f"{x['key']}"
   - Deeply nested expressions: f"{f"{f'{x}'}"}"
   - Escaped braces: f"{{escaped}}"
   - Quotes in expressions: f"{s.format('{x}')}"
   - Malformed f-strings (for validation)
   - Very long f-string content
   - Special characters in expressions

   Potential Vulnerabilities:
   - Off-by-one errors in span calculation
   - Index out of bounds
   - Infinite loops in brace matching
   - Incorrect depth tracking

   Fuzzing Focus:
   - Nested brace and quote combinations
   - Boundary conditions
   - Malformed f-string patterns
   - Expression length variations
