MINISGL FUZZING ANALYSIS - NOTES FOR TESTING

## IMPORTANT FUNCTIONS FOR FUZZING

### High Priority Targets:

1. **deserialize_type()** - Message deserialization (CRITICAL)
   - File: message/utils.py
   - Handles deserialization of custom message types
   - Entry point for untrusted data
   - Focus: Type parsing, buffer overflow, state machine

2. **RadixCacheManager._walk()** - Tree traversal for cache (CRITICAL)
   - File: kvcache/radix_manager.py
   - RadixTree KV cache implementation
   - Complex tree traversal logic
   - Focus: Tree structure validation, traversal correctness

3. **DetokenizeManager.detokenize()** - Token decoding (HIGH)
   - File: tokenizer/detokenize.py
   - Token decoding with state machine
   - Stateful processing of token sequences
   - Focus: State transitions, edge cases in token handling

4. **Scheduler._process_one_msg()** - Message routing (HIGH)
   - File: scheduler/scheduler.py
   - Core scheduling loop message processor
   - Routes messages through system
   - Focus: Message validation, routing logic

5. **OpenAICompletionRequest validation** - HTTP request validation (MEDIUM)
   - File: server/api_server.py
   - Validates incoming API requests
   - Focus: Input validation, boundary conditions

## TEST STRATEGY

- Target deserialization functions with malformed data
- Test tree operations with invalid node structures
- Generate token sequences with edge cases
- Fuzz message routing with invalid message types
- Test HTTP request validation with malformed payloads

## EDGE CASES TO EMPHASIZE

- Empty/null inputs
- Maximum size constraints
- Invalid type combinations
- Malformed message formats
- Deep nesting/recursion
