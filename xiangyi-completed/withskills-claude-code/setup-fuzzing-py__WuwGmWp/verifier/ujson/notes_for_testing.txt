# ujson Library - Fuzzing Target Notes

## Library Overview
ujson (UltraJSON) is an ultra fast JSON encoder and decoder written in C
with Python bindings. It's designed to be a drop-in replacement for Python's
standard json module. Key fuzzing targets are the encode/decode functions
which handle untrusted input.

## Important Files for Fuzzing
- src/ujson/python/ujson.c (score: 95) - Python module interface
- src/ujson/lib/ultrajsondec.c (score: 95) - JSON decoder in C
- src/ujson/lib/ultrajsonenc.c (score: 95) - JSON encoder in C
- src/ujson/python/JSONtoObj.c (score: 90) - JSON to Python object conversion
- src/ujson/python/objToJSON.c (score: 90) - Python object to JSON conversion

## Selected Functions Under Test (FUTs)

### FUT 1: ujson.decode() / ujson.loads()
- File: (C extension) exposed as ujson.decode/loads
- Why: Primary JSON decoding function - parses untrusted input
- Input: s (str | bytes | bytearray)
- Harnessability: HIGH
- Input model: JSON strings (valid and invalid)
- Oracles: No crash, JSONDecodeError for invalid JSON (acceptable)
- Edge cases: Malformed JSON, deep nesting, large numbers, Unicode, null bytes

### FUT 2: ujson.encode() / ujson.dumps()
- File: (C extension) exposed as ujson.encode/dumps
- Why: JSON encoding function with various options
- Input: obj (Any), various options (ensure_ascii, indent, etc.)
- Harnessability: HIGH
- Input model: Python objects (dicts, lists, strings, numbers, etc.)
- Oracles: No crash, TypeError for non-serializable (acceptable)
- Edge cases: Deep nesting, circular refs, special floats (nan, inf), large ints

### FUT 3: ujson.load()
- File: (C extension) exposed as ujson.load
- Why: File-like object reading and JSON parsing
- Input: fp (file-like object with read method)
- Harnessability: MEDIUM (requires file-like object)
- Input model: StringIO/BytesIO containing JSON data
- Oracles: No crash, JSONDecodeError for invalid JSON

## Recommended Harness Approach
1. Create fuzz driver that calls ujson.decode() with fuzzed strings/bytes
2. Also fuzz ujson.encode() with random Python objects (from atheris)
3. Catch expected exceptions (JSONDecodeError, TypeError, OverflowError)
4. Any other exceptions or crashes indicate bugs
5. Can combine both: encode random objects, decode back, verify round-trip

## Seed Corpus Ideas
- Valid JSON: "{}", "[]", '{"key": "value"}', '[1, 2, 3]'
- Numbers: "0", "123", "-456", "3.14159", "1e10", "1E-10"
- Strings: '"hello"', '"\\u0000"', '"\\n\\r\\t"'
- Nested: '{"a": {"b": {"c": 1}}}'
- Edge values: "null", "true", "false"
- Invalid JSON: "{", "[1,]", "{'key': 'value'}", "NaN", "Infinity"
- Unicode: '"\u4e2d\u6587"', '"\ud83d\ude80"'
- Large: Very long strings, deep nesting, huge numbers

## Dependencies
None (pure C extension with no Python dependencies beyond stdlib)

## Notes
ujson already has a fuzz.py file in tests/ for brute-force fuzzing of encode.
Our fuzz driver will complement this by using LibFuzzer for coverage-guided
fuzzing of both encode and decode paths.
