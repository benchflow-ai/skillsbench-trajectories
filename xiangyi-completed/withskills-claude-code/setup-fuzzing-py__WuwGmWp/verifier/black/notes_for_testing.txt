# Black Library - Fuzzing Target Notes

## Library Overview
Black is the uncompromising Python code formatter. It parses Python source code
and reformats it according to a consistent style. Key areas for fuzzing are
parsing and formatting of Python code.

## Important Files for Fuzzing
- src/black/__init__.py (score: 95) - Main entry points: format_str, format_file_contents
- src/black/parsing.py (score: 95) - lib2to3_parse, parse_ast functions
- src/blib2to3/ (score: 90) - Python parser (lib2to3 fork)
- src/black/linegen.py (score: 80) - Line generation and transformation

## Selected Functions Under Test (FUTs)

### FUT 1: format_str()
- File: src/black/__init__.py:1177
- Why: Primary API for formatting Python source code strings
- Input: src_contents (str), mode (Mode object)
- Harnessability: HIGH
- Input model: Arbitrary Python source code strings
- Oracles: No crash, InvalidInput for unparseable code (acceptable)
- Edge cases: Malformed Python, Unicode, deep nesting, long lines, edge syntax

### FUT 2: lib2to3_parse()
- File: src/black/parsing.py:55
- Why: Core parsing function that converts source to AST
- Input: src_txt (str), target_versions (Collection[TargetVersion])
- Harnessability: HIGH
- Input model: Python source code strings
- Oracles: No crash, InvalidInput for syntax errors (acceptable)
- Edge cases: Invalid syntax, mixed Python versions, edge tokens

### FUT 3: parse_ast()
- File: src/black/parsing.py:137
- Why: Parses source using Python's ast module for safety check
- Input: src (str)
- Harnessability: HIGH
- Input model: Python source code strings
- Oracles: No crash, SyntaxError for invalid code (acceptable)
- Edge cases: Version-specific syntax, type comments

### FUT 4: format_file_contents()
- File: src/black/__init__.py (around line 1100)
- Why: Full formatting pipeline including decode/encode
- Input: src_contents (str), fast (bool), mode (Mode)
- Harnessability: HIGH
- Input model: Python source code strings
- Oracles: No crash, NothingChanged or InvalidInput (acceptable)

## Recommended Harness Approach
1. Create fuzz driver that calls format_str() with fuzzed Python code strings
2. Use a simple Mode() object with default settings
3. Catch expected exceptions (InvalidInput, NothingChanged)
4. Any other exceptions indicate bugs
5. Can also fuzz with variations in Mode settings (line_length, target_versions)

## Seed Corpus Ideas
- Valid Python code snippets: "def f(x): return x"
- Edge syntax: decorators, async/await, walrus operator, match statements
- Unicode identifiers: "def \u03bb(x): pass"
- Nested structures: deeply nested functions, classes
- Long lines: very long string literals, long expressions
- Comments: various comment styles, trailing comments
- Formatting edge cases: trailing commas, blank lines
