# MiniSGL Library - Fuzzing Target Notes

## Library Overview
MiniSGL is a minimal LLM inference library for serving language models.
It handles tokenization, detokenization, message passing, and text processing.
Key fuzzing targets are text processing and deserialization functions.

## Important Files for Fuzzing
- python/minisgl/tokenizer/detokenize.py (score: 90) - Detokenization with text processing
- python/minisgl/message/utils.py (score: 90) - Serialization/deserialization utilities
- python/minisgl/tokenizer/tokenize.py (score: 80) - Tokenization wrapper

## Selected Functions Under Test (FUTs)

### FUT 1: find_printable_text()
- File: python/minisgl/tokenizer/detokenize.py:39
- Why: Text processing that finds printable substrings - handles CJK and Unicode
- Input: text (str)
- Harnessability: HIGH
- Input model: Arbitrary strings, especially with Unicode, CJK, partial words
- Oracles: Returns valid substring, no crash
- Edge cases: Empty strings, only whitespace, mixed CJK/Latin, surrogate chars

### FUT 2: _is_chinese_char()
- File: python/minisgl/tokenizer/detokenize.py:14
- Why: Character classification for CJK characters - Unicode boundary handling
- Input: cp (int) - Unicode codepoint
- Harnessability: HIGH
- Input model: Integer codepoints (0 to 0x10FFFF)
- Oracles: Returns bool, no crash
- Edge cases: Boundary values, invalid codepoints, edge Unicode ranges

### FUT 3: deserialize_type()
- File: python/minisgl/message/utils.py:52
- Why: Deserializes JSON-like data into typed objects - potential security boundary
- Input: cls_map (dict), data (dict)
- Harnessability: MEDIUM (requires class map)
- Input model: Dictionary with __type__ field and arbitrary values
- Oracles: Returns valid object or raises ValueError
- Edge cases: Missing fields, wrong types, nested structures, malformed tensors

### FUT 4: serialize_type()
- File: python/minisgl/message/utils.py:20
- Why: Serializes objects to JSON-like format
- Input: self (any object)
- Harnessability: MEDIUM
- Input model: Various Python objects
- Oracles: Returns dict with __type__, no crash

## Recommended Harness Approach
1. Create fuzz driver that calls find_printable_text() with fuzzed strings
2. Test _is_chinese_char() with random integers
3. For deserialize_type(), create valid class_map and fuzz the data dict
4. Catch expected exceptions (ValueError, KeyError, AssertionError)

## Seed Corpus Ideas
- Text strings: "hello world", "test text ", "\n", "hello\n"
- CJK text: "\u4e2d\u6587", mixed "hello\u4e2d\u6587world"
- Unicode edge cases: surrogate pairs, replacement char \ufffd
- Serialized data: {"__type__": "SamplingParams", "temperature": 0.0}
- Tensor data: {"__type__": "Tensor", "buffer": b"...", "dtype": "torch.float32"}

## Dependencies
