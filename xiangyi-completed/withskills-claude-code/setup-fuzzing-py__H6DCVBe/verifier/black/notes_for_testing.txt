BLACK LIBRARY - FUZZING NOTES
==============================

Library Overview:
- Black is a Python code formatter
- Parses Python code into AST and reformats it
- Key modules: parsing.py, linegen.py, trans.py, nodes.py

High-Value Fuzzing Targets:
----------------------------

1. black.parsing.lib2to3_parse()
   Location: /app/black/src/black/parsing.py
   Why: Parses Python source code strings into AST
   Input: Python source code as string
   Risk: Parser crashes, infinite loops, memory exhaustion
   Test Focus:
   - Malformed Python syntax
   - Deeply nested structures
   - Very long lines
   - Unicode edge cases
   - Comments with special characters
   - Invalid indentation patterns

2. black.format_str()
   Location: /app/black/src/black/__init__.py
   Why: Main entry point for formatting Python code
   Input: Source code string and mode options
   Risk: Formatting bugs, crashes, infinite loops
   Test Focus:
   - Various Python syntax features
   - Edge cases in AST transformation
   - Mode combinations
   - Target version compatibility

3. black.trans.transform()
   Location: /app/black/src/black/trans.py
   Why: Transforms AST nodes, complex logic
   Input: AST nodes
   Risk: Transformation bugs, infinite recursion
   Test Focus:
   - Deeply nested expressions
   - Complex comprehensions
   - String concatenations
   - F-strings with expressions

4. black.lines.Line processing
   Location: /app/black/src/black/lines.py
   Why: Line-level processing and breaking
   Input: Line objects from parsed code
   Risk: Infinite loops in line breaking
   Test Focus:
   - Very long lines
   - Complex bracket matching
   - Mixed quote styles

5. black.comments.normalize_trailing_commas()
   Location: /app/black/src/black/comments.py
   Why: Comment handling is error-prone
   Input: Code with various comment patterns
   Risk: Comment loss, incorrect placement
   Test Focus:
   - Comments in unusual positions
   - Multi-line comments
   - Comments with special characters

6. black.handle_ipynb_magics processing
   Location: /app/black/src/black/handle_ipynb_magics.py
   Why: Handles Jupyter notebook magic commands
   Input: Jupyter notebook cells with magics
   Risk: Magic command parsing bugs
   Test Focus:
   - Various magic syntaxes
   - Nested magics
   - Invalid magic patterns

Additional Test Considerations:
--------------------------------
- String processing (strings.py)
- Bracket matching (brackets.py)
- Numeric literal normalization (numerics.py)
- Range operations (ranges.py)
- File handling (files.py)
- Different Python target versions
- Preservation of AST semantics (critical invariant)

Oracle Strategies:
------------------
- No crashes on any syntactically valid Python
- AST equivalence: ast.parse(input) ≈ ast.parse(output)
- Idempotence: format(format(x)) == format(x)
- No information loss for valid syntax
- Deterministic output for same input

Dependencies to Install:
------------------------
- platformdirs
- pathspec
- mypy_extensions (check pyproject.toml)
