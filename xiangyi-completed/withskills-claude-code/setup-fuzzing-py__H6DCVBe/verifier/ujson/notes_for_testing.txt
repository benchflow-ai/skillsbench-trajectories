UJSON LIBRARY - FUZZING NOTES
==============================

Library Overview:
- UltraJSON is a fast JSON encoder/decoder with C extensions
- Native C code for performance (security-critical)
- Key files: JSONtoObj.c, objToJSON.c, ujson.c

High-Value Fuzzing Targets:
----------------------------

1. ujson.loads() - JSON decoder
   Location: /app/ujson/src/ujson/python/JSONtoObj.c
   Why: Parses untrusted JSON strings in native C code
   Input: JSON strings
   Risk: CRITICAL - Buffer overflow, integer overflow, crashes, memory corruption
   Test Focus:
   - Deeply nested objects/arrays (stack overflow)
   - Very large numbers (integer/float overflow)
   - Long strings (buffer overflow)
   - Invalid UTF-8 sequences
   - Escape sequence handling
   - Null bytes
   - Incomplete JSON
   - Special numeric values (Infinity, NaN)
   - Very large array/object counts

2. ujson.dumps() - JSON encoder
   Location: /app/ujson/src/ujson/python/objToJSON.c
   Why: Encodes Python objects to JSON in native C
   Input: Python objects (dict, list, str, int, float, etc)
   Risk: CRITICAL - Buffer overflow, type confusion, crashes
   Test Focus:
   - Circular references
   - Very large collections
   - Deeply nested structures
   - Unicode edge cases (surrogate pairs, emoji)
   - Special float values
   - Objects with custom __repr__
   - encode_html_chars option with special chars
   - ensure_ascii option edge cases

3. ujson.dumps() with options
   Input: Python objects + encoder options
   Why: Option combinations can trigger edge cases
   Risk: Option validation bugs, unexpected behavior
   Test Focus:
   - encode_html_chars=True with HTML entities
   - ensure_ascii=False with various Unicode
   - escape_forward_slashes combinations
   - indent option with deep nesting
   - Sort keys with special key names

Additional Test Considerations:
--------------------------------
- Integer boundary values (INT_MAX, INT_MIN)
- Float special values (inf, -inf, nan)
- Very long string keys and values
- Array length limits
- Recursion depth limits
- Memory allocation failures
- Type coercion edge cases
- Encoding round-trip (dumps/loads should be inverse)

Oracle Strategies:
------------------
- CRITICAL: No crashes/segfaults (C code is unsafe)
- No memory leaks (valgrind testing)
- No buffer overflows (ASAN testing)
- For valid JSON: loads(dumps(x)) should preserve structure
- For invalid JSON: loads() should raise JSONDecodeError cleanly
- Output should be valid JSON (validate with standard library)
- Encoder options should be respected

Known Security Considerations:
-------------------------------
- README states "fundamentally ill-suited" for security changes
- Maintenance-only mode
- Known buffer overflow risks
- Recommend migration to orjson for production

Fuzzing Priorities:
-------------------
1. ujson.loads() - HIGHEST PRIORITY (parsing untrusted data in C)
2. ujson.dumps() - HIGH PRIORITY (encoding edge cases)
3. Option combinations - MEDIUM PRIORITY

Dependencies to Install:
------------------------
- Minimal - standard library only
- May need build tools for C extension
