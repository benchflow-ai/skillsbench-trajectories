# Arrow Library - Fuzz Testing Notes

## Library Overview
Arrow is a Python library for working with dates, times, and timestamps. It provides
parsing, formatting, and manipulation of date/time objects.

## Important Files
1. arrow/parser.py - DateTimeParser class for parsing datetime strings
2. arrow/factory.py - ArrowFactory class with `get()` method that accepts various inputs
3. arrow/formatter.py - DateTimeFormatter for formatting datetime objects
4. arrow/api.py - Public API entry points (get, now, utcnow)

## Selected Functions Under Test (FUTs)

### FUT 1: DateTimeParser.parse_iso()
- File: arrow/parser.py:252-371
- Purpose: Parses datetime strings in ISO 8601-like format
- Input: str (datetime_string), bool (normalize_whitespace)
- Why fuzz: Main parsing entry point, handles complex format detection and regex matching
- Oracles: Should not crash, should raise ParserError for invalid inputs
- Acceptable exceptions: ParserError, ParserMatchError

### FUT 2: DateTimeParser.parse()
- File: arrow/parser.py:373-439
- Purpose: Parses datetime string using specified format(s)
- Input: str (datetime_string), str|list (format), bool (normalize_whitespace)
- Why fuzz: Complex regex pattern generation, token parsing logic
- Oracles: Should not crash, should raise ParserMatchError for unmatched formats
- Acceptable exceptions: ParserError, ParserMatchError

### FUT 3: TzinfoParser.parse()
- File: arrow/parser.py:894-937
- Purpose: Parses timezone strings
- Input: str (tzinfo_string)
- Why fuzz: Handles timezone offset parsing, ZoneInfo lookups
- Oracles: Should not crash, should raise ParserError for invalid timezone strings
- Acceptable exceptions: ParserError

### FUT 4: arrow.get()
- File: arrow/api.py:83-86 (delegates to factory.py:85-297)
- Purpose: Main factory function for creating Arrow objects from various inputs
- Input: Various types (str, int, float, datetime, etc.)
- Why fuzz: Entry point that parses strings via DateTimeParser
- Oracles: Should not crash, should raise ParserError or TypeError for invalid inputs
- Acceptable exceptions: ParserError, TypeError, ValueError

## Recommended Fuzzing Strategy
1. Focus on string parsing functions (parse_iso, parse, TzinfoParser.parse)
2. Use crash-only oracle (no exceptions should escape except documented ones)
3. Generate malformed date strings, edge cases (extreme dates, timezone offsets)
4. Test with various locales

## Seed Corpus Ideas
- Valid ISO 8601 dates: "2021-10-12", "2021-10-12T14:30:00"
- Timestamps: "1634025000", "-1000000"
- Timezone strings: "UTC", "+05:30", "America/New_York"
- Malformed inputs: Empty strings, special characters, very long strings
