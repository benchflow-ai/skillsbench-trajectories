# Black Library - Fuzz Testing Notes

## Library Overview
Black is an uncompromising Python code formatter. It parses Python source code and
reformats it according to a consistent style.

## Important Files
1. src/black/__init__.py - Main module with format_str, format_file_contents functions
2. src/black/parsing.py - lib2to3_parse, parse_ast functions for Python parsing
3. src/black/mode.py - Mode dataclass for configuration
4. src/blib2to3/pgen2/driver.py - Low-level parsing driver
5. src/blib2to3/pgen2/tokenize.py - Python tokenizer

## Selected Functions Under Test (FUTs)

### FUT 1: black.format_str()
- File: src/black/__init__.py:1177-1213
- Purpose: Main API for formatting Python code strings
- Input: str (src_contents), Mode (mode), Collection (lines)
- Why fuzz: Primary entry point for code formatting, exercises full parsing and
  transformation pipeline
- Oracles: Should not crash unexpectedly, should raise InvalidInput for unparseable code
- Acceptable exceptions: InvalidInput, NothingChanged

### FUT 2: black.parsing.lib2to3_parse()
- File: src/black/parsing.py:55-102
- Purpose: Parse Python source using lib2to3 grammar
- Input: str (src_txt), Collection (target_versions)
- Why fuzz: Core parsing function, handles multiple Python grammar versions
- Oracles: Should not crash, should raise InvalidInput for syntax errors
- Acceptable exceptions: InvalidInput

### FUT 3: black.parsing.parse_ast()
- File: src/black/parsing.py:137-160+
- Purpose: Parse Python source using AST module
- Input: str (src)
- Why fuzz: AST parsing with multiple Python version fallbacks
- Oracles: Should not crash, should raise SyntaxError for invalid code
- Acceptable exceptions: SyntaxError

### FUT 4: black.format_file_contents()
- File: src/black/__init__.py:1068-1093
- Purpose: Format file contents with validation
- Input: str (src_contents), bool (fast), Mode (mode)
- Why fuzz: Higher-level formatting with safety checks
- Oracles: Should not crash, should raise NothingChanged if no changes needed
- Acceptable exceptions: InvalidInput, NothingChanged

## Recommended Fuzzing Strategy
1. Focus on format_str() as the main fuzz target (accepts string input, returns string)
2. Use crash-only oracle - any unhandled exception indicates a bug
3. Generate malformed Python code, edge cases (deeply nested, very long lines, unicode)
4. Test with default Mode configuration

## Seed Corpus Ideas
- Valid Python snippets: "def f(): pass", "x = 1 + 2"
- Complex Python: "async def f(): await g()"
- Malformed Python: Missing colons, unmatched brackets, invalid syntax
- Edge cases: Empty strings, whitespace only, very long lines
