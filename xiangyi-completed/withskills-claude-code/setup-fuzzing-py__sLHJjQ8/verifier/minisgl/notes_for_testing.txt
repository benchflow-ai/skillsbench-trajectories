# MiniSGL Library - Fuzz Testing Notes

## Library Overview
MiniSGL is a Python library for serving large language models (LLMs). It provides
scheduling, attention backends, KV caching, and message serialization utilities.

## Important Files
1. python/minisgl/message/utils.py - serialize_type, deserialize_type functions
2. python/minisgl/tokenizer/tokenize.py - TokenizeManager for text tokenization
3. python/minisgl/core.py - Core data structures (SamplingParams, Req, Batch)
4. python/minisgl/scheduler/ - Request scheduling logic

## Selected Functions Under Test (FUTs)

### FUT 1: deserialize_type()
- File: python/minisgl/message/utils.py:52-69
- Purpose: Deserialize dict data back into typed objects
- Input: Dict (cls_map), Dict (data)
- Why fuzz: Handles untrusted data deserialization, type reconstruction
- Oracles: Should not crash unexpectedly, should raise ValueError for invalid data
- Acceptable exceptions: ValueError, KeyError, TypeError

### FUT 2: serialize_type()
- File: python/minisgl/message/utils.py:20-35
- Purpose: Serialize typed objects to dict format
- Input: Any object with __dict__
- Why fuzz: Handles various object types, tensor serialization
- Oracles: Should not crash, should return valid dict
- Acceptable exceptions: AssertionError (for non-1D tensors)

### FUT 3: _deserialize_any()
- File: python/minisgl/message/utils.py:38-49
- Purpose: Recursive deserialization of nested structures
- Input: Dict (cls_map), Any (data)
- Why fuzz: Handles nested dict/list structures, type conversion
- Oracles: Should not crash, should raise ValueError for unknown types
- Acceptable exceptions: ValueError, TypeError

## Recommended Fuzzing Strategy
1. Focus on deserialize_type() as the main fuzz target (accepts dict input)
2. Use crash-only oracle for serialization
3. Generate malformed dict structures, edge cases (missing __type__, invalid dtype)
4. Note: This library requires torch, which may limit fuzzing environments

## Seed Corpus Ideas
- Valid serialized data: {"__type__": "Tensor", "buffer": b"...", "dtype": "torch.int32"}
- Malformed data: Missing keys, wrong types, invalid type names
- Nested structures: Lists of dicts, dicts of lists
- Edge cases: Empty dicts, None values, very deep nesting

## Dependencies (from pyproject.toml)
- torch
- transformers>=4.56.0
- msgpack
- numpy (implied by torch)

## Note
This library has heavy dependencies (torch, transformers, sgl_kernel) that may be
difficult to install in a fuzzing environment. Consider fuzzing only the
serialization/deserialization functions which have fewer dependencies.
