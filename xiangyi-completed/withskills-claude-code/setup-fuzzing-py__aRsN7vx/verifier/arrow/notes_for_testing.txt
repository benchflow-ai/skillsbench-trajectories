Library Analysis: Arrow
========================

Arrow is a Python library for better dates & times. It provides human-friendly datetime parsing and formatting.

Important Files for Fuzzing:
----------------------------

1. arrow/parser.py (Score: 10/10)
   - Contains DateTimeParser and TzinfoParser classes
   - Handles parsing of ISO 8601 and custom datetime formats
   - Heavy use of regex patterns for input parsing
   - Multiple input boundaries: strings → datetime objects
   - Rationale: Critical parsing logic with complex regex, format string handling, timezone parsing

2. arrow/factory.py (Score: 8/10)
   - ArrowFactory.get() method with many input types
   - Polymorphic input handling (str, int, float, datetime, date, tzinfo, tuples)
   - Delegates to parser for string inputs
   - Rationale: Central API with diverse input types and dispatching logic

3. arrow/formatter.py (Score: 6/10)
   - DateTimeFormatter for datetime → string conversion
   - Format token parsing and substitution
   - Rationale: Output formatting, less critical but still has parsing logic

Important Functions for Fuzzing:
--------------------------------

1. DateTimeParser.parse_iso() - arrow/parser.py:252
   - Accepts: datetime_string (str), normalize_whitespace (bool)
   - Returns: datetime object
   - High-value target: Parses ISO 8601-like datetime strings
   - Complex logic with multiple format attempts
   - Handles: date/time separation, timezone parsing, format detection
   - Existing tests: test_parser.py has extensive coverage but edge cases likely exist

2. DateTimeParser.parse() - arrow/parser.py:373
   - Accepts: datetime_string (str), fmt (str or List[str]), normalize_whitespace (bool)
   - Returns: datetime object
   - High-value target: Parses datetime with custom format strings
   - Generates regex patterns from format tokens
   - Can raise ParserMatchError
   - Existing tests: Well-tested but format combinations are vast

3. TzinfoParser.parse() - arrow/parser.py:895
   - Accepts: tzinfo_string (str)
   - Returns: dt_tzinfo object
   - High-value target: Parses timezone strings
   - Handles: 'local', 'UTC', 'Z', ISO format offsets, ZoneInfo names
   - Can raise ParserError
   - Existing tests: Covered but corner cases in timezone names/offsets

4. ArrowFactory.get() - arrow/factory.py:85
   - Accepts: Variable args/kwargs with many type combinations
   - Returns: Arrow object
   - High-value target: Main API entry point with polymorphic dispatch
   - Handles: timestamps, strings, datetimes, dates, tzinfo, tuples
   - Delegates to parser for string inputs
   - Existing tests: Good coverage in test_factory.py

5. DateTimeFormatter.format() - arrow/formatter.py:37
   - Accepts: dt (datetime), fmt (str)
   - Returns: formatted string
   - Medium-value target: Format string → output conversion
   - Token substitution via regex

Existing Test Coverage:
-----------------------

- test_parser.py: Extensive parser tests with various formats
  - ISO 8601 formats
  - Custom format strings
  - Timezone parsing
  - Edge cases for various tokens
  - Missing: extreme nesting, very long strings, malformed but partially valid inputs

- test_factory.py: Tests for ArrowFactory.get() with different input types
  - Timestamp conversion
  - String parsing delegation
  - Type errors
  - Missing: boundary values, type confusion attacks

- test_formatter.py: Formatter tests
  - Token replacement
  - Format strings
  - Missing: deeply nested brackets, unusual token combinations

Test Gaps and Fuzzing Opportunities:
------------------------------------

1. Malformed datetime strings that partially match formats
2. Extremely long datetime strings
3. Unusual timezone offset formats
4. Format strings with edge cases (deeply nested brackets, unusual tokens)
5. Very large/small timestamp values
6. Unicode characters in datetime strings
7. Whitespace edge cases
8. Format string and input mismatches that might bypass validation

Selected Functions Under Test for Fuzzing:
------------------------------------------

PRIMARY TARGET 1: DateTimeParser.parse()
- Path: arrow/parser.py:373
- Justification: Core parsing logic, format string + datetime string combination
- Input model: Two strings (datetime_string, format_string)
- Oracle: Should either return valid datetime or raise ParserError/ParserMatchError
- Harness complexity: Medium (instantiate parser, call parse)

PRIMARY TARGET 2: DateTimeParser.parse_iso()
- Path: arrow/parser.py:252
- Justification: ISO 8601 parsing with auto-detection logic
- Input model: Single datetime string
- Oracle: Should either return valid datetime or raise ParserError
- Harness complexity: Low (instantiate parser, call parse_iso)

PRIMARY TARGET 3: TzinfoParser.parse()
- Path: arrow/parser.py:895
- Justification: Timezone string parsing, many formats
- Input model: Single timezone string
- Oracle: Should either return tzinfo or raise ParserError
- Harness complexity: Low (static method, just call with string)

Dependencies:
-------------
- python-dateutil>=2.7.0
- backports.zoneinfo (for Python < 3.9) or zoneinfo
- tzdata (for Python >= 3.9)

Fuzzing Strategy:
----------------
1. Focus on string inputs to parsing functions
2. Test both valid and invalid formats
3. Explore boundary conditions (empty strings, very long strings)
4. Test various encoding edge cases
5. Combine format strings with mismatched datetime strings
