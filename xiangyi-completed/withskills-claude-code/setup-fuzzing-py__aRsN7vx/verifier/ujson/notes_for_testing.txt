Library Analysis: ujson (UltraJSON)
======================================

ujson is a fast JSON encoder and decoder written as a C extension for Python.

Important Files for Fuzzing:
----------------------------

1. src/ujson/lib/ultrajsondec.c (Score: 10/10)
   - Native C code for JSON decoding
   - Parses untrusted JSON input
   - Memory-unsafe operations (manual allocation, buffer handling)
   - Rationale: CRITICAL - Native parser processing untrusted input, high risk for memory safety issues

2. src/ujson/lib/ultrajsonenc.c (Score: 9/10)
   - Native C code for JSON encoding
   - Serializes Python objects to JSON
   - Memory management and buffer operations
   - Rationale: Native encoder with memory operations

3. src/ujson/python/JSONtoObj.c (Score: 9/10)
   - Python C API wrapper for JSON decoding
   - Bridges Python and C decoder
   - Rationale: Entry point for decoding, handles Python/C type conversion

4. src/ujson/python/objToJSON.c (Score: 9/10)
   - Python C API wrapper for JSON encoding
   - Bridges Python and C encoder
   - Rationale: Entry point for encoding, handles Python/C type conversion

Important Functions for Fuzzing:
--------------------------------

1. ujson.loads() / ujson.decode()
   - Python API function (implemented in C)
   - Accepts: s (str | bytes | bytearray)
   - Returns: Any Python object
   - High-value target: Main JSON parsing entry point
   - Native implementation in ultrajsondec.c
   - Can raise JSONDecodeError
   - Existing tests: test_ujson.py, tests/fuzz.py

2. ujson.dumps() / ujson.encode()
   - Python API function (implemented in C)
   - Accepts: obj (Any), plus options (ensure_ascii, indent, etc.)
   - Returns: JSON string
   - High-value target: Main JSON serialization entry point
   - Native implementation in ultrajsonenc.c
   - Existing tests: test_ujson.py, tests/fuzz.py (extensive!)

3. ujson.load()
   - Accepts: fp (SupportsRead)
   - Returns: Any Python object
   - Wraps loads() with file reading
   - Existing tests: test_ujson.py

4. ujson.dump()
   - Accepts: obj (Any), fp (SupportsWrite)
   - Returns: None
   - Wraps dumps() with file writing
   - Existing tests: test_ujson.py

Existing Test Coverage:
-----------------------

- test_ujson.py: Comprehensive unit tests
  - Valid JSON parsing
  - Various data types (strings, numbers, arrays, objects)
  - Unicode handling
  - Error cases
  - Round-trip encoding/decoding
  - Special values (null, true, false, NaN, Infinity)
  - Options testing (ensure_ascii, indent, etc.)

- tests/fuzz.py: EXISTING FUZZER!
  - Brute force fuzzer for ujson.dumps()
  - Generates random JSON-serializable objects
  - Tests reference counting (memory leak detection)
  - Tests various encoding options
  - Permutations of indent, ensure_ascii, encode_html_chars, escape_forward_slashes
  - Missing: Direct fuzzing of ujson.loads() with malformed JSON

Test Gaps and Fuzzing Opportunities:
------------------------------------

1. Malformed JSON strings for loads()
   - Truncated JSON
   - Invalid escape sequences
   - Deeply nested structures
   - Very large numbers
   - Extremely long strings
   - Invalid Unicode sequences

2. Edge cases in encoding
   - Circular references
   - Custom objects with __dict__
   - Extreme numeric values
   - Very deep nesting levels

3. Native code memory safety
   - Buffer overflows in parsing
   - Integer overflows in size calculations
   - Use-after-free scenarios
   - Memory leaks

4. Unicode edge cases
   - Surrogate pairs
   - Invalid UTF-8 sequences
   - Null bytes in strings

Selected Functions Under Test for Fuzzing:
------------------------------------------

PRIMARY TARGET 1: ujson.loads()
- Native C function
- Justification: Parses untrusted JSON input, native code with memory operations
- Input model: JSON string (str | bytes | bytearray)
- Oracle: Should either return valid Python object or raise JSONDecodeError
- Harness complexity: Low (direct function call)
- Risk: HIGH - Native parser, memory safety critical

PRIMARY TARGET 2: ujson.dumps()
- Native C function
- Justification: Serializes arbitrary Python objects, native code
- Input model: Python object (with constraints for JSON-serializable types)
- Oracle: Should either return valid JSON string or raise exception
- Harness complexity: Medium (need to generate valid Python objects)
- Risk: MEDIUM - Native encoder, memory safety important
- Note: Already has fuzzer in tests/fuzz.py

PRIMARY TARGET 3: ujson.loads() with bytes/bytearray
- Same as PRIMARY TARGET 1 but with different input types
- Justification: Different code paths for bytes vs string
- Input model: bytes or bytearray (raw binary input)
- Oracle: Should either parse successfully or raise JSONDecodeError
- Harness complexity: Low

Dependencies:
-------------
- Pure C extension, minimal dependencies
- Python >= 3.10 (based on build system)
- setuptools for building

Fuzzing Strategy:
----------------
1. PRIORITY: Fuzz ujson.loads() with malformed JSON strings
   - This is the highest-risk function (native parser of untrusted input)
   - Focus on memory safety issues

2. Continue fuzzing ujson.dumps() (already has harness)
   - Leverage existing tests/fuzz.py
   - Extend to cover more edge cases

3. Test encoding/decoding round-trip properties
   - For valid JSON, loads(dumps(obj)) should preserve structure
   - Use this as an oracle for correctness

4. Focus on:
   - Deep nesting (stack overflow potential)
   - Large allocations (integer overflow potential)
   - Unicode edge cases
   - Escape sequence handling
   - Number parsing edge cases

Native Code Considerations:
--------------------------
- C extension requires compilation
- Memory errors may manifest as segfaults
- AddressSanitizer (ASAN) recommended for memory error detection
- Valgrind can also help detect memory issues
- Reference counting is critical (refcount fuzzing in tests/fuzz.py)
