# MiniSGL Library - Fuzz Testing Analysis

## Library Overview
MiniSGL is a Python library for LLM (Large Language Model) serving, providing
scheduling, attention backends, KV cache management, and messaging infrastructure.
It includes serialization/deserialization utilities for inter-process communication.

## Important Files for Fuzzing
1. python/minisgl/message/utils.py - Serialization/deserialization (HIGH PRIORITY)
2. python/minisgl/message/tokenizer.py - Tokenizer message handling
3. python/minisgl/message/backend.py - Backend messaging
4. python/minisgl/message/frontend.py - Frontend messaging
5. python/minisgl/server/args.py - Argument parsing

## Selected Functions Under Test (FUTs)

### 1. deserialize_type (python/minisgl/message/utils.py:52)
**Why this target:**
- Deserializes arbitrary dictionary data into Python objects
- Uses dynamic class instantiation based on __type__ field
- Uses getattr for dtype conversion (potential security risk)
- Handles tensor buffers from bytes

**Callable contract:**
- Required imports: from minisgl.message.utils import deserialize_type
- Preconditions: cls_map is dict mapping type names to classes, data is dict
- Determinism: Yes
- External dependencies: torch, numpy

**Input model:**
- Primary payload type: Dict (with __type__ field)
- Edge cases: unknown types, malformed tensors, invalid dtype strings
- Attack vectors: type confusion, buffer overflow via malformed buffer

**Oracles:**
- Must-hold: Should not crash on malformed input
- Acceptable exceptions: KeyError (unknown type), ValueError
- Suspicious exceptions: AttributeError, BufferError, segfault

### 2. _deserialize_any (python/minisgl/message/utils.py:38)
**Why this target:**
- Recursive deserialization of nested structures
- Handles dicts, lists, tuples, primitives
- Entry point for untrusted data

**Callable contract:**
- Required imports: from minisgl.message.utils import _deserialize_any
- Preconditions: cls_map is type mapping dict

**Input model:**
- Primary payload type: Any (dict, list, primitives)
- Edge cases: deeply nested structures, circular references

**Oracles:**
- Must-hold: Should not crash
- Acceptable exceptions: ValueError
- Suspicious exceptions: RecursionError, MemoryError

### 3. serialize_type (python/minisgl/message/utils.py:20)
**Why this target:**
- Serializes Python objects to dicts
- Handles tensors specially (converts to bytes)
- Iterates over __dict__ of arbitrary objects

**Callable contract:**
- Required imports: from minisgl.message.utils import serialize_type
- Preconditions: Object with __dict__ or torch.Tensor

**Input model:**
- Primary payload type: Any Python object
- Edge cases: objects with special attributes, non-serializable types

**Oracles:**
- Must-hold: Should not crash
- Output should be JSON-serializable dict

### 4. BaseTokenizerMsg.decoder (python/minisgl/message/tokenizer.py:17)
**Why this target:**
- Deserializes tokenizer messages
- Uses globals() for class lookup (security risk)
- Processes user-controlled JSON

**Callable contract:**
- Required imports: from minisgl.message.tokenizer import BaseTokenizerMsg
- Preconditions: json is a dict with message structure

**Input model:**
- Primary payload type: Dict (JSON from untrusted source)
- Edge cases: missing fields, type injection via __type__

**Oracles:**
- Must-hold: Should not crash or allow type injection
- Acceptable exceptions: KeyError, TypeError

## Harness Recommendations

2. Use atheris/LibFuzzer for coverage-guided fuzzing

4. Test tensor deserialization with various buffer sizes and dtypes

## Seed Corpus Ideas
- Valid serialized dataclass structures
- Tensor serializations with different dtypes
- Nested message structures
- Edge cases: empty dicts, missing __type__, invalid dtypes

## Risk Flags
- Dynamic type instantiation based on user input
- getattr with user-controlled dtype string
- np.frombuffer with user-controlled buffer
- globals() usage for type lookup
