# UltraJSON (ujson) Library - Fuzz Testing Analysis

## Library Overview
ujson is an ultra-fast JSON encoder and decoder written in C with Python bindings.
It is a drop-in replacement for the standard json library with significantly
better performance. As a C extension handling arbitrary input, it's a prime
target for fuzzing to detect memory safety issues.

## Important Files for Fuzzing
1. src/ujson/python/ujson.c - Python bindings (C)
2. src/ujson/python/JSONtoObj.c - JSON decoding (C)
3. src/ujson/python/objToJSON.c - JSON encoding (C)
4. src/ujson/lib/ultrajsondec.c - Core decoder (C)
5. src/ujson/lib/ultrajsonenc.c - Core encoder (C)
6. tests/fuzz.py - Existing fuzzer (reference)

## Selected Functions Under Test (FUTs)

### 1. ujson.decode / ujson.loads
**Why this target:**
- Primary JSON decoding function
- Parses arbitrary JSON strings from user input
- C extension - potential memory corruption
- Complex parsing logic for all JSON types

**Callable contract:**
- Required imports: import ujson
- Preconditions: s must be str, bytes, or bytearray
- Determinism: Yes
- External dependencies: None

**Input model:**
- Primary payload type: str or bytes (JSON string)
- Edge cases: deeply nested objects, very long strings, special floats (NaN, Inf)
- Attack vectors: buffer overflow, integer overflow, malformed UTF-8

**Oracles:**
- Must-hold: Should not crash or cause memory corruption
- Acceptable exceptions: JSONDecodeError
- Suspicious: segfault, ASAN errors, memory leaks

### 2. ujson.encode / ujson.dumps
**Why this target:**
- Primary JSON encoding function
- Serializes arbitrary Python objects
- C extension handling complex Python objects
- Reference count handling (see existing fuzzer)

**Callable contract:**
- Required imports: import ujson
- Preconditions: obj is Python object (varies)
- Determinism: Yes
- Options: ensure_ascii, encode_html_chars, indent, etc.

**Input model:**
- Primary payload type: Python objects (dict, list, str, numbers)
- Edge cases: deeply nested structures, very large numbers, special floats
- Encoding options variations

**Oracles:**
- Must-hold: Should not crash, reference counts should be preserved
- Acceptable exceptions: OverflowError, TypeError
- Suspicious: segfault, ref count changes, memory leaks

### 3. Roundtrip: decode(encode(obj))
**Why this target:**
- Tests both encoder and decoder together
- Ensures data integrity through roundtrip
- Property testing: decode(encode(x)) should equal x (for valid JSON types)

**Callable contract:**
- decode(encode(obj)) == obj for JSON-compatible objects

**Input model:**
- Primary payload type: JSON-compatible Python objects

**Oracles:**
- Must-hold: Roundtrip preserves values
- Acceptable exceptions: TypeError (for non-JSON types)

### 4. ujson.decode with bytes vs str
**Why this target:**
- Different code paths for bytes and str input
- UTF-8 handling differences
- Potential encoding edge cases

**Callable contract:**
- ujson.decode(s) == ujson.decode(s.encode()) for valid UTF-8

**Input model:**
- Primary payload type: bytes with various encodings

**Oracles:**
- Must-hold: Consistent results for equivalent inputs
- Acceptable exceptions: JSONDecodeError

## Harness Recommendations
1. Primary target: ujson.decode with arbitrary byte strings
2. Use atheris/LibFuzzer for coverage-guided fuzzing
3. Enable ASAN/UBSAN for memory error detection
4. Test encode with various Python objects
5. Test roundtrip property
