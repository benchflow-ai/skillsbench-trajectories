# Arrow Library - Fuzz Testing Analysis

## Library Overview
Arrow is a Python library for parsing, formatting, and manipulating dates and times.
It provides a human-friendly interface for datetime operations with timezone support.

## Important Files for Fuzzing
1. arrow/parser.py - Core datetime parsing logic (HIGH PRIORITY)
2. arrow/factory.py - Factory for creating Arrow objects from various inputs
3. arrow/formatter.py - DateTime formatting logic
4. arrow/util.py - Utility functions including timestamp normalization

## Selected Functions Under Test (FUTs)

### 1. DateTimeParser.parse_iso (arrow/parser.py:252-371)
**Why this target:**
- Input surface: Accepts arbitrary datetime strings
- Parses ISO 8601-like datetime formats from user input
- Complex regex-based parsing with multiple code paths
- Handles timezone parsing, time components, subseconds
- High attack surface for malformed inputs

**Callable contract:**
- Required imports: from arrow.parser import DateTimeParser
- Preconditions: Input must be a string
- Determinism: Yes (no randomness)
- External dependencies: None

**Input model:**
- Primary payload type: str (datetime string)
- Edge cases: empty strings, malformed dates, extreme values, unicode, special chars
- Constraints: None (parser should handle any string gracefully)

**Oracles:**
- Must-hold: Should not crash on any input
- Acceptable exceptions: ParserError, ParserMatchError
- Suspicious exceptions: IndexError, KeyError, RecursionError, MemoryError

### 2. DateTimeParser.parse (arrow/parser.py:373-439)
**Why this target:**
- Parses datetime with custom format strings
- Both datetime_string and format are user-controlled
- Regex generation from format string could be exploited
- Complex token-based parsing

**Callable contract:**
- Required imports: from arrow.parser import DateTimeParser
- Preconditions: format must be str or list of str
- Determinism: Yes

**Input model:**
- Primary payload types: (str, str) - datetime string and format
- Edge cases: mismatched formats, special regex chars in format

**Oracles:**
- Must-hold: Should not crash
- Acceptable exceptions: ParserError, ParserMatchError

### 3. TzinfoParser.parse (arrow/parser.py:894-937)
**Why this target:**
- Parses timezone strings from user input
- Handles various timezone formats (+/-HH:MM, named zones)
- Boundary between user input and system timezone database

**Callable contract:**
- Required imports: from arrow.parser import TzinfoParser
- Preconditions: Input must be a string
- Determinism: Yes

**Input model:**
- Primary payload type: str (timezone string)
- Edge cases: invalid zone names, malformed offsets, empty strings

**Oracles:**
- Must-hold: Should not crash
- Acceptable exceptions: ParserError

### 4. normalize_timestamp (arrow/util.py:73-82)
**Why this target:**
- Converts millisecond/microsecond timestamps to standard timestamps
- Boundary checking logic
- Handles numeric edge cases

**Callable contract:**
- Required imports: from arrow.util import normalize_timestamp
- Preconditions: Input should be float/int
- Determinism: Yes

**Input model:**
- Primary payload type: float
- Edge cases: very large numbers, negative numbers, infinity, NaN

**Oracles:**
- Must-hold: Should not crash
- Acceptable exceptions: ValueError

### 5. iso_to_gregorian (arrow/util.py:86-107)
**Why this target:**
- Converts ISO week dates to Gregorian dates
- Date arithmetic with potential edge cases
- Input validation present but may not cover all cases

**Callable contract:**
- Required imports: from arrow.util import iso_to_gregorian
- Preconditions: Three integer arguments
- Determinism: Yes

**Input model:**
- Primary payload type: (int, int, int)
- Edge cases: invalid weeks (0, 54+), invalid days (0, 8+), extreme years

**Oracles:**
- Must-hold: Should not crash on invalid input
- Acceptable exceptions: ValueError

## Harness Recommendations
1. Focus on DateTimeParser.parse_iso as the primary target - it's the main entry point
2. Use atheris/LibFuzzer for coverage-guided fuzzing
3. Create a simple harness that calls parse_iso with fuzz data as string
4. Add differential fuzzing with Python's datetime.fromisoformat for comparison
