# Build Failure Analysis - google/auto Repository

## Overview
The build fails due to Java version incompatibility. The project uses old versions of
`compile-testing` library which have a hard dependency on `com.sun:tools` (tools.jar).
This file does not exist in Java 9+ as the Java compiler classes were modularized.

## Environment
- Java Version: OpenJDK 11.0.27
- Build Tool: Maven

## Root Cause
The `compile-testing` library in versions 0.6, 0.7, and 0.8 declares `com.sun:tools` as
a direct dependency with system scope pointing to `${toolsjar}` (tools.jar):

```xml
<dependency>
  <groupId>com.sun</groupId>
  <artifactId>tools</artifactId>
  <version>${java.version}</version>
  <scope>system</scope>
  <systemPath>${toolsjar}</systemPath>
</dependency>
```

In Java 8 and earlier, tools.jar contained the Java compiler API classes.
In Java 9+, these classes are part of the java.compiler module and tools.jar doesn't exist.

Starting from compile-testing version 0.19, this dependency was moved to a Maven profile
that only activates when tools.jar exists, allowing the library to work with Java 9+.

## Affected Modules and Required Changes

### 1. common/pom.xml
- Current: compile-testing version 0.7
- Fix: Upgrade to version 0.19

### 2. service/pom.xml
- Current: compile-testing version 0.6
- Fix: Upgrade to version 0.19

### 3. factory/pom.xml
- Current: compile-testing version 0.8
- Fix: Upgrade to version 0.19

### 4. value/pom.xml
- Current: compile-testing version 0.6
- Fix: Upgrade to version 0.19

## Error Messages
All modules fail with:
```
Could not find artifact com.sun:tools:jar:11.0.27 at specified path
/usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
```

## Solution
Upgrade compile-testing dependency from old versions (0.6, 0.7, 0.8) to version 0.19
in all four module pom.xml files. Version 0.19 uses a profile-based approach that
only adds the tools.jar dependency when running on Java 8 or earlier.

## Additional Issue: javax.annotation.Generated

### 5. factory/pom.xml - Missing javax.annotation.Generated
In Java 9+, `javax.annotation.Generated` was removed from the standard library.
The code uses this annotation but doesn't have the dependency.
Fix: Add javax.annotation-api dependency.

### 6. value/pom.xml - Missing auto-common dependency
The auto-value module depends on `com.google.auto:auto-common:1.0-SNAPSHOT` which
doesn't exist in remote repositories. It needs to be built locally first, or the
version should be changed to a published release (0.5).
Fix: Change auto-common version from 1.0-SNAPSHOT to 0.5.

### 7. value/pom.xml - Missing javax.annotation.Generated
Same issue as factory module - the code uses javax.annotation.Generated which
was removed from the standard library in Java 9+.
Fix: Add javax.annotation-api dependency.
