UJSON LIBRARY - FUZZING TARGET NOTES
======================================

## Library Overview
UltraJSON (ujson) is an ultra-fast JSON encoder and decoder written in C with Python bindings.
It's designed as a drop-in replacement for Python's json module with better performance.

## Important Functions for Fuzzing

### 1. ujson.loads()
- **Location**: src/ujson/python/ujson.c (C extension), exposed as Python function
- **Purpose**: Deserializes JSON string to Python object
- **Why fuzz**: Parses untrusted JSON input, implemented in C
- **Input surface**: JSON strings (bytes or str)
- **Risks**: Buffer overflows, integer overflows, stack exhaustion, parser bugs
- **Test priority**: CRITICAL
- **Note**: C extension makes this highest priority for memory safety bugs

### 2. ujson.dumps()
- **Location**: src/ujson/python/ujson.c (C extension)
- **Purpose**: Serializes Python object to JSON string
- **Why fuzz**: Handles arbitrary Python objects, C implementation
- **Input surface**: Python objects (dicts, lists, primitives, nested structures)
- **Risks**: Infinite recursion, buffer overflows, integer overflows, type confusion
- **Test priority**: CRITICAL

### 3. ujson.decode() (alias for loads)
- **Location**: src/ujson/python/ujson.c
- **Purpose**: Same as loads(), alternative name
- **Why fuzz**: Same risks as loads()
- **Input surface**: JSON strings
- **Test priority**: CRITICAL

### 4. ujson.encode() (alias for dumps)
- **Location**: src/ujson/python/ujson.c
- **Purpose**: Same as dumps(), alternative name
- **Why fuzz**: Same risks as dumps()
- **Input surface**: Python objects
- **Test priority**: CRITICAL

## Fuzzing Strategy
1. **Primary target: ujson.loads()** - Most critical due to parsing untrusted input in C
   - Test with malformed JSON
   - Deeply nested objects/arrays (stack exhaustion)
   - Very large numbers (integer overflow)
   - Very long strings (buffer overflow)
   - Unicode edge cases (invalid UTF-8, surrogates)
   - Truncated JSON
   - Special float values (NaN, Infinity)

2. **Secondary target: ujson.dumps()** - C serialization risks
   - Circular references (recursion)
   - Deeply nested structures
   - Very large containers
   - Objects with custom __repr__/__str__
   - Mixed type structures

3. **Focus areas**:
   - Memory safety (C code)
   - Integer overflow in size calculations
   - Buffer boundary checks
   - Stack depth limits
   - UTF-8 encoding/decoding

## Expected Exceptions
- ValueError: Expected for invalid JSON syntax
- OverflowError: Expected for numbers too large for C types
- TypeError: Expected for unserializable objects
- MemoryError: Expected for extremely large inputs (acceptable failure mode)
- RecursionError: Expected for circular references

## Crash-Worthy Issues
- Segmentation faults (memory corruption)
- Buffer overflows (out-of-bounds writes)
- Stack overflows (unbounded recursion in C)
- Integer overflows leading to small allocations
- Use-after-free bugs
- Null pointer dereferences
- Hangs/infinite loops
- Memory leaks (long-running fuzzing)
- Assertion failures

## Test Corpus Seeds
- Valid JSON: {}, [], "", "test", 123, 1.5, true, false, null
- Nested: {"a": [{"b": [1, 2, 3]}]}
- Edge numbers: 0, -1, 2^63-1, 1.7e308, -1.7e308
- Unicode: "\u0000", "\uffff", emoji, multi-byte chars
- Malformed: {, [, "unterminated, {]}, 1.2.3, {"a": }

## Resource Limits
- Limit recursion depth to prevent stack exhaustion
- Timeout long-running inputs (potential infinite loops)
- Memory limit to catch allocation bugs
- Input size limit for initial fuzzing (gradually increase)
