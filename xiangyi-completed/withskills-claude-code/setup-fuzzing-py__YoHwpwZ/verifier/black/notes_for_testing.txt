BLACK LIBRARY - FUZZING TARGET NOTES
======================================

## Library Overview
Black is a Python code formatter that reformats Python source code to follow a consistent style.
It uses lib2to3 for parsing and operates on Python AST.

## Important Functions for Fuzzing

### 1. black.format_str()
- **Location**: src/black/__init__.py:1177
- **Purpose**: Main entry point - reformats Python code string
- **Why fuzz**: Accepts arbitrary Python source code as input
- **Input surface**: Python source code strings
- **Risks**: Parser crashes, infinite loops, exponential complexity, malformed AST
- **Test priority**: CRITICAL

### 2. black.parsing.lib2to3_parse()
- **Location**: src/black/parsing.py
- **Purpose**: Parses Python source using lib2to3
- **Why fuzz**: Parser is complex and handles all Python syntax
- **Input surface**: Python source code strings
- **Risks**: Parser bugs, deeply nested structures, edge syntax cases
- **Test priority**: CRITICAL

### 3. black.format_file_contents()
- **Location**: src/black/__init__.py:1068
- **Purpose**: Formats file contents with safety checks
- **Why fuzz**: Production code path with AST validation
- **Input surface**: Python source code + mode configuration
- **Risks**: AST safety check failures, formatting inconsistencies
- **Test priority**: HIGH

### 4. black.format_ipynb_string()
- **Location**: src/black/__init__.py:1145
- **Purpose**: Formats Jupyter notebook JSON
- **Why fuzz**: JSON parsing + cell-based Python code formatting
- **Input surface**: JSON string (Jupyter notebook format)
- **Risks**: Malformed JSON, invalid notebook structure, code injection
- **Test priority**: HIGH

### 5. black.decode_bytes()
- **Location**: src/black/__init__.py:1301
- **Purpose**: Detects encoding and newline styles from bytes
- **Why fuzz**: Encoding detection and handling
- **Input surface**: Bytes with various encodings
- **Risks**: Encoding errors, invalid byte sequences
- **Test priority**: MEDIUM

### 6. black.parsing.parse_ast()
- **Location**: src/black/parsing.py
- **Purpose**: Parses to Python AST
- **Why fuzz**: AST parsing can have edge cases
- **Input surface**: Python source strings
- **Risks**: AST parsing errors, invalid syntax handling
- **Test priority**: HIGH

### 7. black.trans.transform_line()
- **Location**: src/black/linegen.py
- **Purpose**: Transforms parsed lines
- **Why fuzz**: Complex line transformation logic
- **Input surface**: Parsed line objects
- **Test priority**: MEDIUM

## Fuzzing Strategy
1. Start with black.format_str() - main entry point
2. Focus on edge cases: deeply nested code, long lines, mixed indentation
3. Test syntax edge cases: f-strings, walrus operator, match statements, decorators
4. Test malformed input: incomplete syntax, invalid UTF-8, mixed encodings
5. Test resource limits: very large files, deeply nested structures

## Expected Exceptions
- InvalidInput: Expected for syntax errors
- NothingChanged: Expected when no formatting needed
- ASTSafetyError: Expected for AST validation failures
- JSONDecodeError: Expected for invalid notebook JSON

## Crash-Worthy Issues
- Infinite loops in formatting
- Stack overflow from deep recursion
- Memory exhaustion from pathological input
- Uncaught exceptions beyond InvalidInput/ASTSafetyError
- Incorrect output that doesn't parse back
