MINISGL LIBRARY - FUZZING TARGET NOTES
========================================

## Library Overview
MiniSGL appears to be a machine learning/LLM serving library based on the directory structure.
Contains components for attention mechanisms, tokenization, model serving, and distributed execution.

## Important Functions for Fuzzing

### 1. Tokenizer functions
- **Location**: python/minisgl/tokenizer/*.py
- **Purpose**: Tokenizes text input for LLM processing
- **Why fuzz**: Handles arbitrary text input, critical for input processing
- **Input surface**: Text strings in various languages/encodings
- **Risks**: Unicode handling, buffer overflows, invalid UTF-8, extremely long inputs
- **Test priority**: CRITICAL

### 2. Message parsing/handling
- **Location**: python/minisgl/message/*.py
- **Purpose**: Parses and handles messages in distributed system
- **Why fuzz**: Network protocol parsing, serialization/deserialization
- **Input surface**: Protocol messages (likely JSON or Protocol Buffers)
- **Risks**: Deserialization bugs, injection, malformed messages
- **Test priority**: CRITICAL

### 3. Server request handlers
- **Location**: python/minisgl/server/*.py
- **Purpose**: HTTP/API request handling
- **Why fuzz**: User-facing API endpoints
- **Input surface**: HTTP requests, JSON payloads
- **Risks**: JSON parsing, API injection, DoS via malformed requests
- **Test priority**: HIGH

### 4. Model configuration parsing
- **Location**: python/minisgl/models/*.py
- **Purpose**: Parses model configurations
- **Why fuzz**: Config files control model behavior
- **Input surface**: Configuration dicts/JSON
- **Risks**: Config injection, type confusion, invalid values
- **Test priority**: HIGH

### 5. Scheduler functions
- **Location**: python/minisgl/scheduler/*.py
- **Purpose**: Schedules inference requests
- **Why fuzz**: Request scheduling logic
- **Input surface**: Request objects, scheduling parameters
- **Risks**: Logic bugs, resource exhaustion, priority inversions
- **Test priority**: MEDIUM

### 6. Distributed communication
- **Location**: python/minisgl/distributed/*.py
- **Purpose**: Handles distributed training/inference
- **Why fuzz**: Network communication and coordination
- **Input surface**: Network messages, coordination data
- **Risks**: Protocol bugs, Byzantine failures
- **Test priority**: HIGH

### 7. Attention mechanisms
- **Location**: python/minisgl/attention/*.py
- **Purpose**: Attention computation (likely numeric)
- **Why fuzz**: Numeric computation with edge cases
- **Input surface**: Tensor shapes, attention masks, numeric values
- **Risks**: NaN/Inf propagation, shape mismatches, numeric overflow
- **Test priority**: MEDIUM

## Fuzzing Strategy
1. Start with tokenizer - most direct user input path
2. Focus on message parsing - network attack surface
3. Test server endpoints - API security
4. Test with malformed JSON, protocol messages
5. Test unicode edge cases, long inputs, nested structures

## Expected Exceptions
- ValueError: Expected for invalid input values
- TypeError: Expected for wrong input types
- json.JSONDecodeError: Expected for invalid JSON
- UnicodeDecodeError: Expected for invalid encodings

## Crash-Worthy Issues
- Infinite loops in tokenization or parsing
- Memory exhaustion from adversarial inputs
- Buffer overflows in native code (if any)
- Uncaught exceptions in request handlers
- Deserialization vulnerabilities
- DoS via resource exhaustion
