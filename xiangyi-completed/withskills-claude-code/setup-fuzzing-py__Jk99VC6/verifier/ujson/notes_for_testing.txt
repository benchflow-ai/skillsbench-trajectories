UltraJSON (ujson) Library - Fuzzing Target Analysis

PRIMARY TARGETS (Highest Priority):

1. ujson.loads() / ujson.decode() [CRITICAL]
   File: /app/ujson/src/ujson/python/JSONtoObj.c (JSON parser)
   Complexity: High - Complex C-based JSON parser with multiple data types
   Input Surface: JSON strings and bytes with arbitrary content
   Edge Cases:
   - Unicode and surrogate character handling
   - Scientific notation numbers (1e-10, 1e15, etc.)
   - Special float values (Infinity, -Infinity, NaN)
   - Large integers beyond int64/uint64 ranges
   - Deeply nested structures (>1024 levels)
   - Empty/malformed JSON structures
   - Invalid escape sequences
   - UTF-8 validation edge cases
   Potential Issues: Parser crashes, buffer overflows, incorrect parsing of edge cases

2. ujson.dumps() / ujson.encode() [CRITICAL]
   File: /app/ujson/src/ujson/python/objToJSON.c (JSON encoder)
   Complexity: Very High - Complex encoder with 15+ type support and options
   Input Surface: Arbitrary Python objects with configuration options
   Edge Cases:
   - Type conversion complexity (int, float, str, bytes, list, dict, etc.)
   - Custom serializers (__json__, toDict methods)
   - Cyclic reference detection
   - Deep object nesting (>1024 levels)
   - NaN/Infinity handling with allow_nan option
   - HTML character encoding variations
   - Large object serialization
   - Unicode in object keys and values
   Potential Issues: Type errors, recursion limit violations, memory issues

SECONDARY TARGETS (High Priority):

3. ujson.loads() with edge cases
   File: /app/ujson/src/ujson/python/JSONtoObj.c
   Input Surface: Malformed JSON, edge case numeric values
   Edge Cases:
   - Trailing commas
   - Missing colons or commas
   - Invalid escape sequences
   - Surrogate pairs (paired and unpaired)
   - Control characters (0x00-0x1F)
   - Very long strings
   - Very deep arrays/objects

4. ujson.dumps() with configuration options
   File: /app/ujson/src/ujson/python/objToJSON.c
   Input Surface: Python objects with encoder options
   Configuration options to fuzz:
   - indent (0-65537+)
   - ensure_ascii (True/False)
   - encode_html_chars (True/False)
   - escape_forward_slashes (True/False)
   - sort_keys (True/False)
   - allow_nan (True/False)
   - default function (custom serializers)
   Edge Cases: Invalid configuration combinations, large separators

TERTIARY TARGETS (Medium Priority):

5. dump() / ujson.dump()
   File: /app/ujson/src/ujson/python/objToJSON.c
   Input Surface: Python objects written to file objects
   Edge Cases: File I/O errors, encoding errors

6. load() / ujson.load()
   File: /app/ujson/src/ujson/python/JSONtoObj.c
   Input Surface: JSON read from file objects
   Edge Cases: Incomplete JSON, file read errors

FUZZING STRATEGY:
- Primary focus: ujson.loads() with diverse JSON inputs
- Secondary focus: ujson.dumps() with Python objects and configuration variations
- Use structured fuzzing for JSON syntax
- Generate Python objects with various types for encoding
- Test configuration option combinations
- Monitor for memory issues with large/deep structures
- Test numeric edge cases (very large, very small, NaN, Infinity)
- Use existing tests in /app/ujson/tests/ as seed corpus

ORACLE PROPERTIES:
- Round-trip: ujson.loads(ujson.dumps(obj)) should preserve data type
- No crashes on arbitrary JSON input
- Proper error messages for malformed JSON
- Correct UTF-8 and Unicode handling
- Numeric precision preservation
- Consistent behavior across all configuration options
- Reference count correctness (for Python C API)

EDGE CASES TO EMPHASIZE:
- Integer overflow: Numbers > 2^64, < -2^63
- Floating-point edge cases: 1e308, 1e-308, denormalized numbers
- Very large exponents in scientific notation
- NaN/Infinity with various serialization options
- Surrogate character pairs (paired and unpaired)
- Null bytes in strings (\u0000)
- Control characters (0x00-0x1F)
- Very long strings with complex escapes
- Very deep nesting (approaching 1024 limit)
- Invalid UTF-8 sequences in bytes input
- Empty separators and very long separators
- Custom __json__() methods that raise exceptions
- Cyclic object references

EXISTING INFRASTRUCTURE:
- /app/ujson/tests/fuzz.py contains existing fuzzer
- Test infrastructure validates reference counting
- Supports seed-based reproducible testing
