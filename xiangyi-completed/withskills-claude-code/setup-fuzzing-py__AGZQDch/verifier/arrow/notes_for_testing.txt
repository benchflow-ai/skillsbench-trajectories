ARROW LIBRARY - FUZZING TARGET ANALYSIS
================================================================================

## Library Overview
Arrow is a datetime parsing and formatting library for Python that provides
a user-friendly API for working with dates, times, and timezones. It handles
ISO 8601 parsing, custom format strings, and timezone conversions.

## 3. EXISTING UNIT TEST SUMMARY
================================================================================

### Test Coverage Map:
- test_parser.py: Extensive coverage of DateTimeParser class
  - parse_iso() with various ISO 8601 formats
  - parse() with custom format strings
  - Token parsing for all supported tokens
  - Timezone parsing
  - Error cases and edge cases
  - Multiformat parsing

- test_factory.py: Coverage of ArrowFactory.get()
  - Different input types (int, float, str, datetime, etc.)
  - Timezone handling
  - Format string parsing

- test_formatter.py: Coverage of formatting functions
  - Various output formats
  - Token formatting
  - Locale-specific formatting

- test_arrow.py: Integration tests of Arrow class
- test_locales.py: Locale-specific parsing and formatting
- test_util.py: Utility function tests

### Inferred Oracles:
1. Round-trip property: parse(format(dt, fmt), fmt) ≈ dt (modulo precision)
2. No-crash for malformed input strings
3. ParserError raised for unparseable strings (not uncaught exceptions)
4. Deterministic output for deterministic input
5. Timezone-aware results maintain UTC equivalence

### Coverage Gaps:
1. Malformed/adversarial format strings with edge characters
2. Extremely long input strings or format strings
3. Deep nesting of escaped brackets in format strings
4. Unusual unicode characters in datetime strings
5. Edge cases in numeric ranges (year 0, negative timestamps, extreme dates)
6. Pathological regex patterns that cause exponential backtracking
7. Invalid combinations of tokens
8. Locale-specific edge cases with unusual month/day names
9. Timezone strings with unusual formats or invalid names
10. Microsecond rounding edge cases

## 4. SELECTED FUNCTIONS UNDER TEST (FUTs)
================================================================================

### FUT #1: DateTimeParser.parse_iso()

**Why this target:**
- High-value parsing function accepting untrusted string input
- Complex logic with multiple code paths
- Regex-heavy implementation prone to ReDoS
- Core functionality with security implications
- Existing tests focus on valid inputs, limited adversarial testing

**Callable contract:**
- Required imports: from arrow.parser import DateTimeParser
- Initialization: parser = DateTimeParser()
- Preconditions: Input must be a string
- Determinism: Deterministic for same input
- External dependencies: timezone database (tzdata/zoneinfo)

**Input model:**
- Primary payload: arbitrary string (datetime_string parameter)
- Secondary input: boolean (normalize_whitespace parameter)
- Constraints: None (accepts any string)
- Edge classes to emphasize:
  - ISO 8601 variants (basic, extended, with/without timezone)
  - Malformed ISO-like strings
  - Extremely long strings
  - Special characters and unicode
  - Empty strings and whitespace-only strings
  - Strings with embedded nulls

**Oracles:**
- Must-hold: No uncaught exceptions (only ParserError allowed)
- Acceptable: ParserError for invalid input
- Suspicious: Any exception other than ParserError, hangs, crashes
- Strategy: Crash-only fuzzing + exception type checking

**Harness plan:**
- Approach: LibFuzzer with atheris
- Minimal harness: fuzz(data) -> parser.parse_iso(data.decode('utf-8', 'ignore'))
- Seed corpus: Valid ISO 8601 strings from tests
- Timeouts: 1 second per input
- Resource limits: Standard

**Risk flags:**
- Native extension: No (pure Python)
- Potential DoS: Yes (regex backtracking)
- External I/O: Yes (timezone database reads)

**Next actions:**
1. Create atheris-based fuzz harness for parse_iso()
2. Extract seed corpus from test_parser.py
3. Run fuzzer for 10 seconds to validate
4. Monitor for ParserError vs other exceptions


### FUT #2: DateTimeParser.parse()

**Why this target:**
- Accepts two string inputs (datetime + format)
- Format string controls regex generation
- High potential for regex injection and malformed patterns
- More complex than parse_iso due to custom format handling

**Callable contract:**
- Required imports: from arrow.parser import DateTimeParser
- Initialization: parser = DateTimeParser()
- Preconditions: Two string inputs
- Determinism: Deterministic
- External dependencies: timezone database

**Input model:**
- Primary payload: datetime string and format string (two separate inputs)
- For fuzzing: concatenate with delimiter, split in harness
- Edge classes:
  - Valid format tokens: YYYY, MM, DD, HH, mm, ss, etc.
  - Invalid/malicious format tokens
  - Extremely long format strings
  - Format strings with special regex characters
  - Mismatched datetime/format pairs

**Oracles:**
- Must-hold: No uncaught exceptions
- Acceptable: ParserError, ParserMatchError
- Suspicious: re.error, other exceptions

**Harness plan:**
- Approach: Structured fuzzing with format string generation
- Split input into datetime_string and format_string
- Use delimiter (e.g., ||| separator)

**Risk flags:**
- Regex compilation: Yes (format string controls regex)
- Potential DoS: Yes (malicious format patterns)
- External I/O: Yes (timezone database)

**Next actions:**
1. Create harness with input splitting
2. Generate seed corpus with common format patterns
3. Fuzz both valid and invalid format combinations
4. Monitor regex compilation errors


### FUT #3: TzinfoParser.parse()

**Why this target:**
- Parses timezone strings from untrusted input
- Performs ZoneInfo lookups with external data
- Arithmetic operations on timezone offsets
- Relatively simple input/output for high-value boundary

**Callable contract:**
- Required imports: from arrow.parser import TzinfoParser
- Class method (no initialization needed)
- Preconditions: String input
- Determinism: Deterministic
- External dependencies: zoneinfo database

**Input model:**
- Primary payload: timezone string
- Edge classes:
  - Valid: UTC, Z, +05:30, -08:00, America/New_York
  - Malformed: +999:999, invalid zone names
  - Edge: empty string, very long strings
  - Special: unicode, null bytes

**Oracles:**
- Must-hold: No uncaught exceptions
- Acceptable: ParserError
- Suspicious: ZoneInfoNotFoundError should be caught

**Harness plan:**
- Simple single-input harness
- Seed with valid timezone names and offset formats

**Risk flags:**
- File I/O: Yes (zoneinfo database)
- Arithmetic: Yes (timezone offset calculations)

**Next actions:**
1. Create simple harness for timezone parsing
2. Seed with /usr/share/zoneinfo entries
3. Test malformed offset strings
