The build fails in the AutoValue module during integration tests. Specifically, the 'functional' integration test fails to compile because it cannot find the symbol 'MoreObjects' in the package 'com.google.common.base'. Additionally, when building in modern Java environments (Java 9+), several other build errors occur.

Analysis:
1. The error 'cannot find symbol MoreObjects' indicates that a version of Guava older than 18.0 is being used during the compilation of the integration tests. MoreObjects was introduced in Guava 18.0.
2. The 'value/src/it/functional/pom.xml' file specifies 'guava-testlib:18.0' as a test-scope dependency. While 'guava-testlib' depends on 'guava', it's possible that another transitive dependency is bringing in an older version of Guava that takes precedence during conflict resolution.
3. The environment uses Java 11, which causes issues with 'tools.jar' (it no longer exists) and 'javax.annotation.Generated' (it moved to a different module).

Fixes implemented:
1. Explicitly added 'guava:18.0' to 'value/src/it/functional/pom.xml' to ensure correct Guava version during integration tests.
2. Upgraded 'compile-testing' to 0.10 and excluded the 'com.sun:tools' transitive dependency in all modules to fix build on Java 11.
3. Added 'javax.annotation:javax.annotation-api:1.2' dependency to modules that use the '@Generated' annotation, which is no longer part of the default classpath in Java 9+.
4. Updated submodules to use the local '4-SNAPSHOT' parent version to ensure consistency and that my changes to the parent (if any) are inherited.
