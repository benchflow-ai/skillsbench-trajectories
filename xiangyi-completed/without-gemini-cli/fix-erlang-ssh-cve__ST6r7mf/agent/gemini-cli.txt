The critical vulnerability in the Erlang/OTP SSH server allowed unauthenticated attackers to execute arbitrary system commands by sending `SSH_MSG_CHANNEL_OPEN` and subsequent `SSH_MSG_CHANNEL_REQUEST` (exec) messages before the authentication process was completed. I have fixed this vulnerability by modifying `ssh_connection_handler.erl` to strictly enforce that connection layer messages (`{conn_msg, Msg}`) are only processed when the SSH connection is in a `connected` state or during a valid renegotiation (`ext_info` state with `renegotiate` flag). If a connection message is received in any other state (such as during the initial unauthenticated handshake), the server now immediately disconnects with a protocol error.

The fix involves updating the `handle_event` function for `{conn_msg, Msg}` in `lib/ssh/src/ssh_connection_handler.erl` to include a guard check for the valid states and adding a fallback clause to handle invalid states securely.
