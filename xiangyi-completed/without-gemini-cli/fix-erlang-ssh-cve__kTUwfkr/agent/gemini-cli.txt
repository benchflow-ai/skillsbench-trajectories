I will apply the fix to `otp_src_27.3.2/lib/ssh/src/ssh_connection_handler.erl` to postpone processing of connection messages when the SSH connection is not yet fully established and authenticated.
I have investigated the vulnerability and identified that the `ssh_connection_handler` was processing connection layer messages (wrapped in `conn_msg`) regardless of the connection state. This allowed unauthenticated attackers to send `SSH_MSG_CHANNEL_OPEN` and subsequent `SSH_MSG_CHANNEL_REQUEST` ("exec") messages, which were processed by `ssh_connection` and resulted in command execution, even though the channel open confirmation was conceptually queued.

I have fixed this by modifying `otp_src_27.3.2/lib/ssh/src/ssh_connection_handler.erl` to strictly postpone any `conn_msg` events when the connection is not in a fully connected (authenticated) state. This ensures that no connection layer messages are processed until the user has successfully authenticated.

The fix handles both the general pre-authentication states (via `not ?CONNECTED(StateName)`) and the specific `{ext_info, _, init}` state which is also pre-authentication but technically considered "connected" by the internal macro.
