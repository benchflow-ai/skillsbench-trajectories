The build failed because the submodules (auto-common, auto-factory, auto-service, auto-value) are configured to use a parent POM (`com.google.auto:auto-parent:3`) that includes a system dependency on `tools.jar`.
This dependency expects `tools.jar` to be present at `${java.home}/../lib/tools.jar`, which is valid for JDK 8 but not for JDK 11 (the environment where the build is running). In JDK 11, the tools are part of the platform modules and `tools.jar` does not exist.
The local root `pom.xml` defines `com.google.auto:auto-parent:4-SNAPSHOT`, which does not include this problematic dependency.
Additionally, the `compile-testing` dependency (used in test scope) transitively brings in `com.sun:tools` (tools.jar), causing the same error.
The fix is to:
1. Update the submodules to use the local parent version `4-SNAPSHOT` instead of the remote `3`.
2. Exclude `com.sun:tools` from the `compile-testing` dependency in all submodules.
