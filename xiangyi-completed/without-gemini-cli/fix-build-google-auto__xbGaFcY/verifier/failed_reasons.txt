The build failed because the project assumes the presence of `tools.jar`, which was removed in Java 9. The current environment is using Java 11.
The submodules (`auto-common`, `factory`, `service`) inherit from `auto-parent` version 3 (from Maven Central), which likely has a hard dependency on `tools.jar` via a system path that doesn't exist on Java 11.
The local `pom.xml` defines `auto-parent` version 4-SNAPSHOT but it is not being used by the submodules.
Also, the local `pom.xml` handles the `tools.jar` path via a profile `default-profile`, but currently does not declare the dependency itself, or at least the profile logic needs to be robust for Java 11.

Plan:
1. Update `pom.xml` (root) to include the `com.sun:tools` dependency within the `default-profile` (and `mac-profile`). This ensures that the dependency is only added when `tools.jar` actually exists (Java 8 and earlier). On Java 11, the profile will be inactive, and the dependency will be skipped, which is correct as the classes are in the standard modules.
2. Update the submodules (`common/pom.xml`, `factory/pom.xml`, `service/pom.xml`) to inherit from the local `auto-parent` version `4-SNAPSHOT`. This allows them to use the updated profile logic.
