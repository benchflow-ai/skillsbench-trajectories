The critical vulnerability in the Erlang/OTP SSH server allowed unauthenticated attackers to execute arbitrary system commands by sending crafted SSH protocol messages (specifically `SSH_MSG_CHANNEL_OPEN` followed by `SSH_MSG_CHANNEL_REQUEST` with "exec") before the authentication phase was completed.

I have fixed this by modifying `ssh_connection_handler.erl`. I updated the `handle_event` function responsible for processing `conn_msg` (connection layer messages). The fix introduces a check to ensure that such messages are processed only when the connection is in a `connected` state (authenticated) or during renegotiation. If a `conn_msg` is received in any other state (e.g., during the hello exchange or user authentication), it is now postponed until the connection becomes authenticated. This prevents the execution of any channel-related logic (including command execution) by unauthenticated users.

The fix involves wrapping the `ssh_connection:handle_msg` call within a conditional block:
```erlang
    case ?CONNECTED(StateName) or Rengotation of
	true ->
            %% Process message...
            ...
	false ->
	    {keep_state, D0, [postpone]}
    end;
```

This change ensures that the SSH server strictly enforces the protocol requirement that the connection layer runs on top of the user authentication layer.
