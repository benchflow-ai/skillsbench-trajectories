The investigation revealed that the Erlang/OTP SSH server allowed connection protocol messages (RFC 4254), such as `SSH_MSG_CHANNEL_OPEN` and `SSH_MSG_CHANNEL_REQUEST`, to be processed before the user authentication phase was completed. This allowed unauthenticated attackers to open a session channel and send an `exec` request. If the server was configured with the default Erlang shell, it would evaluate the command as an Erlang expression, leading to remote command execution (RCE).

I fixed this vulnerability by adding a check in `ssh_connection_handler.erl` to ensure that connection protocol messages are only processed when the session is authenticated. If such a message is received before authentication, the server now disconnects the client with a `PROTOCOL_ERROR`.

```erlang
handle_event(internal, {conn_msg, Msg}, StateName, #data{ssh_params = #ssh{authenticated = false}} = D0) ->
    Detail = io_lib:format("Connection protocol message ~p received before authentication completed (state ~p)",
                           [element(1,Msg), StateName]),
    ?send_disconnect(?SSH_DISCONNECT_PROTOCOL_ERROR, Detail, StateName, D0);
```

This fix prevents unauthenticated access to the connection protocol while maintaining normal SSH behavior for authenticated users.

I have investigated the remote command execution (RCE) vulnerability in the Erlang/OTP SSH server and implemented a fix.

### Investigation
The vulnerability was located in `ssh_connection_handler.erl`, where SSH connection protocol messages (RFC 4254) were processed regardless of the authentication state. An unauthenticated attacker could:
1.  Establish an SSH transport layer.
2.  Send an `SSH_MSG_CHANNEL_OPEN` message to open a session.
3.  Send an `SSH_MSG_CHANNEL_REQUEST` with the `exec` type.
4.  If the server used the default Erlang shell, the `ssh_cli` module would evaluate the provided command as Erlang code, allowing arbitrary command execution.

### Fix
I modified `otp_src_27.3.2/lib/ssh/src/ssh_connection_handler.erl` to add a guard clause in the `handle_event` function for `conn_msg` events. This clause now checks the `authenticated` field of the SSH parameters. If a connection protocol message is received before authentication is successful, the server will now disconnect the peer with a `PROTOCOL_ERROR`, as mandated by the security requirements of the SSH protocol.
