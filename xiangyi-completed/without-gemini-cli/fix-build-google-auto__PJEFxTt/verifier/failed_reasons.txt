The build failed due to two main reasons:

1. A typo in `.travis.yml`:
   The `install` step refers to `build.pom.xml`, but the file is named `build-pom.xml`. This causes a "Non-readable POM" error at the beginning of the build. Although it has `--fail-never`, it's still incorrect.

2. A compilation error in the functional integration test:
   The file `value/src/it/functional/src/test/java/com/google/auto/value/AutoValueTest.java` uses `com.google.common.base.MoreObjects`, which was introduced in Guava 18.0.
   However, the integration test's `pom.xml` (`value/src/it/functional/pom.xml`) does not explicitly depend on Guava 18.0. It depends on `truth` 0.25, which depends on Guava 17.0, and `guava-testlib` 18.0.
   Maven seems to be resolving Guava to 17.0 for this integration test, leading to "cannot find symbol: class MoreObjects".

Plan:
1. Modify `.travis.yml` to change `build.pom.xml` to `build-pom.xml` in the `install` step.
2. Modify `value/src/it/functional/pom.xml` to explicitly add a dependency on Guava 18.0 to ensure it's available for the tests.
