### Key Implementation Details:
1.  **Data Types**: Created `TaskEvent` and `JobEvent` classes with `fromString` methods to parse the gzipped CSV data.
2.  **Job Stages**: Identified stages for each job using task `SUBMIT` events (eventType 0). A stage is defined by a session of events with an inactivity gap of 10 minutes (600 seconds, or 600,000,000 microseconds).
3.  **Maximum Stage Calculation**: For each job, the job tracks the number of tasks in the current stage and maintains the maximum count seen across all stages.
4.  **Job Completion Trigger**: The final result for each job is emitted once a terminal job event (types 2-6, such as `FINISH`, `FAIL`, or `KILL`) is received. A timer is used to ensure all relevant task events are processed before outputting.
5.  **Watermarking**: Implemented a `WatermarkStrategy` that handles the microsecond timestamps by converting them to milliseconds for Flink's event-time processing.
6.  **Output**: Results are written to the specified local file in the required `(jobId,maxTasks)` format.

The job is designed to run with a parallelism of 1 to ensure correct file output and sequential processing of the trace files.
