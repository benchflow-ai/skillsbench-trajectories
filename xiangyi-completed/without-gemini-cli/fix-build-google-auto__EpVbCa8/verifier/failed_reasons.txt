The build failed in the `auto-value` module's integration tests (specifically `src/it/functional`).

Reasons for failure:
1. Compilation error in `AutoValueTest.java`: The test uses `com.google.common.base.MoreObjects`, which was introduced in Guava 18.0. However, the `functional` project's dependencies resulted in Guava 17.0 being pulled in. This is because `com.google.truth:truth:0.25` depends on Guava 17.0 and was declared before `com.google.guava:guava-testlib:18.0`. In Maven, when two dependencies at the same depth pull in different versions of a transitive dependency, the first one declared wins.
2. Encoding issues: Source files contain non-ASCII characters (e.g., 'É' in 'Éamonn McManus'), but the `functional` project does not specify a source encoding, defaulting to ASCII in some environments (like the one used in the failed build).

Plan:
1. Modify `value/src/it/functional/pom.xml` to:
    a. Set `project.build.sourceEncoding` to `UTF-8`.
    b. Explicitly add `com.google.guava:guava:18.0` as a dependency to ensure it is used instead of Guava 17.0.
    c. Alternatively, move `guava-testlib` before `truth` to let Maven mediation pick Guava 18.0. Explicit dependency is preferred for clarity.
