BUILD ERROR ANALYSIS FOR GOOGLE AUTO REPOSITORY
================================================

Repository: /home/travis/build/failed/google/auto
Date: 2026-01-29

SUMMARY OF ERRORS
=================
The Google Auto project is a Java 6 codebase being built with Java 11, causing compatibility issues with missing tools.jar dependency and version mismatches. All four modules fail to build.

AFFECTED MODULES
================
1. common (auto-common) - Version 1.0-SNAPSHOT
2. factory (auto-factory) - Version 1.0-SNAPSHOT
3. service (auto-service) - Version 1.0-SNAPSHOT
4. value (auto-value) - Version 1.0-SNAPSHOT

CRITICAL ISSUES
===============

Issue #1: Missing tools.jar in Java 11+ (CRITICAL - Affects ALL modules)
--------------------------------------------------------------------------
Error Message:
  "Could not find artifact com.sun:tools:jar:11.0.27 at specified path
   /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

Root Cause:
  - The test dependency "com.google.testing.compile:compile-testing" declares
    a system-scoped dependency on com.sun:tools:jar
  - The dependency is configured with systemPath=${toolsjar} which resolves to
    ${java.home}/../lib/tools.jar
  - In Java 9+ (including Java 11), the tools.jar file NO LONGER EXISTS
  - The JDK was refactored and tools functionality moved to java.compiler module
  - This affects ALL modules because they all depend on compile-testing

Solution:
  Update compile-testing dependency versions to newer versions that don't
  depend on system tools.jar

  Affected modules and current versions:
  - common/pom.xml: compile-testing:0.7
  - factory/pom.xml: compile-testing:0.8
  - service/pom.xml: compile-testing:0.6
  - value/pom.xml: compile-testing:0.6

Issue #2: Incorrect auto-common Dependency Versions
----------------------------------------------------
Error Message:
  "The following artifacts could not be resolved:
   com.google.auto:auto-common:jar:1.0-SNAPSHOT"

Root Cause:
  - value/pom.xml declares dependency on auto-common:1.0-SNAPSHOT
  - This version doesn't exist in Maven Central
  - The common module uses version 1.0-SNAPSHOT (local), but it's not published
  - factory/pom.xml declares auto-common:0.5 (outdated)
  - service/pom.xml declares auto-common:0.3 (outdated)

Files to fix:
  - factory/pom.xml: Change auto-common from 0.5 to 1.0-SNAPSHOT
  - service/pom.xml: Change auto-common from 0.3 to 1.0-SNAPSHOT

Issue #3: Java Version Mismatch
-------------------------------
Configuration Issue:
  - Parent pom.xml sets java.version to 1.6 (ancient)
  - Actual build environment is Java 11
  - This causes compilation warnings and potential incompatibilities

FIX STRATEGY
============

Step 1: Update compile-testing versions to remove tools.jar dependency
  - common: 0.7 → 0.10 (latest available version that removes tools.jar)
  - factory: 0.8 → 0.10
  - service: 0.6 → 0.10
  - value: 0.6 → 0.10

Step 2: Update inter-module dependencies to use local snapshot versions
  - factory: auto-common 0.5 → 1.0-SNAPSHOT
  - service: auto-common 0.3 → 1.0-SNAPSHOT
  - value: auto-common 1.0-SNAPSHOT (already correct)

Step 3: (Optional) Update Java target version
  - Parent pom could be updated from 1.6 to higher version
  - But since 1.6 to 1.11 backward compatibility exists, this is less critical
