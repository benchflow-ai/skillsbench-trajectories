# Testing Notes: Arrow

## Overview
Arrow is a Python library for better dates & times. It provides human-friendly approaches to creating, manipulating, formatting and converting dates and times.

## Main Package Structure
- Main module: arrow/
- Core files: api.py, arrow.py, parser.py, factory.py, formatter.py
- Key functionality: Date parsing, formatting, manipulation

## Key Public APIs

### 1. arrow.get(*args, **kwargs)
- **Location**: arrow/api.py:83, arrow/factory.py
- **Purpose**: Main factory function to create Arrow objects from various inputs
- **Input types**: str (date strings), int/float (timestamps), datetime objects, date objects
- **Potential issues**: String parsing, timezone handling, format string parsing
- **Why fuzz**: Complex parsing logic with many formats, high-value target

### 2. arrow.parser.DateTimeParser
- **Location**: arrow/parser.py
- **Purpose**: Parses datetime strings with format strings
- **Input types**: String data and format patterns
- **Potential issues**: Malformed format strings, invalid dates, edge cases
- **Why fuzz**: Core parsing functionality, handles untrusted input

### 3. Arrow.format(fmt)
- **Location**: arrow/arrow.py
- **Purpose**: Formats Arrow object to string
- **Input types**: Format strings
- **Potential issues**: Invalid format tokens, locale issues

## Functions for Fuzzing Priority

### High Priority
1. **arrow.get(string, format)** - Date string parsing with format
   - Complex parsing logic
   - Many format tokens (YYYY, MM, DD, etc.)
   - Timezone parsing
   - Locale handling

2. **arrow.get(string)** - Auto-detection parsing
   - Tries multiple formats automatically
   - High complexity

3. **Arrow.humanize()** - Human-readable time differences
   - String generation with edge cases

### Medium Priority
1. **Arrow.format(fmt)** - Formatting with custom formats
2. **Arrow.shift()** - Date arithmetic
3. **Arrow.replace()** - Component replacement

## Dependencies to Install
- Required: python-dateutil>=2.7.0, tzdata (Python 3.9+)
- Optional: dateparser, pytest (for testing)

## Testing Approach

### Fuzz Target 1: arrow.get() with format strings
```python
# Feed random date strings and format patterns
arrow.get(fuzzed_date_string, fuzzed_format)
```

### Fuzz Target 2: arrow.get() auto-parsing
```python
# Feed random strings to test auto-detection
arrow.get(fuzzed_string)
```

### Expected Exceptions
- `ParserError`: Invalid date format or unparseable string
- `ValueError`: Invalid date values (e.g., month 13)
- `AttributeError`: Invalid operations
- `ZoneInfoNotFoundError`: Invalid timezone

## Edge Cases to Consider
- Empty strings
- Very long format strings
- Invalid format tokens
- Extreme dates (year 1, year 9999)
- Invalid timezones
- Unicode characters in date strings
- Malformed ISO 8601 strings
- Leap year edge cases
- DST transitions

## Fuzzing Strategy
Focus on `arrow.get()` as main entry point since it:
1. Accepts string input (high attack surface)
2. Performs complex parsing
3. Has multiple code paths based on input type
4. Handles format strings (additional complexity)
5. Is the most commonly used API
