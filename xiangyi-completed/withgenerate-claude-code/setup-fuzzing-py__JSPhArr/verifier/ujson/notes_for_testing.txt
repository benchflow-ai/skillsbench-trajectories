# Testing Notes: ujson (UltraJSON)

## Overview
UltraJSON (ujson) is an ultra-fast JSON encoder and decoder written in pure C with Python bindings. It's designed as a drop-in replacement for the standard json module with better performance.

## Main Package Structure
- Main module: src/ujson/ (C extension)
- Core files:
  - python/ujson.c (Python bindings)
  - python/objToJSON.c (Python object to JSON encoding)
  - python/JSONtoObj.c (JSON to Python object decoding)
  - lib/ultrajsonenc.c (core encoder)
  - lib/ultrajsondec.c (core decoder)
- Key functionality: JSON encoding/decoding

## Key Public APIs

### 1. ujson.loads(json_string, **kwargs)
- **Purpose**: Decode JSON string to Python object
- **Input types**: String (JSON data)
- **Potential issues**: Malformed JSON, deeply nested structures, very large numbers, invalid escape sequences
- **Why fuzz**: Main parsing API, handles untrusted input, C implementation with potential buffer issues

### 2. ujson.dumps(obj, **kwargs)
- **Purpose**: Encode Python object to JSON string
- **Input types**: Python objects (dict, list, str, int, float, bool, None)
- **Potential issues**: Circular references, non-serializable objects, encoding edge cases
- **Why fuzz**: Main encoding API, complex object traversal

### 3. ujson.load(fp, **kwargs)
- **Purpose**: Decode JSON from file-like object
- **Input types**: File object
- **Potential issues**: Same as loads() plus file handling

### 4. ujson.dump(obj, fp, **kwargs)
- **Purpose**: Encode Python object to file
- **Input types**: Python objects
- **Potential issues**: Same as dumps() plus file handling

## Functions for Fuzzing Priority

### High Priority
1. **ujson.loads(json_string)** - JSON parsing
   - C implementation (higher risk for memory safety issues)
   - Handles untrusted input
   - Complex parsing logic
   - Known history of security issues (per README warning)
   - Edge cases: nested arrays/objects, large numbers, Unicode, escape sequences

2. **ujson.dumps(obj)** - JSON encoding
   - Object traversal
   - Type handling
   - String escaping
   - Number formatting

### Medium Priority
1. **ujson.loads() with options** - Test various decoding options
2. **ujson.dumps() with options** - Test encode_html_chars, ensure_ascii, etc.

## Encoder Options to Test
- `encode_html_chars`: Encode HTML special chars
- `ensure_ascii`: Limit to ASCII output
- `escape_forward_slashes`: Escape / characters
- `sort_keys`: Sort dictionary keys
- `indent`: Pretty-print indentation

## Dependencies to Install
- Build dependencies: setuptools, setuptools_scm
- Runtime: None (C extension, no Python dependencies)
- Note: Requires C compiler for building

## Testing Approach

### Fuzz Target 1: ujson.loads() - JSON parsing
```python
import ujson
# Feed random/malformed JSON strings
ujson.loads(fuzzed_json_string)
```

### Fuzz Target 2: ujson.dumps() - JSON encoding
```python
import ujson
# Feed random Python objects (dicts, lists, etc.)
ujson.dumps(fuzzed_python_object)
```

### Expected Exceptions
- `ValueError`: Malformed JSON, invalid values
- `OverflowError`: Numbers too large
- `TypeError`: Non-serializable objects
- `KeyError`: Invalid operations
- Potential crashes: Buffer overflows, memory errors (C code)

## Edge Cases to Consider

### For loads() - Parsing
- Empty strings
- Very large JSON (MB+ size)
- Deeply nested objects/arrays (1000+ levels)
- Very long strings
- Large numbers (beyond float64 range)
- Special numbers: Infinity, -Infinity, NaN
- Invalid escape sequences: \x, \u000, etc.
- Incomplete escape sequences
- Unicode characters: \uXXXX, surrogate pairs
- Null bytes in strings
- Invalid JSON: trailing commas, missing quotes, etc.
- Mixed valid/invalid JSON
- Duplicate keys
- Control characters in strings
- Very long keys
- Empty objects/arrays: {}, []

### For dumps() - Encoding
- Circular references: obj['self'] = obj
- Non-serializable objects: functions, classes, modules
- Large integers (beyond JSON spec)
- Float special values: inf, -inf, nan
- Unicode strings
- Binary data
- Empty containers
- Nested structures
- Custom objects
- Dictionary with non-string keys
- Very long strings/lists

## Fuzzing Strategy
**Primary Focus: ujson.loads()**
This is the highest priority target because:
1. It's a C parser (memory safety risks)
2. Handles untrusted external input
3. Complex parsing logic
4. README explicitly warns about security issues
5. Maintenance-only mode means bugs may not be fixed quickly

The fuzzer should generate:
- Valid JSON variations
- Malformed JSON (syntax errors)
- Edge case values (very large/small numbers)
- Deep nesting
- Long strings
- Unicode and escape sequences
- Boundary conditions

**Secondary Focus: ujson.dumps()**
Test encoding with:
- Various Python object types
- Edge case values
- Complex nested structures
- Special characters

## Security Note
From README: "UltraJSON's architecture is fundamentally ill-suited to making changes without risk of introducing new security vulnerabilities." This makes it an excellent fuzzing target as:
- Known history of vulnerabilities
- C implementation prone to memory issues
- Maintenance-only mode
- Users encouraged to migrate away
