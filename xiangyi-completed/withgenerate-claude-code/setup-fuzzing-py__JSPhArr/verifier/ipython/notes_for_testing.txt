# Testing Notes: IPython

## Overview
IPython is an interactive Python shell with enhanced features for interactive computing. It processes user input, executes code, handles magic commands, and provides rich display capabilities.

## Main Package Structure
- Main module: IPython/
- Core modules: core/interactiveshell.py, core/inputtransformer2.py, core/compilerop.py
- Key functionality: Code execution, input transformation, magic commands, completion

## Key Public APIs

### 1. IPython.core.interactiveshell.InteractiveShell.run_cell(raw_cell)
- **Location**: IPython/core/interactiveshell.py
- **Purpose**: Execute a cell of code (main execution entry point)
- **Input types**: String (Python code + IPython magic commands)
- **Potential issues**: Malformed code, magic command parsing, special syntax
- **Why fuzz**: Main API for code execution

### 2. IPython.core.inputtransformer2.TransformerManager.transform_cell(cell)
- **Location**: IPython/core/inputtransformer2.py
- **Purpose**: Transform IPython syntax to valid Python
- **Input types**: String (IPython-specific syntax)
- **Potential issues**: Magic parsing, special operators (!, ?, %, etc.)

### 3. IPython.core.compilerop.CachingCompiler
- **Location**: IPython/core/compilerop.py
- **Purpose**: Compile Python code with caching
- **Input types**: String (Python source)
- **Potential issues**: Syntax errors, edge cases in compilation

### 4. IPython.core.completer.Completer.complete()
- **Location**: IPython/core/completer.py
- **Purpose**: Code completion
- **Input types**: String (partial code)
- **Potential issues**: Parsing incomplete code, attribute access

## Functions for Fuzzing Priority

### High Priority
1. **run_cell(code)** - Main code execution
   - Processes IPython magic commands (%magic, %%cellmagic)
   - Handles special operators (!, ?, ??)
   - Transforms and compiles code
   - Highest complexity, most common use

2. **transform_cell(cell)** - Input transformation
   - Parses magic commands
   - Handles line/cell magics
   - Shell escape (!)
   - Help operators (?, ??)

3. **CachingCompiler** - Code compilation
   - Compiles Python source
   - Handles syntax errors
   - Caching logic

### Medium Priority
1. **complete()** - Tab completion
2. **prefilter()** - Input preprocessing
3. **compile_ast()** - AST compilation

## Dependencies to Install
- Required: decorator, jedi, matplotlib-inline, prompt_toolkit, pygments,
  stack_data, traitlets
- Optional: pytest, ipykernel (for testing)

## Testing Approach

### Fuzz Target 1: transform_cell() with IPython syntax
```python
# Feed random IPython commands and syntax
from IPython.core.inputtransformer2 import TransformerManager
tm = TransformerManager()
tm.transform_cell(fuzzed_ipython_code)
```

### Fuzz Target 2: Code compilation
```python
# Test compilation with malformed code
from IPython.core.compilerop import CachingCompiler
compiler = CachingCompiler()
compiler(fuzzed_code, '<string>', 'exec')
```

### Expected Exceptions
- `SyntaxError`: Invalid Python syntax
- `IndentationError`: Invalid indentation
- `ValueError`: Invalid operations
- `UsageError`: Invalid magic command usage
- `TokenError`: Tokenization errors

## Edge Cases to Consider
- Empty strings/cells
- Magic commands: %time, %run, %%timeit, etc.
- Shell escapes: !ls, !!python
- Help operators: ?, ??
- System assigns: var = !command
- Multi-line magics
- Nested quotes in magic args
- Very long input lines
- Unicode in code/magics
- Incomplete code blocks
- Mixed tabs/spaces
- Cell separator (# %%)
- IPython-specific syntax (!cmd, ?obj, %magic)
- Async code (await without async def)
- Invalid magic names
- Special variables (_ , __, _i, _ih)

## Fuzzing Strategy
Focus on input transformation since IPython's unique value is handling:
1. Magic commands (% and %%)
2. Shell escapes (!)
3. Help operators (?, ??)
4. Special IPython syntax

The fuzzer should generate:
- Valid Python code
- IPython magic commands
- Mixed Python + IPython syntax
- Shell commands
- Edge cases in parsing
- Malformed magics
- Special characters and operators
