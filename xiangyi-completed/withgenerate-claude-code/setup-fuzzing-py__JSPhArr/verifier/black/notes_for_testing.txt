# Testing Notes: Black

## Overview
Black is an uncompromising Python code formatter. It parses Python code and reformats it according to strict style rules.

## Main Package Structure
- Main module: src/black/
- Core files: __init__.py, parsing.py, linegen.py, lines.py, mode.py
- Parser: blib2to3/ (lib2to3 fork)
- Key functionality: Python code parsing and reformatting

## Key Public APIs

### 1. black.format_str(src: str, *, mode: Mode) -> str
- **Location**: src/black/__init__.py:1177
- **Purpose**: Format Python source code string
- **Input types**: String (Python source code)
- **Potential issues**: Malformed Python syntax, edge cases in parsing
- **Why fuzz**: Main API, complex parsing and transformation

### 2. black.format_file_contents(src: str, *, fast: bool, mode: Mode) -> str
- **Location**: src/black/__init__.py:1068
- **Purpose**: Format file contents
- **Input types**: String (Python source code)
- **Potential issues**: Syntax errors, invalid code structures

### 3. black.lib2to3_parse(src_txt: str, target_versions) -> Node
- **Location**: src/black/parsing.py:55
- **Purpose**: Parse Python source into AST using lib2to3
- **Input types**: String (Python source code)
- **Potential issues**: Parsing errors, invalid syntax
- **Why fuzz**: Core parsing logic, handles untrusted input

### 4. black.format_cell(src: str, *, fast: bool, mode: Mode) -> str
- **Location**: src/black/__init__.py:1096
- **Purpose**: Format Jupyter notebook cell
- **Input types**: String (Python code with IPython magics)
- **Potential issues**: Magic command parsing, special syntax

## Functions for Fuzzing Priority

### High Priority
1. **black.format_str(src, mode=Mode())** - Main formatting API
   - Parses Python source code
   - Performs complex transformations
   - Handles edge cases in Python syntax
   - Most commonly used function

2. **black.lib2to3_parse(src_txt)** - Core parser
   - Lowest level parsing
   - Multiple grammar attempts
   - Error handling

3. **black.format_file_contents(src, fast=True, mode=Mode())** - File formatting
   - Similar to format_str but with file-specific handling
   - Encoding detection

### Medium Priority
1. **black.format_cell()** - Jupyter cell formatting
2. **black.parse_ast()** - AST parsing and validation

## Testing Approach

### Fuzz Target 1: format_str() with random Python code
```python
# Feed random/malformed Python code strings
black.format_str(fuzzed_python_code, mode=black.Mode())
```

### Fuzz Target 2: lib2to3_parse() for parser testing
```python
# Test parser directly with malformed input
black.lib2to3_parse(fuzzed_code)
```

### Expected Exceptions
- `InvalidInput`: Source code fails all parse attempts
- `ParseError`: lib2to3 parsing error
- `TokenError`: Tokenization error
- `IndentationError`: Invalid indentation
- `SyntaxError`: Invalid Python syntax
- `NothingChanged`: Valid code that doesn't need formatting

## Edge Cases to Consider
- Empty strings
- Very long lines (>10000 chars)
- Deeply nested structures
- Invalid Python syntax
- Unicode characters and non-ASCII identifiers
- Mixed indentation (tabs/spaces)
- Incomplete code blocks
- Comments and docstrings
- F-strings with complex expressions
- Decorator chains
- Pattern matching (Python 3.10+)
- Type annotations
- Walrus operator
- Async/await syntax
- Context managers
- Invalid escape sequences

## Fuzzing Strategy
Focus on `black.format_str()` as main entry point since it:
1. Accepts arbitrary string input (high attack surface)
2. Performs complex parsing with lib2to3
3. Does AST validation
4. Transforms and regenerates code
5. Handles all Python syntax versions
6. Is the primary public API

The fuzzer should generate:
- Valid Python code variations
- Malformed syntax
- Edge case constructs
- Mixed valid/invalid code
- Boundary conditions (very long/short inputs)
