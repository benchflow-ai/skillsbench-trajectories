BUILD FAILURE ANALYSIS
======================

Repository: /home/travis/build/failed/google/auto
Date: 2026-01-29

SUMMARY
-------
The Google Auto project build fails on Java 11 due to missing tools.jar dependency.
Three submodules are affected: factory, service, and value.

ROOT CAUSE
----------
The compile-testing library (versions 0.6 and 0.8) used for testing contains a
system-scoped dependency on com.sun:tools:jar, which references tools.jar via the
${toolsjar} property.

In Java 8 and earlier, tools.jar existed at ${java.home}/../lib/tools.jar and
contained compiler APIs needed for annotation processing.

In Java 9+, tools.jar was removed as the Java Platform Module System (JPMS) was
introduced. The compiler APIs became part of the JDK modules and are automatically
available without requiring tools.jar.

The profiles in compile-testing POMs activate when tools.jar exists, setting the
toolsjar property. On Java 11, this file doesn't exist, but Maven still tries to
resolve the dependency, causing build failures.

AFFECTED MODULES
----------------
1. factory (auto-factory) - uses compile-testing 0.8
2. service (auto-service) - uses compile-testing 0.6
3. value (auto-value) - uses compile-testing 0.6 + missing auto-common 1.0-SNAPSHOT

DETAILED ERRORS
--------------
factory/pom.xml:
  - Error: Could not find artifact com.sun:tools:jar:11.0.27 at specified path
    /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
  - Cause: Transitive dependency from compile-testing:0.8

service/pom.xml:
  - Error: Could not find artifact com.sun:tools:jar:11.0.27 at specified path
    /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
  - Cause: Transitive dependency from compile-testing:0.6

value/pom.xml:
  - Error 1: Could not resolve dependencies for auto-common:1.0-SNAPSHOT
  - Error 2: Could not find artifact com.sun:tools:jar:11.0.27 at specified path
    /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
  - Cause 1: Missing SNAPSHOT dependency (needs to be built locally first)
  - Cause 2: Transitive dependency from compile-testing:0.6

SOLUTION STRATEGY
-----------------
The tools.jar dependency needs to be explicitly excluded from the compile-testing
transitive dependencies in all three submodules. This is safe to do because:

1. In Java 9+, the compiler APIs are available by default
2. compile-testing works without tools.jar on modern JVMs
3. The dependency is only used for compilation testing in test scope

Additionally, for the value module, auto-common needs to be built and installed
locally first.

FILES TO BE MODIFIED
-------------------
1. /home/travis/build/failed/google/auto/factory/pom.xml
   - Add exclusion for com.sun:tools in compile-testing dependency

2. /home/travis/build/failed/google/auto/service/pom.xml
   - Add exclusion for com.sun:tools in compile-testing dependency

3. /home/travis/build/failed/google/auto/value/pom.xml
   - Add exclusion for com.sun:tools in compile-testing dependency
   - Fix auto-common dependency version from 1.0-SNAPSHOT to 0.3 or 0.5
     (or build auto-common locally first)

IMPLEMENTATION APPROACH
-----------------------
For each module, add an <exclusions> block to the compile-testing dependency:

<dependency>
  <groupId>com.google.testing.compile</groupId>
  <artifactId>compile-testing</artifactId>
  <version>X.X</version>
  <scope>test</scope>
  <exclusions>
    <exclusion>
      <groupId>com.sun</groupId>
      <artifactId>tools</artifactId>
    </exclusion>
  </exclusions>
</dependency>

This tells Maven to exclude the tools.jar dependency when resolving the
compile-testing dependency tree.
