BUILD ERROR ANALYSIS - Google Auto Repository
==============================================

FAILED BUILD MODULES:
- service (auto-service)
- factory (auto-factory)
- value (auto-value)
- common (auto-common) - potentially also affected

ROOT CAUSE:
-----------
The build fails with the following error when trying to compile Java modules:

"Could not find artifact com.sun:tools:jar:11.0.27 at specified path
/usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

This is a DEPENDENCY RESOLUTION ERROR, not a code error.

ANALYSIS:
---------
The parent POM (pom.xml) defines profiles that attempt to locate tools.jar:

1. default-profile: Looks for ${java.home}/../lib/tools.jar (typical Linux/Windows)
2. mac-profile: Looks for ${java.home}/../Classes/classes.jar (macOS)

These profiles define a property <toolsjar> that points to the location of tools.jar.

PROBLEM:
The child modules (service, factory, value) do NOT have explicit dependency declarations
for com.sun:tools in their POM files. However, somewhere in the dependency chain
(likely inherited through compile-testing or another transitive dependency), a
dependency on com.sun:tools is being pulled in with a path-based system scope.

In Java 9+, tools.jar was removed and its contents merged into the main JDK. The
path ${java.home}/../lib/tools.jar does NOT exist in Java 11, causing Maven to fail
when it tries to resolve this system-scoped dependency.

MODULES AFFECTED:
1. auto-service/pom.xml - Uses compile-testing:0.6 (test dependency)
2. auto-factory/pom.xml - Uses compile-testing:0.8 (test dependency)
3. auto-value/pom.xml - Uses compile-testing:0.6 (test dependency)

These compile-testing dependencies likely transitively depend on tools.jar being available.

FIX STRATEGY:
-------------
Since Java 9+/11 no longer has/needs tools.jar (its classes are in the base JVM),
we need to prevent Maven from trying to resolve the non-existent com.sun:tools
dependency.

There are two approaches:
A) Add explicit exclusions in the modules that depend on compile-testing
B) Configure the parent POM to properly handle Java 9+ where tools.jar doesn't exist

SECONDARY ERROR - javax.annotation.Generated Missing:
After fixing the tools.jar issue, the factory module fails with:
"cannot find symbol: class Generated in package javax.annotation"

This occurs because in Java 9+, javax.annotation.Generated was removed from the JDK
and must be provided as an external dependency (javax.annotation:javax.annotation-api).

The factory module imports javax.annotation.Generated but doesn't declare
this dependency.

RECOMMENDED FIX:
There are two problems to fix:

1. TOOLS.JAR ISSUE (Primary):
   Add exclusions to eliminate the com.sun:tools dependency that compile-testing
   transitively requires. This dependency path was:
   - compile-testing:0.6/0.8 declares com.sun:tools with system scope
   - compile-testing tries to find it at ${toolsjar}
   - But on Java 11, tools.jar doesn't exist

   SOLUTION: Add <exclusions> to compile-testing dependencies in:
   - service/pom.xml
   - factory/pom.xml
   - value/pom.xml

2. JAVAX.ANNOTATION.GENERATED MISSING (Secondary):
   The factory module needs javax.annotation:javax.annotation-api as a dependency.

   SOLUTION: Add javax.annotation:javax.annotation-api dependency to factory/pom.xml

Both are BUILD CONFIGURATION ISSUES, not source code issues.
