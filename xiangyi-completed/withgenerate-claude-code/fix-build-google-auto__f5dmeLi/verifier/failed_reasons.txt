BUILD FAILURE ANALYSIS
======================

Repository: /home/travis/build/failed/google/auto
Build System: Maven
Java Version: OpenJDK 11.0.27

ERROR SUMMARY
-------------
Build fails with the following error:
"Could not resolve dependencies for project com.google.auto:auto-common:jar:1.0-SNAPSHOT:
Could not find artifact com.sun:tools:jar:11.0.27 at specified path
/usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

ROOT CAUSE
----------
The build failure is caused by incompatibility between JDK 11 and the Maven configuration.

1. The system is running JDK 11, which does NOT have tools.jar file
   - In JDK 8 and earlier: Compiler tools were in lib/tools.jar
   - In JDK 9+: tools.jar was removed; tools moved to java.compiler and jdk.compiler modules

2. The parent POM (pom.xml in /home/travis/build/failed/google/auto/pom.xml)
   defines two Maven profiles that set the ${toolsjar} property:
   - default-profile: Activates when ${java.home}/../lib/tools.jar EXISTS
   - mac-profile: Activates when ${java.home}/../Classes/classes.jar EXISTS

3. Since neither file exists in JDK 11, NEITHER profile activates,
   leaving ${toolsjar} property UNDEFINED

4. The compile-testing library (used as test dependency in common, factory, service, value modules)
   has a system-scoped dependency on com.sun:tools:jar that references ${toolsjar}:

   <dependency>
     <groupId>com.sun</groupId>
     <artifactId>tools</artifactId>
     <version>${java.version}</version>
     <scope>system</scope>
     <systemPath>${toolsjar}</systemPath>
   </dependency>

5. When Maven tries to resolve this dependency with an undefined ${toolsjar},
   it defaults to looking for tools.jar relative to the JDK installation, which fails

ERROR LOCATION
--------------
Configuration errors are in:
- /home/travis/build/failed/google/auto/pom.xml (parent POM)
  Lines 167-208: Profile definitions that don't handle JDK 9+

AFFECTED MODULES
----------------
All modules that depend on compile-testing (test scope):
- common/pom.xml (line 55-59: compile-testing 0.7)
- factory/pom.xml (line 72-76: compile-testing 0.8)
- service/pom.xml (line 55-59: compile-testing 0.6)
- value/pom.xml (line 80-84: compile-testing 0.6)

SOLUTION APPROACH
-----------------
The parent POM needs to be fixed to handle JDK 9+ where tools.jar doesn't exist.

Option 1 (Recommended): Add a JDK 9+ profile with a safe default for ${toolsjar}
- Add a new profile that activates for JDK [9,)
- Set ${toolsjar} to ${java.home} (which always exists) or similar safe value
- This prevents the undefined property error

Option 2: Remove the profiles entirely and set a safe default in <properties>
- Set <toolsjar>${java.home}</toolsjar> directly
- The compile-testing dependency will still fail to find the actual tools,
  but may handle it gracefully for test compilation

Option 3: Upgrade to newer compile-testing versions
- Newer versions may handle JDK 9+ better
- However, this requires version bumps which may cause other compatibility issues

Recommended fix: Option 1 - Add JDK 9+ profile

FIXES APPLIED
-------------
The following fixes have been successfully applied:

   - Added jdk9-plus-profile that activates for JDK [9,)

2. Module POMs (common, factory, service, value):
