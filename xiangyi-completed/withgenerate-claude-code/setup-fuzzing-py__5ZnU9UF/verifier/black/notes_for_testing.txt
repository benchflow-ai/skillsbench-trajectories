# Black Library - Testing Notes

## Library Purpose
Black is "The uncompromising code formatter" for Python. It automatically formats Python code to conform to PEP 8 style guide, with opinionated style choices.

## Main Module/Package
- Import path: `import black`
- Main entry points: `black.format_str()`, `black.format_file_contents()`
- Key classes: `Mode`, parsing functions

## High-Priority Functions for Fuzzing

### 1. format_str()
- **Location**: `black.__init__.format_str` (line ~1177)
- **Purpose**: Format a Python source code string
- **Input types**: str (Python source code), Mode object (configuration)
- **Edge cases**:
  - Invalid Python syntax
  - Deeply nested code
  - Very long lines
  - Unicode characters in code
  - String literals with special characters
  - Complex f-strings
  - Malformed comments
- **Exceptions**: InvalidInput, NothingChanged, various parsing errors
- **Why fuzz**: Parses arbitrary Python code strings - high attack surface

### 2. format_file_contents()
- **Location**: `black.__init__.format_file_contents` (line ~1068)
- **Purpose**: Format Python file contents
- **Input types**: str (file contents), bool (fast mode), Mode object
- **Edge cases**:
  - Invalid file encoding
  - Mixed tabs and spaces
  - Very large files
  - Syntax errors
- **Exceptions**: InvalidInput, NothingChanged
- **Why fuzz**: File content parsing with encoding handling

### 3. lib2to3_parse()
- **Location**: `black.parsing.lib2to3_parse`
- **Purpose**: Parse Python source code into AST using lib2to3
- **Input types**: str (source code), TargetVersion
- **Edge cases**:
  - Syntax errors
  - Python 2 vs 3 syntax differences
  - New Python syntax features
  - Edge cases in grammar
- **Exceptions**: InvalidInput, ASTSafetyError
- **Why fuzz**: Core parsing function, uses lib2to3 parser

### 4. parse_ast()
- **Location**: `black.parsing.parse_ast`
- **Purpose**: Parse Python source into AST
- **Input types**: str (source code)
- **Edge cases**:
  - Syntax errors
  - Very long expressions
  - Nested structures
- **Exceptions**: InvalidInput, SyntaxError
- **Why fuzz**: Another AST parser path

### 5. normalize_string_quotes()
- **Location**: `black.strings` module
- **Purpose**: Normalize quote styles in strings
- **Input types**: str (Python code with strings)
- **Edge cases**:
  - Mixed quote types
  - Escaped quotes
  - Triple-quoted strings
  - Raw strings, f-strings
- **Exceptions**: Various string processing errors
- **Why fuzz**: Complex string processing logic

## Dependencies
- click (CLI framework)
- mypy-extensions
- pathspec
- platformdirs
- tomli (for Python <3.11)
- typing-extensions

## Known Issues
- Parsing edge cases in Python syntax
- String processing can be complex
- AST manipulation can have bugs
- Performance issues with very large files

## Testing Strategy
1. Primary focus: `format_str()` with various Python code inputs
2. Secondary: Parsing functions (lib2to3_parse, parse_ast)
3. Test with:
   - Valid Python code (should not crash)
   - Invalid Python syntax (should raise InvalidInput)
   - Edge cases: deeply nested code, long lines, complex strings
   - Unicode and special characters
   - All Python syntax features (f-strings, walrus operator, etc.)
4. Catch expected exceptions: InvalidInput, NothingChanged, SyntaxError
5. Let unexpected exceptions crash (bugs!)
6. Focus on code that should parse (even if ugly) but might crash formatter
