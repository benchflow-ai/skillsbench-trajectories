# UltraJSON (ujson) Library - Testing Notes

## Library Purpose
UltraJSON (ujson) is an ultra-fast JSON encoder and decoder written in pure C with Python bindings. It's designed as a drop-in replacement for Python's standard json module with better performance.

## Main Module/Package
- Import path: `import ujson`
- Main functions: `ujson.loads()`, `ujson.dumps()`, `ujson.load()`, `ujson.dump()`
- Implementation: C extension module (Python bindings to C code)

## High-Priority Functions for Fuzzing

### 1. ujson.loads()
- **Location**: C function `JSONToObj` exposed as `ujson.loads`
- **Purpose**: Parse JSON string into Python objects
- **Input types**: str or bytes (JSON data)
- **Edge cases**:
  - Invalid JSON syntax
  - Deeply nested structures (stack overflow)
  - Very large numbers
  - Unicode edge cases
  - Malformed escape sequences
  - Null bytes in strings
  - Integer overflow/underflow
  - Floating point edge cases (inf, nan)
- **Exceptions**: ValueError (JSON decode error)
- **Why fuzz**: C parser handling untrusted input - HIGH SECURITY IMPACT
- **Security note**: README warns about buffer overflow vulnerabilities

### 2. ujson.dumps()
- **Location**: C function `objToJSON` exposed as `ujson.dumps`
- **Purpose**: Serialize Python objects to JSON string
- **Input types**: Python objects (dict, list, str, int, float, bool, None)
- **Edge cases**:
  - Circular references
  - Very deep nesting
  - Large integers
  - Special float values (inf, -inf, nan)
  - Unicode strings
  - Non-serializable objects
- **Exceptions**: TypeError, OverflowError
- **Why fuzz**: C serialization code can have bugs

### 3. ujson.load()
- **Location**: C function reading from file
- **Purpose**: Parse JSON from file object
- **Input types**: file-like object
- **Edge cases**:
  - Same as loads() but from file
  - Large files
  - Encoding issues
- **Exceptions**: ValueError, IOError
- **Why fuzz**: File parsing adds complexity

### 4. ujson.dump()
- **Location**: C function writing to file
- **Purpose**: Serialize to JSON file
- **Input types**: Python object + file object
- **Edge cases**:
  - Same as dumps() but to file
  - Write failures
- **Exceptions**: TypeError, IOError
- **Why fuzz**: File handling adds edge cases

## Dependencies
- None (pure C extension, no Python dependencies)
- Requires C compiler to build

## Known Issues
- README WARNING: "fundamentally ill-suited to making changes without risk of introducing new security vulnerabilities"
- Library is in maintenance-only mode
- Known history of buffer overflow vulnerabilities
- Users encouraged to migrate to orjson

## Testing Strategy
1. **PRIMARY FOCUS**: `ujson.loads()` - most critical for security
2. **Secondary**: `ujson.dumps()` - can have edge cases
3. Test with:
   - Random JSON-like strings (many will be invalid)
   - Valid but edge-case JSON (deep nesting, large numbers)
   - Unicode strings
   - Very long strings
   - Malformed escape sequences
   - Special numeric values
4. Catch expected exceptions: ValueError (JSON errors)
5. Let unexpected exceptions crash - these are BUGS or SECURITY ISSUES
6. Focus on inputs that might cause:
   - Buffer overflows
   - Stack overflows (deep nesting)
   - Integer overflows
   - Memory corruption
7. This is a C extension - crashes are possible and important to find!

## Critical Security Note
Since this is a C parser known to have security issues, any crashes found are VERY IMPORTANT and should be reported. Focus fuzzing effort here.
