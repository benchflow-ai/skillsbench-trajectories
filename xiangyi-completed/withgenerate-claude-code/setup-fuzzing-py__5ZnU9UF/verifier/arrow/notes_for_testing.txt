# Arrow Library - Testing Notes

## Library Purpose
Arrow is a Python library for better date and time handling. It provides a sensible and human-friendly approach to creating, manipulating, formatting and converting dates, times and timestamps.

## Main Module/Package
- Import path: `import arrow`
- Main entry points: `arrow.get()`, `arrow.now()`, `arrow.utcnow()`
- Key classes: `Arrow` (datetime wrapper), `ArrowFactory`

## High-Priority Functions for Fuzzing

### 1. arrow.get()
- **Location**: `arrow.api.get` (calls `arrow.factory.ArrowFactory.get`)
- **Purpose**: Parse various inputs into Arrow datetime objects
- **Input types**: str (datetime strings), int/float (timestamps), datetime objects, tuples
- **Edge cases**:
  - Invalid datetime strings
  - Various date format strings (ISO, RFC, custom)
  - Out-of-range timestamps
  - Malformed format strings
  - Invalid timezone strings
- **Exceptions**: ParserError, ValueError, TypeError
- **Why fuzz**: This is the main parsing function - parses arbitrary string inputs

### 2. Arrow.format()
- **Location**: `arrow.arrow.Arrow.format`
- **Purpose**: Format Arrow object to string using format string
- **Input types**: str (format string)
- **Edge cases**:
  - Invalid format tokens
  - Malformed format strings
  - Special characters in format
- **Exceptions**: ValueError
- **Why fuzz**: String formatting with custom patterns is error-prone

### 3. DateTimeParser.parse()
- **Location**: `arrow.parser.DateTimeParser.parse`
- **Purpose**: Core parsing logic for datetime strings
- **Input types**: str (datetime string), str (format string)
- **Edge cases**:
  - Unicode characters
  - Very long strings
  - Regex pattern injection via format strings
  - Locale-specific parsing
- **Exceptions**: ParserError, ParserMatchError
- **Why fuzz**: Complex regex-based parsing, high bug potential

### 4. Arrow.shift()
- **Location**: `arrow.arrow.Arrow.shift`
- **Purpose**: Shift datetime by specified units
- **Input types**: dict/kwargs with time units
- **Edge cases**:
  - Very large shift values
  - Multiple conflicting shifts
  - Invalid keyword arguments
- **Exceptions**: ValueError, AttributeError
- **Why fuzz**: Arithmetic operations on dates can overflow

## Dependencies
- python-dateutil>=2.7.0
- tzdata (Python 3.9+) or backports.zoneinfo (Python <3.9)

## Known Issues
- Parsing is complex due to multiple format support
- Timezone handling can be tricky
- Locale-specific parsing adds complexity

## Testing Strategy
1. Primary focus: `arrow.get()` with string parsing (highest attack surface)
2. Secondary: Format string processing in `Arrow.format()`
3. Test with:
   - Random strings (invalid dates)
   - Valid but edge-case dates (year 0, year 9999)
   - Various format strings
   - Timezone strings
   - Unicode and special characters
4. Catch expected exceptions: ParserError, ValueError, TypeError
5. Let unexpected exceptions crash (bugs!)
