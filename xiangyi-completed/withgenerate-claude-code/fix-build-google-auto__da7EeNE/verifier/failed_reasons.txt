# Build Failure Analysis: google/auto

## Repository Information
- Repository: google/auto
- Location: /home/travis/build/failed/google/auto
- Build System: Maven
- Java Version: OpenJDK 11.0.27

## Build Error Summary

All four submodules (common, factory, service, value) failed to build with two main issues:

### Issue 1: tools.jar Not Found (All Modules)
```
ERROR: Could not find artifact com.sun:tools:jar:11.0.27 at specified path
/usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
```

### Issue 2: javax.annotation.Generated Not Found (factory, value)
```
ERROR: cannot find symbol
  symbol:   class Generated
  location: package javax.annotation
```

## Root Cause Analysis

### Issue 1: tools.jar Removal in Java 9+
The `tools.jar` file was removed in Java 9 as part of the Java Platform Module System (JPMS)
introduced in JEP 261. This codebase was written for Java 6/8 and has dependencies that
require `tools.jar`, which doesn't exist in Java 11.

**Affected Dependency**: The `compile-testing` library (used for testing annotation processors)
has a dependency on `com.sun:tools` in older versions:
- common/pom.xml: compile-testing version 0.7
- factory/pom.xml: compile-testing version 0.8
- service/pom.xml: compile-testing version 0.6
- value/pom.xml: compile-testing version 0.6

### Issue 2: javax.annotation.Generated Package Change in Java 9+
In Java 9+, the `javax.annotation.Generated` class was moved to `javax.annotation.processing.Generated`.

**Affected Files**:
- factory/src/main/java/com/google/auto/factory/processor/FactoryWriter.java:39
- value/src/main/java/com/google/auto/value/processor/AutoValueProcessor.java:51
- value/src/main/java/com/google/auto/value/processor/AutoAnnotationProcessor.java:36

## Applied Fixes

### patch_1.diff (common module)
- Upgraded compile-testing from 0.7 to 0.19
- Upgraded truth from 0.25 to 1.1

### patch_2.diff (factory module)
- Upgraded compile-testing from 0.8 to 0.19
- Upgraded truth from 0.25 to 1.1
- Changed import from `javax.annotation.Generated` to `javax.annotation.processing.Generated`
  in FactoryWriter.java

### patch_3.diff (service module)
- Upgraded compile-testing from 0.6 to 0.19
- Upgraded truth from 0.24 to 1.1

### patch_4.diff (value module)
- Upgraded compile-testing from 0.6 to 0.19
- Upgraded truth from 0.25 to 1.1
- Changed import from `javax.annotation.Generated` to `javax.annotation.processing.Generated`
  in AutoValueProcessor.java and AutoAnnotationProcessor.java

## Verification Results

After applying all fixes:
- common module: BUILD SUCCESS
- factory module: BUILD SUCCESS
- service module: BUILD SUCCESS
- value module: BUILD SUCCESS

All modules now compile successfully with `mvn compile`.

## Notes

1. The truth version upgrade (0.24/0.25 -> 1.1) is required because compile-testing 0.19
   depends on truth 1.1.

2. There may be test compilation failures due to API changes in the newer truth library
   (e.g., `named()` and `hasMessage()` methods were changed). These would require
   additional test code updates if full test compatibility is needed.

3. The code still shows deprecation warnings about Java 6 source/target compatibility
   and deprecated SimpleElementVisitor6/SimpleTypeVisitor6 usage, but these are warnings
   only and do not prevent compilation.
