BUILD FAILURE ANALYSIS
======================
Repository: /home/travis/build/failed/google/auto/service
Date: 2026-01-29
Java Version: OpenJDK 11.0.27

ERROR SUMMARY
-------------
Build fails with dependency resolution error:
"Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

ROOT CAUSE ANALYSIS
-------------------

1. DIRECT CAUSE:
   The build is trying to resolve a system-scoped dependency to tools.jar, but the file doesn't exist.

   Expected path: /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
   Reality: This file does not exist in Java 11 (or any Java 9+)

2. WHY tools.jar IS MISSING:
   - In Java 8 and earlier: Compiler classes (javac, etc.) were packaged in JAVA_HOME/lib/tools.jar
   - In Java 9+: The module system was introduced, and these classes were moved to modules
   - The tools.jar file was removed entirely starting with Java 9
   - The classes are now in jdk.compiler and java.compiler modules

3. WHERE THE DEPENDENCY COMES FROM:
   - The project pom.xml (auto-service) has a test dependency on compile-testing:0.6
   - compile-testing:0.6 has a system-scoped dependency on com.sun:tools
   - This dependency is defined in compile-testing's pom.xml:

     <dependency>
       <groupId>com.sun</groupId>
       <artifactId>tools</artifactId>
       <version>${java.version}</version>
       <scope>system</scope>
       <systemPath>${toolsjar}</systemPath>
     </dependency>

   - The ${toolsjar} property is set by profiles in the parent POM (auto-parent:3)
   - The profile detects Java 8 and sets: ${java.home}/../lib/tools.jar
   - This path doesn't exist in Java 11

4. TRANSITIVE DEPENDENCY CHAIN:
   auto-service:1.0-SNAPSHOT (the project)
     └── compile-testing:0.6 (test scope)
         └── com.sun:tools:11.0.27 (system scope) ← FAILS HERE

ERROR TYPE
----------
Category: Build Configuration Error
Subcategory: Java Version Compatibility Issue
Specific: System-scoped dependency pointing to non-existent file (tools.jar on Java 9+)

IMPACT
------
- Build cannot proceed past dependency resolution phase
- Tests cannot run (compile-testing is a test dependency)
- The actual source code compilation is blocked before it starts

PROPOSED SOLUTIONS
------------------

SOLUTION 1: Exclude the tools.jar dependency (RECOMMENDED)
   - Since compile-testing is only a test dependency, we can exclude the problematic transitive dependency
   - Modern versions of compile-testing (0.7+) don't require tools.jar on Java 9+
   - However, we're stuck with version 0.6, so we need to exclude it explicitly
   - The javax.tools API (for javac) is available in Java 11 without tools.jar

   Implementation:
   Add an exclusion to the compile-testing dependency in pom.xml

   Pros:
   - Minimal change to the POM
   - Maintains compatibility with Java 11
   - No version changes required

   Cons:
   - If tests actually use tools.jar classes directly, they might fail
   - Need to verify tests still pass

SOLUTION 2: Update compile-testing to a newer version
   - Newer versions (0.18+) have removed the tools.jar dependency
   - They work correctly with Java 9+

   Implementation:
   Update compile-testing version from 0.6 to 0.18 or later

   Pros:
   - More future-proof
   - Better Java 9+ support
   - Cleaner solution

   Cons:
   - May require API changes in test code
   - Higher risk of breaking existing tests
   - Not chosen for this fix due to potential test incompatibilities

SOLUTION 3: Add Java version profile to exclude on Java 9+
   - Use Maven profiles to conditionally exclude the dependency

   Pros:
   - Works on both Java 8 and Java 11

   Cons:
   - More complex
   - Adds profile complexity to the POM
   - Overkill for this specific issue

RECOMMENDED FIX
---------------
Use Solution 1: Exclude the com.sun:tools dependency from compile-testing

This is the safest and most minimal change that will fix the build without
risking test compatibility issues. The javax.tools API is available in the
JDK without needing the old tools.jar file.
