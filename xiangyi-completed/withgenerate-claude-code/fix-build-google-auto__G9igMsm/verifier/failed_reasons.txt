## Build Environment

- **Build Tool**: Maven

## Error Summary

### Primary Error
```
Could not resolve dependencies for project X: Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
```

### Affected Modules
1. **auto-common** (common/pom.xml)
2. **auto-factory** (factory/pom.xml)
3. **auto-service** (service/pom.xml)
4. **auto-value** (value/pom.xml)

## Root Cause Analysis

### The Problem
The build fails because of a dependency on `com.sun:tools` (tools.jar) which no longer exists in Java 9+.

### Technical Details
1. In Java 8 and earlier, the JDK included `$JAVA_HOME/lib/tools.jar` containing:
   - Java compiler API (com.sun.tools.javac.*)
   - Annotation processing utilities
   - Other development tools

2. In Java 9+ (including Java 11 which is the current environment), `tools.jar` was removed as part of Project Jigsaw (JDK modularization). These classes are now part of:
   - `java.compiler` module
   - `jdk.compiler` module

### Dependency Chain
The `com.sun:tools` dependency comes from the `compile-testing` library:

```
auto-common -> compile-testing:0.7 (test scope) -> com.sun:tools (system scope)
auto-factory -> compile-testing:0.8 (test scope) -> com.sun:tools (system scope)
auto-service -> compile-testing:0.6 (test scope) -> com.sun:tools (system scope)
auto-value -> compile-testing:0.6 (test scope) -> com.sun:tools (system scope)
```

The compile-testing library (versions 0.6, 0.7, 0.8) has a system-scoped dependency:
```xml
<dependency>
  <groupId>com.sun</groupId>
  <artifactId>tools</artifactId>
  <version>${java.version}</version>
  <scope>system</scope>
  <systemPath>${java.home}/../lib/tools.jar</systemPath>
</dependency>
```

### Secondary Issue (auto-value only)
The auto-value module also has a dependency on `com.google.auto:auto-common:1.0-SNAPSHOT` which is not available in Maven Central (it's a snapshot version that needs to be built locally first).

## Proposed Fix

### Strategy
Update the `compile-testing` dependency to version 0.18 which:
1. Removed the `tools.jar` dependency
2. Is compatible with Java 9, 11, 17, and newer
3. Uses the standard javax.annotation.processing API

### Files to Modify
1. **common/pom.xml** (line 57): Update compile-testing from 0.7 to 0.18
2. **factory/pom.xml** (line 74): Update compile-testing from 0.8 to 0.18
3. **service/pom.xml** (line 57): Update compile-testing from 0.6 to 0.18
4. **value/pom.xml** (line 82): Update compile-testing from 0.6 to 0.18
5. **value/pom.xml** (line 49): Update auto-common from 1.0-SNAPSHOT to 0.10 (a released version)

### Additional Changes Required
The compile-testing 0.18 has updated dependencies (truth version, guava version) that should be compatible with the existing codebase.

## Secondary Error (Discovered After Initial Fix)

### Error Message
```
cannot find symbol
  symbol:   class Generated
  location: package javax.annotation
```

### Affected Files
1. factory/src/main/java/com/google/auto/factory/processor/FactoryWriter.java (line 39, 60)
2. value/src/main/java/com/google/auto/value/processor/AutoAnnotationProcessor.java (line 36)
3. value/src/main/java/com/google/auto/value/processor/AutoValueProcessor.java (line 51)

### Root Cause
In Java 9, `javax.annotation.Generated` was moved to `javax.annotation.processing.Generated`.
The old `javax.annotation.Generated` was part of Java EE annotations that were deprecated in Java 9
and removed in Java 11.

### Additional Fix Required
Change import from:
```java
import javax.annotation.Generated;
```
To:
```java
import javax.annotation.processing.Generated;
```

And update the string literal in FactoryWriter.java line 60 from:
```java
.emitImports("javax.annotation.Generated");
```
To:
```java
.emitImports("javax.annotation.processing.Generated");
```
