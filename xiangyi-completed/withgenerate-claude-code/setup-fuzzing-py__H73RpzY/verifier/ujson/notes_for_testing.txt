Library: UltraJSON (ujson)
Purpose: Ultra-fast C-based JSON encoder/decoder with Python bindings
Version: 5.8.0+ (from pyproject.toml)
Python: 3.10+

MAIN ENTRY POINTS:
1. ujson.loads(json_string) -> object
   - Purpose: Parse JSON string to Python object
   - Input format: str, bytes, or bytearray with JSON data
   - Location: src/ujson/python/JSONtoObj.c:JSONToObj()
   - Core: src/ujson/lib/ultrajsondec.c

2. ujson.dumps(obj, **kwargs) -> str
   - Purpose: Serialize Python object to JSON string
   - Input format: Any JSON-serializable Python object
   - Location: src/ujson/python/objToJSON.c:objToJSON()
   - Core: src/ujson/lib/ultrajsonenc.c (25,526 lines!)

INPUT FORMATS:
- Type: String/bytes for loads(), Python objects for dumps()
- Encoding: UTF-8 for strings
- Structure: Valid/invalid JSON syntax
- Limits: Max recursion depth = 1024, max stack buffer = 1024 bytes

FUZZ TARGETS (priority order):
1. ujson.loads(json_string) - src/ujson/python/JSONtoObj.c
   - JSON string parsing with validation
   - Tests: Valid JSON, malformed JSON, edge cases, nested structures
   - Key functions:
     * decode_string() - Handles string escape sequences
     * decode_numeric() - Integer/float parsing
     * decodeDouble() - Double precision parsing
     * decode_array() - Recursive array parsing
     * decode_object() - Recursive object parsing
     * SkipWhitespace() - Whitespace handling

2. ujson.dumps(obj, **kwargs) - src/ujson/python/objToJSON.c
   - Python object serialization
   - Tests: Various Python types, nested structures, serialization options
   - Key parameters:
     * ensure_ascii (bool) - Escape non-ASCII
     * encode_html_chars (bool) - Escape <>&"
     * escape_forward_slashes (bool) - Escape /
     * sort_keys (bool) - Sort dict keys
     * indent (int) - Indentation level
     * allow_nan (bool) - Allow NaN/Infinity
     * reject_bytes (bool) - Reject bytes objects
     * default (callable) - Custom serializer

EXPECTED EXCEPTIONS:
- ujson.JSONDecodeError (subclass of ValueError)
  * "Unexpected character found when decoding..."
  * "Reached object decoding depth limit"
  * "Invalid UTF-8 sequence length..."
  * "Unmatched '\"' when decoding 'string'"
  * "Key name of object must be 'string'..."
- TypeError: Non-string keys in dicts, circular references
- ValueError: Invalid values

DEPENDENCIES:
- double-conversion (bundled in src/ujson/deps/)
- Python 3.10+
- C compiler with C++ support
- Python development headers

KEY MODULES:
- src/ujson/python/ujson.c - Module initialization and API registration
- src/ujson/python/JSONtoObj.c - Decoder entry point
- src/ujson/python/objToJSON.c - Encoder entry point
- src/ujson/lib/ultrajson.h - Type definitions and limits
- src/ujson/lib/ultrajsondec.c - Core JSON decoder (834 lines)
- src/ujson/lib/ultrajsonenc.c - Core JSON encoder (25,526 lines)

FUZZING STRATEGY FOR DECODER:
1. Valid JSON:
   - Primitives: null, true, false, numbers, strings
   - Collections: arrays, objects, nested structures
   - Escape sequences: \", \\, \/, \b, \f, \n, \r, \t, \uXXXX

2. Boundary values for numbers:
   - Integer boundaries: 2^31-1, 2^63-1, -2^31, -2^63
   - Float boundaries: 1e308, 1e-308, NaN, Infinity, -Infinity
   - Special values: 0, -0, very large exponents

3. Edge cases:
   - Empty structures: {}, []
   - Very deeply nested (1000+ levels)
   - Very long strings
   - Invalid escape sequences
   - Incomplete structures
   - Malformed numbers
   - Duplicate keys in objects
   - Non-ASCII characters in strings
   - UTF-8 invalid sequences

4. Recursion/resource exhaustion:
   - Deeply nested arrays: [[[[...]]]]
   - Deeply nested objects: {"a": {"b": {"c": ...}}}
   - Very large arrays with many elements
   - Very large object keys/values

FUZZING STRATEGY FOR ENCODER:
1. Python types:
   - None, True, False
   - Integers (small, large, negative)
   - Floats (normal, special: inf, -inf, nan)
   - Strings (ASCII, Unicode, escape-worthy)
   - Lists/tuples with mixed types
   - Dicts with string/non-string keys

2. Nested structures:
   - Deeply nested lists and dicts
   - Mixed nesting (lists in dicts, vice versa)
   - Circular references (will cause infinite loop?)

3. Serialization options:
   - Various combinations of ensure_ascii, encode_html_chars, etc.
   - Different indent levels
   - sort_keys with various key types

MAINTENANCE NOTE:
Library is in MAINTENANCE-ONLY mode. Architecture is "fundamentally ill-suited" to changes without security risks. Focus fuzzing on:
- Buffer overflows in string/numeric parsing
- Stack exhaustion (recursion depth)
- Memory leaks (reference counting)
- Integer overflows in size calculations
- UTF-8 handling edge cases

NOTES:
- C implementation makes this critical for fuzzing
- Recursion depth limit (1024) good DoS vector
- String escape handling complex and error-prone
- Number parsing delegates to double-conversion library
- Encoder is very large (25k lines) - many edge cases possible
