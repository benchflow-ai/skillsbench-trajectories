Library: Mini-SGLang (minisgl)
Purpose: Lightweight high-performance LLM inference framework with optimizations
Version: 0.1.0 (from pyproject.toml)
Python: 3.10+

MAIN ENTRY POINTS:
1. launch_server(model_path, port=8000, run_shell=False)
   - Purpose: Launch OpenAI-compatible API server
   - Location: python/minisgl/server/launch.py
   - Modes: API server or interactive shell

2. LLM.generate(prompts, sampling_params) -> List[Dict[str, str | List[int]]]
   - Purpose: Offline batch inference
   - Input format: String prompts or token IDs, SamplingParams
   - Location: python/minisgl/llm/llm.py

3. HTTP API Endpoints (FastAPI):
   - POST /generate - Text generation request
   - POST /v1/chat/completions - OpenAI-compatible chat
   - GET /v1/models - List models

INPUT FORMATS:
- Type: String (prompts, model paths), JSON (requests), integers (token IDs)
- Encoding: UTF-8
- Structure: Prompt strings, chat message arrays, numerical parameters
- Configuration: SamplingParams with temperature, top_k, top_p, max_tokens

FUZZ TARGETS (priority order):
1. HTTP Request parsing (FastAPI) - python/minisgl/server/api_server.py
   - GenerateRequest and OpenAICompletionRequest Pydantic models
   - Tests: Missing fields, type mismatches, extreme values, malformed JSON

2. Message serialization/deserialization - python/minisgl/message/utils.py
   - serialize_type() and deserialize_type()
   - Tests: Malformed JSON, invalid type names, corrupted buffers, circular refs

3. Tokenizer input processing - python/minisgl/tokenizer/tokenize.py
   - TokenizeManager.tokenize(messages)
   - Tests: Very long strings, invalid UTF-8, mixed chat/text formats

4. Detokenizer processing - python/minisgl/tokenizer/detokenize.py
   - DetokenizeManager.detokenize(), find_printable_text()
   - Tests: Invalid token sequences, slicing/indexing edge cases

5. Sampling parameter validation - python/minisgl/core.py
   - SamplingParams validation and is_greedy property
   - Tests: Out-of-bounds values, NaN, infinity, invalid combinations

6. Request batch management - python/minisgl/core.py
   - Req and Batch classes with tensor operations
   - Tests: Shape mismatches, index bounds, length invariants

7. CLI argument parsing - python/minisgl/server/args.py
   - parse_args() with model path, dtype, parallelism options
   - Tests: Invalid paths, invalid dtypes, boundary values

8. Model loading - python/minisgl/model/model_runner.py
   - Model instantiation and initialization
   - Tests: Invalid model paths, missing dependencies

EXPECTED EXCEPTIONS:
- json.JSONDecodeError: Malformed JSON in requests
- pydantic.ValidationError: Invalid request parameters
- ValueError: Invalid parameter values
- TypeError: Type mismatches in message serialization
- KeyError: Invalid type names in deserialization
- torch.cuda.CudaError: CUDA-related issues (GPU only)
- FileNotFoundError: Missing model files

FUZZING STRATEGY:
1. API Request fuzzing (highest priority):
   - Valid requests with extreme numerical values
   - Missing required fields (prompt or messages)
   - Type mismatches (string vs array, etc.)
   - Very large payloads
   - Malformed JSON
   - Out-of-range parameters

2. Message structure fuzzing:
   - Invalid message roles
   - Empty messages array
   - Very long message content
   - Non-string content fields
   - Circular references in serialization
   - Missing __type__ field in deserialization

3. Tokenizer input fuzzing:
   - Very long text (>100MB)
   - Invalid UTF-8 sequences
   - Control characters and null bytes
   - Mixed chat/text formats
   - Malformed chat message structure

4. Sampling parameter fuzzing:
   - Boundary values: temperature (negative, >2, NaN, inf)
   - top_k: negative, zero, extremely large
   - top_p: <0, >1, NaN, inf
   - max_tokens: 0, negative, extremely large

5. Tensor operation fuzzing:
   - Mismatched tensor shapes in batch operations
   - Invalid index ranges
   - Zero-length tensors
   - Dtype mismatches

6. CLI argument fuzzing:
   - Invalid model paths (symlinks, traversal attempts)
   - Invalid dtype strings
   - Out-of-range parallelism values
   - Negative memory ratios

REQUEST FORMATS:

/generate endpoint:
{
  "prompt": "string",
  "max_tokens": int (default 16),
  "temperature": float (default 1.0),
  "top_k": int (default -1),
  "top_p": float (default 1.0),
  "stream": bool (default false)
}

/v1/chat/completions endpoint:
{
  "messages": [
    {"role": "user|assistant|system", "content": "string"},
    ...
  ] OR "prompt": "string",
  "max_tokens": int,
  "temperature": float,
  "top_k": int,
  "top_p": float,
  "model": "string (model identifier)",
  "stream": bool
}

SAMPLING PARAMETERS:
- temperature: float, default 0.0 (0 = greedy, >0 = sampling)
- top_k: int, default -1 (negative = disabled)
- top_p: float, default 1.0 (nucleus sampling)
- ignore_eos: bool, default false
- max_tokens: int, default 1024

CRITICAL LIMITS:
- Max recursion depth in serialization: Not explicitly set
- Max input length: Not enforced at API level
- Max concurrent requests: Configurable (default likely 256)
- Memory limits: Based on GPU/system memory

NOTES:
- GPU-dependent library (Linux CUDA only)
- Performance-critical for inference
- Message serialization/deserialization handles torch.Tensor objects
- Fuzzing should focus on API request validation and serialization robustness
- System failures (OOM, CUDA errors) expected with extreme inputs
