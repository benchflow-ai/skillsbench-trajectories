BUILD FAILURE ANALYSIS
=====================

Repository: google/auto
Build command: mvn -B -U -f build-pom.xml verify

Two distinct errors cause the build to fail:

ERROR 1: com.sun:tools:jar dependency resolution failure
---------------------------------------------------------
Module: auto-common (and transitively all downstream modules)
Error message:
  "Could not find artifact com.sun:tools:jar:11.0.27 at specified path
   /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

Root cause:
  The compile-testing library (versions 0.6, 0.7, 0.8) used as a test
  dependency in auto-common, auto-service, auto-factory, and auto-value
  declares a system-scoped dependency on com.sun:tools with a systemPath
  pointing to ${java.home}/../lib/tools.jar.

  This tools.jar file existed in Java 8 and earlier but was removed in
  Java 9 as part of Project Jigsaw (the module system). The classes from
  tools.jar were incorporated into the java.compiler and jdk.compiler modules.

  The build environment runs Maven with Java 11 JRE (openjdk 11.0.27),
  which does not have tools.jar. Additionally, this is only a JRE (not JDK),
  so javac is not available either.

  However, Java 7 and Java 8 JDKs are installed on the system:
  - /usr/lib/jvm/java-7-openjdk-amd64 (JDK with tools.jar)
  - /usr/lib/jvm/java-8-oracle (JDK with tools.jar)

  The parent POM (pom.xml) has profiles for detecting tools.jar but they
  cannot resolve the issue because the file simply doesn't exist for Java 11.

Fix:
  Set JAVA_HOME to /usr/lib/jvm/java-8-oracle to use a JDK that has both
  javac and tools.jar. The project targets Java 1.6 source level, so Java 8
  is fully compatible.

  Additionally, as a defensive measure, exclude the com.sun:tools transitive
  dependency from compile-testing in module POMs and add a Java 9+ profile
  to the parent POM.


ERROR 2: MoreObjects class not found in integration test
---------------------------------------------------------
Module: auto-value (integration test: value/src/it/functional)
Error message:
  "cannot find symbol: class MoreObjects
   location: package com.google.common.base"
File: value/src/it/functional/src/test/java/com/google/auto/value/AutoValueTest.java:20

Root cause:
  The functional integration test imports com.google.common.base.MoreObjects
  (Guava class introduced in version 18.0). The test POM has guava-testlib:18.0
  (test scope) which transitively depends on guava:18.0. However, truth:0.25
  also depends on guava:17.0.

  Maven's dependency mediation uses "nearest wins" strategy. Since truth:0.25
  is declared before guava-testlib:18.0 in the POM, and truth's transitive
  guava:17.0 is at the same depth or nearer, Maven resolves guava to version
  17.0 instead of 18.0.

  MoreObjects does NOT exist in Guava 17.0 - it was introduced in 18.0.

Fix:
  Add a direct guava:18.0 dependency (test scope) to the functional integration
  test POM (value/src/it/functional/pom.xml). A direct dependency always wins
  over transitive dependencies in Maven's mediation.
