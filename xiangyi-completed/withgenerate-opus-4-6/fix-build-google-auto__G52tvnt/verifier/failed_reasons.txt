BUILD FAILURE ANALYSIS - google/auto
=====================================

Repository: /home/travis/build/failed/google/auto
Build Command: mvn -B -U -f build-pom.xml verify --fail-at-end -Dsource.skip=true -Dmaven.javadoc.skip=true
(from .travis.yml)

ENVIRONMENT:
- Java: OpenJDK 11.0.27 (openjdk-11-jdk-headless)
- Maven: 3.x
- Originally designed for: oraclejdk7 / openjdk7

ERRORS:
========

All 3 compiled modules (common, factory, service) fail with the SAME error:
  "Could not find artifact com.sun:tools:jar:11.0.27 at specified path
   /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

AutoValue module is SKIPPED because it depends on auto-common which fails first.

ROOT CAUSE:
===========

1. The parent POM (auto-parent, version 3, from Maven Central) defines a profile
   called "default-profile" with:
   - <activeByDefault>true</activeByDefault>
   - <file><exists>${java.home}/../lib/tools.jar</exists></file>

   On Java 11, tools.jar does NOT exist (removed in Java 9, JEP 220), BUT the
   profile still activates because activeByDefault=true takes precedence when
   no other profile-activation criteria match.

   This profile sets the property:
     <toolsjar>${java.home}/../lib/tools.jar</toolsjar>
   to a non-existent file path.

2. The compile-testing library (used by common v0.7, service v0.6, factory v0.8)
   declares a system-scoped dependency:
     <dependency>
       <groupId>com.sun</groupId>
       <artifactId>tools</artifactId>
       <version>${java.version}</version>
       <scope>system</scope>
       <systemPath>${toolsjar}</systemPath>
     </dependency>

   Since ${toolsjar} points to a non-existent file, Maven cannot resolve this
   system dependency and the build fails.

3. In Java 9+, the classes that were in tools.jar (javax.tools, javax.lang.model,
   javax.annotation.processing) are now part of the java.compiler module, which
   is included by default in the JDK. So the tools.jar dependency is NOT needed.

FIX PLAN:
=========

Two changes are needed:

1. PARENT POM (pom.xml): Add a new profile "jdk9-plus-profile" that activates
   for Java 9+ (using <jdk>[9,)</jdk> activation). This profile should NOT set
   a toolsjar property pointing to tools.jar. Instead, it should point to a JAR
   that actually exists (like jrt-fs.jar) so that the system-scoped dependency
   can be resolved without error.

   Also remove <activeByDefault>true</activeByDefault> from the default-profile
   since file-based activation is sufficient for Java 8 environments.

2. SUBMODULE POMs (common/pom.xml, service/pom.xml, factory/pom.xml, value/pom.xml):
   Add <exclusions> for com.sun:tools on the compile-testing dependency in each
   submodule. This ensures the obsolete system-scoped dependency is not inherited.

FILES TO MODIFY:
================
- pom.xml (parent POM) - Add jdk9+ profile, fix default-profile activation
- common/pom.xml - Exclude com.sun:tools from compile-testing 0.7
- service/pom.xml - Exclude com.sun:tools from compile-testing 0.6
- factory/pom.xml - Exclude com.sun:tools from compile-testing 0.8
- value/pom.xml - Exclude com.sun:tools from compile-testing 0.6

ERROR TYPE: Build configuration issue (not code errors)
