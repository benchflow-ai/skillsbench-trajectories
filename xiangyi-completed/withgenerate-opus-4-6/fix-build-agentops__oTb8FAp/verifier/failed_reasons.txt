ERROR #1 (CRITICAL): Unconditional Import of Optional Dependency Module
==============================================================================

File: agentops/__init__.py (line 12)
Code: from .langchain_callback_handler import LangchainCallbackHandler, AsyncLangchainCallbackHandler

Problem:
  The package __init__.py unconditionally imports langchain_callback_handler,
  which in turn imports from langchain_core and langchain. However, langchain
  is listed as an OPTIONAL dependency in pyproject.toml under
  [project.optional-dependencies]. This means `import agentops` fails with
  ModuleNotFoundError when langchain is not installed.

Impact:
  ALL 5 test files fail to even collect because `import agentops` raises:
    ModuleNotFoundError: No module named 'langchain_core'

  This is a fatal error — no tests can run.

Fix:
  Wrap the import in a try/except ImportError block in __init__.py:

    try:
        from .langchain_callback_handler import (
            LangchainCallbackHandler,
            AsyncLangchainCallbackHandler
        )
    except ImportError:
        pass

ERROR #2 (CRITICAL): Outdated LangChain Import Path
==============================================================================

File: agentops/langchain_callback_handler.py (line 8)
Code: from langchain.callbacks.base import BaseCallbackHandler, AsyncCallbackHandler

Problem:
  LangChain restructured its package layout. The callbacks module was moved
  from langchain.callbacks.base to langchain_core.callbacks. The current
  import path doesn't exist in modern langchain versions (>= 0.1).

Impact:
  Even when langchain IS installed, the import fails with:
    ModuleNotFoundError: No module named 'langchain.callbacks'

Fix:
  Change the import to use langchain_core.callbacks:

    from langchain_core.callbacks import BaseCallbackHandler, AsyncCallbackHandler

ERROR #3 (NON-CRITICAL): GitHub Actions Workflow YAML Float Parsing
==============================================================================

File: .github/workflows/python-testing.yml (line 18)
Code: python-version: [3.7,3.8,3.9,3.10,3.11,3.12]

Problem:
  In YAML, unquoted numbers like 3.10 are parsed as the float 3.1 (trailing
  zero is dropped). This means the matrix would create a Python 3.1 job
  instead of Python 3.10.

  Additionally, the matrix python-version is defined but never used — the
  setup-python step hardcodes python-version: '3.11'. The matrix variable
  ${{ matrix.python-version }} should be used instead.

Impact:
  The CI matrix doesn't actually test across multiple Python versions as
  intended. However, since the setup step uses '3.11' directly, the CI
  still runs (just only on 3.11).

Fix:
  Quote all version strings and use the matrix variable:

    python-version: ['3.7', '3.8', '3.9', '3.10', '3.11', '3.12']
    ...
    python-version: ${{ matrix.python-version }}

ERROR #4 (MODERATE): Missing _tags_for_future_session Initialization
==============================================================================

File: agentops/client.py (lines 94-97)
Code:
  if auto_start_session:
      self.start_session(tags, self.config, inherited_session_id)
  else:
      self._tags_for_future_session = tags

Problem:
  The `_tags_for_future_session` attribute is only set when
  `auto_start_session=False` (the else branch). When `auto_start_session=True`,
  the attribute is never initialized. However, `start_session()` (line 251)
  references `self._tags_for_future_session` unconditionally:
      tags or self._tags_for_future_session

  This raises AttributeError when `start_session()` is called later with
  tags=None and `auto_start_session` was True during __init__.

Impact:
  Any code path where init is called with auto_start_session=True and tags=None,
  followed by another start_session() call, raises an AttributeError.

Fix:
  Initialize `_tags_for_future_session` alongside other instance attributes:
      self._tags_for_future_session: Optional[List[str]] = tags

ERROR #5 (MODERATE): Test Isolation - Singleton Not Reset Between Tests
==============================================================================

Problem:
  The Client class uses a singleton pattern (via the @singleton decorator).
  Once a Client is created in one test class, subsequent test classes receive
  the same instance. Their `setup_method` calls to `agentops.init()` are no-ops
  because the singleton already exists. This means:
  - Sessions from previous tests may still be active
  - Configuration from previous tests persists
  - Tests pass individually but fail when run together

Impact:
  Tests fail when run as a full suite but pass individually.

Fix:
  Create a tests/conftest.py with an autouse fixture that clears the singleton
  dict before and after each test:

    @pytest.fixture(autouse=True)
    def clear_agentops_singleton():
        from agentops.client import Client
        Client.__closure__[1].cell_contents.clear()
        yield
        Client.__closure__[1].cell_contents.clear()
