# Build Failure Analysis - Google Auto Project

## Repository: google/auto

## Error Summary
All submodules fail to build with the error:
```
Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
```

Additionally, factory and value modules fail with:
```
cannot find symbol: class Generated, location: package javax.annotation
```

## Root Cause Analysis

### Issue 1: tools.jar Dependency (Primary)
The project uses the `compile-testing` library for annotation processor testing. The versions used
(0.6, 0.7, 0.8) declare a mandatory dependency on `com.sun:tools` with a system path to `tools.jar`.

In JDK 8 and earlier, `tools.jar` existed at `$JAVA_HOME/lib/tools.jar` and contained the
annotation processing API. Starting from JDK 9, `tools.jar` was removed - the annotation
processing API is now part of the JDK module system (`java.compiler` module).

Since the build environment uses JDK 11 (OpenJDK 11.0.27), the `tools.jar` file does not exist,
causing the dependency resolution to fail.

### Issue 2: javax.annotation.Generated (Secondary)
The `javax.annotation.Generated` annotation was removed from the JDK in Java 9+. It was part of
Java EE which was deprecated in JDK 9 and removed in JDK 11. The factory and value modules use
this annotation for code generation marking.

### Issue 3: Truth API Changes (Tertiary)
Upgrading compile-testing to 0.18 brings in Truth 0.44 which has API changes:
- `hasMessage(String)` was replaced with `hasMessageThat().isEqualTo(String)`

## Affected Files

### POM Files
1. common/pom.xml - compile-testing:0.7, truth:0.25, junit:4.11
2. factory/pom.xml - compile-testing:0.8, truth:0.25, uses javax.annotation.Generated
3. service/pom.xml - compile-testing:0.6, truth:0.24, junit:4.11
4. value/pom.xml - compile-testing:0.6, truth:0.25, junit:4.11, uses javax.annotation.Generated

### Source Files
1. common/src/test/java/com/google/auto/common/AnnotationMirrorsTest.java - uses deprecated Truth API

## Solution Applied

### Fix 1: Upgrade compile-testing to 0.18
In version 0.18, the `com.sun:tools` dependency is moved inside a Maven profile that only
activates when `${java.home}/../lib/tools.jar` exists. This means:
- On JDK 8: Profile activates, tools.jar is used
- On JDK 9+: Profile does not activate, dependency is not added (not needed since API is in JDK)

### Fix 2: Add javax.annotation-api dependency
Added `javax.annotation:javax.annotation-api:1.3.2` to factory and value modules to provide
the `javax.annotation.Generated` annotation that was removed from the JDK.

### Fix 3: Upgrade Truth and JUnit
- Upgraded truth from 0.24/0.25 to 0.44 (required by compile-testing 0.18)
- Upgraded junit from 4.11 to 4.12 (required by compile-testing 0.18)

### Fix 4: Update Test Code
- Changed `assertThat(e).hasMessage(...)` to `assertThat(e).hasMessageThat().isEqualTo(...)`
  in AnnotationMirrorsTest.java to match the new Truth API.

## Patch Files Created
1. patch_1.diff - common/pom.xml dependency updates
2. patch_2.diff - AnnotationMirrorsTest.java Truth API fix
3. patch_3.diff - service/pom.xml dependency updates
4. patch_4.diff - factory/pom.xml dependency updates + javax.annotation-api
5. patch_5.diff - value/pom.xml dependency updates + javax.annotation-api

## Error Type
Build configuration error - incompatible dependency versions with JDK 11
