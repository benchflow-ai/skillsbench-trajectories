UJSON LIBRARY - FUZZING NOTES
==============================

Key Modules:
- /app/ujson/src/ujson/__init__.py (Main API)
- C extension implementation (optimized JSON encoding/decoding)

TOP FUZZING TARGETS:
====================

1. HIGHEST PRIORITY:
   - ujson.encode(obj, ensure_ascii=True, encode_html_chars=False,
                  escape_forward_slashes=True, sort_keys=False, indent=0,
                  allow_nan=True, reject_bytes=True, default=None,
                  separators=None) -> str
     * Fast JSON encoding of Python objects
     * C-based implementation with complex logic
     * Multiple parameter combinations
     * Special float handling (NaN, Infinity)
     * Default handler for custom types
     * Separator tuple handling

   - ujson.decode(json_str) -> obj
     * Fast JSON decoding
     * Accepts strings, bytes, or byte-like objects
     * Handles special float values (NaN, Infinity, -Infinity)
     * Type conversion edge cases

   - ujson.dumps(obj, ...) - Alias for encode()

   - ujson.loads(json_str) - Alias for decode()

   - ujson.dump(obj, fp, **kwargs)
     * File-based encoding
     * File handle error handling

   - ujson.load(fp)
     * File-based decoding
     * File handle error handling

2. FUZZING STRATEGIES:

   Encoding fuzzing:
   - Special float values: NaN, Infinity, -Infinity, very large/small numbers
   - HTML character escaping (<, >, &)
   - Forward slash escaping
   - Dictionary key ordering (sort_keys parameter)
   - Pretty-printing with various indent levels (0-100)
   - ASCII-only output vs Unicode preservation
   - Custom default handlers
   - Separator customization (item and key separators)
   - Bytes object handling (reject_bytes parameter)
   - Circular references (should fail)
   - Very deeply nested structures (100+ levels)
   - Large strings (1MB+)
   - Unicode handling (emojis, surrogate pairs)
   - Special dict types (OrderedDict, defaultdict)
   - Custom objects with __dict__
   - Decimal and UUID types

   Decoding fuzzing:
   - Malformed JSON syntax
   - Unterminated strings and arrays/objects
   - Invalid escape sequences
   - Invalid numeric formats (multiple dots, invalid exponents)
   - Very deeply nested JSON (1000+ levels)
   - Very long strings
   - Invalid Unicode escape sequences (\uXXXX)
   - Duplicate keys in objects
   - Numbers at boundaries (int min/max, float precision)
   - Special float values in JSON (NaN, Infinity)
   - Trailing commas
   - Comments in JSON (not valid)
   - Leading zeros in numbers
   - Multiple values in stream

Test Input Categories - Encoding:
- Empty objects/arrays/strings
- Nested structures (dicts within lists, etc)
- Mixed types in lists
- Very large numbers (2^64, 10^308)
- All encoding parameter combinations
- Bytes vs str
- Custom objects (require default handler)
- None, True, False, empty values
- Unicode strings (all ranges)

Test Input Categories - Decoding:
- Minimal valid JSON: {}, [], 0, "str", true, false, null
- Pathological numbers: 1e1000, 0.0000000000001, -0
- Very long keys/values
- Deep nesting
- Invalid escape sequences in strings
- Malformed arrays/objects
- Type mismatches (non-string keys expected as strings)
- Control characters in strings
- Huge files (10MB+ of JSON)

Edge Cases to Test:
- Empty indent parameter (0)
- Very large indent (1000+)
- reject_bytes=True with byte input to encode
- allow_nan=False with NaN values
- Circular reference detection
- Memory limits with huge structures
- File I/O error handling
