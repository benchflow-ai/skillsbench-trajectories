MINISGL LIBRARY - FUZZING NOTES
================================

Key Modules:
- /app/minisgl/python/minisgl/llm/llm.py (LLM class, generate method)
- /app/minisgl/python/minisgl/core.py (SamplingParams, Req, Batch classes)
- /app/minisgl/python/minisgl/scheduler/scheduler.py (Scheduler, scheduling logic)
- /app/minisgl/python/minisgl/engine/engine.py (Engine, forward_batch)
- /app/minisgl/python/minisgl/kvcache/ (KV cache management)
- /app/minisgl/python/minisgl/server/launch.py (launch_server entry point)

TOP FUZZING TARGETS:
====================

1. HIGHEST PRIORITY:
   - LLM.generate(prompts: List[str] | List[List[int]],
                  sampling_params: SamplingParams) -> List[Dict]
     * Full inference pipeline
     * Accepts string or token ID lists
     * SamplingParams parameter validation
     * Handles request batching and scheduling

   - SamplingParams class parameters:
     * temperature (float) - should be >= 0.0
     * top_k (int) - should be -1 or >= 0
     * top_p (float) - should be in (0, 1.0]
     * max_tokens (int) - should be > 0
     * ignore_eos (bool)
     Fuzzing: negative values, extreme values, invalid combinations

   - Engine.forward_batch(batch: Batch, args: BatchSamplingArgs) -> ForwardOutput
     * Core model forward pass
     * Batch state validation
     * KV cache interactions
     * CUDA graph execution

   - Scheduler.run_forever()
     * Main scheduling loop
     * Message queue processing
     * Prefill and decode scheduling
     * Cache allocation and eviction

   - CacheManager operations:
     * allocate(num_pages) -> page indices
     * evict(size) -> evicted indices
     * match_prefix(input_ids) -> (cache_handle, cached_tensor)
     * insert_prefix(input_ids, indices) -> int
     Fuzzing: cache exhaustion, invalid indices, corrupted state

2. HIGH PRIORITY:
   - Batch processing:
     * PrefillManager.try_add_one(req)
     * DecodeManager.schedule_next_batch()
     * Mixed prefill/decode batch validation

   - Attention backend:
     * AttentionBackend.forward(q, k, v, layer_id, batch)
     * Backend selection and validation
     * Attention mask computation
     * Rotary position embeddings

   - Sampler:
     * sample(logits, temperatures, top_k, top_p)
     * Sampling with various parameter combinations
     * Edge cases at boundaries

   - Tokenization:
     * TokenizeManager.tokenize(messages)
     * Message serialization/deserialization
     * Detokenization

   - Model loading:
     * create_model(model_path, model_config)
     * Model weight loading
     * Config validation

3. FUZZING STRATEGIES:

   SamplingParams fuzzing:
   - Negative temperature
   - Negative top_k (valid: -1 or >=0)
   - top_p out of range (< 0, > 1.0, == 0)
   - max_tokens = 0 or negative
   - Extreme values (temperature=1000, max_tokens=1000000)
   - NaN and Infinity values

   Batch processing fuzzing:
   - Very large batch sizes
   - Mixed prefill/decode in same batch
   - Invalid request states
   - Cache misses during prefill
   - Token budget exhaustion
   - Invalid sequence lengths

   Cache fuzzing:
   - Allocate more pages than available
   - Evict all pages
   - Match non-existent prefixes
   - Insert duplicate prefixes
   - Cache corruption/integrity violations
   - Page table index out of bounds
   - Radix tree traversal edge cases

   Tensor/Memory fuzzing:
   - Wrong tensor shapes in forward
   - Dtype mismatches
   - CUDA device mismatches
   - Out of memory conditions
   - Invalid position indices
   - Batch size mismatches

   Request handling fuzzing:
   - Empty request queue
   - Request state transitions (incomplete states)
   - Very long input sequences (>100K tokens)
   - Zero-token outputs requested
   - Invalid UID/request IDs

   Model config fuzzing:
   - Zero or negative layer count
   - Invalid head dimensions
   - Mismatched hidden sizes
   - Invalid vocab sizes
   - Negative RMS norm epsilon
   - Invalid rotary config

   Distributed/TP fuzzing:
   - Invalid rank/world size
   - TP communication failures
   - AllReduce with shape mismatches
   - Rank synchronization failures

Test Input Categories:
- Empty prompt lists
- Very long prompts (>100K tokens)
- Extremely short prompts (single token)
- Mixed string and token ID lists
- Unicode strings with special chars
- Binary/control characters in prompts
- Duplicate prompts
- Circular reference in message dicts
- Invalid UTF-8 sequences
- Very large token IDs (>vocab_size)

Edge Cases to Test:
- max_tokens close to max_seq_len
- temperature = 0 (greedy) vs > 0 (sampling)
- top_p = 1.0 (no filtering) vs small values
- max_tokens = 1 (single token)
- Batch size = 1 vs very large (1000+)
- Cache at capacity
- Multiple concurrent requests
- Request cancellation mid-generation
- Model weight loading from invalid path
- Backend unavailable (FlashInfer/FlashAttention)
- CUDA memory pressure
- Very deep attention (100+ layers)
