IPYTHON LIBRARY - FUZZING NOTES
================================

Key Modules:
- /app/ipython/IPython/core/display_functions.py (display, update_display, publish_display_data)
- /app/ipython/IPython/core/guarded_eval.py (guarded_eval, safe code evaluation)
- /app/ipython/IPython/core/splitinput.py (split_user_input, input parsing)
- /app/ipython/IPython/core/formatters.py (DisplayFormatter, format)
- /app/ipython/IPython/core/inputtransformer2.py (PromptStripper, line transformation)
- /app/ipython/IPython/utils/text.py (text utilities, formatters)
- /app/ipython/IPython/utils/wildcard.py (pattern matching, namespace filtering)

TOP FUZZING TARGETS:
====================

1. HIGHEST PRIORITY:
   - display(*objs, include=None, exclude=None, metadata=None, transient=False,
             display_id=None, raw=False, clear=False, **kwargs)
     * Complex parameter handling (raw, include, exclude, metadata, transient, display_id, clear)
     * Handles arbitrary Python objects
     * MIME type negotiation
     * Metadata dict handling

   - guarded_eval(code: str, context: EvaluationContext)
     * Code evaluation with security policies
     * Potential code injection vectors
     * AST node evaluation
     * Restricted evaluation modes

   - split_user_input(line, pattern=None) -> tuple
     * Regex-based parsing of user input
     * Command line parsing with escape characters
     * ReDoS potential in regex patterns
     * Returns (pre_char, func_name, the_rest)

   - DisplayFormatter.format(obj, include=None, exclude=None)
     * Handles multiple MIME types and formatters
     * Complex formatter selection logic
     * Formatter-specific options

   - LineInfo / input transformation
     * Escape character handling (!, ?, %, @)
     * Input preprocessing before execution

2. HIGH PRIORITY:
   - EvalFormatter / FullEvalFormatter / DollarFormatter classes
     * Variable substitution in strings
     * String formatting with expression evaluation
     * Potential injection/evaluation vectors

   - filter_ns(ns, name_pattern, type_pattern, ignore_case, show_all)
     * Pattern matching on namespace variables
     * Wildcard matching with regex
     * Type filtering

   - list_namespace(namespace, type_pattern, filter, ignore_case, show_all)
     * Namespace exploration and filtering
     * Pattern matching on object names

   - arg_split(s, posix, strict) -> list
     * Command argument parsing
     * Shell-like quote handling
     * Potential for parsing confusion

   - Inspector.info(obj_name) / object_info(obj_name)
     * Object introspection
     * Reflection/attribute access
     * Source code extraction

   - indent / dedent / format_screen functions
     * String manipulation utilities
     * Whitespace handling

3. FUZZING STRATEGIES:

   Display function fuzzing:
   - Multiple object types in sequence
   - Include/exclude MIME type specifications
   - Metadata dict with various key/value types
   - transient and display_id combinations
   - raw=True with non-string objects
   - clear=True with preceding objects
   - HTML injection in display data
   - Base64 encoding edge cases (images, files)
   - Circular references in displayed objects

   Code evaluation fuzzing (guarded_eval):
   - Malicious code attempts (exec, eval, __import__)
   - Attribute access chains (obj.__class__.__bases__)
   - Dynamic imports and module access
   - Builtin function calls
   - Invalid Python syntax
   - Deeply nested expressions
   - Lambda functions and comprehensions

   Input parsing fuzzing (split_user_input):
   - Special characters (!, ?, %, @)
   - Escape sequences
   - Very long input lines
   - Unicode in command names
   - Regex pattern ReDoS attempts
   - Edge cases with whitespace and quotes

   Formatter fuzzing:
   - Unknown MIME types
   - Invalid include/exclude specifications
   - Nested custom formatters
   - Objects that raise during formatting
   - Objects with __repr__/__str__ that fail

   Text utilities fuzzing:
   - Very long strings for indentation
   - Extremely large indent/dedent counts
   - Mixed whitespace (tabs, spaces)
   - Unicode character handling
   - Control characters and special chars
   - Empty strings and None values

   Wildcard/namespace fuzzing:
   - Complex regex patterns (ReDoS)
   - Invalid pattern syntax
   - Type pattern edge cases
   - Large namespaces (10000+ items)
   - Case sensitivity with Unicode

Test Input Categories:
- Empty strings and None
- Very long strings (>1MB)
- Strings with control characters
- Unicode strings (all ranges, emojis)
- Python code with syntax errors
- Pathological regex patterns
- Circular object references
- Large object graphs
- Custom classes and instances
- Lambda and function objects
- Module and package objects
- Special objects (iterators, generators)

Edge Cases to Test:
- HTML/JavaScript injection in display
- File path traversal in display
- Memory exhaustion with circular refs
- Timeout/hang on complex evals
- Exception handling in formatters
- Encoding mismatches (bytes vs str)
- Stream handling (stdin/stdout manipulation)
