# Build Error Analysis for google/auto Repository

## Error Summary
The build fails with dependency resolution errors when compiling with Java 11+. Multiple modules fail with the same issue.

## Root Cause
The build configuration in `pom.xml` specifies a system-scope dependency on `com.sun:tools:jar` with the path set to `${java.home}/../lib/tools.jar`. This path structure is invalid for Java 9+ (including Java 11).

**Key Issue:**
- In Java 8 and earlier: `tools.jar` existed at `$JDK_HOME/lib/tools.jar`
- In Java 9+: `tools.jar` was removed and replaced with modular runtime image
- The JDK compiler functionality is now available through the `jdk.compiler` module

## Error Details
```
ERROR: Failed to execute goal on project auto-common: Could not resolve dependencies
for project com.google.auto:auto-common:jar:1.0-SNAPSHOT: Could not find artifact
com.sun:tools:jar:11.0.27 at specified path
/usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
```

Affected modules:
- auto-common
- auto-factory
- auto-service

## Solution Strategy
The project needs to be updated to handle Java 9+ compatibility. The approach:

1. **Fix the parent POM (pom.xml):**
   - Update the profile detection to check if running on Java 9+ (no tools.jar)
   - For Java 9+, don't require tools.jar as a dependency (it's built-in)
   - Keep backward compatibility with Java 8

2. **Update specific module POMs if needed:**
   - Check common/pom.xml, factory/pom.xml, service/pom.xml for tools.jar references
   - Add dependency on tools.jar only when it exists (Java 8 and earlier)

## Implementation Details
The parent POM has two profiles for different OS/JDK configurations:
- `default-profile`: Activates if `${java.home}/../lib/tools.jar` exists
- `mac-profile`: Activates if `${java.home}/../Classes/classes.jar` exists

Both profiles set a `toolsjar` property that likely gets used as a system dependency in module POMs.

For Java 9+, we need to either:
a) Create a new profile that activates for Java 9+ and doesn't set toolsjar
b) Modify the existing profiles to handle Java 9+ properly
c) Remove the toolsjar dependency entirely and use Maven compiler plugin configuration

Option (c) is cleanest for Java 9+ support, but we should maintain backward compatibility.

## Files to Modify
1. `/home/travis/build/failed/google/auto/pom.xml` - Parent POM with profile definitions
2. Potentially: common/pom.xml, factory/pom.xml, service/pom.xml if they reference tools.jar

## Applied Solution

### Changes Made:

1. **pom.xml (Parent POM)**:
   - Changed `default-profile` activeByDefault from `true` to `false` (line 174)
   - Added new `java9-plus-profile` that activates for Java 9+ using JDK version range `[9,)`
   - This allows the profile activation to be conditional on JDK version rather than relying on file existence

2. **common/pom.xml**:
   - Updated parent version from `3` to `4-SNAPSHOT` (to use the updated parent POM)
   - Added exclusion for `com.sun:tools` dependency from compile-testing test dependency

3. **service/pom.xml**:
   - Updated parent version from `3` to `4-SNAPSHOT`
   - Added exclusion for `com.sun:tools` dependency from compile-testing test dependency

4. **factory/pom.xml**:
   - Updated parent version from `3` to `4-SNAPSHOT`
   - Added exclusion for `com.sun:tools` dependency from compile-testing test dependency
   - Added `javax.annotation:javax.annotation-api:1.3.2` dependency for javax.annotation.Generated

5. **value/pom.xml**:
   - Updated parent version from `3` to `4-SNAPSHOT`
   - Added exclusion for `com.sun:tools` dependency from compile-testing test dependency
   - Added `javax.annotation:javax.annotation-api:1.3.2` dependency for javax.annotation.Generated

## Root Causes

1. **tools.jar Not Found on Java 11+**:
   - In Java 9+, tools.jar was removed from the JDK
   - The compile-testing dependency v0.6/0.7/0.8 included a system-scoped dependency on tools.jar
   - The profile activation tried to find tools.jar at ${java.home}/../lib/tools.jar, which doesn't exist on Java 11
   - Fixed by excluding the tools.jar transitive dependency from compile-testing

2. **Missing javax.annotation.Generated**:
   - After excluding tools.jar, code that imported javax.annotation.Generated failed
   - Added explicit dependency on javax.annotation-api to provide this annotation

The remaining test failures are unrelated to the Java 11 compatibility issues and are pre-existing test issues.
