ARROW LIBRARY - FUZZING NOTES
=============================

Library Purpose:
Arrow is a datetime library providing enhanced datetime functionality with timezone support,
parsing, formatting, and humanization capabilities.

KEY FUNCTIONS FOR FUZZING (Priority Order):
============================================

HIGH PRIORITY (Core Parsing Logic):
1. DateTimeParser.parse(datetime_string: str, fmt: str|list) - Main generic parser
   - Generates dynamic regex from format strings
   - Location: arrow/parser.py:373
   - Inputs to fuzz: Various datetime strings with different formats
   - Edge cases: Invalid formats, malformed strings, special characters

2. DateTimeParser.parse_iso(datetime_string: str, normalize_whitespace: bool) - ISO 8601 parsing
   - Location: arrow/parser.py:252
   - Inputs to fuzz: ISO 8601 variants, edge cases in date/time components
   - Edge cases: Missing components, extra whitespace, invalid formats

3. TzinfoParser.parse(tzinfo_string: str) - Timezone parsing
   - Location: arrow/parser.py:895
   - Inputs to fuzz: IANA names, ISO offsets (±HH:MM), special values ("utc", "local", "Z")
   - Edge cases: Invalid timezone names, malformed offsets

4. DateTimeParser._build_datetime(parsed_dict) - Complex datetime construction
   - Location: arrow/parser.py:696
   - Inputs to fuzz: Parsed components with various combinations
   - Edge cases: Invalid day/month/year combinations, leap years, DST transitions

MEDIUM PRIORITY:
5. ArrowFactory.get(*args, **kwargs) - Polymorphic entry point
   - Handles Arrow objects, datetime, date, timestamps, strings
   - Location: arrow/factory.py:85
   - Edge cases: Mixed argument types, invalid conversions

6. Arrow.dehumanize(input_string: str, locale: str) - Natural language time parsing
   - Location: arrow/arrow.py:1344
   - Inputs to fuzz: Human-readable relative time strings ("2 days ago", "in a month")
   - Edge cases: Locale-specific strings, complex patterns

7. Arrow.format(fmt: str, locale: str) - Format string handling
   - Location: arrow/arrow.py:1105
   - Inputs to fuzz: Various format strings with tokens
   - Edge cases: Invalid tokens, special sequences

8. Arrow.is_between(other1, other2, bounds: str) - Bounds validation
   - Location: arrow/arrow.py:1485
   - Inputs to fuzz: Bounds parameter "()", "(]", "[)", "[]"
   - Edge cases: Invalid bounds strings

UTILITY FUNCTIONS:
9. util.validate_bounds(bounds: str) - Validates bounds parameter
10. util.is_timestamp(value) - Timestamp validation
11. util.normalize_timestamp(ts) - Timestamp normalization
12. util.iso_to_gregorian(iso_tuple) - ISO week to Gregorian conversion
13. util.validate_ordinal(ordinal) - Ordinal day validation
14. util.next_weekday(start_date, weekday) - Next weekday calculation

INPUT PATTERNS TO TEST:
=======================
- Datetime strings in various formats (ISO, custom patterns)
- Format strings with various tokens (YYYY, MM, DD, HH, mm, ss, X, Z, W, etc.)
- Timezone specifications (IANA names, offsets, special values)
- Humanized time strings (locale-aware)
- Edge case dates (leap years, DST transitions, century boundaries)
- Invalid/malformed inputs (missing components, extra data, special characters)
- Unicode characters in locale-specific strings
- Very large/small year values

POTENTIAL VULNERABILITIES:
==========================
- Regex denial of service (ReDoS) in pattern matching
- Integer overflow in timestamp conversions
- Invalid datetime construction (e.g., Feb 30)
- Locale-specific string matching failures
- Memory issues with very long format strings
- Infinite loops in parsing with complex patterns

FUZZ STRATEGY:
==============
1. Generate random datetime strings and format combinations
2. Test timezone parsing with various IANA names and offsets
3. Fuzz humanized time strings with different locales
4. Combine valid and invalid date components
5. Test boundary conditions (year 1-9999, month 1-12, day 1-31)
6. Test with unicode and special characters
7. Test format string combinations
8. Test edge cases: leap years, DST transitions
