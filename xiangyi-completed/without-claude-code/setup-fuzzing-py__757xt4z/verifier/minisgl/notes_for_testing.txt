MINISGL LIBRARY - FUZZING NOTES
================================

Library Purpose:
Mini-SGLang is a lightweight, high-performance inference framework for Large Language Models (LLMs).
It provides efficient request scheduling, caching, and serving capabilities with tensor-based operations.

KEY FUNCTIONS FOR FUZZING (Priority Order):
============================================

CRITICAL PRIORITY (Serialization & Data Structures):
1. serialize_type() & deserialize_type()
   - Location: python/minisgl/message/utils.py
   - Handles arbitrary type serialization/deserialization
   - Complex recursive logic with type mapping
   - Inputs to fuzz: Various Python types, tensors, nested structures
   - Edge cases: Malformed type data, missing types, buffer corruption
   - Potential issues: Deserialization vulnerabilities, type confusion

2. CacheManager.allocate() / free() / check_integrity()
   - Location: python/minisgl/scheduler/cache.py
   - Manages memory page allocation/deallocation
   - Complex index management with assertions
   - Inputs to fuzz: Allocation/deallocation sequences, concurrent operations
   - Edge cases: Out-of-order operations, double-free, use-after-free patterns
   - Potential issues: Buffer overflows, state consistency violations

3. TableManager.allocate() / free()
   - Location: python/minisgl/scheduler/table.py
   - Manages free slot tracking
   - Inputs to fuzz: Slot allocation/deallocation patterns
   - Edge cases: Exhausting slots, concurrent allocations
   - Potential issues: Slot management correctness, state corruption

HIGH PRIORITY:
4. PrefillAdder._try_allocate_one() / _add_one_req()
   - Location: python/minisgl/scheduler/prefill.py
   - Allocates table slots and cache handles
   - Complex budget calculations and cache matching
   - Inputs to fuzz: Requests with varying seq_len, cached_len, output_len
   - Edge cases: Resource exhaustion, cache coherency issues
   - Potential issues: Logic errors in resource allocation

5. Req.__post_init__()
   - Location: python/minisgl/core.py
   - Validates request invariants
   - Multiple assertions on state consistency
   - Inputs to fuzz: Request parameters with invalid combinations
   - Edge cases: Negative values, boundary conditions
   - Potential issues: State invariant violations, assertion failures

6. TokenizeManager.tokenize()
   - Location: python/minisgl/tokenizer/tokenize.py
   - Processes user input text/chat templates
   - Handles both string and list inputs with template application
   - Inputs to fuzz: Various text inputs, chat formats, template strings
   - Edge cases: Very long inputs, special tokens, invalid templates
   - Potential issues: Tensor shape mismatches, template injection

MEDIUM PRIORITY:
7. Sampler.prepare() / sample()
   - Location: python/minisgl/engine/sample.py
   - Processes sampling parameters and generates next tokens
   - Handles temperature, top-k, top-p with boundary conditions
   - Inputs to fuzz: Sampling parameters with edge case values
   - Edge cases: temp=0, top_k=-1/0, top_p=0/1, extreme values
   - Potential issues: Numerical errors, array indexing, dtype issues

8. AttentionLayer.forward()
   - Location: python/minisgl/layers/attention.py
   - Complex tensor splitting and reshaping
   - ROPE and normalization application
   - Inputs to fuzz: Tensors with various shapes and dimensions
   - Edge cases: Mismatched shapes, zero dimensions
   - Potential issues: Tensor shape validation, dimension mismatches

9. FIMetadata.__post_init__()
   - Location: python/minisgl/attention/fi.py
   - Validates device placement of multiple tensors
   - Inputs to fuzz: Metadata with tensors on different devices
   - Edge cases: Mixed device placement, mismatched dimensions
   - Potential issues: Device consistency checks, tensor property validation

UTILITY FUNCTIONS:
10. divide_even() / divide_up() / divide_down()
    - Location: python/minisgl/utils/misc.py
    - Integer division utilities with assertions
    - Inputs to fuzz: Various integer combinations
    - Edge cases: Division by zero, very large numbers
    - Potential issues: Integer overflow/underflow, assertion failures

11. make_positions()
    - Location: python/minisgl/attention/utils.py
    - Generates position indices for attention
    - Complex offset calculations across multiple requests
    - Inputs to fuzz: Request batches with varying lengths
    - Edge cases: Very long sequences, concurrent requests
    - Potential issues: Index calculation errors, off-by-one bugs

12. UserMsg.decoder() via BaseBackendMsg.decoder()
    - Location: python/minisgl/message/backend.py
    - Deserializes messages including tensor data
    - Inputs to fuzz: Malformed message structures
    - Edge cases: Corrupted tensor buffers, missing fields
    - Potential issues: Deserialization errors, corrupted tensors

INPUT PATTERNS TO TEST:
=======================

Request Parameters:
- seq_len: 0, 1, very large values (>10000)
- cached_len: 0 to seq_len (invalid: > seq_len)
- output_len: 1, very large values (>1000)
- device_len: Various combinations with max_device_len

Sampling Parameters:
- temperature: 0, 0.5, 1.0, 2.0, extreme values
- top_k: -1, 0, 1, large values, invalid (< -1)
- top_p: 0, 0.5, 1.0, invalid (< 0 or > 1)
- top_k_variant: various values
- max_tokens: 0, 1, negative, very large
- ignore_eos: True/False combinations

Cache Operations:
- Allocation with zero pages
- Deallocation of unallocated handles
- Allocation/deallocation sequences
- Cache exhaustion scenarios
- Out-of-order operations

Tensor Operations:
- Mismatched shapes across tensors
- Different dtypes (float32, float16, int32)
- Different devices (CPU, CUDA)
- Zero dimensions
- Very large dimensions (memory exhaustion)

Message Serialization:
- Malformed JSON structures
- Missing required fields
- Wrong dtypes for fields
- Corrupted tensor buffers
- Invalid UIDs

POTENTIAL VULNERABILITIES:
==========================
- Buffer overflows in cache/slot management
- Integer overflow in dimension/offset calculations
- Memory exhaustion from large tensor allocations
- Division by zero in sampling calculations
- Assertion failures on invalid input
- Type confusion in serialization
- State corruption from concurrent operations
- Stack overflow from deep recursion
- Off-by-one errors in index calculations

ASSERTION-HEAVY FUNCTIONS (Good for Fuzzing):
==============================================
- CacheManager.check_integrity() - Multiple consistency checks
- Req.__post_init__() - Multiple state validations
- divide_even() / divide_up() / divide_down() - Division assertions
- FIMetadata.__post_init__() - Device/tensor validations
- PrefillAdder._try_allocate_one() - Resource consistency

FUZZ STRATEGY:
==============
1. Generate random request parameters with various combinations
2. Test sampling parameters at boundaries and invalid values
3. Fuzz cache allocation/deallocation sequences
4. Test tensor operations with mismatched shapes/dtypes
5. Fuzz serialization/deserialization with corrupted data
6. Test with concurrent operations
7. Test memory exhaustion scenarios
8. Generate invalid type combinations for serialize_type()
9. Test offset calculations with edge case dimensions
10. Validate state consistency after operations
11. Test error handling for resource exhaustion
12. Fuzz with unicode and special characters in tokenization
