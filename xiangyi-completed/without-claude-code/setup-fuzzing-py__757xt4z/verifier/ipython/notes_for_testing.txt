IPYTHON LIBRARY - FUZZING NOTES
================================

Library Purpose:
IPython is an enhanced interactive Python shell that processes user input through
multiple transformation and compilation stages before execution.

KEY FUNCTIONS FOR FUZZING (Priority Order):
============================================

CRITICAL PRIORITY (Input Transformation Pipeline):
1. TransformerManager.transform_cell(cell: str) -> str
   - Location: IPython/core/inputtransformer2.py:635
   - Entry point for transforming all user input
   - Handles: Magic syntax, system commands, escaped commands, help queries
   - Processing pipeline: cleanup → line transforms → token transforms
   - Inputs to fuzz: Various IPython syntax combinations
   - Edge cases: Malformed magic commands, unterminated strings, broken tokens

2. split_user_input(line: str, pattern) -> tuple
   - Location: IPython/core/splitinput.py:43
   - Parses line into components using complex regex
   - Input: Raw user input string
   - Output: Tuple of (indent, escape, function, rest)
   - Inputs to fuzz: Special characters, escape sequences, unicode
   - Edge cases: Lines starting with !, %, ??, function names with dots/underscores

3. PrefilterManager.prefilter_lines(lines: str, continue_prompt: str) -> str
   - Location: IPython/core/prefilter.py:306
   - Applies prefilter transformations to multiline input
   - Inputs to fuzz: Multiline input with various line combinations
   - Edge cases: Mixed magic/normal lines, continuation lines

HIGH PRIORITY:
4. InteractiveShell.run_cell(raw_cell: str) -> ExecutionResult
   - Location: IPython/core/interactiveshell.py:3084
   - Main entry point for executing user code
   - Handles: All code execution with transformations
   - Inputs to fuzz: Any valid/invalid Python code plus IPython syntax

5. InteractiveShell.transform_cell(raw_cell: str) -> str
   - Location: IPython/core/interactiveshell.py:3006
   - Applies all transformations to cell input
   - Inputs to fuzz: Raw cell input with mixed syntax

6. CachingCompiler.ast_parse(source: str, filename: str, symbol: str) -> ast.AST
   - Location: IPython/core/compilerop.py:81
   - Parses Python code to AST
   - Inputs to fuzz: Valid and invalid Python source
   - Edge cases: Incomplete syntax, malformed statements

MEDIUM PRIORITY (Token-Based Transformers):
7. MagicAssign.find() / transform()
   - Location: IPython/core/inputtransformer2.py:234
   - Transforms magic assignments: a = %foo or a = !command
   - Inputs to fuzz: Lines with assignment and magic/system commands
   - Edge cases: Multiple assignments, nested expressions

8. SystemAssign.find() / transform()
   - Location: IPython/core/inputtransformer2.py:266
   - Transforms system command assignments: a = !ls
   - Inputs to fuzz: System commands with pipes, redirects
   - Edge cases: Complex shell expressions

9. EscapedCommand.find() / transform()
   - Location: IPython/core/inputtransformer2.py:407
   - Handles escaped commands: !command, %magic, ??, ?
   - Inputs to fuzz: Escape character combinations, special syntax
   - Edge cases: Escaped escapes, multiline commands

10. HelpEnd.find() / transform()
    - Location: IPython/core/inputtransformer2.py:462
    - Transforms help queries: obj?, obj??
    - Inputs to fuzz: Help syntax combinations
    - Edge cases: Chained help, help on special names

UTILITY FUNCTIONS:
11. arg_split(s: str, posix: bool = False, strict: bool = True) -> list
    - Location: IPython/utils/_process_common.py:185
    - Splits arguments shell-style using shlex
    - Inputs to fuzz: Quoted strings, escape sequences, special shell characters
    - Edge cases: Unmatched quotes, backslashes, complex escaping

12. IPCompleter._complete() and helper methods
    - Location: IPython/core/completer.py:3573
    - Provides code completion
    - Inputs to fuzz: Incomplete code, partial names
    - Edge cases: Invalid syntax in completion context

13. guarded_eval(code: str, context: dict) -> Any
    - Location: IPython/core/guarded_eval.py:433
    - Safely evaluates code with access policies
    - Inputs to fuzz: AST expressions with various complexity
    - Edge cases: Restricted operations, type confusion

INPUT PATTERNS TO TEST:
=======================

Magic Commands:
- Line magics: %timeit, %cd, %magic_name arg1 arg2
- Cell magics: %%time, %%bash, %%sql
- Assignments: a = %time x, a = !ls -la
- Nested magics: %magic1 %magic2

System Commands:
- Simple: !ls, !pwd
- With pipes: !ls | grep foo
- With redirects: !ls > file.txt
- With special characters: !echo "hello world"

Help Syntax:
- ?obj (one question mark)
- ??obj (two question marks)
- ?func? (search)
- help(obj)

Input Continuation:
- Backslash continuation: x = 1 + \
                             2
- Parenthesis continuation: (x +
                              y)
- String continuation

Edge Cases:
- Mixed indentation (tabs vs spaces)
- Unicode characters in commands
- Very long input lines
- Special escape sequences (\n, \t, etc.)
- Empty input
- Only whitespace
- Comments mixed with magic
- Multiple transformations needed

POTENTIAL VULNERABILITIES:
==========================
- Regex denial of service in input splitting patterns
- Command injection through system commands
- Code injection through magic commands
- Stack overflow from deeply nested syntax
- Memory exhaustion from very long input
- Infinite loops in transformation logic
- Token parsing edge cases (unterminated strings)
- Unicode handling issues
- Type confusion in AST evaluation

TRANSFORMATION FLOW TO TEST:
============================
1. Input sanitization (leading/trailing whitespace)
2. Prompt stripping (for pasted input)
3. Line-based transformations (cell magics, etc.)
4. Token-based transformations (assignments, escapes, help)
5. Prefilter transformations (line routing)
6. AST parsing and compilation
7. Code execution
