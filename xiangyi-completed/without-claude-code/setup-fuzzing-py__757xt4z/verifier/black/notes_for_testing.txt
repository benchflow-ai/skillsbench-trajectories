BLACK LIBRARY - FUZZING NOTES
==============================

Library Purpose:
Black is a Python code formatter that parses Python source code and reformats it
according to strict style rules.

KEY FUNCTIONS FOR FUZZING (Priority Order):
============================================

CRITICAL PRIORITY (Main Entry Points):
1. format_str(src_contents: str, *, mode: Mode, lines: Collection) -> str
   - Location: src/black/__init__.py
   - Main formatting entry point, tests entire pipeline
   - Inputs to fuzz: Python source code of varying validity and complexity
   - Edge cases: Malformed syntax, edge cases in Python grammar

2. lib2to3_parse(src_txt: str, target_versions: Collection) -> Node
   - Location: src/black/parsing.py
   - Parses Python source to lib2to3 AST
   - Tries multiple grammar versions (Python 3.0-3.10+)
   - Inputs to fuzz: Python source code, edge case syntax
   - Edge cases: Syntax errors, grammar ambiguities, version-specific features

HIGH PRIORITY:
3. LineGenerator.visit_* methods (multiple visitor methods)
   - Location: src/black/linegen.py
   - Transforms lib2to3 AST nodes into formatted lines
   - Inputs to fuzz: Various AST node types
   - Edge cases: Complex nested structures, decorators, type annotations

4. transform_line(current_line: Line, ..., features: Collection[Feature]) -> Iterator[Line]
   - Location: src/black/linegen.py
   - Complex line transformation logic
   - Inputs to fuzz: Line structures with various content
   - Edge cases: Very long lines, complex expressions

5. StringMerger.transform() / StringSplitter.transform()
   - Location: src/black/trans.py
   - String concatenation and splitting logic
   - Inputs to fuzz: Various string combinations and formats
   - Edge cases: Raw strings, f-strings, docstrings, unicode

MEDIUM PRIORITY:
6. normalize_string_quotes(s: str, is_bytestring: bool, quote: str, prefix: str) -> str
   - Location: src/black/strings.py
   - Quote normalization
   - Inputs to fuzz: Strings with various quote types and escapes
   - Edge cases: Mixed quotes, escape sequences, unicode

7. hug_power_op(left: Node, right: Node) -> bool
   - Location: src/black/trans.py
   - Power operator spacing normalization
   - Inputs to fuzz: Power operator expressions

8. generate_comments(leaf: LN, mode: Mode) -> Iterator[Leaf]
   - Location: src/black/comments.py
   - Comment extraction and processing
   - Inputs to fuzz: Code with various comment styles

9. format_cell(src: str, *, fast: bool, mode: Mode) -> str
   - Location: src/black/handle_ipynb_magics.py
   - Jupyter notebook cell formatting
   - Inputs to fuzz: IPython magic commands and cell content

FUZZ TARGETS - Code Patterns:
=============================
1. Expression complexity:
   - Deeply nested parentheses: ((((x))))
   - Complex boolean expressions: (a and b) or (c and d)
   - Function calls with many arguments
   - Dictionary/list comprehensions

2. String variations:
   - Raw strings (r"...")
   - f-strings with expressions: f"{x + y}"
   - Triple-quoted strings
   - Mixed quote types
   - Unicode and escape sequences

3. Python syntax edge cases:
   - Type annotations: def func(x: Dict[str, List[int]]) -> None
   - Decorators: @decorator with arguments
   - Lambda expressions: lambda x: x + 1
   - Async/await: async def foo() / await bar()
   - Pattern matching (Python 3.10+): match x:
   - Walrus operator: if (x := 5) > 3:

4. Comment positions:
   - Inline comments
   - Block comments
   - Comments on various statement types

5. Line length edge cases:
   - Very long lines (should trigger splitting)
   - Lines near length limit
   - Long strings that cannot be split

6. Bracket/parenthesis variations:
   - Mismatched brackets (should error gracefully)
   - Nested brackets: [[[]]]
   - Bracket combinations: () [] {}

INPUT PATTERNS TO TEST:
=======================
- Valid Python code of increasing complexity
- Invalid/malformed Python syntax
- Edge cases in Python grammar
- Very long source files
- Code with various encoding declarations
- Code with unicode characters
- Code with mixed line endings
- Code with tabs and spaces
- Code with trailing whitespace
- Empty input / whitespace-only input

POTENTIAL VULNERABILITIES:
==========================
- Regex denial of service in pattern matching
- Stack overflow from deeply nested structures
- Memory exhaustion from very long input
- Infinite loops in transformation logic
- Edge cases in AST traversal
- Buffer overflows in C extension (lib2to3)
- Unexpected behavior on invalid syntax
- Performance issues with complex expressions

MODE CONFIGURATIONS TO TEST:
============================
- Different target_versions (Python 3.6-3.10+)
- Different line_length values
- string_normalization: True/False
- is_pyi: True/False (Python stub files)
- preview: True/False
- magic_trailing_comma: True/False
- Various skip decorators

IDEMPOTENCE PROPERTIES TO CHECK:
================================
1. format_str(format_str(code)) == format_str(code)
2. AST of original == AST of formatted
3. Second formatting pass == first formatting pass
4. Result is syntactically valid Python

FUZZ STRATEGY:
==============
1. Generate syntactically valid Python code (using Hypothesmith or similar)
2. Generate invalid/malformed Python code to test error handling
3. Test format strings and comment combinations
4. Test various mode configurations
5. Test idempotence property
6. Test with deeply nested structures
7. Test with very long input
8. Test with unicode and special characters
9. Validate output is syntactically correct
