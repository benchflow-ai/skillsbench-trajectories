UJSON LIBRARY - FUZZING NOTES
==============================

Library Purpose:
ujson is a high-performance JSON encoder/decoder library written primarily in C
with Python bindings. It provides fast serialization and deserialization of JSON data.

KEY FUNCTIONS FOR FUZZING (Priority Order):
============================================

CRITICAL PRIORITY (Main Entry Points):
1. ujson.decode() / ujson.loads() - JSON string to Python object
   - Location: src/ujson/lib/ultrajsondec.c:JSON_DecodeObject()
   - Main JSON parsing entry point
   - Inputs to fuzz: JSON strings of varying structure
   - Edge cases: Nested structures, edge case values, invalid syntax
   - Potential issues: Stack overflow, buffer overflow, integer overflow

2. ujson.encode() / ujson.dumps() - Python object to JSON string
   - Location: src/ujson/lib/ultrajsonenc.c:JSON_EncodeObject()
   - Main JSON serialization entry point
   - Inputs to fuzz: Python objects of various types and structures
   - Edge cases: Circular references, deep nesting, special values
   - Potential issues: Memory exhaustion, infinite loops, buffer overflows

HIGH PRIORITY (Core Parsing Functions):
3. decode_string()
   - Location: src/ujson/lib/ultrajsondec.c:362
   - Parses JSON strings with escape sequence handling
   - Handles UTF-8 and UTF-16 surrogate pairs
   - Inputs to fuzz: JSON strings with escape sequences
   - Edge cases: Unicode, surrogates, malformed escapes, null bytes
   - Potential issues: Buffer overflow, invalid UTF-8, surrogate injection

4. decode_numeric()
   - Location: src/ujson/lib/ultrajsondec.c:91
   - Parses integers and long integers
   - Performs overflow detection
   - Inputs to fuzz: Numeric strings at boundaries
   - Edge cases: INT32/INT64/UINT64 overflow, leading zeros
   - Potential issues: Integer overflow, precision loss

5. decodeDouble()
   - Location: src/ujson/lib/ultrajsondec.c:79
   - Parses floating-point numbers
   - Uses double-conversion library for precision
   - Inputs to fuzz: Float representations, special values
   - Edge cases: Very large/small numbers, NaN, Infinity, denormalized
   - Potential issues: Precision loss, special value handling

6. decode_array()
   - Location: src/ujson/lib/ultrajsondec.c:589
   - Parses JSON arrays
   - Enforces depth limit (JSON_MAX_OBJECT_DEPTH = 1024)
   - Inputs to fuzz: Nested arrays
   - Edge cases: Deeply nested, empty arrays, mixed types
   - Potential issues: Stack overflow, depth limit bypass, memory issues

7. decode_object()
   - Location: src/ujson/lib/ultrajsondec.c:653
   - Parses JSON objects
   - Enforces depth limit
   - Requires string keys
   - Inputs to fuzz: Nested objects, key variations
   - Edge cases: Deeply nested, duplicate keys, non-string keys
   - Potential issues: Stack overflow, memory corruption, key collision

MEDIUM PRIORITY (Encoding Functions):
8. Buffer_AppendLongUnchecked()
   - Location: src/ujson/lib/ultrajsonenc.c:585
   - Encodes 64-bit integers
   - Inputs to fuzz: Integer boundary values
   - Edge cases: INT64_MIN, INT64_MAX, zero
   - Potential issues: Integer overflow, incorrect formatting

9. Buffer_AppendUnsignedLongUnchecked()
   - Location: src/ujson/lib/ultrajsonenc.c:614
   - Encodes unsigned 64-bit integers
   - Inputs to fuzz: Unsigned integer boundary values
   - Edge cases: UINT64_MAX, zero
   - Potential issues: Integer overflow, formatting errors

10. String encoding with escape processing
    - Escapes special characters: quotes, backslashes, control chars
    - Inputs to fuzz: Strings with special characters
    - Edge cases: Control characters, unicode, null bytes
    - Potential issues: Incorrect escaping, buffer overflow

UTILITY FUNCTIONS:
11. SkipWhitespace()
    - Location: src/ujson/lib/ultrajsondec.c:311
    - Skips whitespace between tokens
    - Inputs to fuzz: Various whitespace combinations
    - Edge cases: Only whitespace, no whitespace, mixed whitespace

12. decode_true() / decode_false() / decode_null()
    - Parses boolean and null literals
    - Inputs to fuzz: Variations of these keywords
    - Edge cases: Partial keywords, case variations

PYTHON INTEGRATION FUNCTIONS:
13. JSONToObj()
    - Location: python/JSONtoObj.c:163
    - Main Python decoder function
    - Accepts bytes, bytearray, or string input
    - Constructs Python objects (dict, list, str, int, float, bool, None)
    - Inputs to fuzz: Various input types and encodings
    - Edge cases: Different encodings (UTF-8, UTF-16), invalid bytes
    - Potential issues: Type confusion, memory corruption

14. objToJSON()
    - Location: python/objToJSON.c:660
    - Main Python encoder function
    - Handles: dict, list, str, int, float, bool, None, Decimal
    - Supports custom serialization via default callback
    - Inputs to fuzz: Python objects of various types
    - Edge cases: Circular references, unsupported types, Decimal precision

INPUT PATTERNS TO TEST:
=======================

JSON Structure Variations:
- Empty: {}, []
- Single element: {"a": 1}, [1]
- Nested arrays: [[[[]]]]
- Nested objects: {"a": {"b": {"c": {}}}}
- Mixed nesting: {"a": [{"b": [1, 2]}]}
- Large arrays: [1, 2, 3, ..., 1000000]
- Large objects: {"key1": val1, "key2": val2, ...}

Numeric Edge Cases:
- Zero: 0, 0.0, -0, -0.0
- Boundaries: INT32_MIN/MAX, INT64_MIN/MAX, UINT64_MAX
- Floats: Very large (1e308), very small (1e-308)
- Special: NaN, Infinity, -Infinity
- Precision: Many decimal places
- Exponents: 1e10, 1E-5, 1.5e20

String Edge Cases:
- Empty: ""
- Escape sequences: "\"", "\\", "\n", "\t", "\r", "\b", "\f"
- Unicode: "\u0041", "\uFFFF", surrogate pairs "\uD800\uDC00"
- Control characters: null bytes, tabs, newlines
- Long strings: Megabytes of data
- Special chars: quotes, backslashes, slashes

Depth Testing:
- Increasing nesting depth: [[[[...]]]]
- Depth at limit: 1024 levels
- Depth beyond limit: 1025+ levels
- Mixed depth: Objects and arrays alternating

Encoding Variations:
- UTF-8 encoded JSON
- UTF-16 encoded JSON
- Invalid UTF-8 sequences
- BOM markers

Malformed JSON:
- Missing commas: [1 2]
- Trailing commas: [1, 2,]
- Unquoted keys: {key: value}
- Single-quoted keys: {'key': value}
- Invalid escapes: "\x", "\g"
- Incomplete values: [1, 2,
- Extra data after JSON: {} extra

POTENTIAL VULNERABILITIES:
==========================
- Stack overflow from deeply nested structures (recursion limit bypass)
- Buffer overflow in string escape processing
- Integer overflow in numeric parsing
- Memory exhaustion from large allocations
- Use-after-free in memory management
- Out-of-bounds access in array/object parsing
- Double-free in cleanup code
- Null pointer dereference
- Type confusion in object conversion
- Infinite loops in parsing logic
- Surrogate pair injection/corruption
- Circular reference handling in encoder

ENCODING OPTIONS TO TEST:
=========================
- forceASCII: True/False (ASCII escape non-ASCII characters)
- encodeHTMLChars: True/False (escape <, >, & for HTML safety)
- escapeForwardSlashes: True/False (escape / characters)
- sortKeys: True/False (dictionary key ordering)
- indent: None, 0, 2, 4 (pretty-printing)
- allowNan: True/False (NaN/Infinity handling)
- rejectBytes: True/False (bytes object handling)

FUZZ STRATEGY:
==============
1. Generate valid JSON with increasing complexity
2. Generate invalid/malformed JSON to test error handling
3. Test numeric boundaries and overflow cases
4. Test string escape sequences and unicode handling
5. Test deeply nested structures (arrays and objects)
6. Test with very large inputs (memory stress)
7. Test encoding options combinations
8. Test with various character encodings
9. Test surrogate pair handling
10. Test round-trip: encode -> decode -> encode
11. Test with circular references (for encoder)
12. Test custom type handling with default callback
13. Validate output is valid JSON
14. Check for memory leaks and corruption
15. Test error messages for invalid input
