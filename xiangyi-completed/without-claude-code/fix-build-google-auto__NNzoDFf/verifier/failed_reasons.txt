BUILD FAILURE ANALYSIS FOR google/auto PROJECT
==============================================

Repository: /home/travis/build/failed/google/auto
Java Version: OpenJDK 11.0.27

ERROR SUMMARY:
--------------
The build fails with the following error:
"Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

ROOT CAUSE:
-----------
1. The project uses Java 11, but the parent POM (auto-parent version 3) has profile configurations
   designed for Java 8 and earlier that reference tools.jar

2. In Java 9+, tools.jar was removed and the tools are now part of the JDK module system

3. The parent POM defines profiles that set the `toolsjar` property to point to tools.jar:
   - default-profile: ${java.home}/../lib/tools.jar
   - mac-profile: ${java.home}/../Classes/classes.jar

4. The auto-common module depends on com.google.testing.compile:compile-testing:0.7
   which has a system-scoped dependency on com.sun:tools that uses the ${toolsjar} property

5. When the profile activates (checking if tools.jar exists), it fails in Java 11 because
   the file doesn't exist

AFFECTED MODULES:
-----------------
- auto-common (fails during dependency resolution)
- auto-factory (skipped due to common failure)
- auto-service (skipped due to common failure)
- auto-value (skipped due to common failure)

SOLUTION:
---------
There are two approaches to fix this:

Option 1 (Recommended): Disable the profile activation for Java 11+
- Modify the parent POM profiles to only activate for Java 8 and earlier
- Add a new profile for Java 9+ that doesn't set the toolsjar property
- This allows compile-testing to handle the tools dependency appropriately for newer JDKs

Option 2: Update dependency versions
- Upgrade compile-testing to a version that supports Java 11+
- However, this may require code changes to maintain compatibility

----------------------------------

1. TOOLS.JAR DEPENDENCY ISSUE:
