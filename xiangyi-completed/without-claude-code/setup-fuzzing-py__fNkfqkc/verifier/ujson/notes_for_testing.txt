ujson Library - Testing Notes
==============================

Library Purpose: Ultra-fast JSON encoder/decoder for Python

Key Functions for Fuzzing:
---------------------------

1. dumps(obj: Any, **kwargs) -> str / encode(obj: Any, **kwargs) -> str
   - Serializes Python objects to JSON string
   - Inputs: Any Python object (dicts, lists, strings, numbers, Decimal, datetime)
   - Options: ensure_ascii, encode_html_chars, escape_forward_slashes, sort_keys, indent
   - Test with: deeply nested objects, circular references, unusual types
   - Location: ujson module

2. loads(s: str | bytes | bytearray) -> Any / decode(s: str | bytes | bytearray) -> Any
   - Parses JSON from string/bytes into Python objects
   - Inputs: String, bytes, or bytearray containing JSON
   - Test with: malformed JSON, extreme nesting, large numbers, invalid UTF-8
   - Location: ujson module

3. dump(obj: Any, fp: SupportsWrite[str], **kwargs) -> None
   - Writes JSON-encoded object to file-like object
   - Inputs: Python object + file-like object
   - Test with: custom file-like objects, write failures
   - Location: ujson module

4. load(fp: SupportsRead[str | bytes | bytearray]) -> Any
   - Parses JSON from file-like object
   - Inputs: File-like object supporting read()
   - Test with: custom file-like objects, partial reads, encoding issues
   - Location: ujson module

Fuzzing Strategy:
-----------------
- Focus on loads/decode with malformed JSON strings
- Test extreme nesting levels (DoS potential)
- Test large number parsing (overflow/precision issues)
- Test various encoding options and their combinations
- Test with invalid UTF-8 sequences in bytes input
- Test custom serialization with default callback
- Test round-trip encoding/decoding consistency
- Look for crashes with pathological inputs

Important Edge Cases:
---------------------
- Very large integers/floats
- Extreme Unicode characters
- HTML/XML special characters (with encode_html_chars)
- NaN and Infinity values (with allow_nan)
- Circular references (should raise error)
- Deeply nested structures (stack overflow potential)
