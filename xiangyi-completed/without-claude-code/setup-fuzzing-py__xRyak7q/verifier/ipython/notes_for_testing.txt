================================================================================
                    IPython Library - Fuzz Testing Analysis
================================================================================

LIBRARY DESCRIPTION
-------------------
IPython (Interactive Python) is an enhanced interactive Python shell that offers
introspection, rich media, shell syntax, tab completion, and history. It is the
kernel behind Jupyter notebooks and provides a command-line interface with
advanced features like magic commands (%command), system shell access (!command),
help queries (?object), and sophisticated code completion.

The library processes untrusted user input in many forms - code cells, magic
commands, special syntax, and various escape sequences - making it an excellent
candidate for fuzz testing to discover parsing bugs, crashes, and potential
security vulnerabilities.

1. IPython.core.inputtransformer2.TransformerManager.transform_cell()
--------------------------------------------------------------------------------
Module Path: IPython/core/inputtransformer2.py
Function: TransformerManager.transform_cell(cell: str) -> str

INPUT TYPE: String (arbitrary Python code with IPython special syntax)

DESCRIPTION:
The primary entry point for transforming IPython input cells into valid Python
code. This function handles all IPython special syntax including:
- Magic commands (%magic, %%cellmagic)
- System shell commands (!command, !!command)
- Help queries (?object, object?, object??)
- Auto-quoting (,func args -> func("args"))
- Auto-parenthesis (/func args -> func(args))
- Prompt stripping (>>> and In[1]: style prompts)

WHY FUZZ:
This is the MOST CRITICAL function to fuzz test. It:
- Processes arbitrary user input
- Uses complex regex patterns and tokenization
- Has nested transformation loops with a 500-iteration limit
- Converts special syntax to Python AST calls
- Could have edge cases with malformed escape sequences, unterminated strings,
  deeply nested brackets, or unusual Unicode characters

- Edge cases with special characters, Unicode, empty input
- Used by prefilter system for command dispatch

================================================================================
                        INPUT CATEGORIES TO TEST
================================================================================

1. ESCAPE SEQUENCES
   - Magic: %, %%, %magic, %%cellmagic
   - Shell: !, !!, !command, !!command
   - Help: ?, ??, object?, object??
   - Auto-quote: ,func args
   - Auto-paren: /func args
   - Quote2: ;func args

2. MALFORMED INPUT
   - Unclosed quotes and brackets
   - Mismatched parentheses
   - Invalid Unicode sequences
   - Embedded null bytes
   - Very long lines
   - Deeply nested structures

3. EDGE CASES
   - Empty input
   - Whitespace-only input
   - Lines ending with backslash
   - Mixed line endings (\n, \r\n, \r)
   - Cursor positions at boundaries
   - Very large cursor positions

4. UNICODE
   - Non-ASCII identifiers
   - RTL text
   - Emoji
   - Combining characters
   - Zero-width characters
   - Invalid UTF-8 sequences (for bytes input)

5. SPECIAL PATTERNS
   - Regex metacharacters in user patterns
   - Format string specifiers (%s, %r, etc.)
   - Python string escapes (\n, \t, \\)
   - Shell metacharacters

6. AST EDGE CASES (for guarded_eval)
   - Complex expressions
   - Nested function calls
   - Attribute chains
   - Subscript operations
   - Generator expressions
   - Lambda expressions
