                    UJSON LIBRARY ANALYSIS FOR FUZZ TESTING

================================================================================
1. LIBRARY DESCRIPTION
================================================================================

UltraJSON (ujson) is an ultra-fast JSON encoder and decoder written in pure C
with Python bindings. Developed originally by ESN (an Electronic Arts Inc.
studio), it serves as a drop-in replacement for Python's standard library JSON
module with significantly better performance.

Key characteristics:
- Written in C for maximum performance
- Uses the double-conversion library for precise floating-point handling
- Supports Python 3.x
- Currently in maintenance-only mode due to architectural concerns about
  security vulnerability risks (per the README warning)
- Provides both encoding (Python -> JSON) and decoding (JSON -> Python)

The library is currently marked as maintenance-only, with the maintainers
recommending migration to orjson for new projects. This is particularly
relevant for fuzzing, as the maintainers have acknowledged that the
architecture is "fundamentally ill-suited to making changes without risk of
introducing new security vulnerabilities."

================================================================================
2. PUBLIC API FUNCTIONS FOR FUZZ TESTING
================================================================================

The module exposes 6 main public functions (defined in ujson.c):

------------------------------------------------------------------------------
2.1 ujson.loads / ujson.decode (aliases of same function)
------------------------------------------------------------------------------
Module Path: ujson.loads / ujson.decode
Implementation: JSONToObj() in /app/ujson/src/ujson/python/JSONtoObj.c

Function Signature:
    ujson.loads(obj)
    ujson.decode(obj)

Input Types:
    - str (Unicode string)
    - bytes
    - bytearray
    - memoryview (C-contiguous buffer, CPython only - not PyPy)

What It Does:
    Parses a JSON-formatted string/bytes and converts it to Python objects.

Why It's a Prime Fuzzing Target:
    - HIGHEST PRIORITY for fuzzing
    - Directly processes untrusted input (the JSON string)
    - Complex parsing logic in C handles:
        * String decoding with escape sequences (\n, \t, \uXXXX, etc.)
        * Unicode and UTF-8 validation
        * Surrogate pair handling
        * Numeric parsing (integers, floats, scientific notation)
        * Nested array/object structures with depth limits
        * Special values: NaN, Infinity, -Infinity, null, true, false
    - Memory allocation for variable-length strings and nested structures
    - Buffer management for escape sequence processing
    - Historical source of security vulnerabilities in JSON parsers

Interesting Edge Cases for Fuzzing:
    - Deeply nested structures (tests depth limit: JSON_MAX_OBJECT_DEPTH=1024)
    - Very large numbers that overflow int64/uint64
    - Malformed UTF-8 sequences
    - Unicode escape sequences (\uXXXX) including surrogate pairs
    - Incomplete/truncated JSON
    - Trailing data after valid JSON
    - Very long strings
    - Embedded null bytes (\u0000)
    - Invalid escape sequences

------------------------------------------------------------------------------
2.2 ujson.dumps / ujson.encode (aliases of same function)
------------------------------------------------------------------------------
Module Path: ujson.dumps / ujson.encode
Implementation: objToJSON() in /app/ujson/src/ujson/python/objToJSON.c

Function Signature:
    ujson.dumps(obj, ensure_ascii=True, encode_html_chars=False,
                escape_forward_slashes=True, sort_keys=False, indent=0,
                allow_nan=True, reject_bytes=True, default=None,
                separators=None)
    ujson.encode(obj, ...)  # same parameters

Input Types:
    - Any Python object that is JSON-serializable:
        * dict, list, tuple
        * str, bytes (if reject_bytes=False)
        * int, float (including NaN, Infinity with allow_nan=True)
        * bool, None
        * decimal.Decimal
        * Objects with toDict() method
        * Objects with __json__() method
        * Any type handled by custom default() function

What It Does:
    Serializes Python objects to JSON string format.

Why It's a Good Fuzzing Target:
    - HIGH PRIORITY for fuzzing
    - Processes arbitrary Python objects
    - String escaping logic (control chars, unicode, HTML chars)
    - UTF-8 encoding/validation
    - Handles recursive structures (with depth limit)
    - Buffer management for output
    - Integer conversion (including very large numbers)
    - Floating-point formatting via double-conversion library
    - The default() callback allows arbitrary code execution on objects

Interesting Edge Cases for Fuzzing:
    - Very large integers (beyond int64 range)
    - Deep recursion (tests limit: JSON_MAX_RECURSION_DEPTH=1024)
    - Unicode strings with surrogate characters
    - Very long strings
    - Strings with embedded null bytes
    - Large indent values
    - Custom separators (especially with unicode or null bytes)
    - Objects that raise exceptions in toDict() or __json__()
    - Objects with complex __repr__() for error messages
    - Circular references

------------------------------------------------------------------------------
2.3 ujson.load
------------------------------------------------------------------------------
Module Path: ujson.load
Implementation: JSONFileToObj() in /app/ujson/src/ujson/python/JSONtoObj.c

Function Signature:
    ujson.load(file)

Input Types:
    - File-like object with .read() method

What It Does:
    Reads JSON from a file-like object and parses it.

Why It's a Fuzzing Target:
    - MEDIUM PRIORITY (delegates to loads after reading)
    - Wrapper around ujson.loads that first reads from file
    - Tests the file interface handling
    - Same underlying parsing vulnerabilities as loads()

Interesting Edge Cases for Fuzzing:
    - Mock file objects with unusual read() behavior
    - File objects that raise exceptions during read
    - File objects without proper read() method

------------------------------------------------------------------------------
2.4 ujson.dump
------------------------------------------------------------------------------
Module Path: ujson.dump
Implementation: objToJSONFile() in /app/ujson/src/ujson/python/objToJSON.c

Function Signature:
    ujson.dump(obj, file, ...)  # same encoding parameters as dumps

Input Types:
    - First arg: Any JSON-serializable Python object
    - Second arg: File-like object with .write() method

What It Does:
    Serializes Python object to JSON and writes to file.

Why It's a Fuzzing Target:
    - MEDIUM PRIORITY (delegates to dumps)
    - Wrapper around ujson.dumps that writes result to file
    - Tests the file interface handling
    - Same underlying serialization as dumps()

Interesting Edge Cases for Fuzzing:
    - Mock file objects with unusual write() behavior
    - File objects that raise exceptions during write
    - File objects without proper write() method

================================================================================
3. CORE C FUNCTIONS (Internal, but critical for understanding)
================================================================================

These functions are not directly callable from Python but represent the core
parsing/encoding logic where vulnerabilities are most likely to exist:

------------------------------------------------------------------------------
3.1 decode_string (ultrajsondec.c:362)
------------------------------------------------------------------------------
What It Does:
    Parses JSON string literals including escape sequence handling.

Security-Critical Operations:
    - UTF-8 validation (2, 3, 4-byte sequences)
    - Unicode escape sequence parsing (\uXXXX)
    - Surrogate pair combining
    - Buffer reallocation for escape output
    - Overlong UTF-8 sequence detection

------------------------------------------------------------------------------
3.2 decode_numeric (ultrajsondec.c:91)
------------------------------------------------------------------------------
What It Does:
    Parses JSON numbers (integers, floats, special values).

Security-Critical Operations:
    - Integer overflow handling
    - Fallback to arbitrary-precision strings for huge numbers
    - NaN/Infinity parsing
    - Floating-point conversion via double-conversion library

------------------------------------------------------------------------------
3.3 decode_array / decode_object (ultrajsondec.c:589, 653)
------------------------------------------------------------------------------
What It Does:
    Parses JSON arrays and objects recursively.

Security-Critical Operations:
    - Depth limit checking (JSON_MAX_OBJECT_DEPTH)
    - Memory allocation for containers
    - Proper cleanup on parse errors

------------------------------------------------------------------------------
3.4 Buffer_EscapeStringValidated (ultrajsonenc.c:302)
------------------------------------------------------------------------------
What It Does:
    Escapes strings for JSON output with UTF-8 validation.

Security-Critical Operations:
    - UTF-8 sequence validation
    - Surrogate pair generation for non-BMP characters
    - Control character escaping
    - HTML character escaping (optional)
    - Buffer overflow prevention

------------------------------------------------------------------------------
3.5 Buffer_EscapeStringUnvalidated (ultrajsonenc.c:191)
------------------------------------------------------------------------------
What It Does:
    Fast path string escaping without UTF-8 validation.

Security-Critical Operations:
    - Used when ensure_ascii=False
    - Control character escaping
    - Less validation = higher risk

================================================================================
4. FUZZING RECOMMENDATIONS
================================================================================

Priority 1 - CRITICAL (Highest Risk):
--------------------------------------
1. ujson.loads() with arbitrary bytes/strings
   - Focus: Malformed JSON, invalid UTF-8, escape sequences, deep nesting
   - This is the primary attack surface for untrusted input

2. ujson.loads() with very large inputs
   - Focus: Memory exhaustion, integer overflows in size calculations

Priority 2 - HIGH:
------------------
3. ujson.dumps() with complex Python objects
   - Focus: Deep recursion, large strings, unicode edge cases

4. ujson.dumps() with unusual parameter combinations
   - Focus: Large indent values, custom separators, combined flags

Priority 3 - MEDIUM:
--------------------
5. ujson.load()/ujson.dump() with mock file objects
   - Focus: Interface edge cases, exception handling

================================================================================
5. SPECIFIC INPUT PATTERNS TO FUZZ
================================================================================

For ujson.loads() / decode():
-----------------------------
- Truncated JSON at various points
- Very deep nesting: [[[[...]]]]  or {{{{...}}}}
- Very long strings: "aaaa...aaaa"
- Escape sequences: \n \t \\ \" \/ \b \f \r \uXXXX
- Invalid escape sequences: \x \q \uGGGG
- Incomplete escape sequences: "\u123  "\u
- Surrogate pairs: \uD83D\uDCA9 (valid), \uD800 (unpaired high), \uDC00 (unpaired low)
- Mixed valid/invalid UTF-8 bytes
- Overlong UTF-8 sequences (security issue)
- Numbers: 1e999, -1e999, 1e-999, 99999999999999999999999
- Special values: NaN, Infinity, -Infinity, null, true, false
- Trailing garbage after valid JSON
- Leading whitespace variations
- Unicode null: \u0000 embedded in strings
- Very large objects/arrays (millions of elements)

For ujson.dumps() / encode():
-----------------------------
- Deeply nested dicts/lists
- Very large integers (> 2^64)
- Negative very large integers (< -2^63)
- Strings with all possible byte values (0x00-0xFF)
- Unicode strings with surrogate characters
- decimal.Decimal with unusual values
- Objects with __json__() returning invalid data
- Objects with toDict() returning invalid data
- Objects whose __repr__() raises exceptions
- indent parameter: 0, 1, 100, 65536, 2^31
- separators with unicode, null bytes, very long strings
- sort_keys with unhashable/uncomparable keys
- default function that returns self (infinite recursion)
- default function that raises exceptions

================================================================================
6. KNOWN VULNERABILITY AREAS (Historical)
================================================================================

Based on the codebase structure and comments:

1. Buffer Management:
   - Buffer_Realloc in ultrajsonenc.c
   - Escape buffer reallocation in decode_string

2. Integer Overflows:
   - Size calculations in string allocation
   - Nesting depth counters
   - Position/offset calculations

3. UTF-8 Handling:
   - Overlong sequence detection
   - Invalid continuation bytes
   - Surrogate handling

4. Recursion:
   - Deep nesting without proper stack checking
   - default() function recursion depth

5. Type Confusion:
   - Object_beginTypeContext handling of various Python types
   - Dictionary key conversion

================================================================================
7. CONFIGURATION CONSTANTS
================================================================================

From ultrajson.h:

- JSON_DOUBLE_MAX_DECIMALS: 15 (max decimal places for doubles)
- JSON_MAX_RECURSION_DEPTH: 1024 (default encoder max depth)
- JSON_MAX_OBJECT_DEPTH: 1024 (default decoder max depth)
- JSON_MAX_STACK_BUFFER_SIZE: 1024 (stack buffer before heap allocation)

These constants define limits that fuzzing should test around (e.g., depths
of 1023, 1024, 1025 to test boundary conditions).
