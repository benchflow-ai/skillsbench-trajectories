     5→================================================================================
     6→1. LIBRARY DESCRIPTION
     7→================================================================================
     8→
     9→UltraJSON (ujson) is an ultra-fast JSON encoder and decoder written in pure C
    10→with Python bindings. Developed originally by ESN (an Electronic Arts Inc.
    11→studio), it serves as a drop-in replacement for Python's standard library JSON
    12→module with significantly better performance.
    13→
    14→Key characteristics:
    15→- Written in C for maximum performance
    16→- Uses the double-conversion library for precise floating-point handling
    17→- Supports Python 3.x
    18→- Currently in maintenance-only mode due to architectural concerns about
    19→  security vulnerability risks (per the README warning)
    20→- Provides both encoding (Python -> JSON) and decoding (JSON -> Python)
    21→
    22→The library is currently marked as maintenance-only, with the maintainers
    23→recommending migration to orjson for new projects. This is particularly
    24→relevant for fuzzing, as the maintainers have acknowledged that the
    25→architecture is "fundamentally ill-suited to making changes without risk of
    26→introducing new security vulnerabilities."
    27→
    28→================================================================================
    29→2. PUBLIC API FUNCTIONS FOR FUZZ TESTING
    30→================================================================================
    31→
    32→The module exposes 6 main public functions (defined in ujson.c):
    33→
    34→------------------------------------------------------------------------------
    35→2.1 ujson.loads / ujson.decode (aliases of same function)
    36→------------------------------------------------------------------------------
    37→Module Path: ujson.loads / ujson.decode
    38→Implementation: JSONToObj() in /app/ujson/src/ujson/python/JSONtoObj.c
    39→
    40→Function Signature:
    41→    ujson.loads(obj)
    42→    ujson.decode(obj)
    43→
    44→Input Types:
    45→    - str (Unicode string)
    46→    - bytes
    47→    - bytearray
    48→    - memoryview (C-contiguous buffer, CPython only - not PyPy)
    49→
    50→What It Does:
    51→    Parses a JSON-formatted string/bytes and converts it to Python objects.
    52→
    53→Why It's a Prime Fuzzing Target:
    54→    - HIGHEST PRIORITY for fuzzing
    55→    - Directly processes untrusted input (the JSON string)
    56→    - Complex parsing logic in C handles:
    57→        * String decoding with escape sequences (\n, \t, \uXXXX, etc.)
    58→        * Unicode and UTF-8 validation
    59→        * Surrogate pair handling
    60→        * Numeric parsing (integers, floats, scientific notation)
    61→        * Nested array/object structures with depth limits
    62→        * Special values: NaN, Infinity, -Infinity, null, true, false
    63→    - Memory allocation for variable-length strings and nested structures
    64→    - Buffer management for escape sequence processing
    65→    - Historical source of security vulnerabilities in JSON parsers
    66→
    67→Interesting Edge Cases for Fuzzing:
    68→    - Deeply nested structures (tests depth limit: JSON_MAX_OBJECT_DEPTH=1024)
    69→    - Very large numbers that overflow int64/uint64
    70→    - Malformed UTF-8 sequences
    71→    - Unicode escape sequences (\uXXXX) including surrogate pairs
    72→    - Incomplete/truncated JSON
    73→    - Trailing data after valid JSON
    74→    - Very long strings
    75→    - Embedded null bytes (\u0000)
    76→    - Invalid escape sequences
    77→
    78→------------------------------------------------------------------------------
    79→2.2 ujson.dumps / ujson.encode (aliases of same function)
    80→------------------------------------------------------------------------------
    81→Module Path: ujson.dumps / ujson.encode
    82→Implementation: objToJSON() in /app/ujson/src/ujson/python/objToJSON.c
    83→
    84→Function Signature:
    85→    ujson.dumps(obj, ensure_ascii=True, encode_html_chars=False,
    86→                escape_forward_slashes=True, sort_keys=False, indent=0,
    87→                allow_nan=True, reject_bytes=True, default=None,
    88→                separators=None)
    89→    ujson.encode(obj, ...)  # same parameters
    90→
    91→Input Types:
    92→    - Any Python object that is JSON-serializable:
    93→        * dict, list, tuple
    94→        * str, bytes (if reject_bytes=False)
    95→        * int, float (including NaN, Infinity with allow_nan=True)
    96→        * bool, None
    97→        * decimal.Decimal
    98→        * Objects with toDict() method
    99→        * Objects with __json__() method
   100→        * Any type handled by custom default() function
   101→
   102→What It Does:
   103→    Serializes Python objects to JSON string format.
   104→
   105→Why It's a Good Fuzzing Target:
   106→    - HIGH PRIORITY for fuzzing
   107→    - Processes arbitrary Python objects
   108→    - String escaping logic (control chars, unicode, HTML chars)
   109→    - UTF-8 encoding/validation
   110→    - Handles recursive structures (with depth limit)
   111→    - Buffer management for output
   112→    - Integer conversion (including very large numbers)
   113→    - Floating-point formatting via double-conversion library
   114→    - The default() callback allows arbitrary code execution on objects
   115→
   116→Interesting Edge Cases for Fuzzing:
   117→    - Very large integers (beyond int64 range)
   118→    - Deep recursion (tests limit: JSON_MAX_RECURSION_DEPTH=1024)
   119→    - Unicode strings with surrogate characters
   120→    - Very long strings
   121→    - Strings with embedded null bytes
   122→    - Large indent values
   123→    - Custom separators (especially with unicode or null bytes)
   124→    - Objects that raise exceptions in toDict() or __json__()
   125→    - Objects with complex __repr__() for error messages
   126→    - Circular references
   127→
   128→------------------------------------------------------------------------------
   129→2.3 ujson.load
   130→------------------------------------------------------------------------------
   131→Module Path: ujson.load
   132→Implementation: JSONFileToObj() in /app/ujson/src/ujson/python/JSONtoObj.c
   133→
   134→Function Signature:
   135→    ujson.load(file)
   136→
   137→Input Types:
   138→    - File-like object with .read() method
   139→
   140→What It Does:
   141→    Reads JSON from a file-like object and parses it.
   142→
   143→Why It's a Fuzzing Target:
   144→    - MEDIUM PRIORITY (delegates to loads after reading)
   145→    - Wrapper around ujson.loads that first reads from file
   146→    - Tests the file interface handling
   147→    - Same underlying parsing vulnerabilities as loads()
   148→
   149→Interesting Edge Cases for Fuzzing:
   150→    - Mock file objects with unusual read() behavior
   151→    - File objects that raise exceptions during read
   152→    - File objects without proper read() method
   153→
   154→------------------------------------------------------------------------------
   155→2.4 ujson.dump
   156→------------------------------------------------------------------------------
   157→Module Path: ujson.dump
   158→Implementation: objToJSONFile() in /app/ujson/src/ujson/python/objToJSON.c
   159→
   160→Function Signature:
   161→    ujson.dump(obj, file, ...)  # same encoding parameters as dumps
   162→
   163→Input Types:
   164→    - First arg: Any JSON-serializable Python object
   165→    - Second arg: File-like object with .write() method
   166→
   167→What It Does:
   168→    Serializes Python object to JSON and writes to file.
   169→
   170→Why It's a Fuzzing Target:
   171→    - MEDIUM PRIORITY (delegates to dumps)
   172→    - Wrapper around ujson.dumps that writes result to file
   173→    - Tests the file interface handling
   174→    - Same underlying serialization as dumps()
   175→
   176→Interesting Edge Cases for Fuzzing:
   177→    - Mock file objects with unusual write() behavior
   178→    - File objects that raise exceptions during write
   179→    - File objects without proper write() method

   181→================================================================================
   182→3. CORE C FUNCTIONS (Internal, but critical for understanding)
   183→================================================================================
   184→
   185→These functions are not directly callable from Python but represent the core
   186→parsing/encoding logic where vulnerabilities are most likely to exist:
   187→
   188→------------------------------------------------------------------------------
   189→3.1 decode_string (ultrajsondec.c:362)
   190→------------------------------------------------------------------------------
   191→What It Does:
   192→    Parses JSON string literals including escape sequence handling.
   193→
   194→Security-Critical Operations:
   195→    - UTF-8 validation (2, 3, 4-byte sequences)
   196→    - Unicode escape sequence parsing (\uXXXX)
   197→    - Surrogate pair combining
   198→    - Buffer reallocation for escape output
   199→    - Overlong UTF-8 sequence detection
   200→
   201→------------------------------------------------------------------------------
   202→3.2 decode_numeric (ultrajsondec.c:91)
   203→------------------------------------------------------------------------------
   204→What It Does:
   205→    Parses JSON numbers (integers, floats, special values).
   206→
   207→Security-Critical Operations:
   208→    - Integer overflow handling
   209→    - Fallback to arbitrary-precision strings for huge numbers
   210→    - NaN/Infinity parsing
   211→    - Floating-point conversion via double-conversion library
   212→
   213→------------------------------------------------------------------------------
   214→3.3 decode_array / decode_object (ultrajsondec.c:589, 653)
   215→------------------------------------------------------------------------------
   216→What It Does:
   217→    Parses JSON arrays and objects recursively.
   218→
   219→Security-Critical Operations:
   220→    - Depth limit checking (JSON_MAX_OBJECT_DEPTH)
   221→    - Memory allocation for containers
   222→    - Proper cleanup on parse errors
   223→
   224→------------------------------------------------------------------------------
   225→3.4 Buffer_EscapeStringValidated (ultrajsonenc.c:302)
   226→------------------------------------------------------------------------------
   227→What It Does:
   228→    Escapes strings for JSON output with UTF-8 validation.
   229→
   230→Security-Critical Operations:
   231→    - UTF-8 sequence validation
   232→    - Surrogate pair generation for non-BMP characters
   233→    - Control character escaping
   234→    - HTML character escaping (optional)
   235→    - Buffer overflow prevention
   236→
   237→------------------------------------------------------------------------------
   238→3.5 Buffer_EscapeStringUnvalidated (ultrajsonenc.c:191)
   239→------------------------------------------------------------------------------
   240→What It Does:
   241→    Fast path string escaping without UTF-8 validation.
   242→
   243→Security-Critical Operations:
   244→    - Used when ensure_ascii=False
   245→    - Control character escaping
   246→    - Less validation = higher risk

   248→================================================================================
   249→4. FUZZING RECOMMENDATIONS
   250→================================================================================
   251→
   252→Priority 1 - CRITICAL (Highest Risk):
   253→--------------------------------------
   254→1. ujson.loads() with arbitrary bytes/strings
   255→   - Focus: Malformed JSON, invalid UTF-8, escape sequences, deep nesting
   256→   - This is the primary attack surface for untrusted input
   257→
   258→2. ujson.loads() with very large inputs
   259→   - Focus: Memory exhaustion, integer overflows in size calculations
   260→
   261→Priority 2 - HIGH:
   262→------------------
   263→3. ujson.dumps() with complex Python objects
   264→   - Focus: Deep recursion, large strings, unicode edge cases
   265→
   266→4. ujson.dumps() with unusual parameter combinations
   267→   - Focus: Large indent values, custom separators, combined flags
   268→
   269→Priority 3 - MEDIUM:
   270→--------------------
   271→5. ujson.load()/ujson.dump() with mock file objects
   272→   - Focus: Interface edge cases, exception handling
   273→
   274→================================================================================
   275→5. SPECIFIC INPUT PATTERNS TO FUZZ
   276→================================================================================
   277→
   278→For ujson.loads() / decode():
   279→-----------------------------
   280→- Truncated JSON at various points
   281→- Very deep nesting: [[[[...]]]]  or {{{{...}}}}
   282→- Very long strings: "aaaa...aaaa"
   283→- Escape sequences: \n \t \\ \" \/ \b \f \r \uXXXX
   284→- Invalid escape sequences: \x \q \uGGGG
   285→- Incomplete escape sequences: "\u123  "\u
   286→- Surrogate pairs: \uD83D\uDCA9 (valid), \uD800 (unpaired high), \uDC00 (unpaired low)
   287→- Mixed valid/invalid UTF-8 bytes
   288→- Overlong UTF-8 sequences (security issue)
   289→- Numbers: 1e999, -1e999, 1e-999, 99999999999999999999999
   290→- Special values: NaN, Infinity, -Infinity, null, true, false
   291→- Trailing garbage after valid JSON
   292→- Leading whitespace variations
   293→- Unicode null: \u0000 embedded in strings
   294→- Very large objects/arrays (millions of elements)
   295→
   296→For ujson.dumps() / encode():
   297→-----------------------------
   298→- Deeply nested dicts/lists
   299→- Very large integers (> 2^64)
   300→- Negative very large integers (< -2^63)
   301→- Strings with all possible byte values (0x00-0xFF)
   302→- Unicode strings with surrogate characters
   303→- decimal.Decimal with unusual values
   304→- Objects with __json__() returning invalid data
   305→- Objects with toDict() returning invalid data
   306→- Objects whose __repr__() raises exceptions
   307→- indent parameter: 0, 1, 100, 65536, 2^31
   308→- separators with unicode, null bytes, very long strings
   309→- sort_keys with unhashable/uncomparable keys
   310→- default function that returns self (infinite recursion)
   311→- default function that raises exceptions

   313→================================================================================
   314→6. KNOWN VULNERABILITY AREAS (Historical)
   315→================================================================================
   316→
   317→Based on the codebase structure and comments:
   318→
   319→1. Buffer Management:
   320→   - Buffer_Realloc in ultrajsonenc.c
   321→   - Escape buffer reallocation in decode_string
   322→
   323→2. Integer Overflows:
   324→   - Size calculations in string allocation
   325→   - Nesting depth counters
   326→   - Position/offset calculations
   327→
   328→3. UTF-8 Handling:
   329→   - Overlong sequence detection
   330→   - Invalid continuation bytes
   331→   - Surrogate handling
   332→
   333→4. Recursion:
   334→   - Deep nesting without proper stack checking
   335→   - default() function recursion depth
   336→
   337→5. Type Confusion:
   338→   - Object_beginTypeContext handling of various Python types
   339→   - Dictionary key conversion
   340→
   341→================================================================================
   342→7. CONFIGURATION CONSTANTS
   343→================================================================================
   344→
   345→From ultrajson.h:
   346→
   347→- JSON_DOUBLE_MAX_DECIMALS: 15 (max decimal places for doubles)
   348→- JSON_MAX_RECURSION_DEPTH: 1024 (default encoder max depth)
   349→- JSON_MAX_OBJECT_DEPTH: 1024 (default decoder max depth)
   350→- JSON_MAX_STACK_BUFFER_SIZE: 1024 (stack buffer before heap allocation)
   351→
   352→These constants define limits that fuzzing should test around (e.g., depths
   353→of 1023, 1024, 1025 to test boundary conditions).
