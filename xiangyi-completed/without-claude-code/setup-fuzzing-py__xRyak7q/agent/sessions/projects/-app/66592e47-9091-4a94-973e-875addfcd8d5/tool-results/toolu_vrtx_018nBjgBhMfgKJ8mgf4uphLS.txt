     1→================================================================================
     2→                    MINISGL FUZZ TESTING ANALYSIS
     3→================================================================================
     4→
     5→LIBRARY OVERVIEW
     6→--------------------------------------------------------------------------------
     7→Mini-SGLang (minisgl) is a lightweight yet high-performance inference framework
     8→for Large Language Models (LLMs). It is a compact implementation of SGLang with
     9→approximately 5,000 lines of Python code, designed to serve as both a capable
    10→inference engine and a transparent reference implementation.
    11→
    12→Key features include:
    13→- OpenAI-compatible API server for LLM inference
    14→- Radix cache for KV cache reuse across requests with shared prefixes
    15→- Tensor parallelism for multi-GPU inference
    16→- Message serialization for inter-process communication
    17→- Integration with FlashAttention and FlashInfer kernels
    18→
    19→The library uses msgpack for serialization, PyZMQ for messaging, and integrates
    20→with HuggingFace transformers for model loading.
    21→
    22→================================================================================
    23→                    PRIORITY 1: SERIALIZATION/DESERIALIZATION
    24→================================================================================
    25→
    26→These functions are the HIGHEST priority for fuzz testing because they handle
    27→untrusted data transformation and can lead to arbitrary code execution, memory
    28→corruption, or denial of service if improperly validated.
    29→
    30→--------------------------------------------------------------------------------
    31→1. minisgl.message.utils.deserialize_type
    32→--------------------------------------------------------------------------------
    33→Module Path: /app/minisgl/python/minisgl/message/utils.py
    34→Function: deserialize_type(cls_map: Dict[str, Type], data: Dict) -> Any
    35→
    36→Input:
    37→  - cls_map: A dictionary mapping type names to Python classes
    38→  - data: A dictionary containing serialized object data with "__type__" key
    39→
    40→Description:
    41→  Reconstructs Python objects from serialized dictionary representation.
    42→  Handles special case for torch.Tensor deserialization from raw bytes.
    43→
    44→Why fuzz:
    45→  - Dynamically instantiates classes based on user-controlled "__type__" field
    46→  - Performs numpy dtype conversion from string (e.g., "torch.int32" -> np.int32)
    47→  - Uses np.frombuffer on raw bytes which can cause buffer overflows with
    48→    mismatched dtype/length
    49→  - The cls_map lookup could be exploited if the __type__ field contains
    50→    unexpected values
    51→  - Could lead to arbitrary object instantiation vulnerabilities
    52→
    53→Fuzzing approach:
    54→  - Fuzz the data dictionary with malformed "__type__" values
    55→  - Fuzz buffer sizes vs declared dtype for Tensor deserialization
    56→  - Test edge cases with missing keys, wrong types, nested structures
    57→  - Test with very large or empty buffers
    58→
