UltraJSON Library - Testing Notes
==================================

Library Purpose:
- Ultra-fast JSON encoder/decoder for Python
- C implementation for high performance
- NOTE: Library is in maintenance-only mode due to security concerns

Critical Functions for Fuzzing:
================================

1. ujson.loads(str) / ujson.decode(str) - HIGHEST PRIORITY
   Location: /app/ujson/src/ujson/python/JSONtoObj.c:163
   - Parses JSON strings to Python objects
   - Handles all JSON types (null, bool, number, string, array, object)

2. ujson.dumps(obj) / ujson.encode(obj) - HIGHEST PRIORITY
   Location: /app/ujson/src/ujson/python/objToJSON.c
   - Encodes Python objects to JSON strings
   - Multiple encoding options

3. JSON_DecodeObject()
   Location: /app/ujson/src/ujson/lib/ultrajsondec.c
   - Core C decoder implementation
   - Recursive descent parser

4. JSON_EncodeObject()
   Location: /app/ujson/src/ujson/lib/ultrajsonenc.c
   - Core C encoder implementation
   - Handles Python object type detection

Encoding Options (Fuzzing Targets):
====================================
- ensure_ascii: Force ASCII output, escape non-ASCII
- encode_html_chars: Encode <, >, & as \uXXXX
- escape_forward_slashes: Escape / as \/
- sort_keys: Sort dictionary keys
- indent: Pretty-print indentation level
- allow_nan: Allow NaN/Infinity output
- reject_bytes: Reject bytes objects
- default: Custom encoder function
- separators: Item and key separators tuple

Input Categories for Fuzzing:
==============================
- Malformed JSON strings (missing quotes, brackets, commas)
- Deeply nested objects and arrays
- Very long strings and numbers
- Special numeric values (NaN, Infinity, -Infinity)
- Unicode characters and escape sequences
- Invalid UTF-8 sequences
- Control characters in strings
- Extremely large integers
- High-precision floating-point numbers
- Empty objects and arrays
- Duplicate keys in objects
- Mixed encoding (bytes vs strings)
- Null bytes in strings
- Recursive object references
- Very large arrays/objects

Key Edge Cases:
===============
- JSON_MAX_RECURSION_DEPTH: 1024 (encoder)
- JSON_MAX_OBJECT_DEPTH: 1024 (decoder)
- JSON_DOUBLE_MAX_DECIMALS: 15 (float precision)
- JSON_MAX_STACK_BUFFER_SIZE: 1024
- Surrogate pair handling in strings
- Unicode escape sequences (\uXXXX)
- Scientific notation (1e10, 1.5e-20)
- Leading zeros in numbers
- Trailing commas
- Comments in JSON (not standard)
- Single-quoted strings (not standard)
- Unquoted keys (not standard)
- Special float values with allow_nan=True/False
- Integer overflow (int32, int64, uint64 boundaries)
- Memory allocation failures
- String buffer overflows

Known Security Considerations:
==============================
From README: "UltraJSON's architecture is fundamentally ill-suited
to making changes without risk of introducing new security vulnerabilities."
- High priority for finding memory safety issues
- Buffer overflow vulnerabilities
- Integer overflow/underflow
- Type confusion bugs
- Null pointer dereferences
