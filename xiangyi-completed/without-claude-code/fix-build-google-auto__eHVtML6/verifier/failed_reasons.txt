# Build Failure Analysis for google/auto Repository

## Summary
The build fails because of a dependency on `com.sun:tools:jar` (tools.jar) which no longer exists
in Java 9+ (the environment is running Java 11).

## Error Messages
```
Could not resolve dependencies for project com.google.auto:auto-common:jar:1.0-SNAPSHOT:
Could not find artifact com.sun:tools:jar:11.0.27 at specified path
/usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
```

Same error occurs for:
- auto-common (uses compile-testing 0.7)
- auto-factory (uses compile-testing 0.8)
- auto-service (uses compile-testing 0.6)
- auto-value (uses compile-testing 0.6)

## Root Cause
The `compile-testing` library (versions 0.6, 0.7, 0.8) has a hardcoded system-scoped dependency
on `com.sun:tools` which requires the `tools.jar` file to exist.

In Java 8 and earlier:
- tools.jar was located at ${java.home}/../lib/tools.jar
- It contained the Java compiler API classes

In Java 9+:
- tools.jar no longer exists
- The compiler API classes are now part of the java.compiler module (JEP 220)
- The classes are available without needing a separate JAR

## Current versions of compile-testing used:
- common/pom.xml: compile-testing 0.7
- factory/pom.xml: compile-testing 0.8
- service/pom.xml: compile-testing 0.6
- value/pom.xml: compile-testing 0.6

## Solution
Upgrade the `compile-testing` dependency to version 0.21.0 (or later), which uses profile-based
activation for the tools.jar dependency - only activating when the file actually exists.
This makes it compatible with both Java 8 and Java 9+.

However, compile-testing 0.21.0 requires Java 8+ (source/target 1.8), while the current project
targets Java 1.6. This is acceptable since:
1. The project is building on Java 11, which supports Java 8 bytecode
2. compile-testing is only a test dependency, not a runtime dependency
3. Modern JVMs can still run Java 6 bytecode

Additionally, updating compile-testing will require updating related test dependencies:
- truth (from 0.24/0.25 to 1.1.3)
- guava (remains at 18.0 for main code, but test scope gets updated transitively)
- junit (from 4.11/4.12 to 4.13.2)

## Files to Modify
1. common/pom.xml - Update compile-testing from 0.7 to 0.21.0
2. factory/pom.xml - Update compile-testing from 0.8 to 0.21.0
3. service/pom.xml - Update compile-testing from 0.6 to 0.21.0
4. value/pom.xml - Update compile-testing from 0.6 to 0.21.0

## Changes Required
For each pom.xml, update the compile-testing dependency:
- Old: <version>0.X</version>
- New: <version>0.21.0</version>

## Additional Issue: javax.annotation.Generated not found

After fixing the tools.jar issue, a second Java 9+ compatibility issue appears:
```
cannot find symbol
  symbol:   class Generated
  location: package javax.annotation
```

### Root Cause
The `javax.annotation.Generated` annotation was part of the `java.xml.ws.annotation` module
which was deprecated in Java 9 (JEP 320) and removed in Java 11.

In Java 9+, the annotation moved to `javax.annotation.processing.Generated`.

### Affected Files
1. factory/src/main/java/com/google/auto/factory/processor/FactoryWriter.java
2. value/src/main/java/com/google/auto/value/processor/AutoValueProcessor.java
3. value/src/main/java/com/google/auto/value/processor/AutoAnnotationProcessor.java

### Solution
Change the import from:
- `import javax.annotation.Generated;`
to:
- `import javax.annotation.processing.Generated;`

Note: javax.annotation.processing.Generated is available since Java 9. Since we're building
on Java 11, this import will work. However, this means the compiled code will only work on
Java 9+, not Java 6 as originally targeted.

### Additional String References to Update
The FactoryWriter.java also emits the import as a string literal that needs updating:
- `writer.emitImports("javax.annotation.Generated");`
should become:
- `writer.emitImports("javax.annotation.processing.Generated");`
