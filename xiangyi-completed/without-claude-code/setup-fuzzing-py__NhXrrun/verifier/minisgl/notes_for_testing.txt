# MiniSGL Library - Fuzz Testing Notes

## Library Overview
Mini-SGLang is a lightweight LLM inference framework providing OpenAI-compatible API,
tokenization, detokenization, and inference scheduling.

## Critical Functions for Fuzz Testing

### TIER 1 - CRITICAL (API & Request Handling)

1. generate(req: GenerateRequest) - Text generation endpoint
   - Module: minisgl.server.api_server.generate
   - Input: GenerateRequest (prompt: str, max_tokens: int, ignore_eos: bool)
   - Fuzz: Prompt strings, parameter boundaries

2. v1_completions(req: OpenAICompletionRequest) - OpenAI-compatible endpoint
   - Module: minisgl.server.api_server.v1_completions
   - Input: Complex Pydantic model with prompt, messages, temperature, top_k, top_p, stop sequences
   - Fuzz: All parameter combinations, edge values

3. deserialize_type(cls_map, data) - Message deserialization
   - Module: minisgl.message.utils.deserialize_type
   - Input: JSON dictionary with __type__ field
   - Security risk: Type name lookup in cls_map
   - Fuzz: Invalid type names, malformed data, type confusion

### TIER 2 - HIGH PRIORITY (Tokenization)

4. TokenizeManager.tokenize(msgs: List[TokenizeMsg]) - Text tokenization
   - Module: minisgl.tokenizer.tokenize.TokenizeManager.tokenize
   - Input: List of TokenizeMsg (text: str or List[Dict])
   - Fuzz: Long strings, Unicode, malformed chat templates

5. DetokenizeManager.detokenize(msgs: List[DetokenizeMsg]) - Token to text
   - Module: minisgl.tokenizer.detokenize.DetokenizeManager.detokenize
   - Input: DetokenizeMsg (next_token: int, finished: bool, uid: int)
   - Fuzz: Token ID boundaries, invalid IDs

6. SamplingParams validation - Parameter validation
   - Module: minisgl.core.SamplingParams
   - Fields: temperature, top_k, top_p, ignore_eos, max_tokens
   - Fuzz: Boundary values, negative values, extreme floats

### TIER 3 - MEDIUM PRIORITY (Configuration & Kernels)

7. parse_args(args, run_shell) - Argument parsing
   - Module: minisgl.server.args.parse_args
   - Input: Command-line arguments list
   - Fuzz: Invalid paths, out-of-range numbers, invalid dtype strings

8. indexing(weights, indices, output, vocab_range) - Token indexing
   - Module: minisgl.kernel.index.indexing
   - Input: Tensors (weights, indices)
   - Fuzz: Out-of-bounds indices, shape mismatches

9. store_cache(k_cache, v_cache, indices, k, v) - Cache operations
   - Module: minisgl.kernel.store.store_cache
   - Input: Multiple tensors with shape requirements
   - Fuzz: Shape inconsistencies

10. Scheduler._process_one_msg(msg) - Message processing
    - Module: minisgl.scheduler.scheduler.Scheduler._process_one_msg
    - Input: Backend message
    - Fuzz: Invalid message types, malformed UIDs

## Key Input Categories for Fuzzing

### API Inputs:
- Prompt strings (various lengths, Unicode, special chars)
- Message arrays for chat (malformed structures)
- Numeric parameters (negative, zero, extreme values)
- Boolean flags
- Stop sequences

### Tokenization:
- Empty strings
- Very long strings
- Unicode/CJK characters
- Malformed chat message structures
- Invalid token IDs

### Configuration:
- Model paths (path traversal)
- Data type strings
- Port numbers
- Memory ratios

## Edge Cases to Focus On:
- Empty prompts
- Very long prompts (memory exhaustion)
- Unicode edge cases
- Negative max_tokens
- Temperature = 0 vs very small values
- top_k = -1 (disabled) vs 0
- top_p = 0 or > 1
- Invalid model names
- Malformed JSON in requests
- Token ID at vocabulary boundaries
