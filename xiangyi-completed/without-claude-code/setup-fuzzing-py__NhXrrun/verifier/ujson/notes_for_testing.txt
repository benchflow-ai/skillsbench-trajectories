# UltraJSON (ujson) Library - Fuzz Testing Notes

## Library Overview
UltraJSON is an ultra-fast JSON encoder and decoder written in C with Python bindings.
It handles JSON serialization and deserialization with various encoding/decoding options.

## Critical Functions for Fuzz Testing

### TIER 1 - CRITICAL (Primary API)

1. ujson.decode() / ujson.loads() - JSON parsing
   - Input: str, bytes, bytearray (JSON data)
   - Fuzz: Malformed JSON, edge cases, invalid UTF-8
   - HIGHEST PRIORITY - parser vulnerabilities

2. ujson.encode() / ujson.dumps() - JSON encoding
   - Input: Any Python object
   - Parameters:
     - ensure_ascii (bool): ASCII output with \uXXXX escapes
     - encode_html_chars (bool): Encode <, >, & as unicode
     - escape_forward_slashes (bool): Escape / as \/
     - sort_keys (bool): Sort dict keys
     - indent (int): Indentation spaces (0-65536+)
     - allow_nan (bool): Allow NaN/Infinity
     - reject_bytes (bool): Reject bytes objects
     - default (callable): Custom handler
     - separators (tuple): Custom separators
   - Fuzz: All parameter combinations, edge objects

### TIER 2 - HIGH PRIORITY (File I/O)

3. ujson.load(fp) - Read and decode from file
   - Input: File-like object with read() method
   - Fuzz: File I/O errors, large files

4. ujson.dump(obj, fp) - Encode and write to file
   - Input: Object + file-like object with write() method
   - Fuzz: File I/O errors, object edge cases

## Key Input Categories for Fuzzing

### For decode()/loads():
- Empty strings, single characters
- Incomplete JSON: [, {, "abc, {key:
- Invalid JSON: gibberish, wrong syntax, trailing commas
- Numbers: exponentials (1e40, 1e-40), very large (>2^64)
- Strings: empty, with escapes, with nulls, with surrogates
- Deeply nested: [[[[...]]]], {a:{b:{c:{...}}}}
- Unicode: various UTF-8 sequences, invalid sequences
- Special values: NaN, Infinity, -Infinity
- Whitespace: leading, trailing, internal placement

### For encode()/dumps():
- All Python types: int, float, str, bytes, bool, None, list, dict
- Large collections: lists with many items, deeply nested dicts
- Custom objects with __json__() or toDict()
- Objects with exception-raising methods
- Extreme integers and floats (denormalized)
- Unicode strings with all UTF-8 ranges
- All combinations of boolean flags
- Edge case indent values (0, 1, 65536+)
- Custom separators with edge cases

## Edge Cases to Focus On:
- Deeply nested objects (max recursion ~1024)
- Circular references (stack overflow potential)
- Large buffer allocations
- Unicode/surrogate pair handling
- Very large integers (precision loss)
- NaN, Infinity, -Infinity
- Invalid UTF-8 sequences
- Unterminated strings/arrays/objects
- Trailing data after valid JSON
- Integer overflow scenarios
- Memory pressure scenarios

## Potential Vulnerabilities:
- Buffer overflows in C code
- Stack overflow with deep nesting
- Memory leaks
- Reference counting bugs
- Integer overflow in size calculations
- Invalid memory access with malformed input
