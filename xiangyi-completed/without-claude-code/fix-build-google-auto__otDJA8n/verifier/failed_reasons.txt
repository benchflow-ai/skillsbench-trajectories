   Error: Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar

ROOT CAUSE:
-----------

The project uses compile-testing library (versions 0.6, 0.7, 0.8) which have a system-scoped dependency on com.sun:tools JAR.

In JDK 8 and earlier:
- tools.jar contained the Java compiler API
- Located at ${java.home}/../lib/tools.jar

Starting with JDK 9:
- tools.jar was removed as compiler classes were integrated into the main JDK modules
- The functionality is now part of jrt-fs.jar at ${java.home}/lib/jrt-fs.jar

The parent pom.xml (version 3 and 4-SNAPSHOT) and compile-testing library POMs all have Maven profiles with:
- activeByDefault=true for the default-profile
- File existence checks that don't prevent activation
- No JDK 9+ support

With JDK 11, the default-profile activates even though tools.jar doesn't exist, causing the build to fail when Maven tries to resolve the system-scoped dependency.

SOLUTION IMPLEMENTED:
---------------------

Modified the Maven profiles in multiple POM files to use JDK version-based activation instead of file existence checks:

1. Changed default-profile and mac-profile to only activate on JDK < 9 using <jdk>(,9)</jdk>
2. Added new jdk9-plus-profile that activates on JDK 9+ using <jdk>[9,)</jdk>
3. Set toolsjar property to ${java.home}/lib/jrt-fs.jar for JDK 9+
