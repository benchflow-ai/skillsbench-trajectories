LIBRARY OVERVIEW
--------------------------------------------------------------------------------
Black is "the uncompromising code formatter" for Python. It takes Python source
code as input and reformats it according to a consistent style. The library:

- Parses Python source code using a modified lib2to3 parser (blib2to3)
- Builds an abstract syntax tree (AST) representation
- Reformats the code according to Black's style rules
- Optionally validates that the reformatted code is semantically equivalent

Version: Requires Python >= 3.10
License: MIT

--------------------------------------------------------------------------------
DIRECTORY STRUCTURE
--------------------------------------------------------------------------------

/app/black/src/black/           - Main Black formatting library
/app/black/src/blib2to3/        - Modified lib2to3 parser (Python grammar parsing)
/app/black/src/blib2to3/pgen2/  - Parser generator modules (tokenizer, parser)
/app/black/src/blackd/          - HTTP daemon for Black (aiohttp-based server)
/app/black/scripts/             - Utility scripts including existing fuzz.py
/app/black/tests/               - Test suite

--------------------------------------------------------------------------------
KEY MODULES AND THEIR PURPOSES
--------------------------------------------------------------------------------

CORE FORMATTING (src/black/):

__init__.py     - Main entry point. Contains format_str(), format_file_contents(),
                  lib2to3_parse() wrapper, and CLI main() function.

parsing.py      - AST parsing and validation. Contains lib2to3_parse(),
                  parse_ast(), stringify_ast() for AST comparison.

mode.py         - Configuration dataclasses: Mode, TargetVersion, Feature, Preview.
                  Defines formatting options and Python version features.

linegen.py      - Line generation from AST nodes (LineGenerator class).

lines.py        - Line representation and empty line tracking (EmptyLineTracker).

strings.py      - String literal processing: quote normalization, escape sequences,
                  f-string handling, unicode escape normalization.

trans.py        - String transformations (more complex string processing).

nodes.py        - AST node utilities and symbol definitions.

comments.py     - Comment handling and normalization (normalize_fmt_off).

brackets.py     - Bracket matching and depth tracking.

ranges.py       - Line range handling for partial formatting.

handle_ipynb_magics.py - Jupyter notebook magic command handling.


PARSER (src/blib2to3/):

pgen2/driver.py     - High-level parser driver (Driver class).
pgen2/parse.py      - Core parser engine (Parser class, ParseError).
pgen2/tokenize.py   - Tokenizer using pytokens library.
pgen2/grammar.py    - Grammar representation.
pgen2/token.py      - Token type definitions.
pytree.py           - Parse tree node classes (Node, Leaf).
pygram.py           - Python grammar definitions.

================================================================================
IMPORTANT FUNCTIONS TO FUZZ
================================================================================

The following functions are prime targets for fuzz testing as they directly
process external/untrusted input (Python source code strings).

--------------------------------------------------------------------------------
1. format_str() - PRIMARY FUZZ TARGET
--------------------------------------------------------------------------------
Location: /app/black/src/black/__init__.py

Signature:
    def format_str(
        src_contents: str,
        *,
        mode: Mode,
        lines: Collection[tuple[int, int]] = ()
    ) -> str

Description:
    Main public API for formatting Python code as a string. This is the most
    important function to fuzz as it's the primary entry point.

Example:
    >>> import black
    >>> black.format_str("def f(arg:str='')->None:...", mode=black.Mode())
    'def f(arg: str = "") -> None:\n    ...\n'

Fuzz Strategy:
    - Generate random syntactically-valid Python code
    - Vary Mode parameters (line_length, target_versions, preview, etc.)
    - Test with edge cases: empty strings, unicode, very long lines

--------------------------------------------------------------------------------
2. lib2to3_parse() - PARSER FUZZ TARGET
--------------------------------------------------------------------------------
Location: /app/black/src/black/parsing.py

Signature:
    def lib2to3_parse(
        src_txt: str,
        target_versions: Collection[TargetVersion] = ()
    ) -> Node

Description:
    Parses Python source code into a lib2to3 syntax tree. This is the core
    parsing function that processes raw input. Raises InvalidInput on failure.

Fuzz Strategy:
    - Test with malformed Python code
    - Test boundary conditions in grammar parsing
    - Test with various Python version target combinations

--------------------------------------------------------------------------------
3. parse_ast() - STANDARD LIBRARY AST PARSING
--------------------------------------------------------------------------------
Location: /app/black/src/black/parsing.py

Signature:
    def parse_ast(src: str) -> ast.AST

Description:
    Parses source using Python's built-in ast.parse with multiple version
    attempts and type comment handling.

Fuzz Strategy:
    - Test with code that has type comments
    - Test syntax that differs across Python versions

--------------------------------------------------------------------------------
4. format_file_contents() - FILE CONTENT FORMATTING
--------------------------------------------------------------------------------
Location: /app/black/src/black/__init__.py

Description:

Fuzz Strategy:

Fuzz Strategy:
    - Test with code that has subtle AST differences
    - Look for cases where formatting changes semantics (bugs)

================================================================================
EXISTING FUZZ INFRASTRUCTURE
================================================================================

Black already has fuzzing support in /app/black/scripts/fuzz.py:

- Uses Hypothesis with hypothesmith for property-based testing
- Generates syntactically-valid Python code
- Tests format_str() with various Mode configurations
- Verifies idempotence (formatting twice gives same result)
- Verifies semantic equivalence (AST unchanged)
- Supports Atheris for coverage-guided fuzzing

The existing fuzz test can be run with:
    python scripts/fuzz.py        # Basic testing
    pytest scripts/fuzz.py        # Using pytest
    # With Atheris for coverage-guided fuzzing (if installed)

================================================================================
RECOMMENDED FUZZING STRATEGIES
================================================================================

1. SYNTACTIC FUZZING (Primary):
   - Use hypothesmith to generate valid Python source
   - Verify format_str() doesn't crash
   - Verify output is valid Python (can be compiled)
   - Verify output is idempotent (format(format(x)) == format(x))
   - Verify AST equivalence (semantics preserved)

2. MUTATION FUZZING:
   - Take valid Python code and mutate characters
   - Test error handling in parser (InvalidInput should be raised cleanly)
   - Look for hangs or crashes on malformed input

3. BOUNDARY TESTING:
   - Very long lines (test line_length handling)
   - Deeply nested structures (brackets, functions, classes)
   - Unicode edge cases (emoji, RTL, zero-width chars)
   - Empty input, whitespace-only input

4. ENCODING FUZZING:
   - Test decode_bytes() with various byte sequences
   - Mixed encodings, invalid UTF-8 sequences
   - Different BOM markers

5. JUPYTER NOTEBOOK FUZZING:
   - Malformed JSON structures
   - Non-Python cells
   - IPython magic variations
   - Mixed content types

6. MODE VARIATION:
   - Test all combinations of Mode flags
   - Different target_versions combinations
   - Preview features enabled/disabled

================================================================================
CRASH/HANG SENSITIVE AREAS
================================================================================

Based on code analysis, pay special attention to:

1. Parser backtracking (parse.py Recorder class) - can be slow on ambiguous input
2. String processing in trans.py - complex regex operations
3. F-string parsing - nested f-strings can be complex
4. Very long lines - memory and performance issues
5. Deeply nested structures - stack depth issues
6. Invalid escape sequences in strings
