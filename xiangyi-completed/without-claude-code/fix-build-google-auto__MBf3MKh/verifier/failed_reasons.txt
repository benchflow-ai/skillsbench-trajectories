BUILD ERROR ANALYSIS FOR GOOGLE AUTO PROJECT
==============================================

REPOSITORY: /home/travis/build/failed/google/auto
ERROR TYPE: Dependency Resolution Failure

ISSUE SUMMARY:
The build fails with: "Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

ROOT CAUSE:
The build depends on com.google.testing.compile:compile-testing:0.7, which has a hard dependency on com.sun:tools with system scope and systemPath=${toolsjar}.

The compile-testing library and the parent POMs define profiles that set ${toolsjar} based on whether tools.jar exists at the traditional Java 6-8 locations:
- ${java.home}/../lib/tools.jar (default-profile, Linux)
- ${java.home}/../Classes/classes.jar (mac-profile, macOS)

In Java 9+, the JDK structure changed fundamentally. The tools.jar file no longer exists at these locations. Instead, the compiler tools are built-in modules. The build fails because:
1. The "default-profile" profile check fails to find ${java.home}/../lib/tools.jar
2. The "mac-profile" check also fails
3. Without a matching profile, ${toolsjar} remains undefined
4. Maven tries to resolve com.sun:tools at ${java.home}/../lib/tools.jar (literally the string, not expanded)
5. The artifact cannot be found, causing the build to fail

AFFECTED MODULES:
- common (auto-common) - depends on compile-testing:0.7
- factory (auto-factory) - depends on compile-testing:0.8
- value (auto-value) - depends on compile-testing:0.6
- service (auto-service) - likely depends on compile-testing

DEPENDENCY CHAIN:
com.google.testing.compile:compile-testing:0.7 -> com.sun:tools:${java.version}:system:${toolsjar}

MAVEN CONFIGURATION ISSUE:
The profiles are designed for Java 6-8. On Java 9+, neither profile activation condition is met, leaving ${toolsjar} undefined.

SOLUTION APPLIED:

PRIMARY FIX - Exclude Tools Dependency:
1. Excluded com.sun:tools dependency from all test dependencies that transitively include it
   - Applied to common/pom.xml, factory/pom.xml, service/pom.xml, value/pom.xml
   - This prevents Maven from trying to resolve the Java 6-8 system dependency
   - Ensures compile-testing works without requiring system tools.jar

SECONDARY FIXES - Java 9+ Compatibility:
1. Added Java 9+ compatible profiles to parent pom (java9-profile and no-tools-jar)
   - Sets ${toolsjar} property to empty value for Java 9+
   - Provides fallback in case other dependencies also try to use tools.jar

2. Updated all child modules to use parent version 4-SNAPSHOT (instead of version 3)
   - Ensures they use the patched parent pom with Java 9+ profiles
   - Modules updated: common, factory, service, value

3. Added javax.annotation:javax.annotation-api dependency
   - Required by factory and value modules that use @Generated annotation
   - In Java 9+, javax.annotation.Generated is no longer part of the standard library
   - Must be explicitly added as a dependency (version 1.3.2)

BUILD RESULT:
All patches have been successfully applied. The build now succeeds completely on Java 11.
