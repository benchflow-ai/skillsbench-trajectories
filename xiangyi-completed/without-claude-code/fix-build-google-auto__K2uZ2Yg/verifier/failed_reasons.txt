BUILD FAILURE ANALYSIS
======================

Repository: /home/travis/build/failed/google/auto
Build System: Maven
Java Version: 11.0.27 (openjdk)

ERROR SUMMARY
-------------
The build fails in the 'common' module with the following error:
"Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

ROOT CAUSE
----------
1. The common/pom.xml references parent version 3:
   - <artifactId>auto-parent</artifactId>
   - <version>3</version>

2. auto-parent version 3 was built locally and installed in ~/.m2/repository/com/google/auto/auto-parent/3/
   This version includes profiles that define a 'toolsjar' property pointing to tools.jar

3. The toolsjar property points to ${java.home}/../lib/tools.jar, which exists in Java 8 and earlier
   but was removed in Java 9+. The current environment uses Java 11, where tools.jar no longer exists.

4. The auto-parent version 3 POM has these profiles:
   - default-profile: Sets toolsjar to ${java.home}/../lib/tools.jar (activated by default if file exists)
   - mac-profile: Sets toolsjar to ${java.home}/../Classes/classes.jar (for Mac)

5. Since tools.jar doesn't exist in Java 11, Maven cannot resolve the dependency and the build fails.

ADDITIONAL CONTEXT
------------------
- The current repository HEAD has auto-parent version 4-SNAPSHOT in pom.xml
- Git history shows commit 50b4910 removed the toolsjar property with message:
  "Remove the unused toolsjar property"
- However, the common module still references parent version 3, creating a mismatch
- Auto-parent version 3 was never officially tagged in git (only versions 2, 4, 5, 6 exist as tags)
- Version 3 appears to have been created by a previous local build

SOLUTION
--------
The fix requires THREE changes:

1. Update common/pom.xml to reference auto-parent version 4-SNAPSHOT instead of version 3.
   This ensures common module uses the current parent POM.

2. Remove the toolsjar profiles from pom.xml (auto-parent 4-SNAPSHOT).
   These profiles define the toolsjar property that points to the non-existent tools.jar file.
   As noted in git commit 50b4910, the toolsjar property is unused and should be removed.

   The profiles to remove are:
   - default-profile: Activates when ${java.home}/../lib/tools.jar exists
   - mac-profile: Activates when ${java.home}/../Classes/classes.jar exists

3. Exclude the com.sun:tools dependency from com.google.testing.compile:compile-testing
   in common/pom.xml (and other modules: factory, service, value).

   The compile-testing library version 0.7 has a system-scoped dependency on tools.jar
   which is not needed in Java 9+ and causes the build to fail. By adding an exclusion:

   <exclusions>
     <exclusion>
       <groupId>com.sun</groupId>
       <artifactId>tools</artifactId>
     </exclusion>
   </exclusions>

   The build can proceed without attempting to resolve the tools.jar dependency.

After applying these changes, the common module builds successfully on Java 11.

Alternative solutions considered but not recommended:
1. Keep the old profiles and add Java 11+ profile (overly complex)
2. Downgrade to Java 8 (not a proper fix for compatibility)
3. Create dummy tools.jar (hacky workaround)
4. Upgrade compile-testing to a newer version (would require more extensive testing)
