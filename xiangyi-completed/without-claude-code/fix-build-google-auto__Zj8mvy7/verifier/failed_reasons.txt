BUILD FAILURE ANALYSIS FOR google/auto
==========================================

Repository Location: /home/travis/build/failed/google/auto/

Build Command Used:
  mvn -B -U -f build-pom.xml verify --fail-at-end -Dsource.skip=true -Dmaven.javadoc.skip=true

Java Version:
  OpenJDK 11.0.27

ROOT CAUSE:
-----------
The build fails because three modules (auto-common, auto-factory, auto-service) depend on
com.google.testing.compile:compile-testing library which has a transitive dependency on
com.sun:tools:jar. This dependency references the tools.jar file which was part of JDK 8
and earlier but was removed in Java 9+.

AFFECTED MODULES AND DEPENDENCIES:
-----------------------------------
1. auto-common (common/pom.xml)
   - Uses compile-testing version 0.7

2. auto-factory (factory/pom.xml)
   - Uses compile-testing version 0.8

3. auto-service (service/pom.xml)
   - Uses compile-testing version 0.6

SOLUTION:
---------
The compile-testing library versions 0.6, 0.7, and 0.8 are incompatible with Java 9+.
We need to upgrade to a newer version of compile-testing that supports Java 9+.

According to the compile-testing project history, version 0.9+ removed the dependency
on tools.jar and became compatible with Java 9+.

PROPOSED FIXES:
---------------
1. Update auto-common/pom.xml:
   - Change compile-testing version from 0.7 to 0.15
   - Change truth version from 0.25 to 0.37

2. Update auto-factory/pom.xml:
   - Change compile-testing version from 0.8 to 0.15
   - Change truth version from 0.25 to 0.37
   - Add javax.annotation-api dependency version 1.3.2

3. Update auto-service/pom.xml:
   - Change compile-testing version from 0.6 to 0.15
   - Change truth version from 0.24 to 0.37

4. Update auto-value/pom.xml:
   - Change compile-testing version from 0.6 to 0.15
   - Change truth version from 0.25 to 0.37

Version 0.15 is chosen for compile-testing because it no longer depends on tools.jar
and is compatible with Java 9+. Truth version 0.37 is required for API compatibility
with compile-testing 0.15.

The javax.annotation-api dependency is needed for auto-factory because the
javax.annotation.Generated class was removed from the JDK in Java 9 and moved
to a separate module.
