BUILD FAILURE ANALYSIS
======================

Repository: /home/travis/build/failed/google/auto
Build Command: mvn -f build-pom.xml clean compile

ERROR DESCRIPTION:
------------------
The build fails with the following error:
"Could not resolve dependencies for project com.google.auto:auto-common:jar:1.0-SNAPSHOT:
Could not find artifact com.sun:tools:jar:11.0.27 at specified path
/usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

ROOT CAUSE:
-----------
1. The compile-testing:0.7 dependency (used by auto-common module) declares a system-scoped
   dependency on com.sun:tools:jar with systemPath=${toolsjar}

2. The toolsjar property is defined in Maven profiles in both:
   - auto-parent POM (version 3 and 4-SNAPSHOT)
   - compile-testing POM

3. These profiles are activated based on the existence of tools.jar file:
   - default-profile: checks ${java.home}/../lib/tools.jar
   - mac-profile: checks ${java.home}/../Classes/classes.jar

4. PROBLEM: In JDK 9+, tools.jar was removed and its classes were integrated into the JDK
   modules. The current environment uses OpenJDK 11.0.27, which does not have tools.jar.

5. Since the profile activation condition fails (file doesn't exist), the toolsjar property
   is not set properly, causing Maven to use ${java.version} literal value (11.0.27) instead.

SOLUTION:
---------
Add a new profile for JDK 9+ that doesn't rely on tools.jar. For Java 9+, the tools.jar
classes are already available on the classpath, so we need to:

1. Update auto-parent pom.xml (version 4-SNAPSHOT) to add a JDK 9+ profile that sets
   toolsjar to a dummy/non-existent path or handles it appropriately

2. Alternative: Since tools.jar is not needed for JDK 9+, we could make the compile-testing
   dependency scope 'provided' and add conditional profile, but we cannot modify external
   dependencies. Instead, we need to override the toolsjar property for JDK 9+.

IMPLEMENTATION PLAN:
--------------------
Modify /home/travis/build/failed/google/auto/pom.xml to add a JDK 9+ compatible profile
that sets the toolsjar property to point to the JDK itself or to bypass the requirement.

For JDK 9+, we'll add a profile that activates when JDK version is 9 or higher and sets
toolsjar to ${java.home}/lib/rt.jar (which also doesn't exist but won't matter) or better
yet, we can exclude the tools dependency or use a different approach.

ACTUAL FIX:
-----------
Add a JDK 9+ profile that properly handles the missing tools.jar by setting an appropriate
fallback. Since the tools classes are in the JDK for Java 9+, we can point to the jrt-fs.jar
which is present in JDK 11.
