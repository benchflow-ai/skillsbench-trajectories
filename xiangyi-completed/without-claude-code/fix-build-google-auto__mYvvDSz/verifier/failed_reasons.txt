BUILD ERROR ANALYSIS
====================

Repository: google/auto
Issue: Build failure when compiling the auto-common module

ROOT CAUSES IDENTIFIED:

1. TOOLS.JAR DEPENDENCY ISSUE IN TRANSITIVE DEPENDENCIES
   - The compile-testing 0.7 POM dependency includes com.sun:tools as a system-scoped dependency
   - This dependency requires ${toolsjar} which is set via a profile
   - With Java 11, tools.jar was removed from the standard JDK distribution
   - The tools.jar file is expected at: /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
   - This file does not exist, causing Maven to fail when resolving the tools.jar dependency
   - compile-testing itself also has the same profile issue that we need to fix

2. PARENT VERSION MISMATCH
   - The child modules (common, factory, service, value) specify parent version "3"
   - The root pom.xml is version "4-SNAPSHOT"
   - This causes Maven to fetch parent:3 from remote which includes the same tools.jar profile issue
   - Aligning to version 4-SNAPSHOT ensures the local parent with the fix is used

ERROR MESSAGE:
   "Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

SOLUTION:
   1. Fix the auto-parent pom.xml profile to detect Java 9+ and use an empty toolsjar property
   2. Update all child modules to reference parent version 4-SNAPSHOT
   3. Make the tools.jar dependency in compile-testing optional by excluding it
