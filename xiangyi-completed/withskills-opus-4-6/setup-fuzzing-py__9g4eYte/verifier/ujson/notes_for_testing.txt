Top Fuzzing Targets for ujson
=============================

Target: ujson.loads
File: /app/ujson/src/ujson/python/JSONtoObj.c -> /app/ujson/src/ujson/lib/ultrajsondec.c
Import: import ujson
Why: Primary untrusted input parser. Parses arbitrary JSON strings/bytes through C extension code with manual memory management, UTF-8 validation, unicode escape handling, and numeric overflow logic. Highest risk for memory corruption and crashes. No existing fuzz coverage for this function.
Input type: str, bytes, bytearray
Example usage: ujson.loads('{"key": [1, 2.5, "hello", null, true]}')

Target: ujson.loads (bytes input)
File: /app/ujson/src/ujson/python/JSONtoObj.c -> /app/ujson/src/ujson/lib/ultrajsondec.c
Import: import ujson
Why: Same decoder but exercises the bytes/buffer protocol path in JSONToObj(), which handles C-contiguous buffer extraction. Malformed UTF-8 byte sequences can reach the C decoder directly without Python's unicode validation, making this an especially valuable attack surface for memory safety issues.
Input type: bytes, bytearray
Example usage: ujson.loads(b'{"key": "value", "num": 12345}')

Target: ujson.dumps
File: /app/ujson/src/ujson/python/objToJSON.c -> /app/ujson/src/ujson/lib/ultrajsonenc.c
Import: import ujson
Why: Encodes Python objects to JSON via C extension with complex buffer management (Buffer_Realloc, RESERVE_STRING), UTF-8 string escaping (both validated and unvalidated paths), and recursive object traversal. Long strings, deep nesting, and special characters stress buffer allocation logic.
Input type: dict, list, str, int, float, bool, None (and nested combinations)
Example usage: ujson.dumps({"key": "value\x00\ud800", "nums": [1, 2.5, -9223372036854775808]})

Target: ujson.dumps (with options)
File: /app/ujson/src/ujson/python/objToJSON.c -> /app/ujson/src/ujson/lib/ultrajsonenc.c
Import: import ujson
Why: Different option combinations activate different code paths in the encoder: ensure_ascii toggles between Buffer_EscapeStringValidated and Buffer_EscapeStringUnvalidated; encode_html_chars changes escape behavior for <>&; indent changes buffer reservation calculations; sort_keys activates SortedDict_iterNext; separators changes separator strings. Fuzzing option combinations with adversarial input maximizes code coverage.
Input type: dict/list + keyword arguments (ensure_ascii, encode_html_chars, escape_forward_slashes, sort_keys, indent, separators)
Example usage: ujson.dumps({"a": "<script>&</script>"}, ensure_ascii=False, encode_html_chars=True, indent=4, sort_keys=True, separators=(", ", ": "))

Target: ujson.loads/ujson.dumps round-trip
File: /app/ujson/src/ujson/python/JSONtoObj.c, /app/ujson/src/ujson/python/objToJSON.c
Import: import ujson
Why: Round-trip testing catches inconsistencies between encoder output and decoder expectations. The encoder may produce edge-case output (e.g., surrogate pairs, extreme floats, very large integers) that the decoder fails to re-parse correctly, revealing bugs in either direction.
Input type: str (valid or near-valid JSON)
Example usage: result = ujson.dumps(ujson.loads('{"a": 1e308, "b": "\\uD83D\\uDCA9"}'))
