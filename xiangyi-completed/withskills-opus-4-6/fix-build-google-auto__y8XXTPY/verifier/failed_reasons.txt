BUILD FAILURE ANALYSIS
=====================

Repository: google/auto
Location: /home/travis/build/failed/google/auto/
Build System: Maven (multi-module via build-pom.xml)
Java Version in Environment: OpenJDK 11.0.27
Java Version Expected by Project: JDK 7 (oraclejdk7/openjdk7 per .travis.yml)

FAILING MODULES
===============
1. auto-common (common/)
2. auto-factory (factory/)
3. auto-service (service/)
4. auto-value (value/) - not reached due to earlier failures, but has the same issue

ROOT CAUSE
==========
All four modules depend on com.google.testing.compile:compile-testing (various
versions: 0.6, 0.7, 0.8) as a test dependency. Each version of compile-testing
declares a system-scoped dependency on com.sun:tools with:

    <groupId>com.sun</groupId>
    <artifactId>tools</artifactId>
    <version>${java.version}</version>
    <scope>system</scope>
    <systemPath>${toolsjar}</systemPath>

The ${toolsjar} property resolves via parent POM profiles to:
  - ${java.home}/../lib/tools.jar  (default-profile)
  - ${java.home}/../Classes/classes.jar  (mac-profile)

On Java 11, tools.jar was removed (the javax.annotation.processing and
javax.lang.model APIs are part of the java.compiler module). The file
/usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar does not exist, causing
Maven dependency resolution to fail immediately with:

    Could not find artifact com.sun:tools:jar:11.0.27 at specified path
    /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar

This prevents any compilation, testing, or packaging from occurring.

FIX PLAN
========
For each of the 4 module POMs (common/pom.xml, factory/pom.xml,
service/pom.xml, value/pom.xml), add an exclusion for com.sun:tools from
the compile-testing dependency:

    <dependency>
      <groupId>com.google.testing.compile</groupId>
      <artifactId>compile-testing</artifactId>
      <version>...</version>
      <scope>test</scope>
      <exclusions>
        <exclusion>
          <groupId>com.sun</groupId>
          <artifactId>tools</artifactId>
        </exclusion>
      </exclusions>
    </dependency>

On Java 11, the classes formerly in tools.jar are part of the JDK modules
(java.compiler, jdk.compiler), so the exclusion is safe and the code will
compile correctly.

Additionally, update the parent POM's java.version property from 1.6 to 1.8,
since Java 11 does not support source/target level 1.6.
