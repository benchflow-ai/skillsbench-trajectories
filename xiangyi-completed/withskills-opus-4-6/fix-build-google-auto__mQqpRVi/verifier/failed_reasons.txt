BUILD FAILURE ANALYSIS: google/auto

ROOT CAUSES OF BUILD FAILURE
=============================

ERROR 1: Missing tools.jar (com.sun:tools system dependency)
-------------------------------------------------------------
Module(s) affected: ALL modules (via compile-testing transitive dependency)
Error message: "Could not find artifact com.sun:tools:jar:11.0.27 at specified
  path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

Cause: The compile-testing library (versions 0.6, 0.7, 0.8 used across modules)
declares a system-scoped dependency on com.sun:tools with systemPath pointing to
${java.home}/../lib/tools.jar. On Java 9+, tools.jar no longer exists as a
separate file (its classes are part of the JDK modules). Additionally, only JRE
(not JDK) is installed, so the path resolves to /usr/lib/jvm/lib/tools.jar which
does not exist.

Fix: Copy tools.jar from the existing Java 8 Oracle JDK installation at
/usr/lib/jvm/java-8-oracle/lib/tools.jar to /usr/lib/jvm/lib/tools.jar.
This satisfies the system dependency resolution. (Already applied during analysis.)

ERROR 2: javax.annotation.Generated not found (Java 9+ removal)
-----------------------------------------------------------------
Module(s) affected: factory, value
Error message: "cannot find symbol - class Generated - location: package
  javax.annotation"

Files with compilation errors (main sources only):
  1. factory/src/main/java/com/google/auto/factory/processor/FactoryWriter.java:39
     - import javax.annotation.Generated;
     - Used at line 60 (emitImports) and line 85 (Generated.class annotation)

  2. value/src/main/java/com/google/auto/value/processor/AutoValueProcessor.java:51
     - import javax.annotation.Generated;
     - Used at line 457: Generated.class.getName() to get the string
       "javax.annotation.Generated" for getTypeElement lookup

  3. value/src/main/java/com/google/auto/value/processor/AutoAnnotationProcessor.java:36
     - import javax.annotation.Generated;
     - Used at lines 169, 375: Generated.class to get TypeMirror

Cause: javax.annotation.Generated was deprecated in Java 9, and the module
java.xml.ws.annotation that contained it was removed in Java 11 (JEP 320).
The replacement is javax.annotation.processing.Generated (available since Java 9).
Since this project targets Java 1.6 source, the Java 9+ class is not available.

Fix: Replace the static import and class references with string-based lookups.
Instead of importing javax.annotation.Generated and using Generated.class, use
the fully qualified class name as a string constant and resolve it dynamically.
This approach is already partially used in AutoValueProcessor (which has a null
check for the type element). The fix needs to:
  - Remove the import of javax.annotation.Generated
  - Use string constant "javax.annotation.Generated" directly
  - For FactoryWriter: use the string directly in emitImports and emitAnnotation
  - For AutoValueProcessor: use string constant instead of Generated.class.getName()
  - For AutoAnnotationProcessor: use string-based type element lookup

  - service (auto-service) - compiles with same warnings
