1.1  black.format_str()
     File: /app/black/src/black/__init__.py (line 1177)
------------------------------------------------------------------------------

Signature:
    def format_str(
        src_contents: str,
        *,
        mode: Mode,
        lines: Collection[tuple[int, int]] = ()
    ) -> str

WHY THIS IS THE #1 FUZZ TARGET:
  - This is THE primary public API entry point for formatting Python source
    code as a string. It is the function used by all integrations, editor
    plugins, and programmatic callers.
  - It accepts arbitrary user-provided source code strings.
  - Internally it calls lib2to3_parse(), LineGenerator, transform_line(),
    and all the formatting machinery. A single call exercises a huge portion
    of the codebase.
  - The existing scripts/fuzz.py (Hypothesis-based fuzzer) already targets
    this function, confirming it is the right entry point.

INPUT TYPE: str (Python source code)

MINIMAL SETUP:
    import black
    mode = black.Mode()
    result = black.format_str(src_contents, mode=mode)

ACCEPTABLE EXCEPTIONS:
  - black.parsing.InvalidInput  -- raised for unparseable Python source
  - black.report.NothingChanged -- raised when output == input
  - IndentationError            -- from tokenizer on malformed indentation
  - TokenError                  -- from tokenizer on incomplete tokens

SUSPICIOUS / BUG-INDICATING EXCEPTIONS:
  - AssertionError              -- internal consistency violation
  - ASTSafetyError              -- formatted code is not AST-equivalent to input
  - IndexError, KeyError, AttributeError, TypeError -- unexpected internal errors
  - RecursionError              -- possible infinite recursion in tree processing
  - Any segfault or memory error

MODE VARIATIONS TO FUZZ:
  - mode.line_length: integers from 0 to 200+ (edge cases at 0, 1, very large)
  - mode.target_versions: various sets of TargetVersion enums
  - mode.is_pyi: True/False
  - mode.string_normalization: True/False
  - mode.magic_trailing_comma: True/False
  - mode.preview: True/False
  - mode.unstable: True/False
  - mode.skip_source_first_line: True/False

WHY THIS IS A GOOD FUZZ TARGET:

    is not semantically equivalent will be detected.
  - Also handles Jupyter notebook formatting (format_ipynb_string) when

INPUT TYPE: str (Python source code or JSON notebook content)

MINIMAL SETUP:
    import black
    mode = black.Mode()
    try:
        result = black.format_file_contents(src, fast=False, mode=mode)
    except black.NothingChanged:
        pass

ACCEPTABLE EXCEPTIONS:
  - black.report.NothingChanged -- when source is already formatted
  - black.parsing.InvalidInput  -- unparseable source
  - json.decoder.JSONDecodeError -- when mode.is_ipynb and input is not valid JSON

SUSPICIOUS EXCEPTIONS:
  - black.parsing.ASTSafetyError -- formatted code differs semantically (BUG)
  - AssertionError from assert_stable -- formatting not idempotent (BUG)
  - Any crash/segfault

1.3  black.parsing.lib2to3_parse()
     File: /app/black/src/black/parsing.py (line 55)
------------------------------------------------------------------------------

Signature:
    def lib2to3_parse(
        src_txt: str,
        target_versions: Collection[TargetVersion] = ()
    ) -> Node

WHY THIS IS A GOOD FUZZ TARGET:
  - This is the core parser that converts Python source strings into the
    concrete syntax tree (CST) used throughout Black.
  - It uses blib2to3 (a fork of lib2to3) which has its own grammar-based
    parser and tokenizer.
  - Parser bugs (crashes, infinite loops, incorrect trees) can cause
    downstream formatting errors or crashes.
  - Exercises the pgen2 parser, tokenizer, and grammar matching.

INPUT TYPE: str (Python source code)

MINIMAL SETUP:
    from black.parsing import lib2to3_parse
    from black.mode import TargetVersion
    node = lib2to3_parse(src_txt, target_versions=set())

ACCEPTABLE EXCEPTIONS:
  - black.parsing.InvalidInput  -- unparseable source
  - blib2to3.pgen2.parse.ParseError -- grammar mismatch
  - blib2to3.pgen2.tokenize.TokenError -- tokenization failure

SUSPICIOUS EXCEPTIONS:
  - AssertionError, IndexError, KeyError -- parser internal errors
  - RecursionError -- deeply nested or pathological input
  - Any crash

Signature:
    def parse_ast(src: str) -> ast.AST

WHY THIS IS A GOOD FUZZ TARGET:

INPUT TYPE: str (Python source code)

ACCEPTABLE EXCEPTIONS:
  - SyntaxError -- invalid Python source

SUSPICIOUS EXCEPTIONS:
  - Any non-SyntaxError crash

Signature:
    def decode_bytes(src: bytes, mode: Mode) -> tuple[FileContent, Encoding, NewLine]

WHY THIS IS A GOOD FUZZ TARGET:

    mode = black.Mode()

ACCEPTABLE EXCEPTIONS:
  - SyntaxError -- from tokenize.detect_encoding on malformed encoding lines
  - UnicodeDecodeError -- when detected encoding cannot decode the bytes
  - LookupError -- unknown encoding name

SUSPICIOUS EXCEPTIONS:
  - Any crash without a clear encoding-related cause

================================================================================
3. FUZZING STRATEGY RECOMMENDATIONS
================================================================================

STRATEGY 1: Pure format_str (highest priority)
  - Generate random valid Python source (use Hypothesmith or mutations)
  - Call format_str() with random Mode configurations
  - Check: no crashes, output is valid Python, output is stable

STRATEGY 2: format_file_contents with fast=False (equivalence checking)
  - Same as Strategy 1 but with AST safety checks enabled
  - Catches semantic changes introduced by formatting

STRATEGY 3: Differential: lib2to3_parse vs ast.parse
  - Parse same source with both parsers
  - Check for consistency between what lib2to3 accepts and what ast accepts

STRATEGY 4: Round-trip bytes decoding
  - Generate random bytes (with valid/invalid encoding cookies)
  - Call decode_bytes() and verify correct encoding detection

STRATEGY 5: Notebook formatting
  - Generate JSON structures resembling Jupyter notebooks
  - Call format_ipynb_string()
  - Check for crashes and valid JSON output

STRATEGY 6: String normalization
  - Generate string literals with various prefixes, quotes, escapes
  - Call normalize_string_quotes() and verify correctness

EXISTING FUZZER REFERENCE:
  The project already has scripts/fuzz.py which uses Hypothesis +
  Hypothesmith to generate syntactically valid Python and test
  format_str() with random Mode configurations. This is a good
  starting point but could be extended with the strategies above.

================================================================================
5. EXCEPTION TAXONOMY
================================================================================

EXPECTED (should be caught and handled by fuzzer):
  - black.parsing.InvalidInput (subclass of ValueError)
  - black.report.NothingChanged
  - SyntaxError (from ast.parse or tokenize)
  - blib2to3.pgen2.parse.ParseError
  - blib2to3.pgen2.tokenize.TokenError
  - IndentationError
  - json.decoder.JSONDecodeError (notebook parsing)
  - ValueError (malformed line ranges, etc.)
  - UnicodeDecodeError / LookupError (encoding issues)

BUG-INDICATING (should be reported):
  - black.parsing.ASTSafetyError (formatted code is not equivalent)
  - AssertionError (internal invariant violation)
  - IndexError, KeyError, TypeError, AttributeError (unexpected state)
  - RecursionError (infinite recursion in tree processing)
  - MemoryError
  - Any segfault, SIGABRT, or other signal
  - Hangs / infinite loops (timeout detection needed)
