================================================================================
IPython Fuzzing Target Analysis - Detailed Notes for Testing
================================================================================

This document identifies key functions in the IPython library that are strong
candidates for fuzz testing. Each function is analyzed for its input surface,
accessibility without a full interactive session, and potential bug classes.

================================================================================
1. TransformerManager.transform_cell()
================================================================================
File: /app/ipython/IPython/core/inputtransformer2.py
Class: TransformerManager
Method: transform_cell(self, cell: str) -> str

WHY IT IS A GOOD FUZZ TARGET:
  - This is the primary entry point for transforming user input cells into
    executable Python code. All IPython special syntax flows through here.
  - Accepts arbitrary user-controlled string input.
  - Performs tokenization, regex matching, and multi-pass transformations.
  - Contains a loop with TRANSFORM_LOOP_LIMIT (500) iterations, meaning
    adversarial input could cause excessive computation.
  - Chains together multiple transforms: cleanup, line transforms, and
    token-based transforms (MagicAssign, SystemAssign, EscapedCommand, HelpEnd).

INPUT TYPE: str (a cell of IPython input code)

ACCEPTABLE EXCEPTIONS:
  - SyntaxError (from invalid Python syntax)
  - tokenize.TokenError (from incomplete/malformed tokens)
  - RuntimeError("Input transformation still changing after 500 iterations")

SUSPICIOUS EXCEPTIONS:
  - IndexError, KeyError (potential off-by-one in line/token processing)
  - RecursionError (unexpected infinite recursion)
  - MemoryError (excessive memory allocation from crafted input)
  - Any unhandled exception from the tokenizer or regex engine

HOW TO CALL:
  from IPython.core.inputtransformer2 import TransformerManager
  tm = TransformerManager()
  result = tm.transform_cell(fuzzed_string)

2. TransformerManager.check_complete()
--------------------------------------------------------------------------------
File: /app/ipython/IPython/core/inputtransformer2.py
Class: TransformerManager
Method: check_complete(self, cell: str) -> (str, int|None)

WHY IT IS A GOOD FUZZ TARGET:
  - Used to determine if user input is complete, incomplete, or invalid.
  - Performs tokenization, transformation, and uses codeop.compile_command.
  - Complex control flow: inspects tokens, checks parenthesis nesting,
    examines trailing characters, and delegates to the Python compiler.
  - Returns status as one of 'complete', 'incomplete', 'invalid'.

INPUT TYPE: str (Python/IPython input code)

ACCEPTABLE EXCEPTIONS:
  - SyntaxError (caught internally, returns 'invalid')
  - tokenize.TokenError (caught internally)
  - RuntimeError from transform loop limit

SUSPICIOUS EXCEPTIONS:
  - IndexError (accessing tokens_by_line[-1] or similar)
  - UnboundLocalError
  - Any crash in the tokenizer

HOW TO CALL:
  from IPython.core.inputtransformer2 import TransformerManager
  tm = TransformerManager()
  status, indent = tm.check_complete(fuzzed_string)

3. make_tokens_by_line()
--------------------------------------------------------------------------------
File: /app/ipython/IPython/core/inputtransformer2.py
Function: make_tokens_by_line(lines: List[str]) -> List[List[TokenInfo]]

WHY IT IS A GOOD FUZZ TARGET:
  - Core tokenization function used by multiple transformers.
  - Groups tokens by logical line, tracking parenthesis nesting.
  - Wraps Python's tokenize.generate_tokens, catching TokenError.
  - Edge cases with multi-line strings, unusual line endings, and
    malformed token sequences could expose bugs.

INPUT TYPE: List[str] (lines with line endings preserved)

ACCEPTABLE EXCEPTIONS:
  - tokenize.TokenError (caught internally)

SUSPICIOUS EXCEPTIONS:
  - IndexError, StopIteration propagation
  - Infinite loops (parenlev tracking issues)

HOW TO CALL:
  from IPython.core.inputtransformer2 import make_tokens_by_line
  lines = fuzzed_string.splitlines(keepends=True)
  tokens = make_tokens_by_line(lines)

5. split_user_input()
--------------------------------------------------------------------------------
File: /app/ipython/IPython/core/splitinput.py
Function: split_user_input(line: str, pattern=None) -> (str, str, str, str)

WHY IT IS A GOOD FUZZ TARGET:
  - Splits a single line of user input into (pre, esc, ifun, the_rest).
  - Uses complex regex matching with the line_split pattern.
  - Falls back to manual string splitting if regex doesn't match.
  - Returns components used for downstream handler dispatch.

INPUT TYPE: str (single line of user input)

ACCEPTABLE EXCEPTIONS:
  - None expected (should always return a tuple)

SUSPICIOUS EXCEPTIONS:
  - AttributeError (if match returns None unexpectedly)
  - re.error (regex catastrophic backtracking with crafted input)
  - IndexError

HOW TO CALL:
  from IPython.core.splitinput import split_user_input
  pre, esc, ifun, the_rest = split_user_input(fuzzed_string)

7. guarded_eval()
--------------------------------------------------------------------------------
File: /app/ipython/IPython/core/guarded_eval.py
Function: guarded_eval(code: str, context: EvaluationContext)

WHY IT IS A GOOD FUZZ TARGET:
  - Evaluates code strings with policy-based restrictions.
  - Used for tab completion and introspection safety.
  - Parses AST and walks nodes with eval_node().
  - Complex policy-checking logic for attribute access, item access, calls.
  - Security-critical: designed to prevent unwanted side effects.
  - Should be fuzzed with "limited" and "minimal" evaluation policies to
    test guard bypass potential.

INPUT TYPE: str (Python expression)

ACCEPTABLE EXCEPTIONS:
  - GuardRejection (the expected guard mechanism)
  - SyntaxError (from ast.parse)
  - NameError, TypeError, ValueError (normal eval failures)

SUSPICIOUS EXCEPTIONS:
  - Any execution of side-effects in "minimal" or "limited" mode
  - RecursionError (deeply nested AST)
  - MemoryError

HOW TO CALL:
  from IPython.core.guarded_eval import guarded_eval, EvaluationContext
  context = EvaluationContext(
      locals={},
      globals={},
      evaluation="limited"  # or "minimal"
  )
  try:
      result = guarded_eval(fuzzed_string, context)
  except Exception:
      pass

8. eval_node()
--------------------------------------------------------------------------------
File: /app/ipython/IPython/core/guarded_eval.py
Function: eval_node(node: ast.AST, context: EvaluationContext)

WHY IT IS A GOOD FUZZ TARGET:
  - Recursive AST evaluator with policy enforcement.
  - Handles all major AST node types (BinOp, Compare, Call, Attribute, etc.)
  - Complex dispatch logic with many isinstance checks.
  - Can be fuzzed by generating random AST trees or by parsing fuzzed
    code strings first.

INPUT TYPE: ast.AST node (from ast.parse of fuzzed strings)

HOW TO CALL:
  import ast
  from IPython.core.guarded_eval import eval_node, EvaluationContext
  context = EvaluationContext(locals={}, globals={}, evaluation="limited")
  try:
      tree = ast.parse(fuzzed_string, mode="eval")
      result = eval_node(tree, context)
  except Exception:
      pass

14. source_to_unicode()
--------------------------------------------------------------------------------
File: /app/ipython/IPython/utils/openpy.py
Function: source_to_unicode(txt, errors='replace', skip_encoding_cookie=True)

WHY IT IS A GOOD FUZZ TARGET:

HOW TO CALL:

15. EscapedCommand.transform() and related transform methods
--------------------------------------------------------------------------------
File: /app/ipython/IPython/core/inputtransformer2.py
Classes: MagicAssign, SystemAssign, EscapedCommand, HelpEnd

WHY THEY ARE GOOD FUZZ TARGETS:
  - Each transforms a specific IPython special syntax pattern.
  - MagicAssign: handles "a = %magic" patterns
  - SystemAssign: handles "a = !command" patterns
  - EscapedCommand: handles %magic, !command, ?help, etc.
  - HelpEnd: handles "obj?" and "obj??" patterns
  - They use assemble_continued_line() which joins backslash-continued lines.
  - find_end_of_continued_line() could go out of bounds.

INPUT TYPE: List[str] (lines of code)

HOW TO CALL:
  These are called indirectly via TransformerManager.transform_cell().
  For direct testing, instantiate with a start position and call transform().

16. filter_ns() / list_namespace()
--------------------------------------------------------------------------------
File: /app/ipython/IPython/utils/wildcard.py
Functions: filter_ns(ns, name_pattern, type_pattern, ignore_case, show_all)
           list_namespace(namespace, type_pattern, filter, ...)

WHY THEY ARE GOOD FUZZ TARGETS:
  - filter_ns converts wildcards to regex using simple string replacement:
    name_pattern.replace("*",".*").replace("?",".")
  - This can create catastrophic backtracking with crafted patterns.
  - list_namespace recursively splits on '.' and filters namespaces.

INPUT TYPE: str (name_pattern with wildcards)

ACCEPTABLE EXCEPTIONS:
  - re.error (from invalid regex patterns)

SUSPICIOUS EXCEPTIONS:
  - ReDoS (catastrophic regex backtracking)
  - RecursionError (deeply nested dotted patterns)

HOW TO CALL:
  from IPython.utils.wildcard import filter_ns
  ns = {"foo": 1, "bar": 2}
  result = filter_ns(ns, name_pattern=fuzzed_string)

================================================================================
PRIORITY RANKING FOR FUZZING:
================================================================================

HIGH PRIORITY (most likely to find bugs, security-sensitive):
  1. TransformerManager.transform_cell() - main input entry point
  2. TransformerManager.check_complete() - complex tokenization + compilation
  3. guarded_eval() - security-critical guard evaluation
  4. token_at_cursor() - complex offset arithmetic
  5. source_to_unicode() - encoding detection from untrusted bytes

MEDIUM PRIORITY (good coverage, simpler logic):
  6. make_tokens_by_line() - core tokenization
  7. split_user_input() - regex-based line splitting
  8. CachingCompiler.ast_parse() - AST parsing with flags
  9. filter_ns() - wildcard-to-regex conversion (ReDoS potential)
  10. Parser.format2() - syntax highlighting tokenization
  11. arg_split() - shell-like argument splitting

LOWER PRIORITY (simpler functions, fewer edge cases):
  12. cell_magic() - cell magic parsing
  13. pretty() - object pretty-printing
  14. EvalFormatter/FullEvalFormatter - format string eval
  15. strip_email_quotes() - text processing
  16. dedent() - text processing
  17. line_at_cursor() - simple line extraction
  18. CachingCompiler.cache() - code caching


================================================================================
GENERAL NOTES ON FUZZING APPROACH:
================================================================================

1. All string-accepting functions should be fuzzed with:
   - Empty strings
   - Very long strings
   - Strings with null bytes
   - Strings with various Unicode categories (RTL marks, combining chars, etc.)
   - Strings with mixed line endings (\n, \r, \r\n)
   - Strings with backslash continuations
   - Strings with deeply nested brackets/parentheses
   - Strings with IPython special characters: !, !!, ?, ??, %, %%, ,, ;, /

2. For bytes-accepting functions (source_to_unicode):
   - Fuzz with random bytes
   - Include encoding cookies (# -*- coding: xxx -*-)
   - Use invalid encoding names
   - Mix valid and invalid byte sequences

3. The TransformerManager can be instantiated without any interactive session,
   making it ideal for standalone fuzzing.

4. guarded_eval requires an EvaluationContext but can be created with empty
   dicts for locals/globals, making it easy to fuzz standalone.

5. Most functions gracefully handle SyntaxError and tokenize.TokenError.
   Look for crashes that bypass these exception handlers.
