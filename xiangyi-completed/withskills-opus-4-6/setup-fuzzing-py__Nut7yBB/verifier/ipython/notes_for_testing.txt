Fuzzing Target Note 1

- Target: TransformerManager.transform_cell

- File / location: /app/ipython/IPython/core/inputtransformer2.py
  Class: TransformerManager, method: transform_cell (line 635)

- Why this target:
  * Input surface: Accepts any str representing a cell of Python/IPython code.
    This is the primary entry point for all user input transformation in IPython.
  * Boundary considerations: Empty strings, strings without trailing newlines,
    strings with mixed line endings (\r\n, \r, \n), extremely long lines,
    deeply nested brackets, unterminated strings, mix of IPython special syntax
    (%, !, ?, %%, !!, ??, /foo, ,foo, ;foo), continued lines with backslashes.
  * Complexity: Multi-phase pipeline: (1) cleanup transforms (leading empty
    lines, leading indent, prompt stripping), (2) line transforms (cell magic),
    (3) token transforms (iterative: MagicAssign, SystemAssign, EscapedCommand,
    HelpEnd). The token transform loop has a 500-iteration safety limit
    (TRANSFORM_LOOP_LIMIT) but could still be expensive.
  * Test gaps: Existing tests use ~20 curated input strings. No randomized or
    adversarial inputs. No testing of pathological tokenization cases, mixed
    encodings, null bytes, or control characters in cells.

- Callable contract:
  * Import: from IPython.core.inputtransformer2 import TransformerManager
  * Preconditions: Input must be str. No other state required beyond creating
    a TransformerManager() instance (stateless between calls).
  * Determinism: Yes, purely deterministic given the same input string.
  * Dependencies: Python stdlib only (ast, re, tokenize, codeop). No I/O,
    no network, no file system access.

- Input model:
  * Payload type: str (arbitrary Python/IPython source code)
  * Parsing steps: (1) Ensure trailing newline, (2) splitlines(keepends=True),
    (3) Apply cleanup_transforms sequentially, (4) Apply line_transforms,
    (5) Repeatedly tokenize and apply token_transformers until no changes.
  * Constraints: Input should be str. The function adds '\n' if missing.
  * Edge cases: Empty string, only whitespace, only escape characters,
    deeply nested brackets causing tokenize.TokenError, cells starting with
    '%%' (cell magic), lines with backslash continuations, strings with
    embedded null bytes (\x00), cells with only '?' or '??'.

- Oracles:
  * Must-hold properties: Function must always return a str. Must not raise
    unhandled exceptions (should handle tokenize.TokenError internally).
    Must terminate (TRANSFORM_LOOP_LIMIT prevents infinite loops).
  * Acceptable exceptions: SyntaxError (from Python's tokenizer for truly
    malformed input), RuntimeError (from exceeding TRANSFORM_LOOP_LIMIT).
  * Suspicious exceptions: Any MemoryError, RecursionError, IndexError,
    KeyError, AttributeError, or segfault indicates a bug.

- Harness plan:
  * Approach: Use atheris to generate random str inputs. Create one
    TransformerManager instance and call transform_cell() in a loop.
  * Signature: def TestOneInput(data: bytes): cell = data.decode('utf-8',
    errors='replace'); tm.transform_cell(cell)
  * Seed corpus: Include cells from test_inputtransformer2.py, typical
    IPython inputs ("%magic", "!shell", "x?", "%%cellmagic\nbody"), empty
    string, pure whitespace, Unicode strings.

- Risk flags:
  * Native extensions: None (pure Python path).
  * DoS paths: The TRANSFORM_LOOP_LIMIT (500) prevents infinite loops but
    each iteration does tokenization which could be slow for large inputs.
    Consider limiting input size to ~10KB.
  * External I/O: None.

- Next actions:
  1. Write atheris harness targeting transform_cell
  2. Build seed corpus from existing test vectors
  3. Run with input size limit of 10KB
  4. Monitor for hangs (tokenization on pathological input)

- Target: TransformerManager.check_complete

- File / location: /app/ipython/IPython/core/inputtransformer2.py
  Class: TransformerManager, method: check_complete (line 646)

- Why this target:
  * Input surface: Accepts any str representing Python/IPython code. Returns
    a tuple (status: str, indent: int|None) where status is one of
    'complete', 'incomplete', 'invalid'.
  * Boundary considerations: This function does even more complex analysis
    than transform_cell: it calls transform pipeline + tokenization +
    bracket analysis + compile_command(). Interacts with Python's compiler.
  * Complexity: The function (1) tokenizes, (2) applies transforms, (3) checks
    for sunken brackets, (4) analyzes last token type, (5) checks for colons
    (block starts), (6) calls codeop.compile_command with the transformed code.
    Many branches and early returns.
  * Test gaps: Tests in test_inputtransformer2.py only cover check_complete
    for known specific inputs. No fuzzing of edge cases.

- Callable contract:
  * Import: from IPython.core.inputtransformer2 import TransformerManager
  * Preconditions: Input must be str. TransformerManager() is stateless.
  * Determinism: Yes.
  * Dependencies: stdlib only (tokenize, codeop, ast, re). The compile_command
    call goes through Python's parser.

- Input model:
  * Payload type: str
  * Parsing steps: (1) Check trailing newline, append if needed,
    (2) splitlines, (3) cleanup transforms, (4) cell magic check,
    (5) line+token transforms, (6) tokenize and bracket analysis,
    (7) compile_command.
  * Constraints: str input, any content.
  * Edge cases: Strings ending with backslash, strings with only brackets,
    deeply nested structures, strings with cell magic markers (%%),
    multi-line strings, f-strings with nested expressions,
    input that triggers SyntaxWarning in compile.

- Oracles:
  * Must-hold properties: Must always return a 2-tuple (str, int|None).
    Status must be one of {'complete', 'incomplete', 'invalid'}.
    When status is not 'incomplete', indent must be None.
  * Acceptable exceptions: None -- this function is designed to not raise.
    It catches SyntaxError, OverflowError, ValueError, TypeError,
    MemoryError, SyntaxWarning internally.
  * Suspicious exceptions: Any uncaught exception (RuntimeError from
    TRANSFORM_LOOP_LIMIT is possible but rare), RecursionError,
    IndexError, segfault.

- Harness plan:
  * Approach: atheris harness, share TransformerManager with Target 1.
  * Signature: Same as Target 1 but calling check_complete(cell).
  * Seed corpus: Share with Target 1, add incomplete fragments ("if x:",
    "def f(", "for i in", open brackets, etc.)

- Risk flags:
  * DoS: compile_command can be slow for some pathological inputs.
    Limit input size to ~10KB.
  * Native extensions: compile_command calls CPython's parser (C extension).
  * External I/O: None.

- Next actions:
  1. Combine harness with Target 1
  2. Add oracle assertions for return value invariants
  3. Run with moderate timeouts

- Target: guarded_eval

- File / location: /app/ipython/IPython/core/guarded_eval.py
  Function: guarded_eval (line 433)

- Why this target:
  * Input surface: Accepts arbitrary str (code) + EvaluationContext. The code
    string is parsed with ast.parse() and then evaluated node-by-node with
    policy enforcement via eval_node().
  * Boundary considerations: This is a SECURITY-CRITICAL function. It is
    designed to prevent dangerous operations when evaluating user expressions
    for tab completion. Fuzzing could reveal policy bypass paths.
  * Complexity: eval_node() handles ~30 AST node types including:
    BinOp, Compare, Call, Attribute, Subscript, Name, IfExp, Constant,
    Tuple, List, Set, Dict, Slice, UnaryOp, Assign, AnnAssign,
    FunctionDef, ClassDef, For, While, If, Lambda, Await, Assert.
    Each branch has policy checks (can_call, can_get_item, can_get_attr,
    can_operate). Recursive evaluation of sub-nodes.
  * Test gaps: test_guarded_eval.py tests specific expressions. No fuzzing
    of arbitrary expressions. No testing of deep nesting or unusual AST
    combinations that might bypass guards.

- Callable contract:
  * Import: from IPython.core.guarded_eval import guarded_eval,
    EvaluationContext, GuardRejection
  * Preconditions: code must be a valid str. context must be an
    EvaluationContext with evaluation policy set.
  * Determinism: Yes (for a given context).
  * Dependencies: ast (stdlib), no I/O.

- Input model:
  * Payload type: str (Python expression / statement)
  * Parsing steps: (1) If in_subscript mode, wraps code in subscript syntax,
    (2) ast.parse(code, mode="exec"), (3) recursive eval_node walk.
  * Constraints: Must be parseable by ast.parse(). Invalid syntax will raise
    SyntaxError at the ast.parse step.
  * Edge cases: Deeply nested expressions, chained attribute access,
    complex subscript operations, f-strings, walrus operator,
    starred expressions, comprehensions, lambda chains,
    expressions mixing allowed and disallowed operations.

- Oracles:
  * Must-hold properties:
    - In "forbidden" mode: must always raise GuardRejection.
    - In "minimal" mode: must reject attribute/item/call access.
    - In "limited" mode: must only allow whitelisted operations.
    - Must never execute os.system, subprocess, __import__, eval, exec.
  * Acceptable exceptions: GuardRejection, NameError, SyntaxError,
    TypeError, ValueError.
  * Suspicious exceptions: Any successful return in forbidden mode.
    Any side effect (file creation, network access). RecursionError
    (may indicate lack of depth limiting).

- Harness plan:
  * Approach: Generate random Python expressions. Test with "limited"
    and "minimal" contexts. Assert that GuardRejection is raised for
    known-dangerous patterns.
  * Signature: def TestOneInput(data: bytes): code = data.decode(
    'utf-8', errors='replace'); try: guarded_eval(code, limited_ctx)
    except (GuardRejection, SyntaxError, NameError, ...): pass
  * Seed corpus: Expressions from test_guarded_eval.py, dangerous
    expressions ("__import__('os').system('id')", "eval('1+1')"),
    deeply nested attribute chains, lambda expressions.

- Risk flags:
  * In "dangerous" mode, guarded_eval calls Python's eval() directly.
    Never fuzz with "dangerous" mode as context.
  * RecursionError: Deeply nested AST could cause stack overflow in
    eval_node's recursive calls. No explicit depth limit exists.
  * Native extensions: ast.parse calls CPython's parser.
  * External I/O: None in limited/minimal mode.

- Next actions:
  1. Write harness using "limited" and "minimal" contexts only
  2. Add seed corpus of known-dangerous expressions
  3. Add oracle: assert no file/network side effects
  4. Monitor for RecursionError crashes

- Target: token_at_cursor

- File / location: /app/ipython/IPython/utils/tokenutil.py
  Function: token_at_cursor (line 98)

- Why this target:
  * Input surface: Accepts (cell: str, cursor_pos: int). The cell is any
    Python code string. cursor_pos is an integer offset into the string.
  * Boundary considerations: cursor_pos can be 0, len(cell), negative,
    or beyond the string length. The function tracks line offsets and
    maintains call stacks -- off-by-one errors are likely.
  * Complexity: Tokenizes the entire cell, builds offset mapping for each
    line, tracks name tokens, call stack (for function calls), handles
    attribute access (dot-separated names). Multiple interacting state
    variables: names, call_names, closing_call_name, most_recent_outer_name,
    offsets dictionary, intersects_with_cursor.
  * Test gaps: test_tokenutil.py has ~10 test functions with specific
    cell/cursor combinations. No fuzz testing with arbitrary code or
    cursor positions.

- Callable contract:
  * Import: from IPython.utils.tokenutil import token_at_cursor
  * Preconditions: cell must be str, cursor_pos must be int.
  * Determinism: Yes.
  * Dependencies: tokenize (stdlib), io.StringIO. No I/O.

- Input model:
  * Payload type: (str, int) pair
  * Parsing steps: (1) Tokenize cell via generate_tokens(StringIO(cell)),
    (2) Iterate tokens building offset map, (3) Track names and call stack,
    (4) Find token at cursor_pos based on offsets.
  * Constraints: cell is str, cursor_pos is int (ideally 0 <= cursor_pos
    <= len(cell), but function should handle out-of-range gracefully).
  * Edge cases: Empty cell, cursor at 0, cursor at len(cell), cursor beyond
    cell length, cells with syntax errors (tokenize.TokenError caught by
    generate_tokens wrapper), multi-line strings, cells with only whitespace,
    cells with deeply nested function calls, cells with many dots.

- Oracles:
  * Must-hold properties: Must always return a str (possibly empty "").
    Must not raise exceptions for any valid (str, int) input.
  * Acceptable exceptions: None expected (tokenize errors are caught).
  * Suspicious exceptions: IndexError, KeyError (in offsets dict),
    StopIteration, any crash or segfault.

- Harness plan:
  * Approach: Use atheris FuzzedDataProvider. Extract cell as UTF-8 string,
    cursor_pos as ConsumeIntInRange(0, len(cell)+10).
  * Signature: def TestOneInput(data: bytes): fdp = FuzzedDataProvider(data);
    cell = fdp.ConsumeUnicode(fdp.remaining_bytes() - 4);
    cursor_pos = fdp.ConsumeIntInRange(0, max(len(cell)+10, 1));
    token_at_cursor(cell, cursor_pos)
  * Seed corpus: Cells from test_tokenutil.py, empty string, long multi-line
    Python code, cells with syntax errors.

- Risk flags:
  * DoS: Tokenization of very large strings could be slow. Limit cell
    size to ~10KB.
  * Native extensions: tokenize uses CPython's tokenizer.
  * External I/O: None.

- Next actions:
  1. Write atheris harness with two-part input (cell + cursor_pos)
  2. Build seed corpus from test_tokenutil.py test vectors
  3. Assert no exceptions raised
  4. Run with input size limit

- Target: source_to_unicode

- File / location: /app/ipython/IPython/utils/openpy.py
  Function: source_to_unicode (line 17)

- Why this target:
  * Input surface: Accepts bytes (or str passthrough or file-like buffer).
    Detects Python source encoding from encoding cookie and decodes.
  * Boundary considerations: Arbitrary byte sequences as Python source.
    The encoding cookie regex matching, encoding detection via
    tokenize.detect_encoding, and TextIOWrapper decoding all touch
    boundary-sensitive code paths.
  * Complexity: (1) Check if input is str (passthrough), (2) if bytes,
    wrap in BytesIO, (3) call tokenize.detect_encoding to find encoding
    from cookie, (4) wrap in TextIOWrapper with detected encoding,
    (5) optionally strip encoding cookie lines.
  * Test gaps: test_openpy.py has only 3 tests using one specific ISO-8859-5
    encoded file. No testing with arbitrary byte buffers, malformed encoding
    cookies, exotic encodings, truncated headers.

- Callable contract:
  * Import: from IPython.utils.openpy import source_to_unicode
  * Preconditions: txt should be bytes, str, or file-like with readline.
  * Determinism: Yes.
  * Dependencies: tokenize.detect_encoding (stdlib), io.BytesIO,
    io.TextIOWrapper. No network, no file I/O beyond reading the buffer.

- Input model:
  * Payload type: bytes (primary fuzzing type)
  * Parsing steps: (1) type check (str returns immediately), (2) BytesIO
    wrap, (3) detect_encoding reads first two lines looking for
    "coding[:=]\s*([-\w.]+)" pattern, (4) TextIOWrapper decodes full
    buffer with detected (or default ASCII) encoding.
  * Constraints: bytes input. Any byte sequence is valid input.
  * Edge cases: Empty bytes, bytes with BOM markers, bytes with
    conflicting encoding cookies, bytes with invalid encoding names,
    bytes with null bytes, very long first lines, bytes that look like
    encoding cookies but aren't (embedded in strings), truncated
    multi-byte sequences.

- Oracles:
  * Must-hold properties: Must always return a str. With errors='replace',
    should never raise a decoding error. The only expected exception is
    SyntaxError from detect_encoding (caught internally, falls back to ASCII).
  * Acceptable exceptions: SyntaxError (caught internally).
  * Suspicious exceptions: UnicodeDecodeError (should be prevented by
    errors='replace'), LookupError (unknown encoding not caught),
    ValueError, any crash.

- Harness plan:
  * Approach: Direct byte fuzzing -- pass raw fuzzer bytes to
    source_to_unicode.
  * Signature: def TestOneInput(data: bytes):
    source_to_unicode(data, errors='replace', skip_encoding_cookie=True)
    source_to_unicode(data, errors='replace', skip_encoding_cookie=False)
  * Seed corpus: Python source files with various encoding cookies
    (UTF-8, Latin-1, ISO-8859-5, Shift_JIS), empty file, BOM-prefixed
    files, files with only encoding cookie.

- Risk flags:
  * LookupError: If detect_encoding returns an encoding name not known
    to Python's codec registry, TextIOWrapper will raise LookupError.
    This is NOT caught by the function's except SyntaxError handler.
    This is a real bug candidate.
  * Native extensions: tokenize.detect_encoding may interact with C-level
    codec lookup.
  * External I/O: None (operates on in-memory buffer).

- Next actions:
  1. Write simple atheris harness passing raw bytes
  2. Seed with real Python files in various encodings
  3. Specifically test for LookupError on exotic encoding names
  4. Test both skip_encoding_cookie=True and False paths
