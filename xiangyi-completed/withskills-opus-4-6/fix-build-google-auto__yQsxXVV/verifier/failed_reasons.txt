BUILD FAILURE ANALYSIS - google/auto
=====================================

REPOSITORY: /home/travis/build/failed/google/auto/
PROJECT: Google Auto (multi-module Maven project)
MODULES: common, service, factory, value

ENVIRONMENT:
- Java: OpenJDK 11.0.27 (Java 11)
- Maven: available
- JDK: openjdk-11-jdk-headless installed

=== ROOT CAUSE ===

All 4 modules fail with the same error:

  ERROR: Could not resolve dependencies for project ...:
  Could not find artifact com.sun:tools:jar:11.0.27 at specified path
  /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar

EXPLANATION:
The project was designed for Java 6/7/8. In those JDK versions, the Java
compiler API classes were packaged in a separate file: $JAVA_HOME/lib/tools.jar.
The library `com.google.testing.compile:compile-testing` (used in test scope by
all modules) declares a system-scoped dependency on `com.sun:tools` with
systemPath set to `${toolsjar}`.

The `toolsjar` property is set by the parent POM (auto-parent:3) via a Maven
profile called "default-profile" which has activeByDefault=true and sets:
  <toolsjar>${java.home}/../lib/tools.jar</toolsjar>

In Java 9+, tools.jar was removed. The classes it contained were folded into
the JDK's module system (specifically the java.compiler module). Therefore,
the file /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar does not exist,
and Maven cannot resolve the com.sun:tools system dependency.

ADDITIONALLY for the value module:
- auto-value depends on auto-common:1.0-SNAPSHOT which isn't published and
  must be built locally first (mvn install on common module before value).

=== AFFECTED FILES ===

1. common/pom.xml - compile-testing:0.7 (test scope) pulls in com.sun:tools
2. service/pom.xml - compile-testing:0.6 (test scope) pulls in com.sun:tools
3. factory/pom.xml - compile-testing:0.8 (test scope) pulls in com.sun:tools
4. value/pom.xml   - compile-testing:0.6 (test scope) pulls in com.sun:tools
                   - also depends on auto-common:1.0-SNAPSHOT (not available)

=== FIX PLAN ===

For each module POM (common, service, factory, value):
  Add an exclusion for com.sun:tools from the compile-testing dependency.
  This is safe because in Java 9+, the classes from tools.jar are part of the
  JDK module system and don't need to be on the classpath separately.

  <dependency>
    <groupId>com.google.testing.compile</groupId>
    <artifactId>compile-testing</artifactId>
    <version>...</version>
    <scope>test</scope>
    <exclusions>
      <exclusion>
        <groupId>com.sun</groupId>
        <artifactId>tools</artifactId>
      </exclusion>
    </exclusions>
  </dependency>

Build order: common first (install), then service/factory/value can build.

=== SECOND ERROR (discovered after fixing the first) ===

After fixing the tools.jar issue, factory and value modules fail with:

  ERROR: cannot find symbol
    symbol:   class Generated
    location: package javax.annotation

EXPLANATION:
In Java 9+, javax.annotation.Generated was removed from the default module
path (it was part of the java.xml.ws.annotation module, deprecated in Java 9
and removed in Java 11). The factory and value modules import and use
javax.annotation.Generated directly.

AFFECTED FILES:
- factory/src/main/java/.../FactoryWriter.java:39 - import javax.annotation.Generated
- value/src/main/java/.../AutoValueProcessor.java:51 - import javax.annotation.Generated
- value/src/main/java/.../AutoAnnotationProcessor.java:36 - import javax.annotation.Generated

FIX:
Add javax.annotation:javax.annotation-api:1.3.2 dependency to factory/pom.xml
and value/pom.xml. This provides javax.annotation.Generated on Java 9+.
