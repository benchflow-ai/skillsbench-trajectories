The build failed because of a dependency on `com.sun:tools:jar` (tools.jar), which is not available in the Java 11 environment (OpenJDK 11).
The error message: `Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar` confirms this.

The dependency on `tools.jar` is transitive, coming from `com.google.testing.compile:compile-testing`.
This dependency is present in `auto-common` (v0.7), `auto-factory` (v0.8), and `auto-service` (v0.6).
`compile-testing` declares a system-scope dependency on `tools.jar` relying on `${java.home}/../lib/tools.jar`, which is valid for JDK 8 but not for JDK 9+ (where `tools.jar` was removed).

Plan:
Exclude `com.sun:tools` from the `compile-testing` dependency in:
1. `common/pom.xml`
2. `factory/pom.xml`
3. `service/pom.xml`

This should resolve the build error as the necessary classes are part of the standard modules in Java 11.

UPDATE:
After fixing the `tools.jar` issue, two new errors appeared:
1. `auto-common` test failure: `VisibilityTest` failed because it incorrectly identifies visibility when running on Java 9+. The `Visibility.effectiveVisibilityOfElement` walks up to the Module element (which is new in Java 9+) and incorrectly determines it has DEFAULT visibility, causing `PUBLIC` classes to be seen as `DEFAULT`.
   Fix: Modify `Visibility.java` to stop walking up the element hierarchy when it reaches the `PACKAGE` element.

2. `auto-factory` compilation failure: `cannot find symbol class Generated`. This is because `javax.annotation.Generated` was removed from the JDK in Java 11 (it was part of `java.xml.ws.annotation` module).
   Fix: Add `javax.annotation:javax.annotation-api:1.3.2` dependency to `factory/pom.xml`.
