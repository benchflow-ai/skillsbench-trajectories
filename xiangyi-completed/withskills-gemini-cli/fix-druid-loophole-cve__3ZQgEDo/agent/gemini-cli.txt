### Vulnerability Analysis
The vulnerability allowed authenticated attackers to bypass JavaScript security settings by providing a malicious JSON payload with an empty key `""`. This empty key was being mapped by Jackson to the `JavaScriptConfig` parameter in the `JavaScriptDimFilter` constructor (and other classes) because the parameter lacked a `@JsonProperty` annotation. This allowed attackers to overwrite the injected `JavaScriptConfig` (which has `enabled=false` by default) with a user-provided configuration where `enabled=true`, thus enabling arbitrary code execution via JavaScript.

### Fix
I have applied a patch that explicitly annotates the `JavaScriptConfig` parameter with `@JsonProperty("config")` in all vulnerable classes. This forces Jackson to expect a property named "config" for this parameter. Since the `config` is also annotated with `@JacksonInject`, it will be injected from the context as intended. The empty key `""` in the malicious payload will now be treated as an unknown property and ignored (or handled by `JsonAnySetter` if present, but won't overwrite `config`), effectively blocking the bypass.

Affected classes patched:
1. `org.apache.druid.query.filter.JavaScriptDimFilter`
2. `org.apache.druid.query.aggregation.JavaScriptAggregatorFactory`
3. `org.apache.druid.query.aggregation.post.JavaScriptPostAggregator`
4. `org.apache.druid.query.extraction.JavaScriptExtractionFn`
5. `org.apache.druid.indexing.overlord.setup.JavaScriptWorkerSelectStrategy`
