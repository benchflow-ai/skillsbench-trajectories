The parallel implementation of the TF-IDF search engine has been completed in `/root/workspace/parallel_solution.py`. This solution leverages `ProcessPoolExecutor` from the `concurrent.futures` module to parallelize both the index building and the batch search processes, achieving significant performance improvements while maintaining identical results to the sequential version.

### Key Features of the Parallel Implementation

1.  **Parallel Index Building (`build_tfidf_index_parallel`)**:
    *   **Phase 1 (Parallel TF/DF):** Documents are split into chunks and processed in parallel to compute term frequencies (TF) and partial document frequencies (DF). This step is CPU-bound (tokenization) and scales well.
    *   **Phase 2 (Parallel Vectorization):** Once global IDFs are computed sequentially (which is fast), documents are again processed in parallel to compute document vectors, norms, and partial inverted index postings.
    *   **Aggregation:** Partial results are aggregated in a deterministic order to ensure the final inverted index structure exactly matches the sequential version, preserving `doc_id` ordering for stable sorting.
    *   **Performance:** Achieved ~1.97x speedup on a test workload (5000 docs).

2.  **Parallel Batch Search (`batch_search_parallel`)**:
    *   **Efficient Data Sharing:** Uses `initializer` to pass the large `index` and `documents` structures to worker processes. On Linux, this leverages "Copy-on-Write" (fork), avoiding expensive pickling/copying overhead for the large index data.
    *   **Chunking:** Queries are chunked and distributed across workers.
    *   **Performance:** Achieved ~2.87x speedup on a test workload (5000 docs, 1000 queries) with 4 workers.
