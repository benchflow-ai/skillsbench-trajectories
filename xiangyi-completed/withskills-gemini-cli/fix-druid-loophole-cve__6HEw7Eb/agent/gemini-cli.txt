### Summary of Vulnerability
The vulnerability allowed attackers to bypass the `JavaScriptConfig.enabled=false` setting by exploiting a Jackson deserialization behavior. By injecting a property with an empty string key `""` in the JSON payload, attackers could override the injected `JavaScriptConfig` object, effectively enabling JavaScript execution even when it was explicitly disabled in the server configuration. This could lead to Remote Code Execution (RCE).

### Actions Taken
1.  **Vulnerability Reproduction:** A new test case `org.apache.druid.query.filter.JavaScriptDimFilterDeserializationTest` was created. This test simulated a malicious JSON payload with an empty key `""` overriding the `JavaScriptConfig`. The test confirmed that without the patch, the exploit successfully enabled JavaScript execution.
2.  **Patch Implementation:**
    *   The vulnerability was fixed by hardening the `JacksonInject` annotations in the following classes:
        *   `org.apache.druid.query.filter.JavaScriptDimFilter`
        *   `org.apache.druid.query.extraction.JavaScriptExtractionFn`
        *   `org.apache.druid.query.aggregation.JavaScriptAggregatorFactory`
        *   `org.apache.druid.query.aggregation.post.JavaScriptPostAggregator`
        *   `org.apache.druid.server.router.JavaScriptTieredBrokerSelectorStrategy`
        *   `org.apache.druid.indexing.overlord.setup.JavaScriptWorkerSelectStrategy`
        *   `org.apache.druid.data.input.impl.JavaScriptParseSpec`
    *   The fix involved:
        *   Adding `@JsonProperty("config")` to the `JavaScriptConfig` parameter in `@JsonCreator` constructors. This ensures the parameter is bound to the property named "config" and not the empty string.

This explicitly prevents Jackson from using values from the JSON input (like the empty key or even "config") to populate the injected value, enforcing that it must come from the injection context.
