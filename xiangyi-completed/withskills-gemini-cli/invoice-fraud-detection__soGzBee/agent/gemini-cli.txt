**Methodology:**
1.  **Extraction:** I used `pypdf` to extract text from each page of `/root/invoices.pdf`. I parsed the Vendor Name, Invoice Amount, IBAN, and PO Number using regular expressions.
2.  **Vendor Validation:** I matched extracted vendor names against `/root/vendors.xlsx` using fuzzy matching (SequenceMatcher) to handle minor variations.
3.  **Fraud Detection Logic:** I implemented the checks in the specified order of precedence:
    *   **Unknown Vendor:** Vendor name does not match any approved vendor (similarity threshold < 0.8).
    *   **IBAN Mismatch:** Vendor matches, but the invoice IBAN does not match the approved IBAN.
    *   **Invalid PO:** Extracted PO Number was not found in `/root/purchase_orders.csv`.
    *   **Amount Mismatch:** PO exists, but the invoice amount differs from the PO amount by more than 0.01.
    *   **Vendor Mismatch:** PO exists and amount matches, but the PO is associated with a different Vendor ID than the invoice's vendor.

**Results:**
The findings have been saved to `/root/fraud_report.json`. The analysis identified several fraudulent invoices with reasons including "IBAN Mismatch", "Amount Mismatch", "Unknown Vendor", and "Invalid PO". No "Vendor Mismatch" cases were found in this dataset (likely because other criteria took precedence or such cases didn't occur).
