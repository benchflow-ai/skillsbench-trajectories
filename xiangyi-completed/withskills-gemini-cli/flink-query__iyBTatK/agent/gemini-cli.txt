The Flink job has been implemented in `clusterdata.query.LongestSessionPerJob`.
I have also created the required data types in `clusterdata.datatypes.JobEvent` and `clusterdata.datatypes.TaskEvent`.

The job logic is as follows:
1.  **Parsing**: Reads Job and Task events from the provided CSV paths.
2.  **Timestamps**: Assigns timestamps and watermarks (assuming timestamps in the file are microseconds, converted to milliseconds).
3.  **Task Stages**: Filters task events for `SUBMIT` (type 0). Groups by `jobId` and applies `EventTimeSessionWindows` with a 10-minute gap to identify stages. Counts tasks per stage.
4.  **Job Completion**: Filters job events for `FINISH` (4), `KILL` (5), or `LOST` (6).
5.  **Aggregation**: Connects the stream of stage counts with the stream of job completion events.
    *   Maintains the maximum task count seen so far for each job.
    *   When a job completion event arrives, it registers a timer for `JobEndTime + 10 minutes` to ensure all task sessions (which might end slightly after the job "officially" ends if tasks were submitted right before) are processed.
    *   On the timer, it emits the result `(jobId, maxTasks)`.
6.  **Output**: Writes the result to the specified output path using `writeAsText` with parallelism 1.

The code adheres to the provided skeleton and `AppBase` structure. Note that `writeAsText` is used for simplicity; in a real production environment, `FileSink` would be preferred, but `writeAsText` is sufficient for this assignment and handles the output requirement.

Dependencies in `pom.xml` were sufficient for compilation. The implementation should work correctly on a Flink 1.18+ cluster (or local mini-cluster) given the dependencies are provided at runtime.
