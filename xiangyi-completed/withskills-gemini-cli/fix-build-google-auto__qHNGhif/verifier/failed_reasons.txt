The build fails because the projects (auto-common, auto-factory, auto-service) depend on `auto-parent` version 3.
`auto-parent` version 3 seems to include a system dependency on `tools.jar` (via a profile or directly), which was available in JDK 8 but removed in JDK 9+. The current build environment uses OpenJDK 11, where `tools.jar` is missing.

The repository contains a root `pom.xml` which defines `auto-parent` version `4-SNAPSHOT`. This newer parent configuration does not seem to include the problematic `tools.jar` dependency (it defines a property for it but doesn't appear to use it in a way that breaks the build if missing, or at least it's meant for the current environment).

The fix is to update the parent version in the submodules (`common/pom.xml`, `factory/pom.xml`, `service/pom.xml`, `value/pom.xml`) from `3` to `4-SNAPSHOT` so they use the local parent POM which is compatible with the current environment.
