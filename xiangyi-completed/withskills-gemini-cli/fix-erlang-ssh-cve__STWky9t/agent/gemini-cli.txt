### Vulnerability Analysis
The vulnerability allowed unauthenticated remote command execution because the SSH Connection Protocol messages (defined in RFC 4254) were being processed by the server's state machine even before the SSH Authentication Protocol (RFC 4252) had successfully completed. Specifically, an attacker could:
1. Complete the SSH Transport Layer handshake (KEX).
2. Skip authentication and directly send an `SSH_MSG_CHANNEL_OPEN` message.
3. Follow it with an `SSH_MSG_CHANNEL_REQUEST` of type `"exec"`, which triggered the execution of arbitrary system commands.

### Fix Description
I have implemented a fix in `otp_src_27.3.2/lib/ssh/src/ssh_connection_handler.erl` that enforces the protocol requirement that authentication must be complete before the connection layer is active:
- Added a guard to the `internal` event handler for `{conn_msg, Msg}` that checks the `authenticated` status in the session parameters. 
- If a Connection Protocol message is received and `authenticated` is `false`, the server now immediately disconnects the peer with an `SSH_DISCONNECT_PROTOCOL_ERROR`.
- Updated the packet processing logic to prevent unauthenticated `SSH_MSG_CHANNEL_OPEN` messages from cancelling the `max_initial_idle_time` timeout.
