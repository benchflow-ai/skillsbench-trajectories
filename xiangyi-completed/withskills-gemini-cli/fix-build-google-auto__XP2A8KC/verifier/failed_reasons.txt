Analysis of build failure:
The build failure is caused by several bugs in the AutoValue annotation processor, specifically in the code generation template for builders with collection builders and setters.

1. Nullable collection properties with builders are incorrectly initialized to an empty collection in the Builder's no-arg constructor. This causes tests that expect a null default value to fail.
2. In the property builder method (e.g., `thingsBuilder()`), the code attempts to initialize the builder from the current value of the property without checking if that value is null. For nullable properties, this can lead to a NullPointerException if the property is null.
3. The generated `build()` method and builder getters need to correctly handle the interaction between the property field and the property builder field, ensuring that the latest value is always used and that nullability is respected.

Plan:
1. Modify `value/src/main/java/com/google/auto/value/processor/autovalue.vm` to:
    a. Only initialize collection properties to `empty` in the no-arg constructor if they are not `@Nullable`.
    b. Add a null check before calling `addAll`/`putAll` in the property builder method.
    c. Ensure that the builder's getter for a property with a builder returns the result of `builder.build()` if the builder field is non-null.
2. Fix the `tools.jar` dependency issue in the `pom.xml` files by ensuring they use the local parent and potentially adding a profile for Java 9+ if needed, although the primary goal is to fix the codebase bugs that caused the original failure on Java 7.
