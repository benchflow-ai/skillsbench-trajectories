The task was to repair an FJSP baseline schedule that was infeasible due to machine downtime conflicts and potential precedence violations, while minimizing the makespan increase and adhering to policy budgets (machine changes and start time shifts).

I activated the `fjsp-baseline-repair-with-downtime-and-policy` skill and implemented a Python script to perform the repair.

**Key Actions Taken:**
1.  **Parsed Inputs:** Read `instance.txt` (job operations), `downtime.csv` (machine maintenance windows), `policy.json` (budgets), and `baseline_solution.json`.
2.  **Identified Issues:**
    -   The baseline schedule ignored machine downtime (e.g., Job 1 Op 1 overlapped with Machine 1's downtime).
    -   The baseline contained precedence violations (e.g., Job 2 Op 2 was scheduled before Job 2 Op 1).
3.  **Repair Algorithm:**
    -   Iterated through operations in strict precedence order (Job 0 Op 0 -> Op 1...).
    -   Calculated the earliest valid start time (`anchor`) for each operation, ensuring it does not start earlier than the baseline (`start >= base_start`) and respects the completion of the previous operation (`start >= prev_end`).
    -   Checked for conflicts with machine downtime and previously scheduled operations.
    -   Prioritized the baseline machine to minimize the "Machine Change" (MC) count, finding the earliest feasible slot.
    -   Validated changes against the `policy.json` budgets (`max_machine_changes: 4`, `max_total_start_shift_L1: 120`).
4.  **Result:**
    -   Generated a feasible schedule with a makespan of **44**.
    -   The increase from the baseline makespan (36) was necessary to resolve the overlap with downtime (15-unit shift for multiple operations) and to correct the precedence inversion in Job 2.
    -   Kept Machine Changes (MC) to 0, well within the budget of 4.
    -   Total start time shift was minimized while ensuring feasibility.
