Analysis of build failures:
1. Java 11 incompatibility: The project was using an old parent POM (version 3) from Maven Central which relied on tools.jar. In Java 11, tools.jar no longer exists.
2. Dependency issues: Many dependencies like compile-testing, truth, and guava were outdated and incompatible with Java 11 or each other when updated.
3. javax.annotation.Generated: This annotation was moved/removed in Java 11, causing compilation errors in AutoFactory and AutoValue.
4. Truth compatibility: Updating compile-testing to a Java 11-compatible version required updating Truth, which introduced breaking changes in test methods (withFailureMessage renamed to withMessage).
5. maven-shade-plugin: The version used was incompatible with Java 11 and had illegal relocation patterns (trailing $).
6. Encoding: Integration tests failed due to US-ASCII encoding being used on source files with UTF-8 characters.

Plan:
1. Update all subprojects to use the local parent POM (version 4-SNAPSHOT).
2. Update compile-testing to version 0.15 for Java 11 compatibility.
3. Update Guava to version 23.5-android to maintain Java 6 compatibility while being compatible with newer Truth.
4. Update Truth to version 0.37.
5. Add javax.annotation-api dependency to projects using @Generated.
6. Replace withFailureMessage with withMessage in Truth assertions.
7. Switch to the standard maven-shade-plugin version 3.2.4 and fix relocation patterns.
8. Set project.build.sourceEncoding to UTF-8 in all projects, including integration tests.
