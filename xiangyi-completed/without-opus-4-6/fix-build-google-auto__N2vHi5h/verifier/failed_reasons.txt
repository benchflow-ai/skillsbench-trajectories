BUILD FAILURE ANALYSIS - google/auto
=====================================

Repository: /home/travis/build/failed/google/auto
Build system: Maven (multi-module)
Java version in use: OpenJDK 11.0.27
Modules: common, service, factory, value

ROOT CAUSE
----------
All four modules fail with the same error:

  ERROR: Could not resolve dependencies for project ...:
  Could not find artifact com.sun:tools:jar:11.0.27
  at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar

EXPLANATION
-----------
The project was designed for Java 7/8, where javax.annotation.processing and
javax.lang.model classes lived in tools.jar (located at $JAVA_HOME/../lib/tools.jar).

Starting with Java 9 (module system / Project Jigsaw), tools.jar was removed.
The classes that were in tools.jar are now part of the java.compiler and
jdk.compiler modules and are available automatically on the classpath.

The dependency chain causing the failure:
  1. compile-testing (versions 0.6, 0.7, 0.8) declares a system-scoped dependency:
       <dependency>
         <groupId>com.sun</groupId>
         <artifactId>tools</artifactId>
         <version>${java.version}</version>
         <scope>system</scope>
         <systemPath>${toolsjar}</systemPath>
       </dependency>
  2. The parent POM (auto-parent v3) has profiles that set ${toolsjar} to
     ${java.home}/../lib/tools.jar, which doesn't exist on Java 11.
  3. Maven tries to resolve this system-scoped dependency and fails because
     the file does not exist at the specified path.

AFFECTED MODULES AND THEIR compile-testing VERSIONS
----------------------------------------------------
  - common/pom.xml: compile-testing 0.7 (test scope)
  - service/pom.xml: compile-testing 0.6 (test scope)
  - factory/pom.xml: compile-testing 0.8 (test scope)
  - value/pom.xml: compile-testing 0.6 (test scope)

FIX PLAN
--------
1. Update the root pom.xml (auto-parent) to add a Java 9+ profile that sets
   toolsjar to a dummy/empty value and adds the tools dependency conditionally.

2. Add exclusions for com.sun:tools from compile-testing in each of the four
   module POMs (common, service, factory, value).

3. Also exclude com.sun:tools from auto-common dependencies in service/pom.xml
   and factory/pom.xml since the published auto-common versions (0.3, 0.5)
   may also transitively pull in compile-testing.

SPECIFIC CHANGES
----------------
File 1: pom.xml (root)
  - Add a new profile "jdk9+" that activates on Java 9+ and provides
    an empty/noop toolsjar property to prevent the default profile from
    pointing to a nonexistent file.

File 2: common/pom.xml
  - Add exclusion of com.sun:tools from compile-testing dependency.

File 3: service/pom.xml
  - Add exclusion of com.sun:tools from compile-testing dependency.

File 4: factory/pom.xml
  - Add exclusion of com.sun:tools from compile-testing dependency.

File 5: value/pom.xml
  - Add exclusion of com.sun:tools from compile-testing dependency.
