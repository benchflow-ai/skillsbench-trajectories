Analysis
- Code fails on Python 3.7/3.8 due to use of PEP-585 built-in generics: `self.queue: list[Dict]` in `agentops/worker.py` raises `TypeError: 'type' object is not subscriptable` at import time. This blocks the package on the supported versions in `tox.ini`.
- `Client.__init__` only sets `_tags_for_future_session` when `auto_start_session=False`. When `agentops.init(..., auto_start_session=True)` is called with no tags, `Client.start_session` uses `tags or self._tags_for_future_session`, which raises `AttributeError` because the attribute was never set.
- `Client` is a singleton that never reinitializes on subsequent `agentops.init` calls. Tests call `agentops.init` in multiple classes expecting fresh configuration and/or an auto-started session. Because the same instance is reused, later tests can run without a session (so `record()` is a no-op and timestamps don't update) or inherit stale session state. This is a code-level lifecycle bug.

Plan
- Update `agentops/worker.py` to use `List[Dict]` from `typing` for Python 3.7 compatibility.
- Initialize `_tags_for_future_session` in `Client.__init__` regardless of `auto_start_session`, and guard `start_session` to avoid missing attributes.
- Allow safe re-initialization when `agentops.init` is called again: adjust the singleton wrapper to call `__init__` on existing instances when args/kwargs are provided, and add a lightweight reset in `Client` that stops the worker thread without making HTTP calls, clearing any stale session state.
