Analysis:
- Running `mvn -f build-pom.xml verify` fails in module `auto-common` with `Could not find artifact com.sun:tools:jar:11.0.27 ... tools.jar`. This happens because the build is running on JDK 11, which no longer provides `tools.jar`.
- The module POMs (`common`, `factory`, `service`, `value`) use parent `com.google.auto:auto-parent:3`, which is resolved from Maven Central. That parent declares a system-scoped dependency on `com.sun:tools` pointing at `${java.home}/../lib/tools.jar`, which fails on JDK 9+.
- The repo's root `pom.xml` is `auto-parent` version `4-SNAPSHOT` and does NOT declare the tools.jar dependency; it only defines a `toolsjar` property with a profile that activates when tools.jar exists.

Plan:
- Update each module POM to use the in-repo parent `com.google.auto:auto-parent:4-SNAPSHOT` so the build uses the local parent without the tools.jar dependency.
- Re-run `mvn -f build-pom.xml verify` to confirm the build succeeds on JDK 11.
