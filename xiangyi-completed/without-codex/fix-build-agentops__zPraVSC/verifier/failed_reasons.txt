Analysis:
- The build failures are test-related rather than packaging issues. `agentops.init(...)` is expected to create a fresh, configured client in each test setup, but the `Client` is a singleton that ignores subsequent initialization arguments. After a previous test leaves a session active or a client configured, later tests call `agentops.init(...)` and get the old instance without reconfiguring or restarting a session. This causes `start_session()` to no-op and `record()` to drop events, which breaks tests that assert request counts and timestamp changes.
- There is also a latent crash: when `auto_start_session=True` and `tags` is `None`, `_tags_for_future_session` is never initialized before `start_session()` tries to use it. This can raise `AttributeError` if the first init happens in that mode.

Plan:
- Add a `Client.reconfigure(...)` method that resets runtime state (session/worker) without making network calls, updates the configuration/tags, and optionally starts a new session.
- Update the singleton helper to call `reconfigure(...)` whenever the singleton is requested with init args, so repeated `agentops.init(...)` calls properly reset the client.
- Initialize `_tags_for_future_session` in `Client.__init__` and guard `_handle_unclean_exits` so handlers aren’t registered repeatedly.
