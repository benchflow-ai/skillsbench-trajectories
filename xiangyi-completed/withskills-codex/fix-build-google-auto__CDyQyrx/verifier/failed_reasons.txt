Analysis (2026-01-29):
- Build command `mvn -B -U -f build-pom.xml verify --fail-at-end -Dsource.skip=true -Dmaven.javadoc.skip=true` fails on JDK 11 with multiple issues.
- Issue 1 (dependency resolution): test dependency `com.google.testing.compile:compile-testing` (0.6–0.8) pulls a system-scoped `com.sun:tools` dependency with `systemPath=${toolsjar}`. JDK 11 has no `tools.jar`, so Maven cannot resolve it. This is a build configuration/dependency issue.
- Issue 2 (test failure): `auto-common` test `VisibilityTest#effectiveClassVisibility` expects PUBLIC but gets DEFAULT. On JDK 9+, `Element` hierarchies include `ModuleElement`; `Visibility.effectiveVisibilityOfElement` walks enclosing elements and treats non-package elements with no modifiers as DEFAULT, so module elements incorrectly reduce visibility.
- Issue 3 (compile error): `auto-factory` fails to compile because `javax.annotation.Generated` is missing in JDK 11. The class used to be in the JDK but now requires `javax.annotation-api` as a dependency.

Plan:
1) Exclude `com.sun:tools` from `compile-testing` dependencies in modules that declare it (common, factory, service, value).
2) Update `Visibility.ofElement` to treat module elements as PUBLIC (e.g., by checking `element.getKind().name().equals("MODULE")`) so effective visibility isn’t reduced on JDK 9+.
3) Add `javax.annotation:javax.annotation-api` (scope `provided`) to modules that compile against `javax.annotation.Generated` (factory and value).
4) Re-run the Maven verify command to confirm the build passes.
