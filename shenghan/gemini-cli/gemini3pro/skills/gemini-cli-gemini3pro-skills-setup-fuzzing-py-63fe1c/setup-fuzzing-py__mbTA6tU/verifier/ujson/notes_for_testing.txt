Fuzzing Target Note

- Target: ujson.loads, ujson.dumps
- File / location: ujson/__init__.py
- Why this target:
    - Input surface: JSON parsing and encoding.
    - Complexity: C extension, high risk of segfaults/buffer overflows.
    - Current test gaps: Existing fuzzer is generative (random structures), coverage-guided bytes fuzzing can find parsing edge cases.
- Callable contract:
    - Required imports: `import ujson`
    - Preconditions: None.
    - Determinism concerns: Deterministic.
    - External dependencies: None (stdlib).
- Input model:
    - Primary payload type: `str` (or `bytes` if supported).
    - Decoding: `data.decode("utf-8", "ignore")`.
    - Edge classes: Malformed JSON, deeply nested, unicode surrogates.
- Oracles:
    - Must-hold properties: No crash (segfault).
    - Acceptable exceptions: `ValueError`, `TypeError` (for `dumps` with bad types).
    - Suspicious exceptions: None, mostly crashes are the concern.
- Harness plan:
    - `atheris.Setup`
    - `TestOneInput(data)`:
        - `fdp = atheris.FuzzedDataProvider(data)`
        - `s = fdp.ConsumeUnicode(sys.maxsize)`
        - `try: o = ujson.loads(s) except ValueError: return`
        - `try: ujson.dumps(o) except (ValueError, TypeError, OverflowError): pass`
- Risk flags:
    - C extension crashes are fatal to the fuzzer process (but Atheris handles some, `uv run` will show exit code).
- Next actions:
    1. Setup env (build extension).
    2. Write fuzz.py.
    3. Run.
