Fuzzing Target Note

- Target: black.format_str
- File / location: black/__init__.py
- Why this target:
    - Input surface: Main API for formatting code strings.
    - Complexity: Involves parsing (lib2to3), AST transformation, line generation, printing. High complexity.
    - Current test gaps: Unit tests cover valid code mostly. Fuzzing can find edge cases in parser or formatter crashing on invalid/weird inputs.
- Callable contract:
    - Required imports: `import black`
    - Preconditions: None.
    - Determinism concerns: `format_str` should be deterministic.
    - External dependencies: None.
- Input model:
    - Primary payload type: `str`.
    - Decoding: `data.decode("utf-8", "ignore")`.
    - Edge classes: Invalid syntax (should raise InvalidInput), deeply nested code, huge integers, unicode identifiers.
- Oracles:
    - Must-hold properties: No crash.
    - Acceptable exceptions: `black.InvalidInput`, `black.NothingChanged` (though `format_str` might return same string, `reformat_one` raises it). `format_str` raises `NothingChanged` if `src == dst`, so we should catch it.
    - Suspicious exceptions: `AssertionError`, `IndexError`, `ValueError` (unless wrapped).
- Harness plan:
    - `atheris.Setup(sys.argv, TestOneInput)`
    - `TestOneInput(data)`:
        - `fdp = atheris.FuzzedDataProvider(data)`
        - `s = fdp.ConsumeUnicode(sys.maxsize)`
        - `try: black.format_str(s, mode=black.Mode()) except (black.InvalidInput, black.NothingChanged): pass`
- Risk flags:
    - `ASTSafetyError` might be raised if fuzzing finds a safety bug (which is good!).
- Next actions:
    1. Setup env.
    2. Write fuzz.py.
    3. Run.
