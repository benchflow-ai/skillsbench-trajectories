Analysis:
The build failure is caused by a compilation error in the `auto-value` functional integration test.
Specifically, `com.google.auto.value.AutoValueTest` in `value/src/it/functional` fails to compile because it cannot find the symbol `com.google.common.base.MoreObjects`.
This class was introduced in Guava 18.0.
The integration test's `pom.xml` depends on `com.google.truth:truth:0.25` and `com.google.guava:guava-testlib:18.0`.
Due to Maven's dependency resolution rules, since `truth:0.25` is declared before `guava-testlib:18.0`, and both are at the same distance from the project, the version of Guava pulled in by Truth (which is 17.0) takes precedence over the version pulled in by `guava-testlib` (which is 18.0).
Guava 17.0 does not contain `MoreObjects`, leading to the compilation error.

Plan:
1. Modify `value/src/it/functional/pom.xml` to add a direct dependency on `com.google.guava:guava:18.0` with test scope. This will ensure that Guava 18.0 is used during test compilation regardless of the order of other dependencies.
2. (Optional) Swap the order of dependencies in `value/src/it/functional/pom.xml` so that `guava-testlib:18.0` comes before `truth:0.25`, but adding a direct dependency is more robust.
I'll go with adding the direct dependency.
