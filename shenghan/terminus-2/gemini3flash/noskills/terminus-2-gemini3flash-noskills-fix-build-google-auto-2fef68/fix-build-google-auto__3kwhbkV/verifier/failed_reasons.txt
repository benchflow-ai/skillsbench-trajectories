Analysis:
- Build failure was initially caused by missing tools.jar when running on Java 11. Java 9+ removed tools.jar, but the project and its dependencies (like compile-testing:0.7) expect it.
- Switching to Java 8 resolved the tools.jar issue as it is included in the JDK 8.
- Subsequent compilation errors in auto-value integration tests were due to:
  1. Encoding issues: Source files contained non-ASCII characters but were compiled with ASCII encoding.
  2. Missing symbol (MoreObjects): The functional integration test was picking up an older version of Guava (17.0) that lacked the MoreObjects class, while the test code required it.

Plan:
- Use Java 8 for the build to satisfy tools.jar requirement.
- Update integration test pom.xml files to explicitly use UTF-8 encoding for compilation.
- Update functional integration test pom.xml to explicitly depend on Guava 18.0 to provide MoreObjects class.
