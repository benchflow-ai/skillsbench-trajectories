# UltraJSON (ujson) Library - Fuzz Testing Notes

## Library Overview
UltraJSON is an ultra fast JSON encoder and decoder written in pure C with
Python bindings. It provides fast JSON parsing and serialization as a drop-in
replacement for the standard json module.

## Important Files for Fuzzing
1. src/ujson/python/ujson.c - Main Python module interface
2. src/ujson/python/JSONtoObj.c - JSON parsing (decode)
3. src/ujson/python/objToJSON.c - JSON encoding (encode)
4. src/ujson/lib/ultrajsondec.c - Core decoder in C
5. src/ujson/lib/ultrajsonenc.c - Core encoder in C
6. tests/fuzz.py - Existing fuzzer for reference

## Key Functions Under Test (FUTs)

### 1. ujson.loads() / ujson.decode() [HIGH PRIORITY]
- Input: JSON string/bytes to parse
- Reason: Main entry point for parsing untrusted JSON data
- Edge cases: Deeply nested structures, large numbers, unicode, malformed JSON
- Oracle: No crashes, proper JSONDecodeError on invalid input

### 2. ujson.dumps() / ujson.encode() [HIGH PRIORITY]
- Input: Python object to serialize
- Reason: Main entry point for encoding objects to JSON
- Options: indent, ensure_ascii, encode_html_chars, escape_forward_slashes
- Edge cases: Recursive structures, special floats (inf/nan), large structures
- Oracle: No crashes, valid JSON output, no memory leaks

### 3. ujson.load() [MEDIUM PRIORITY]
- Input: File-like object with JSON data
- Reason: File-based JSON parsing
- Edge cases: Large files, streaming

### 4. ujson.dump() [MEDIUM PRIORITY]
- Input: Python object, file-like output
- Reason: File-based JSON writing
- Edge cases: Large outputs, encoding issues

## Recommended Fuzzing Targets

### Primary Target: ujson.loads()
- Accepts arbitrary byte/string input
- C implementation makes memory bugs possible
- Good for finding buffer overflows, use-after-free, etc.
- Oracles:
  - No crashes or memory corruption
  - Proper exceptions for invalid JSON
  - Memory should be freed properly

### Secondary Target: ujson.dumps()
- C extension serialization
- Test with various Python object types
- Oracles:
  - No crashes
  - Valid JSON output
  - No reference count issues

## Harness Strategy
1. Generate random JSON-like byte strings
2. Call ujson.loads() with fuzzed input
3. Catch expected JSONDecodeError exceptions
4. Report crashes, ASAN violations, or memory issues

For encoding:
1. Generate random Python objects (as in existing fuzz.py)
2. Call ujson.dumps() with various options
3. Check for reference count issues (as in existing tests)
4. Report crashes or memory corruption

## Dependencies
- setuptools>=42
- setuptools_scm[toml]>=3.4
- Build requires C compiler (gcc/clang)

## Notes
- This is a C extension - memory safety bugs are possible
- Existing fuzz.py provides good fuzzing infrastructure for encoding
- Library must be built from source (pip install -e .)
- Consider using AddressSanitizer (ASAN) for memory bug detection:
  CFLAGS='-fsanitize=address' python setup.py build_ext --inplace
- The loads() function is the primary attack surface for untrusted input
