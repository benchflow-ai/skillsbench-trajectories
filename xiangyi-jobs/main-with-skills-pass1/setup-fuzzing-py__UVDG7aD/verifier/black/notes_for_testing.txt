# Black Library - Fuzz Testing Notes

## Library Overview
Black is "The uncompromising code formatter" for Python. It parses Python source code
and reformats it according to its style rules. The core functionality involves parsing
Python code and transforming it.

## Important Files for Fuzzing
1. src/black/__init__.py - Main entry points (format_str, format_file_contents)
2. src/black/parsing.py - Python code parsing (lib2to3_parse, parse_ast)
3. src/blib2to3/pgen2/driver.py - Parser driver
4. src/blib2to3/pgen2/tokenize.py - Tokenization
5. src/black/linegen.py - Line generation from AST

## Key Functions Under Test (FUTs)

### 1. format_str() [HIGH PRIORITY]
- File: src/black/__init__.py:1177
- Signature: format_str(src_contents: str, *, mode: Mode, lines: Collection[tuple[int, int]] = ()) -> str
- Input: Python source code string
- Reason: Main public API for formatting strings, complex parsing and transformation
- Oracles: No crash, valid Python output, idempotence (re-formatting produces same result)

### 2. lib2to3_parse() [HIGH PRIORITY]
- File: src/black/parsing.py:55
- Signature: lib2to3_parse(src_txt: str, target_versions: Collection[TargetVersion] = ()) -> Node
- Input: Python source code string
- Reason: Core parsing function, tries multiple grammars
- Edge cases: Invalid syntax, partial code, edge Python versions, unicode

### 3. format_file_contents() [MEDIUM PRIORITY]
- File: src/black/__init__.py:1068
- Signature: format_file_contents(src_contents: str, *, fast: bool, mode: Mode, lines: Collection[tuple[int, int]] = ()) -> FileContent
- Input: Python source code string
- Reason: Wraps format_str with AST safety checks
- Oracles: No crash, equivalent AST, stable output

### 4. parse_ast() [MEDIUM PRIORITY]
- File: src/black/parsing.py:137
- Signature: parse_ast(src: str) -> ast.AST
- Input: Python source code string
- Reason: Standard library AST parsing with version fallbacks
- Edge cases: Invalid syntax, type comments

### 5. format_cell() [LOWER PRIORITY]
- File: src/black/__init__.py:1096
- Signature: format_cell(src: str, *, fast: bool, mode: Mode) -> str
- Input: Jupyter notebook cell content
- Reason: Handles IPython magics and cell-specific formatting
- Edge cases: Magic commands, trailing semicolons

## Recommended Fuzzing Targets

### Primary Target: format_str()
- Accepts arbitrary Python-like string input
- Complex parsing, transformation, and formatting logic
- Good for finding edge cases in formatting
- Oracles:
  - No crash on any input
  - Valid Python output when input is valid Python
  - Idempotence: format_str(format_str(x)) == format_str(x)
  - AST equivalence: parse(input) ~ parse(output)

### Secondary Target: lib2to3_parse()
- Lower-level parsing function
- Tests parser robustness directly
- Oracles: No crash, raises InvalidInput on bad syntax

## Harness Strategy
1. Generate random Python-like strings (can use structured generation)
2. Call format_str() with fuzzed input and default Mode
3. Catch expected exceptions (InvalidInput, etc.)
4. Report crashes or unexpected exceptions
5. Optionally verify idempotence and AST equivalence
