# MiniSGL Library - Fuzz Testing Notes

## Library Overview
MiniSGL is a Python library for serving Large Language Models (LLMs). It provides
scheduling, attention backends, KV caching, and message serialization/deserialization
for efficient LLM inference.

## Important Files for Fuzzing
1. python/minisgl/message/utils.py - Serialization/deserialization functions
2. python/minisgl/core.py - Core data structures (SamplingParams, Req, Batch)
3. python/minisgl/engine/config.py - Configuration parsing
4. python/minisgl/tokenizer/ - Tokenization utilities

## Key Functions Under Test (FUTs)

### 1. deserialize_type() [HIGH PRIORITY]
- File: python/minisgl/message/utils.py:52
- Signature: deserialize_type(cls_map: Dict[str, Type], data: Dict) -> Any
- Input: Dictionary with serialized data and type mappings
- Reason: Deserializes untrusted data to Python objects, security-critical
- Edge cases: Missing keys, invalid types, malformed buffers, type confusion
- Oracle: No crashes, proper error handling for invalid data

### 2. _deserialize_any() [HIGH PRIORITY]
- File: python/minisgl/message/utils.py:38
- Signature: _deserialize_any(cls_map: Dict[str, Type], data: Any) -> Any
- Input: Any serialized data
- Reason: Recursive deserialization, handles nested structures
- Edge cases: Deep nesting, circular references, type mismatches

### 3. serialize_type() [MEDIUM PRIORITY]
- File: python/minisgl/message/utils.py:20
- Signature: serialize_type(self) -> Dict
- Input: Any Python object
- Reason: Converts objects to serializable format
- Edge cases: Large tensors, unsupported types, edge values

### 4. SamplingParams validation [LOWER PRIORITY]
- File: python/minisgl/core.py:15
- Input: temperature, top_k, top_p, max_tokens
- Reason: Validates sampling parameters
- Edge cases: Boundary values, negative values, extreme floats

### 5. Req.__post_init__() [LOWER PRIORITY]
- File: python/minisgl/core.py:37
- Input: Request parameters
- Reason: Validates request state
- Edge cases: Invalid lengths, boundary conditions

## Recommended Fuzzing Targets

### Primary Target: deserialize_type()
- Accepts dictionary data that could come from untrusted sources
- Security-critical: constructs Python objects from data
- Good for finding type confusion and crash bugs
- Oracles:
  - No crashes on malformed data
  - Proper ValueError/KeyError on invalid inputs
  - No arbitrary code execution

### Secondary Target: Message encoding/decoding
- BatchBackendMsg, UserMsg have encoder/decoder methods
- Round-trip testing: encode then decode
- Oracle: Round-trip produces equivalent object

## Harness Strategy
1. Generate random dictionary structures with __type__ fields
2. Include valid and invalid type names, buffers, nested dicts
3. Call deserialize_type() with fuzzed data
4. Catch expected exceptions (ValueError, KeyError, etc.)
5. Report crashes or unexpected behavior

- Heavy dependency on PyTorch and CUDA libraries
