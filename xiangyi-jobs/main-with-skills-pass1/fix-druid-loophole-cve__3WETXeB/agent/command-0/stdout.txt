### Summary of Changes
The vulnerability was caused by Jackson's default behavior, which allowed user-supplied JSON properties (including empty keys `""`) to override or satisfy parameters intended for server-side injection via `@JacksonInject`. Specifically, attackers could provide a `{"enabled": true}` object mapped to an empty key to bypass security settings that disable JavaScript.

To fix this, I modified all JavaScript-related components that use `JavaScriptConfig` to ensure the configuration is ONLY ever obtained from the server's injector and never from the JSON input. This was achieved by:
- Adding the `com.fasterxml.jackson.annotation.OptBoolean` import to affected classes.
- Updating the `@JacksonInject` annotation on the `JavaScriptConfig` parameter in constructors to include `useInput = OptBoolean.FALSE`.
