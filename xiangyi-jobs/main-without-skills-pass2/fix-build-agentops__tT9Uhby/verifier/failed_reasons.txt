Failure analysis:
- Pytest failure in `tests/test_events.py::TestEvents::test_record_timestamp`.
- `agentops.record()` logs "Cannot record event - no current session" and returns early, so the ActionEvent `end_timestamp` stays equal to `init_timestamp`.
- Root cause is code logic: `agentops.init()` uses a singleton `Client`. If a prior test created the singleton with `auto_start_session=False`, subsequent calls to `init()` do not re-run `Client.__init__`, so no session is started. This leaves `_session` as `None` and `record()` is a no-op.
- Build configuration is fine; this is a code-level lifecycle/initialization bug.

Plan:
- Update `agentops.init()` to handle the existing singleton instance:
  - Refresh configuration when explicit parameters are provided (or when config is missing), falling back to existing config values.
  - Ensure `_tags_for_future_session` is set when tags are provided or missing.
  - If `auto_start_session=True` and there is no active session, start a new session.
- Keep changes minimal and focused to avoid altering unrelated behavior.
