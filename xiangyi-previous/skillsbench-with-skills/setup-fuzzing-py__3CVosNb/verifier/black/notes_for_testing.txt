LIBRARY OVERVIEW
--------------------------------------------------------------------------------
Black is "The uncompromising Python code formatter." It is a widely-used code
formatter that reformats Python code to conform to a consistent style. The core
functionality involves:

1. Parsing Python source code using a lib2to3-based parser (blib2to3)
2. Building an intermediate representation (AST/CST)
3. Reformatting the code according to Black's style rules
4. Validating that the reformatted code is semantically equivalent

Key aspects relevant to fuzzing:
- Accepts arbitrary Python source code as string input
- Uses complex parsing logic (tokenizer + parser)
- Handles edge cases in Python syntax across multiple Python versions
- Processes Jupyter notebook cells with IPython magics
- Contains multiple layers of string processing

Version: Uses Python 3.10+ with support for Python 3.10-3.14 target versions

FUT #1: format_str
--------------------------------------------------------------------------------
Location: /app/black/src/black/__init__.py:1177
Signature: format_str(src_contents: str, *, mode: Mode, lines: Collection[tuple[int, int]] = ()) -> str

Description:
  The main public API for formatting Python source code. Takes a string of
  Python code and returns the reformatted version.

Why it's a good fuzz target:
  - Primary entry point for all formatting operations
  - Accepts arbitrary string input
  - Exercises the full formatting pipeline (parsing, line generation, output)
  - Well-documented expected behavior (idempotent formatting)
  - Already has property-based tests in scripts/fuzz.py

Input Type: str (Python source code)

Harnessability: HIGH
  - Simple function signature
  - Only requires string input and Mode configuration
  - Returns string output (easy to check)
  - No file I/O required

Oracles:
  1. Idempotency: format_str(format_str(code)) == format_str(code)
  2. AST equivalence: AST of input should equal AST of output
  3. No crashes on valid Python syntax
  4. Should raise InvalidInput on syntactically invalid code (not crash)
  5. Output should be valid Python (compile() should succeed)

Edge Cases to Test:
  - Empty string
  - Whitespace-only strings
  - Very long lines (> 10000 characters)
  - Deeply nested structures (> 100 levels)
  - Mixed indentation (tabs and spaces)
  - Unicode identifiers and strings
  - F-strings with complex expressions
  - Match statements (Python 3.10+)
  - Type parameter syntax (Python 3.12+)
  - Triple-quoted strings with embedded quotes
  - Comments at various positions
  - Trailing commas
  - Very long string literals
  - Null bytes in strings
  - Control characters
  - Multiple encoding declarations
  - Future imports
  - Decorators with complex expressions

  - Partial statements
  - Binary data masquerading as text
  - Very long identifiers

  - Unicode normalization edge cases
