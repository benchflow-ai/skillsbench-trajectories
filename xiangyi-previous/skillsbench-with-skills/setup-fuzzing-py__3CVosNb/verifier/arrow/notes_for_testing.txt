# Arrow Library - Fuzzing Target Notes

## Library Overview
Arrow is a Python library that provides better dates and times. It offers a sensible, human-friendly approach to creating, manipulating, formatting, and converting dates, times, and timestamps.

## Important Files
1. arrow/parser.py - Main parsing logic for datetime strings (HIGH PRIORITY)
2. arrow/factory.py - Factory methods for creating Arrow objects
3. arrow/formatter.py - Datetime formatting logic
4. arrow/util.py - Utility functions including timestamp normalization

## Selected Functions Under Test (FUTs)

### FUT 1: DateTimeParser.parse_iso()
- File: arrow/parser.py:252
- Why: Primary ISO 8601 datetime string parsing function. Handles complex input parsing with multiple format detection.
- Input: String representing datetime in ISO 8601-like format
- Harnessability: HIGH
- Oracles:
  - Should not crash on malformed input
  - Should raise ParserError for invalid formats
  - Valid input should produce valid datetime object
- Edge cases:
  - Empty strings
  - Very long strings
  - Invalid date components (month > 12, day > 31)
  - Malformed timezone offsets
  - Unicode characters
  - Null bytes

### FUT 2: DateTimeParser.parse()
- File: arrow/parser.py:373
- Why: General-purpose datetime parsing with custom format strings
- Input: Datetime string and format string(s)
- Harnessability: HIGH
- Oracles:
  - Should not crash on malformed input
  - Should raise ParserMatchError when format doesn't match
- Edge cases:
  - Mismatched format and input
  - Invalid format tokens
  - Empty format strings

### FUT 3: TzinfoParser.parse()
- File: arrow/parser.py:894
- Why: Timezone string parsing - handles various timezone formats
- Input: String representing timezone
- Harnessability: HIGH
- Oracles:
  - Should not crash on malformed input
  - Should raise ParserError for invalid timezone
- Edge cases:
  - Invalid timezone names
  - Malformed UTC offsets
  - Very large offsets

### FUT 4: ArrowFactory.get()
- File: arrow/factory.py:85
- Why: Main entry point for creating Arrow objects from various inputs
- Input: Various types (str, int, float, datetime, etc.)
- Harnessability: MEDIUM (multiple input types)
- Oracles:
  - Should not crash on unexpected input
  - Should raise TypeError for unsupported types

### FUT 5: normalize_timestamp()
- File: arrow/util.py:73
- Why: Timestamp normalization (ms/us to seconds conversion)
- Input: Float timestamp value
- Harnessability: HIGH
- Oracles:
  - Should handle large timestamps correctly
  - Should raise ValueError for too-large timestamps

## Recommended Fuzzing Strategy
1. Primary focus on parse_iso() as it handles untrusted string input
2. Use Atheris for Python fuzzing with LibFuzzer backend
3. Generate random strings with datetime-like patterns
4. Test boundary conditions for date/time components
