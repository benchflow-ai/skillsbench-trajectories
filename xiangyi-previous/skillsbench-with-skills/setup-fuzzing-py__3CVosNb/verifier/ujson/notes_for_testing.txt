1. LIBRARY OVERVIEW
================================================================================

UltraJSON (ujson) is a fast JSON encoder and decoder written in C with Python
bindings. It was originally developed by ESN, an Electronic Arts Inc. studio.

Key Features:
- High-performance JSON parsing and serialization
- Written in C for speed with Python C extension interface
- Supports Python str, bytes, and bytearray input for decoding
- Handles special JSON values: NaN, Infinity, -Infinity (non-standard)
- Configurable recursion depth limits (default 1024)
- UTF-8 encoding/decoding with surrogate pair handling
- Supports unicode escape sequences (\uXXXX)
- Uses double-conversion library for floating-point parsing

Architecture:
- Python bindings in src/ujson/python/
- Core C library in src/ujson/lib/
- JSON decoding: ultrajsondec.c -> JSONtoObj.c -> Python objects
- JSON encoding: ultrajsonenc.c -> objToJSON.c -> JSON string

FUT #1: ujson.loads (PRIMARY TARGET - HIGHEST PRIORITY)
-------------------------------------------------------------------------------

Location:
  Python API: /app/ujson/src/ujson/python/ujson.c:68
  Implementation: /app/ujson/src/ujson/python/JSONtoObj.c:163 (JSONToObj)
  Core parser: /app/ujson/src/ujson/lib/ultrajsondec.c:790 (JSON_DecodeObject)

Function Signature:
  def loads(s: str | bytes | bytearray) -> Any

Description:
  Parses a JSON string and converts it to Python objects (dict, list, str,
  int, float, bool, None). This is the primary entry point for untrusted
  JSON data parsing.

Why it's a good fuzz target:
  - Accepts arbitrary string/bytes input directly
  - Complex parsing logic with multiple code paths (strings, numbers, arrays,
    objects, special values)
  - History of memory safety issues in JSON parsers
  - C implementation vulnerable to buffer overflows, integer overflows
  - UTF-8 decoding and unicode escape handling prone to edge cases
  - Deep recursion handling (stack exhaustion)

Input Type: str | bytes | bytearray
  - Fuzzer should generate both valid and malformed JSON
  - Support for bytes allows testing raw binary input

Harnessability: HIGH
  - Simple function signature with single input parameter
  - No complex setup required
  - Direct mapping from fuzz input to function argument
  - Returns Python object or raises exception

Oracles (Expected Behaviors):
  1. Valid JSON should parse without crashing
  2. Invalid JSON should raise ujson.JSONDecodeError (subclass of ValueError)
  3. No memory leaks or corruption
  4. No segmentation faults or undefined behavior
  5. Result should be equivalent to json.loads() for valid JSON
  6. Deeply nested input should raise error, not crash (depth limit 1024)

Edge Cases to Test:
  - Empty string: ""
  - Whitespace only: "   \t\n\r  "
  - Single values: null, true, false
  - Numeric edge cases:
    * Very large integers (beyond 64-bit range)
    * Very small/large floats (denormals, infinity)
    * Scientific notation edge cases: 1e309, 1e-400
    * Leading zeros: 00, 01, -00
    * Just minus sign: "-"
    * Decimal without digits: ".", ".5", "5."
  - String edge cases:
    * Empty string: '""'
    * Null bytes: '"hello\u0000world"'
    * Invalid UTF-8 sequences
    * Overlong UTF-8 sequences
    * Truncated UTF-8 sequences
    * Surrogate pairs: '\uD800\uDC00'
    * Unpaired surrogates: '\uD800', '\uDC00'
    * Invalid escape sequences: '\x', '\q'
    * Unterminated strings: '"hello'
    * Unterminated escape: '"\\'
  - Array/Object edge cases:
    * Deep nesting: [[[[...]]]]  (> 1024 levels)
    * Trailing commas: [1,2,3,]
    * Missing values: [,,,]
    * Non-string keys: {123: "value"}
    * Duplicate keys
  - Special values:
    * NaN, Infinity, -Infinity (ujson extension)
    * Partial special values: Na, Inf, Infinit
  - Boundary testing:
    * Very large strings (gigabytes if possible)
    * Many array/object elements
  - Malformed input:
    * Random binary data
    * Truncated JSON
    * Extra trailing data
    * Mixed valid/invalid

-------------------------------------------------------------------------------

Location:

Function Signature:

      sort_keys: bool = False,
      indent: int = 0,
      allow_nan: bool = True,
      reject_bytes: bool = True,
      default: Callable[[Any], Any] | None = None,
      separators: tuple[str, str] | None = None,

Description:
  Serializes Python objects to JSON string.

Why it's a fuzz target:
  - Handles arbitrary Python objects
  - Multiple configuration options increase attack surface
  - Recursive object traversal
  - Custom serialization via default callback

Harnessability: MEDIUM
  - Requires constructing Python objects from fuzz input
  - Can use loads() output as dumps() input for differential testing

Oracles:
  - Output should be valid JSON (parseable by json.loads)
  - Roundtrip: loads(dumps(obj)) == obj for JSON-compatible objects
  - No crashes on deeply nested objects

Edge Cases (for encode testing):
  - Cyclic references
  - Very deep object nesting
  - Objects with custom __json__ or toDict methods
  - Large integers beyond 64-bit
  - Special float values (NaN, Inf)
  - Invalid indent values
  - Custom separators with special characters

Primary Fuzzer Harness (for ujson.loads):

```python
import atheris
import sys

with atheris.instrument_imports():
    import ujson

def TestOneInput(data):
    try:
        result = ujson.loads(data)
        # Optional: roundtrip test
        # encoded = ujson.dumps(result)
        # _ = ujson.loads(encoded)
    except (ujson.JSONDecodeError, ValueError, TypeError,
            OverflowError, RecursionError):
        pass  # Expected exceptions for invalid input

if __name__ == "__main__":
    atheris.Setup(sys.argv, TestOneInput)
    atheris.Fuzz()
```

```python
        # Both parsed successfully - results should match
```

================================================================================
7. KNOWN VULNERABILITY AREAS
================================================================================

Based on code analysis, focus fuzzing on:

1. Unicode/UTF-8 Handling (ultrajsondec.c:362-587)
   - decode_string() has complex UTF-8 validation
   - Surrogate pair handling in unicode escapes
   - Overlong sequence detection

2. Numeric Parsing (ultrajsondec.c:91-247)
   - Integer overflow handling for large numbers
   - Float parsing edge cases
   - NaN/Infinity parsing

3. Recursion Depth (ultrajsondec.c:589-745)
   - decode_array() and decode_object() have depth checks
   - Default limit is 1024 (JSON_MAX_OBJECT_DEPTH)

4. Memory Allocation (ultrajsondec.c:376-411)
   - Dynamic buffer allocation for string escapes
   - Potential for memory exhaustion with large strings

5. Buffer Boundary Handling
   - Ensure no reads past buffer end
   - Particularly in partial/truncated input
