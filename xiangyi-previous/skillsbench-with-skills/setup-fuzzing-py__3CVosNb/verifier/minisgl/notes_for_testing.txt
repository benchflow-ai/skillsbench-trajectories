LIBRARY OVERVIEW
--------------------------------------------------------------------------------
Mini-SGLang is a lightweight yet high-performance inference framework for Large
Language Models (LLMs). It is a compact implementation (~5,000 lines of Python)
of SGLang, designed as both a capable inference engine and a transparent
reference for researchers and developers.

Key features include:
- Radix Cache for KV cache reuse across requests
- Chunked Prefill for long-context serving
- Overlap Scheduling to hide CPU overhead
- Tensor Parallelism for multi-GPU scaling
- FlashAttention and FlashInfer kernel integrations
- OpenAI-compatible API server (FastAPI + uvicorn)
- ZeroMQ-based message passing between components
- MsgPack serialization for inter-process communication

Repository Structure:
- python/minisgl/         - Main Python package
  - message/              - Serialization and message types
  - tokenizer/            - Tokenization and detokenization
  - server/               - FastAPI server and argument parsing
  - scheduler/            - Request scheduling
  - kvcache/              - Cache management (radix tree, naive)
  - kernel/               - Native kernel loading utilities
  - utils/                - ZMQ queues, logging, misc utilities
  - env.py                - Environment variable parsing

IMPORTANT FILES
--------------------------------------------------------------------------------
1. /app/minisgl/python/minisgl/message/utils.py
   - Contains serialize_type() and deserialize_type() functions
   - Handles conversion between Python objects and dict/bytes

2. /app/minisgl/python/minisgl/utils/mp.py
   - ZMQ queue implementations with msgpack encoding/decoding
   - Entry points for untrusted message data

3. /app/minisgl/python/minisgl/tokenizer/detokenize.py
   - find_printable_text() function for streaming text output
   - _is_chinese_char() for CJK character detection

4. /app/minisgl/python/minisgl/env.py
   - _PARSE_MEM_BYTES() for parsing memory size strings
   - Environment variable parsing with type conversion

5. /app/minisgl/python/minisgl/server/api_server.py
   - OpenAI API request handling
   - JSON parsing and validation

FUT #1: deserialize_type()
--------------------------------------------------------------------------------
Location: /app/minisgl/python/minisgl/message/utils.py:52

Function Signature:
    def deserialize_type(cls_map: Dict[str, Type], data: Dict) -> Any

Why it's a good fuzz target:
- Parses untrusted dictionary data into Python objects
- Dynamically looks up class types from a map by name
- Handles recursive deserialization of nested structures
- Reconstructs torch tensors from raw bytes buffers
- Uses getattr(np, dtype_str) which could be exploited with unexpected strings
- Called by message decoders for all inter-process communication

Input Type:
- data: Dict - A dictionary with "__type__" key and arbitrary nested values
- cls_map: Dict[str, Type] - Mapping of type names to classes

Harnessability: HIGH
- Pure function with no external dependencies except numpy/torch
- Can be tested with synthetic dict inputs
- No GPU or network requirements
- Fast execution

Oracles:
- Should correctly reconstruct objects matching the original structure
- Should raise KeyError for unknown type names
- Should raise appropriate errors for malformed tensor buffers
- Should not crash on deeply nested structures
- Should not allow arbitrary code execution via type injection

Edge Cases to Test:
- Missing "__type__" key
- Unknown type name not in cls_map
- Invalid dtype string (e.g., "float999", "__class__", "eval")
- Malformed buffer bytes (wrong length for dtype)
- Empty buffer with non-zero expected size
- Deeply nested recursive structures (stack overflow)
- Very large buffer sizes (memory exhaustion)
- Unicode in type names
- Circular references in data
- Numpy dtype injection attempts ("system", "os")

--------------------------------------------------------------------------------

4. Invalid bytes: b"\xff\xff\xff"

================================================================================
FUZZING STRATEGY RECOMMENDATIONS
================================================================================

1. Start with pure functions (_PARSE_MEM_BYTES, find_printable_text,
   _is_chinese_char) as they have no dependencies.

2. Focus on deserialize_type() as it's the highest-value target:
   - Handles untrusted input from network/IPC
   - Complex type dispatch logic
   - Potential for type confusion vulnerabilities

3. For msgpack fuzzing, use structure-aware fuzzing to generate valid
   msgpack that contains malicious payloads.

4. Test the serialize/deserialize round-trip for property-based testing.

5. Consider differential fuzzing between minisgl and SGLang implementations.
