The vulnerability allowed authenticated attackers to execute arbitrary code by:
1. Sending a malicious JavaScript filter with Java API calls
2. Using an empty string key to potentially bypass security checks
3. Executing system commands via java.lang.Runtime.getRuntime().exec()

The fix validates all JavaScript functions in filters and rejects those containing:
- java.lang.Runtime
- java.lang.ProcessBuilder
- java.io.File

Validation occurs at deserialization time in the JavaScriptDimFilter constructor,
ensuring that malicious payloads are rejected immediately.
