FUZZ TESTING NOTES FOR ARROW LIBRARY
====================================

TARGET LIBRARY: arrow (datetime manipulation)
Main Purpose: Provides user-friendly datetime parsing, formatting, and manipulation

PRIMARY FUZZ TARGETS:
======================

1. DateTimeParser.parse_iso(string, normalize_whitespace=False)
   - File: /app/arrow/arrow/parser.py (line ~90)
   - Input: Arbitrary strings
   - Output: Arrow datetime object or ParserError exception
   - Why fuzz: Automatic ISO 8601 format detection with complex regex patterns
   - Fuzzing focus:
     * Malformed date/time strings
     * Edge cases in timezone handling (offsets, named zones)
     * Deep nesting in complex date formats
     * UTF-8 encoding edge cases
     * Whitespace handling variations

2. DateTimeParser.parse(string, fmt)
   - File: /app/arrow/arrow/parser.py (line ~110)
   - Input: datetime string + format string
   - Output: Arrow datetime object or ParserError exception
   - Why fuzz: User-provided format strings with regex generation
   - Fuzzing focus:
     * Format string injection
     * Invalid format tokens
     * Mismatched string/format combinations
     * Edge case timestamps (leap seconds, year boundaries)
     * Microsecond precision edge cases

3. TzinfoParser.parse(tzinfo_string)
   - File: /app/arrow/arrow/parser.py (line ~800)
   - Input: Timezone string (ISO offset, name, or edge case)
   - Output: tzinfo object or ParserError exception
   - Why fuzz: Timezone string parsing with multiple format support
   - Fuzzing focus:
     * Invalid UTC offsets (+/-HH:MM:SS)
     * Invalid timezone names
     * Numeric timezone edge cases
     * Unicode in timezone strings

4. ArrowFactory.get(*args, **kwargs)
   - File: /app/arrow/arrow/factory.py (line ~90)
   - Input: Flexible arguments (strings, timestamps, datetimes, etc.)
   - Output: Arrow datetime object
   - Why fuzz: High-level API with 10+ input handling paths
   - Fuzzing focus:
     * Type confusion (int vs float vs str)
     * Out-of-range timestamps (before year 1 or after year 9999)
     * Multiple format strings interaction
     * Timezone conversion edge cases

5. Arrow.format(fmt)
   - File: /app/arrow/arrow/arrow.py (line ~1200)
   - Input: format string with datetime tokens
   - Output: Formatted datetime string
   - Why fuzz: Inverse parsing - format token handling
   - Fuzzing focus:
     * Invalid format tokens
     * Locale-specific formatting edge cases
     * Boundary dates (year 1, year 9999)

IMPORTANT DETAILS:
==================
- Max year: 9999
- Min year: 1
- Timezone offset range: -12:00 to +14:00
- Microsecond precision: 0-999999
- Supported format tokens: YYYY, MM, DD, HH, hh, mm, ss, S, Z, ZZ, ZZZ, a, A, dddd, ddd, d, MMMM, MMM, etc.
- Exception types: ParserError, ParserMatchError
- Locale support: 100+ languages

ORACLE PROPERTIES:
===================
1. Round-trip: parse(format(dt)) should equal dt (approximately)
2. Timezone consistency: arrow.get(ts).to(tz) should be deterministic
3. No crashes on malformed input (should raise ParserError)
4. Boundary handling: Year 1 and 9999 should be accepted
5. Negative timestamps should work (pre-1970 dates)

SEED CORPUS IDEAS:
===================
- ISO 8601 standard strings: 2023-01-15T10:30:45Z
- Timezone variations: +00:00, -05:00, UTC, America/New_York
- Edge dates: 0001-01-01, 9999-12-31
- Timestamp ranges: -62135596800 (year 1), 253402300799 (year 9999)
- Format strings with all token types
- Locale-specific strings (month/day names in different languages)
