> # Apache Druid 0.20.0 JavaScript Code Execution Vulnerability Fix
>
> ## Vulnerability Description
>
> Authenticated attackers could execute arbitrary code on the server through malicious JavaScript payloads by bypassing JavaScript security settings using an em
pty key ("") in JSON requests.
>
> Example exploit:
> ```json
> {
>   "type": "index",
>   "spec": {
>     "dataSchema": {
>       "transformSpec": {
>         "filter": {
>           "type": "javascript",
>           "function": "function(){java.lang.Runtime.getRuntime().exec('malicious_command');}",
>           "": {
>             "enabled": true
>           }
>         }
>       }
>     }
>   }
> }
> ```
>
> ## Root Cause
>
> The vulnerability existed because Jackson could deserialize JavaScriptConfig objects from user-provided JSON payloads, allowing attackers to override the syst
em-injected configuration and enable JavaScript execution even when it was disabled at the system level.
>
> ## Fix Applied
>
> The fix prevents JavaScriptConfig from being deserialized from user-provided JSON by:
>
> 1. Adding `@JsonIgnore` annotation to the `config` field in all JavaScript-enabled classes
> 2. Adding validation to ensure the config is properly injected and not null
>
> ## Patched Files
>
> 1. **JavaScriptDimFilter.java** - Filter for JavaScript-based dimension filtering
> 2. **JavaScriptAggregatorFactory.java** - Aggregator using JavaScript functions
> 3. **JavaScriptPostAggregator.java** - Post-aggregator using JavaScript functions
> 4. **JavaScriptParseSpec.java** - Parser specification using JavaScript
> 5. **JavaScriptWorkerSelectStrategy.java** - Worker selection strategy using JavaScript
> 6. **JavaScriptExtractionFn.java** - Extraction function using JavaScript
>
> ## Changes Made
>
> For each vulnerable class:
> - Added `@JsonIgnore` annotation to the `JavaScriptConfig config` field
> - Added validation: `Preconditions.checkNotNull(config, "JavaScriptConfig must be injected, not provided via JSON")`
>
> This ensures that:
> - The config field cannot be deserialized from user JSON
> - The config must come from system injection via Guice
> - Any attempt to provide config via JSON will fail validation
>
