Build Failure Analysis for google/auto
========================================

Error: Could not resolve dependencies for project com.google.auto:auto-common:jar:1.0-SNAPSHOT
Specific Error: Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar

Root Cause:
-----------
1. The project is being built with Java 11 (OpenJDK 11.0.27)
2. The compile-testing:0.7 dependency (used in common/pom.xml as a test dependency) has a system-scoped dependency on com.sun:tools
3. This dependency uses ${toolsjar} as the systemPath
4. The toolsjar property is set in profiles that activate based on file existence:
   - default-profile: checks for ${java.home}/../lib/tools.jar
   - mac-profile: checks for ${java.home}/../Classes/classes.jar
5. In Java 9+, tools.jar was removed and its contents were moved into the JDK modules
6. Neither profile activates in Java 11, so ${toolsjar} is undefined
7. Maven tries to resolve the dependency but fails because the path is invalid

Solution:
---------
Update compile-testing to version 0.10 or later which supports Java 9+ and doesn't require tools.jar.
Alternatively, we could add a Java 9+ profile that sets toolsjar to a dummy value or excludes the dependency.

The simplest fix is to update common/pom.xml to use compile-testing version 0.10 instead of 0.7.

Second Issue Found:
-------------------
After fixing the tools.jar issue, a new compilation error appeared:
- Error: cannot find symbol javax.annotation.Generated in factory/src/main/java/com/google/auto/factory/processor/FactoryWriter.java
- Root Cause: In Java 9+, the javax.annotation package was removed from the JDK and moved to a separate module
- Solution: Add javax.annotation-api dependency to factory/pom.xml
