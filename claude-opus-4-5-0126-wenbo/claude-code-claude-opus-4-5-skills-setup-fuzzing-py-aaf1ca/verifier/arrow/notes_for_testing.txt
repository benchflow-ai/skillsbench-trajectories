from fuzz testing. These functions handle user input parsing, data transformation,
and are potential targets for security and robustness testing.

================================================================================
RECOMMENDED FUZZING STRATEGIES
================================================================================

1. String Parsing Fuzzing:
   - Target: parse_iso(), parse(), TzinfoParser.parse(), dehumanize()
   - Strategy: Generate random strings, malformed ISO dates, unusual characters
   - Focus on: Buffer boundaries, regex edge cases, encoding issues

2. Timestamp Fuzzing:
   - Target: fromtimestamp(), normalize_timestamp(), is_timestamp()
   - Strategy: Generate edge case numbers (negative, very large, NaN, Inf)
   - Focus on: Overflow conditions, precision loss, boundary values

3. Format String Fuzzing:
   - Target: parse() with format strings, format()
   - Strategy: Random token combinations, escape sequences, nested brackets
   - Focus on: Pattern injection, regex complexity attacks

4. Locale Fuzzing:
   - Target: get_locale(), locale-dependent methods
   - Strategy: Random locale names, Unicode variants
   - Focus on: KeyError conditions, dictionary lookups

5. Type Confusion Fuzzing:
   - Target: ArrowFactory.get(), is_timestamp(), validate_ordinal()
   - Strategy: Pass unexpected types, mixed type arguments
   - Focus on: Type checking bypass, implicit conversions

================================================================================
KEY CONSTANTS FOR BOUNDARY TESTING
================================================================================

From /app/arrow/arrow/constants.py:
- MAX_TIMESTAMP: Platform-dependent maximum timestamp
- MAX_TIMESTAMP_MS: MAX_TIMESTAMP * 1000
- MAX_TIMESTAMP_US: MAX_TIMESTAMP * 1_000_000
- MAX_ORDINAL: datetime.max.toordinal()
- MIN_ORDINAL: 1

================================================================================
NOTES ON ERROR HANDLING
================================================================================

The library defines custom exceptions for parsing errors:
- ParserError: General parsing failures (ValueError subclass)
- ParserMatchError: Specific match failures during parsing (ParserError subclass)

These should be caught and handled gracefully during fuzzing to identify
crash-inducing inputs vs expected error conditions.
