================================================================================
MINISGL LIBRARY - IMPORTANT FUNCTIONS FOR FUZZ TESTING
================================================================================

OVERVIEW
--------
MiniSGL (Mini-SGLang) is a lightweight yet high-performance inference framework
for Large Language Models (LLMs). It provides GPU-accelerated inference with
advanced optimizations including radix caching, chunked prefill, overlap
scheduling, and tensor parallelism.

The library is approximately 5,000 lines of Python code with C++/CUDA kernels
for performance-critical operations.

HIGH-PRIORITY FUNCTIONS FOR FUZZ TESTING

1. SERIALIZATION/DESERIALIZATION (Critical - Input Parsing)
   Location: /app/minisgl/python/minisgl/message/utils.py

   Functions:
   - serialize_type(self) -> Dict
   - deserialize_type(cls_map: Dict[str, Type], data: Dict) -> Any
   - _serialize_any(value: Any) -> Any
   - _deserialize_any(cls_map: Dict[str, Type], data: Any) -> Any

   Why Fuzz:
   - These functions handle arbitrary user data deserialization
   - They process dictionaries with "__type__" field to reconstruct objects
   - Support tensor serialization/deserialization from raw bytes
   - Potential for type confusion, buffer overflows, or arbitrary code execution
   - Used for inter-process communication (ZMQ messages)

   Interesting Attack Vectors:
   - Malformed "__type__" fields
   - Invalid buffer sizes in tensor deserialization
   - Nested recursive structures
   - Invalid dtype strings

================================================================================
SUGGESTED FUZZ TESTING APPROACHES
================================================================================

1. UNIT FUZZING:
   - Target individual functions with atheris or similar Python fuzzer
   - Focus on serialization/deserialization first
   - Create structured input generators for message types

2. API FUZZING:
   - Use HTTP fuzzing tools against the FastAPI server
   - Test OpenAI-compatible endpoints with malformed requests
   - Focus on streaming edge cases

3. TENSOR FUZZING:
   - Generate random tensors with various shapes, dtypes, and devices
   - Test boundary conditions for kernel operations
   - Include non-contiguous and view tensors

4. INTEGRATION FUZZING:
   - Create sequences of operations that stress the radix cache
   - Test concurrent request handling
   - Simulate network disconnections during streaming
