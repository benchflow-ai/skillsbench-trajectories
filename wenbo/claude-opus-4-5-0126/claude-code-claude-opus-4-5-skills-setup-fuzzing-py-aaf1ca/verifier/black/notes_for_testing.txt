================================================================================
IMPORTANT FUNCTIONS FOR FUZZ TESTING - BLACK CODE FORMATTER
================================================================================

This document identifies key public APIs and functions in the Black library that
are good candidates for fuzz testing. These functions parse input, handle user
data, or perform complex transformations that could benefit from fuzzing.

================================================================================
1. CORE FORMATTING FUNCTIONS (High Priority)
================================================================================

Location: /app/black/src/black/__init__.py

1.1 format_str(src_contents: str, *, mode: Mode, lines: Collection[tuple[int, int]] = ()) -> str
    - PRIMARY ENTRY POINT for programmatic formatting
    - Takes raw Python source code as string input
    - Performs two-pass formatting with lib2to3 parsing
    - High priority for fuzzing due to direct user input handling

1.2 format_file_contents(src_contents: str, *, fast: bool, mode: Mode, lines: Collection[tuple[int, int]] = ()) -> FileContent
    - Reformats file contents with optional safety checks
    - Handles both Python files and Jupyter notebooks
    - Calls format_str internally but adds validation

1.3 format_ipynb_string(src_contents: str, *, fast: bool, mode: Mode) -> FileContent
    - Formats Jupyter notebook JSON content
    - Parses JSON and processes code cells
    - Input is JSON string containing Python code cells

1.4 format_cell(src: str, *, fast: bool, mode: Mode) -> str
    - Formats individual Jupyter notebook cells
    - Handles IPython magics via masking/unmasking
    - Input can contain mixed Python code and magic syntax

1.5 decode_bytes(src: bytes, mode: Mode) -> tuple[FileContent, Encoding, NewLine]
    - Decodes raw bytes to string with encoding detection
    - Handles different newline styles (CRLF, LF, CR)
    - Parses encoding declarations in source files

================================================================================
2. PARSING FUNCTIONS (High Priority)
================================================================================

Location: /app/black/src/black/parsing.py

2.1 lib2to3_parse(src_txt: str, target_versions: Collection[TargetVersion] = ()) -> Node
    - Core parsing function that converts Python source to AST
    - Uses lib2to3/blib2to3 parser with multiple grammar versions
    - Raises InvalidInput on parse failures
    - CRITICAL: Direct input parsing - high fuzzing priority

2.2 parse_ast(src: str) -> ast.AST
    - Uses Python's ast.parse with multiple version attempts
    - Falls back through Python versions 3.3 to current
    - Used for AST equivalence checking

2.3 matches_grammar(src_txt: str, grammar: Grammar) -> bool
    - Tests if source matches a specific grammar
    - Returns boolean, doesn't raise on invalid input

Location: /app/black/src/blib2to3/pgen2/driver.py

2.4 Driver.parse_string(text: str, debug: bool = False) -> NL
    - Lower-level parser that tokenizes and parses
    - Entry point for lib2to3 parsing machinery

2.5 Driver.parse_tokens(tokens: Iterable[TokenInfo], debug: bool = False) -> NL
    - Parses token stream into syntax tree
    - Handles indentation and comment processing

Location: /app/black/src/blib2to3/pgen2/tokenize.py

2.6 tokenize(source: str, grammar: Grammar | None = None) -> Iterator[TokenInfo]
    - Tokenizes Python source into token stream
    - Uses pytokens library with custom transformations
    - Handles f-strings, t-strings, and special tokens

Location: /app/black/src/blib2to3/pgen2/parse.py

2.7 Parser.addtoken(type: int, value: str, context: Context) -> bool
    - Core parsing method that processes tokens
    - Handles soft keywords (match, case, type) with backtracking
    - Complex state machine - good fuzzing target

================================================================================
RECOMMENDED FUZZING STRATEGY
================================================================================

TIER 1 - Highest Priority (Direct input parsing):
- format_str() - Main entry point, accepts arbitrary Python code
- lib2to3_parse() - Core parser, handles all syntax variations
- tokenize() - First stage of parsing, handles raw source

TIER 2 - High Priority (Complex transformations):
- format_ipynb_string() - JSON + Python parsing
- mask_cell() / unmask_cell() - Magic handling
- normalize_string_quotes() - Complex regex transformations
- parse_line_ranges() - User input validation

TIER 3 - Medium Priority (Supporting functions):
- decode_bytes() - Encoding detection
- list_comments() - Comment parsing
- parse_pyproject_toml() - TOML parsing
- adjusted_lines() - Diff-based line mapping

FUZZING INPUT CONSIDERATIONS:
1. Valid Python code with edge cases (deeply nested, long lines)
2. Invalid Python code (syntax errors, encoding issues)
3. Mixed content (Python + IPython magics)
4. Unicode content (various encodings, special characters)
5. Large inputs (memory/performance testing)
6. Jupyter notebook JSON with malformed cells
7. TOML configuration with invalid values
8. Line range strings with boundary conditions
