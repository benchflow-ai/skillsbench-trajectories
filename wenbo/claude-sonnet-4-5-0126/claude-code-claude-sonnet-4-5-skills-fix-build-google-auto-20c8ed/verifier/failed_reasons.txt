BUILD FAILURE ANALYSIS
======================

Repository: /home/travis/build/failed/google/auto
Build System: Maven
Java Version: OpenJDK 11.0.27

ROOT CAUSE:
-----------
The build is failing with dependency resolution errors:
"Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

This error occurs for four modules:
1. auto-common (com.google.auto:auto-common:jar:1.0-SNAPSHOT)
2. auto-factory (com.google.auto.factory:auto-factory:jar:1.0-SNAPSHOT)
3. auto-service (com.google.auto.service:auto-service:jar:1.0-SNAPSHOT)
4. auto-value (com.google.auto.value:auto-value:jar:1.2-SNAPSHOT)

TECHNICAL DETAILS:
------------------
The issue is caused by transitive test dependencies on com.google.testing.compile:compile-testing library (versions 0.6, 0.7, and 0.8).

These compile-testing versions have a system-scoped dependency on com.sun:tools which references the tools.jar file:
- Location expected: ${java.home}/../lib/tools.jar
- Property source: Defined in profiles in both the parent POM and compile-testing POM

The problem: Java 9+ (including Java 11 in use) removed tools.jar from the JDK distribution. The classes previously in tools.jar are now part of the JDK module system and are available without explicit dependencies.

ERROR LOCATION:
---------------
The dependency chain is:
- Module POMs reference com.google.testing.compile:compile-testing (test scope)
  - common/pom.xml uses version 0.7
  - factory/pom.xml uses version 0.8
  - service/pom.xml uses version 0.6
  - value/pom.xml uses version 0.6

- compile-testing library (versions 0.6, 0.7, 0.8) declares:
  <dependency>
    <groupId>com.sun</groupId>
    <artifactId>tools</artifactId>
    <version>${java.version}</version>
    <scope>system</scope>
    <systemPath>${toolsjar}</systemPath>
  </dependency>

IMPLEMENTED FIX:
-----------------
The solution is to upgrade the compile-testing library to version 0.10 and explicitly exclude the com.sun:tools dependency.

While compile-testing 0.10 still has the tools.jar dependency, we exclude it at the module level. This allows the build to proceed using Java 11's built-in compiler API without requiring tools.jar.

Changes implemented:
1. common/pom.xml: Updated compile-testing from 0.7 to 0.10 with exclusion for com.sun:tools
2. factory/pom.xml: Updated compile-testing from 0.8 to 0.10 with exclusion for com.sun:tools
3. service/pom.xml: Updated compile-testing from 0.6 to 0.10 with exclusion for com.sun:tools
4. value/pom.xml: Updated compile-testing from 0.6 to 0.10 with exclusion for com.sun:tools

The exclusion block added to each dependency:
  <exclusions>
    <exclusion>
      <groupId>com.sun</groupId>
      <artifactId>tools</artifactId>
    </exclusion>
  </exclusions>
