## LIBRARY OVERVIEW
Minisgl is a machine learning library focused on efficient tensor operations and neural network layers. It provides PyTorch-compatible layers with optimizations for LLM inference, including attention mechanisms, embeddings, and normalization layers.

Dependencies:
- torch (PyTorch)
- transformers
- sgl_kernel (custom kernel library)
- flashinfer-python
- msgpack (for serialization)
- fastapi, uvicorn (for API server)
- nvidia-cutlass-dsl (CUDA kernels)

==============================================
FUZZING TARGET NOTE #1
==============================================

Target: API Server Request Handler
File / location: python/minisgl/server/api_server.py
Why this target:
  - Input surface: HTTP POST requests with JSON/msgpack payloads
  - Boundary considerations: User input deserialization
  - Complexity: Request parsing, validation, tensor operations
  - Current test gaps: Malformed requests, invalid msgpack data

Callable contract:
  - Required imports: from minisgl.server import api_server, fastapi
  - Preconditions: Server must be initialized
  - Determinism: May depend on model state
  - External dependencies: PyTorch, model weights

Input model:
  - Primary payload type: HTTP request body (bytes)
  - Decoding steps: Deserialize msgpack/JSON → validate → process
  - Constraints to respect: Must be valid HTTP request format
  - Edge classes: Malformed msgpack, invalid JSON, oversized requests

Oracles:
  - Must-hold properties: No crashes, proper error responses
  - Acceptable exceptions: ValidationError, ValueError, HTTP 400/500
  - Suspicious exceptions: SegFault, MemoryError (from native code)
  - Crash-only vs correctness: Crash-only

Harness plan:
  - Recommended approach: Fuzz msgpack deserialization and API endpoints
  - Minimal harness signature: TestOneInput(data: bytes) → deserialize/validate
  - Seed corpus ideas: Valid msgpack messages, API request examples
  - Timeouts: 10 seconds (model inference can be slow)

Risk flags:
  - Native extension: YES (PyTorch, CUDA kernels)
  - Potential DoS paths: Large tensor allocations, expensive operations
  - External I/O: Network, model loading

Next actions:
  1. Focus on msgpack deserialization (import msgpack; msgpack.unpackb(data))
  2. Test API request parsing without full model
  3. Validate tensor shape/type checking
  4. Monitor for memory issues from native code
