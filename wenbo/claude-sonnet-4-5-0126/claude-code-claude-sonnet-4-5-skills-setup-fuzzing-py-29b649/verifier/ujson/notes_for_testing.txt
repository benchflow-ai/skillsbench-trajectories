==============================================
UJSON LIBRARY - FUZZING TARGET ANALYSIS
==============================================

## LIBRARY OVERVIEW
UltraJSON (ujson) is an ultra-fast JSON encoder/decoder written in C with Python bindings. It provides drop-in replacements for json.dumps() and json.loads() with significantly better performance.

Dependencies:
- C extension (double-conversion library for number handling)
- Pure C implementation of JSON parsing and encoding

## IMPORTANT FILES

1. src/ujson/lib/ultrajsondec.c (Score: 10/10)
   - JSON decoder implementation in C
   - Parses JSON strings into Python objects
   - High boundary risk for malformed JSON

2. src/ujson/lib/ultrajsonenc.c (Score: 10/10)
   - JSON encoder implementation in C
   - Converts Python objects to JSON strings
   - Complex type handling

3. src/ujson/python/ujson.c (Score: 9/10)
   - Python C API bindings
   - Entry points for dumps() and loads()

## IMPORTANT FUNCTIONS

### 1. ujson.loads() / ujson.decode() [C extension]
Score: 10/10
- Parses JSON strings into Python objects
- Native C implementation with manual memory management
- Handles all JSON types: objects, arrays, strings, numbers, booleans, null
Rationale:
  - Accepts arbitrary byte/string input
  - Parser with complex state machine
  - Memory allocation/deallocation
  - Unicode handling
  - Number parsing edge cases
Dependencies: ultrajsondec.c, double-conversion
Harnessability: HIGH

### 2. ujson.dumps() / ujson.encode() [C extension]
Score: 10/10
- Converts Python objects to JSON strings
- Native C implementation
- Handles circular references, special types
Rationale:
  - Accepts arbitrary Python objects
  - Type introspection and serialization
  - String escaping and Unicode encoding
  - Number formatting
  - Buffer management
Dependencies: ultrajsonenc.c, objToJSON.c, double-conversion
Harnessability: HIGH

## INFERRED ORACLES

1. No-crash property: Parser should handle any input gracefully
   - Applies to: ujson.loads()
   - Should return object or raise ValueError

2. Round-trip property: loads(dumps(x)) should equal x (for JSON-serializable x)
   - Applies to: dumps() + loads()
   - Critical correctness property

3. Compatibility with stdlib json: For valid inputs, behavior should match json module
   - Applies to: Both dumps() and loads()

4. No memory leaks: Reference counts should remain stable
   - Applies to: Both functions
   - Already tested in tests/fuzz.py

5. Determinism: Same input → same output
   - Applies to: Both functions

## SELECTED FUNCTIONS UNDER TEST FOR FUZZING

==============================================
FUZZING TARGET NOTE #1
==============================================

Target: ujson.loads() / ujson.decode()
File / location: src/ujson/lib/ultrajsondec.c (C extension)
Why this target:
  - Input surface: Accepts arbitrary JSON strings (bytes or str)
  - Boundary considerations: Native C code with manual memory management
  - Complexity: Full JSON parser with Unicode, numbers, nested structures
  - Current test gaps: Malformed JSON, deeply nested, huge documents

Callable contract:
  - Required imports: import ujson
  - Preconditions: Input should be string or bytes
  - Determinism: Deterministic for given input
  - External dependencies: None (pure C)

Input model:
  - Primary payload type: str or bytes (JSON document)
  - Parsing steps: Tokenize, parse, build Python objects, return
  - Constraints to respect: Must be string or bytes type
  - Edge classes: Empty strings, deeply nested arrays/objects, very long strings, special Unicode, invalid UTF-8, malformed JSON syntax, huge numbers

Oracles:
  - Must-hold properties: No crashes, no memory leaks
  - Acceptable exceptions: ValueError (for invalid JSON)
  - Suspicious exceptions: MemoryError, SystemError, SegFault
  - Crash-only vs correctness: Crash-only (focus on robustness)

Harness plan:
  - Recommended approach: Call ujson.loads() with fuzzer-generated bytes/strings
  - Minimal harness signature: TestOneInput(data: bytes) → parse as JSON
  - Seed corpus ideas: Valid JSON documents from tests, edge cases, deeply nested structures
  - Timeouts: 5 seconds (parsing can be slow for huge documents)

Risk flags:
  - Native extension: YES (C code with manual memory management)
  - Potential DoS paths: Deeply nested structures, very large documents
  - External I/O: No

Next actions:
  1. Convert fuzzer bytes to string (try UTF-8, handle errors)
  2. Call ujson.loads(string) in try-except block
  3. Catch and allow ValueError, fail on crashes or unexpected exceptions
  4. Monitor for memory issues and segfaults

FUZZING TARGET NOTE #2
==============================================

Target: ujson.dumps() / ujson.encode()
File / location: src/ujson/lib/ultrajsonenc.c (C extension)
Why this target:
  - Input surface: Accepts arbitrary Python objects
  - Boundary considerations: Native C code, type introspection, buffer management
  - Complexity: Serializes all Python types to JSON
  - Current test gaps: Complex nested objects, unusual types, circular references

Callable contract:
  - Required imports: import ujson
  - Preconditions: Input should be JSON-serializable Python object
  - Determinism: Deterministic for given input and options
  - External dependencies: None (pure C)

Input model:
  - Primary payload type: Python objects (dict, list, int, float, str, bool, None)
  - Encoding steps: Traverse object, serialize each component, build JSON string
  - Constraints to respect: Must be JSON-serializable (no arbitrary objects)
  - Edge classes: Deeply nested dicts/lists, very large collections, special floats (NaN, Inf), Unicode strings, circular references (should fail gracefully)

Oracles:
  - Must-hold properties: No crashes, no memory leaks, valid JSON output
  - Acceptable exceptions: OverflowError, ValueError, TypeError
  - Suspicious exceptions: MemoryError, SystemError, SegFault
  - Crash-only vs correctness: Both (output should be valid JSON)

Harness plan:
  - Recommended approach: Use FuzzGenerator from tests/fuzz.py to create random JSON-able objects
  - Minimal harness signature: TestOneInput(data: bytes) → generate object, call dumps()
  - Seed corpus ideas: Objects from tests, nested structures, edge case numbers
  - Timeouts: 5 seconds

Risk flags:
  - Native extension: YES (C code with manual memory management)
  - Potential DoS paths: Deeply nested objects, very large collections
  - External I/O: No

Next actions:
  1. Use fuzzer data as seed for FuzzGenerator
  2. Generate random Python object
  3. Call ujson.dumps(obj) with various options in try-except
  4. Validate output is valid JSON (parse with json.loads)
  5. Check reference counts for memory leaks
