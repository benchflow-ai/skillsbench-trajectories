FUZZING TARGET NOTES FOR ARROW LIBRARY
======================================

Priority Functions to Fuzz:

1. DateTimeParser.parse_iso() [CRITICAL]
   - File: arrow/parser.py, lines 252-371
   - Input: ISO 8601 datetime strings
   - Attack Surface: Format confusion, regex complexity, timezone edge cases
   - Key Edge Cases:
     * Malformed ISO strings with mixed delimiters
     * Extreme date values (year 0001 to 9999)
     * Edge case times (24:00:00, leap seconds)
     * Timezone offsets (-12:00 to +14:00)
     * Very long datetime strings
     * Unicode whitespace characters
   - Setup: from arrow.parser import DateTimeParser
   - Dependencies: dateutil, backports.zoneinfo

2. DateTimeParser.parse() [CRITICAL]
   - File: arrow/parser.py, lines 373-439
   - Input: (datetime_string, format_string or list of formats)
   - Attack Surface: Format string injection, regex generation, multi-format parsing
   - Key Edge Cases:
     * Malicious format strings with special regex chars
     * Very long format strings
     * Invalid locale names
     * Format/data mismatches
     * Ordinal number formats
   - Setup: Accepts timezone-aware and naive datetimes
   - Dependencies: locale data, complex regex patterns

3. DateTimeParser._parse_token() [HIGH]
   - File: arrow/parser.py, lines 591-693
   - Input: (token, value, parts dict)
   - Attack Surface: Token value interpretation, locale-dependent lookups
   - Key Edge Cases:
     * YY token with century boundary (68 vs 69)
     * Month names with accents/special chars
     * Microsecond rounding edge cases
     * Hour value of 24 (midnight)
     * Weekdate with week 53 in non-53-week years
   - Setup: Parser state with locale info
   - Dependencies: Locale data for month/day names

4. TzinfoParser.parse() [HIGH]
   - File: arrow/parser.py, lines 885-937
   - Input: Timezone identifier or ISO offset string
   - Attack Surface: Timezone database lookup, offset boundary conditions
   - Key Edge Cases:
     * Non-existent timezone names
     * Malformed ISO offset strings
     * Edge case offsets (+14:00, -12:00, +05:30)
     * "local" and "UTC" case variations
     * Invalid offset minutes (non-00/30/45)
     * Very long timezone name strings
   - Setup: Requires ZoneInfo database access
   - Dependencies: zoneinfo module, timezone database

5. DateTimeParser._build_datetime() [HIGH]
   - File: arrow/parser.py, lines 696-828
   - Input: Dictionary with parsed datetime components
   - Attack Surface: Date/time validation, edge case handling
   - Key Edge Cases:
     * Invalid date combinations (Feb 30)
     * Hour 24 with non-zero minutes/seconds
     * Microsecond overflow (exactly 1000000)
     * Weekdate ISO conversion edge cases
     * Day-of-year in wrong year context
     * Leap year calculations
   - Setup: DateTimeParser with locale
   - Dependencies: datetime module, calendar module

RECOMMENDED FUZZING STRATEGY:
- Start with parse_iso() and parse() for broadest coverage
- Use boundary value analysis for date/time components
- Test with multiple locales (en_us, fr_fr, de_de, ja_jp)
- Property-based testing: parse -> format -> parse roundtrip
- Stress test with deeply nested timezone handling

TEST ENVIRONMENT SETUP:
- Python 3.8+
- Dependencies: dateutil, pytz, backports.zoneinfo (Python < 3.9)
- Target: pytest for validation
