FUZZING TARGET NOTES FOR IPYTHON LIBRARY
==========================================

Priority Functions to Fuzz:

1. split_user_input() [CRITICAL]
   - File: IPython/core/splitinput.py, lines 43-68
   - Input: Any user command string
   - Attack Surface: First line of defense for all user input
   - Key Attack Vectors:
     * Empty strings and only whitespace
     * Mixed escape characters: !!?, ??!, %
     * Very long function names with many dots
     * Newline characters in unexpected places
     * Unicode edge cases in regex matching
     * Backslash continuation sequences
     * Deeply nested brackets/parentheses
     * Null bytes and control characters
     * Regex ReDoS patterns
   - Setup: from IPython.core.splitinput import split_user_input
   - Dependencies: re module, line_split regex pattern
   - Regex Pattern: ^(\s*)([,;/%]|!!?|\?\??)?  \s*(%{0,2}[\w\.\*]*)(.*?$|$)
   - Potential Vulnerabilities:
     * ReDoS (Regular Expression Denial of Service)
     * Incorrect escape character detection
     * Unicode handling in regex

2. transform_cell() [CRITICAL]
   - File: IPython/core/inputtransformer2.py, lines 635-644
   - Input: Multi-line cell code with IPython magic syntax
   - Attack Surface: Central transformation hub, orchestrates all transformations
   - Key Attack Vectors:
     * Infinite transformation loops (100-iteration limit)
     * Deeply nested escape sequences: %%?!%...
     * Cells with only escape characters
     * Mixed incomplete escape sequences
     * Very large cells causing memory exhaustion
     * Cells with no trailing newline
     * Cells mixing continuation lines with escapes
     * Invalid UTF-8 sequences
     * Escape sequence breakout attempts
   - Setup: from IPython.core.inputtransformer2 import TransformerManager
   - Dependencies: Input transformer pipeline
   - Potential Vulnerabilities:
     * Stack exhaustion from transformation loops
     * Memory leaks from repeated allocations
     * Infinite recursion in nested transforms
     * Character encoding issues

3. parse_argstring() [HIGH]
   - File: IPython/core/magic_arguments.py, lines 164-170
   - Input: Magic command argument strings
   - Attack Surface: Argument parsing for magic commands
   - Key Attack Vectors:
     * Unmatched/mismatched quotes: "unclosed, 'mixed"quotes'
     * Escape sequences: \x00, \n, \r
     * Very long argument strings
     * Mixed POSIX and non-POSIX modes
     * Shell metacharacters: ; | & > < $
     * Unicode normalization attacks
     * Null bytes terminating strings
     * Excessive whitespace or tabs
     * Glob patterns with unexpected expansion
     * Format string payloads: %x %n
   - Setup: Magic command with user-supplied arguments
   - Dependencies: shlex.split(), argparse module
   - Uses: arg_split() from IPython/utils/process.py
   - Potential Vulnerabilities:
     * Quote escaping bypass
     * Shell metacharacter injection
     * Format string vulnerabilities

4. EscapedCommand.transform() [HIGH]
   - File: IPython/core/inputtransformer2.py, lines 407-448
   - Input: Lines starting with escape characters (!, %, ?, etc.)
   - Attack Surface: Direct executor of escape sequences, code generator
   - Key Attack Vectors:
     * Empty content after escape: % with no function name
     * Very long magic names or arguments
     * Newlines in transformed output
     * Format strings in magic args: %timeit f(%x)
     * Quotes not properly escaped: %run "file.py"
     * Backslash continuation edge cases at EOF
     * Mixed escape sequences in same line
     * Continuation across transformation boundaries
     * Content with %r format sequences
     * Unicode escaping issues in function calls
   - Setup: Transformation of escape-prefixed lines
   - Dependencies: Escape character transformations
   - Transformation Map:
     * ! → get_ipython().system()
     * !! → get_ipython().system_piped()
     * ? → get_ipython().inspector()
     * ?? → get_ipython().inspector_detailed()
     * % → get_ipython().run_line_magic()
     * %% → get_ipython().run_cell_magic()
   - Potential Vulnerabilities:
     * Code injection via format strings
     * Quote escaping bypass
     * Line continuation bypass
     * Generated code syntax errors

5. eval_node() [HIGH]
   - File: IPython/core/guarded_eval.py, lines 765-900+
   - Input: Python AST nodes with evaluation context
   - Attack Surface: Arbitrary AST evaluation with "safety guards"
   - Key Attack Vectors:
     * Policy bypasses (forbidden, minimal, limited, unsafe)
     * AST injection with malicious nodes
     * Decorator evaluation side effects
     * Attribute resolution chains with deep object introspection
     * Type annotation resolution side effects
     * Stack frame access via sys._getframe()
     * Namespace pollution via transient_locals
     * Large or deeply nested AST causing stack overflow
     * Circular reference evaluation
     * Private attribute access bypass
   - Setup: from IPython.core.guarded_eval import eval_node, EvaluationContext
   - Dependencies: AST module, inspection capabilities
   - Policy Levels: forbidden, minimal, limited, unsafe, dangerous
   - Potential Vulnerabilities:
     * Policy bypass allowing arbitrary code execution
     * Side effects during tab completion
     * Stack overflow from nested evaluation
     * Information disclosure via introspection

RECOMMENDED FUZZING STRATEGY:
- Mutation-based fuzzing on user input strings
- Escape sequence fuzzer for split_user_input()
- Multi-line cell fuzzer for transform_cell()
- Argument parser fuzzer with quote/escape variations
- Format string fuzzer for EscapedCommand
- AST fuzzer for eval_node() with various policies
- Property-based testing: parsing stability
- Timeout testing for infinite loop detection

TEST ENVIRONMENT SETUP:
- Python 3.8+
- Dependencies: prompt-toolkit, pickleshare, traitlets, decorator
- Target: pytest for validation
- Consider running in isolated subprocess to detect hangs
