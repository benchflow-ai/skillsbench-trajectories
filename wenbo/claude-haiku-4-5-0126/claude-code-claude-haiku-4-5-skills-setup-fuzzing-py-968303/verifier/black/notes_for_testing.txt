FUZZING TARGET NOTES FOR BLACK LIBRARY
=======================================

Priority Functions to Fuzz:

1. lib2to3_parse() [CRITICAL]
   - File: src/black/parsing.py, lines 55-102
   - Input: Python source code string
   - Attack Surface: Parser grammar handling, multiple grammar versions
   - Key Attack Vectors:
     * Deeply nested structures: ((((...))))
     * Mixed string types (raw, f-strings, unicode)
     * Invalid indentation patterns (mixed tabs/spaces)
     * Grammar version conflicts
     * Unterminated constructs (unclosed brackets/strings)
     * Extremely long identifiers and numeric literals
     * Comment edge cases with fmt directives
   - Setup: from black.parsing import lib2to3_parse
   - Dependencies: lib2to3 library, python grammar files
   - Potential Vulnerabilities:
     * Stack overflow from deeply nested structures
     * ReDoS in token parsing
     * Memory exhaustion

2. format_str() + _format_str_once() [CRITICAL]
   - File: src/black/__init__.py, lines 1177-1298
   - Input: Python source code + optional line ranges
   - Attack Surface: End-to-end formatting, line generation, multi-pass
   - Key Attack Vectors:
     * Invalid line ranges (out of bounds, reversed)
     * Mixed newline types (CRLF, LF, CR)
     * Partial code in ranges
     * Feature auto-detection triggering wrong versions
     * Extremely long lines (10,000+ chars)
     * Circular transformations (code bounces between formats)
     * Unicode in source code
     * Empty files or comment-only files
   - Setup: from black import format_str, Mode, TargetVersion
   - Dependencies: AST parsing, line generation
   - Potential Vulnerabilities:
     * Infinite loops in multi-pass formatting
     * Memory exhaustion from large AST traversal
     * State corruption in LineGenerator
     * Integer overflow in line offset calculations

3. normalize_string_quotes() [HIGH]
   - File: src/black/strings.py, lines 169-239
   - Input: Python string literal (with quotes)
   - Attack Surface: Quote nesting, escape sequences, f-string handling
   - Key Attack Vectors:
     * Complex quote nesting: "'"\"'\"'"
     * Mixed escape sequences: \\, \', \", \n, \x, \u, \U
     * F-strings with backslashes: f"{var}\\"
     * Raw f-strings: fr"..." vs rf"..."
     * Triple-quoted strings with trailing quotes
     * Docstring-like strings
     * Unicode and byte strings
     * Empty strings and strings with only quotes
     * Very long strings
   - Setup: from black.strings import normalize_string_quotes
   - Dependencies: regex patterns for quote detection
   - Potential Vulnerabilities:
     * ReDoS attacks via regex patterns
     * Incorrect escape count calculation
     * F-string validation bypass
     * Stack overflow in recursive escape processing

4. mask_cell() + replace_cell_magics() [HIGH]
   - File: src/black/handle_ipynb_magics.py, lines 146-252
   - Input: Jupyter cell source with IPython magics
   - Attack Surface: IPython magic command handling, token generation
   - Key Attack Vectors:
     * Magic command variations: %, %%, !, ?
     * Multi-line and nested magics
     * Token collision in generated masks
     * Incomplete magic syntax
     * Mixed Python and magic code
     * Special characters in magic arguments
     * Escaped characters and backslashes
     * Empty magics
     * Magics with brackets
   - Setup: from black.handle_ipynb_magics import mask_cell, unmask_cell
   - Dependencies: IPython TransformerManager
   - Potential Vulnerabilities:
     * Token generation collision causing permanent masking
     * Counter overflow after collision attempts
     * AST parsing failure on masked code
     * Transformation manager side effects
     * Unicode normalization issues

5. normalize_fstring_quotes() [HIGH]
   - File: src/black/strings.py, lines 242-304
   - Input: f-string leaf nodes from parsed AST
   - Attack Surface: Complex brace matching, escape handling
   - Key Attack Vectors:
     * Nested braces: f"{x + {y}}"
     * Escapes in expressions: f"{path\\to\\file}"
     * Unmatched braces: f"{", f"}"
     * Complex expressions: f"{(x if y else z)()}"
     * Quote conflicts in f-strings
     * Raw f-strings with escape sequences
     * Empty expressions: f"{}"
     * Multiple expressions in one f-string
     * String continuation with multiple f-strings
     * Unicode identifiers in expressions
   - Setup: Work with parsed leaf nodes from blib2to3
   - Dependencies: blib2to3.pytree, regex patterns
   - Potential Vulnerabilities:
     * ReDoS in regex patterns
     * Incorrect escape count calculations
     * State corruption across segments
     * Unbalanced brace counting

RECOMMENDED FUZZING STRATEGY:
- Mutation-based fuzzing starting from valid Python code
- Grammar-based fuzzing for syntactically valid/invalid code
- Differential fuzzing across Black versions
- Property-based testing: AST preservation after formatting
- Regression testing on previously reported bugs
- Focus on format stability: format(format(x)) == format(x)

TEST ENVIRONMENT SETUP:
- Python 3.7+
- Dependencies: lib2to3, blib2to3, click, pathspec, tomli, ipython
- Target: pytest for validation
- Enable CFLAGS='-DDEBUG' for additional checks
