BUILD FAILURE ANALYSIS
======================

Error Summary:
--------------
The Maven build is failing for three modules:
- auto-common (com.google.auto:auto-common:jar:1.0-SNAPSHOT)
- auto-factory (com.google.auto.factory:auto-factory:jar:1.0-SNAPSHOT)
- auto-service (com.google.auto.service:auto-service:jar:1.0-SNAPSHOT)

Root Cause:
-----------
The build is failing with the following error:
"Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

The actual root cause is that the test dependency 'com.google.testing.compile:compile-testing'
has a transitive system dependency on 'com.sun:tools:jar:11.0.27'.

In Java 9+, the tools.jar file was removed. Its contents were integrated into the JDK modules directly.
The build is running on Java 11.0.27 (OpenJDK), but compile-testing still tries to reference tools.jar.

Debug output shows:
  com.google.testing.compile:compile-testing:jar:0.7:test
     com.sun:tools:jar:11.0.27:system

Impact:
-------
The dependency resolution fails because Maven cannot find tools.jar, which no longer exists in Java 11.
This prevents the three modules from being built.

Solution Plan:
--------------
1. Parent POM: Comment out obsolete profiles referencing tools.jar (COMPLETED)
2. Module POMs: Exclude the tools.jar dependency from compile-testing in test scope

Files to modify:
- /home/travis/build/failed/google/auto/pom.xml - Commented out profiles (COMPLETED)
- /home/travis/build/failed/google/auto/common/pom.xml - Exclude tools.jar from compile-testing
- /home/travis/build/failed/google/auto/factory/pom.xml - Exclude tools.jar from compile-testing
- /home/travis/build/failed/google/auto/service/pom.xml - Exclude tools.jar from compile-testing

Expected Result:
---------------
After excluding the obsolete tools.jar dependency from compile-testing, the build should proceed
without attempting to resolve the non-existent tools.jar dependency.
