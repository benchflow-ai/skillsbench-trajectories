BUILD ERROR ANALYSIS
====================

Repository: /home/travis/build/failed/google/auto (Google Auto Service Project)
Build System: Maven (using build-pom.xml for multi-module build)
Java Version: 11.0.27

ROOT CAUSE:
-----------
The build fails when compiling the auto-common module with the following error:

"Could not find artifact com.sun:tools:jar:11.0.27 at specified path
/usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

TECHNICAL DETAILS:
------------------
1. The error originates from the auto-common module's dependency on compile-testing:0.7
   (declared in common/pom.xml, line 56-58)

2. The compile-testing library (version 0.7) has a system-scoped dependency on com.sun:tools
   that references tools.jar via the ${toolsjar} property

3. In JDK 8 and earlier, tools.jar contained development tools including the compiler API
4. In JDK 9+, tools.jar no longer exists - its contents were reorganized into modules

5. The ${toolsjar} property is defined in parent POM profiles (pom.xml, lines 167-208)
   that activate based on tools.jar existence, which fails in JDK 11+

BUILD CONFIGURATION ISSUE:
--------------------------
The build-pom.xml file properly defines all modules:
- auto-parent (parent)
- auto-common
- auto-factory
- auto-service
- auto-value

However, the dependency chain includes compile-testing which has an incompatible
JDK 11 dependency declaration.

AFFECTED MODULES:
-----------------
All modules are affected because:
- auto-common depends on compile-testing:0.7 (test scope)
- auto-factory depends on compile-testing:0.8 (test scope)
- auto-service depends on compile-testing:0.6 (test scope)
- auto-value depends on compile-testing:0.6 (test scope)

The build fails at the auto-common module (first in reactor build order).

SOLUTION OPTIONS:
-----------------
Option 1: Update compile-testing to newer version
  - Newer versions (0.15+) don't require com.sun:tools dependency
  - However, this may require Java 8+ and the project targets Java 1.6

Option 2: Add tools.jar as a system-scoped dependency explicitly
  - Create a dependency on com.sun:tools with proper JDK 11+ path
  - Not recommended as system-scoped deps are discouraged

Option 3 (RECOMMENDED): Override the dependency in parent POM
  - Add dependencyManagement section to override com.sun:tools scope
  - Mark as provided or omit entirely for JDK 9+
  - Most compatible approach with existing code

Option 4: Use JDK 8 for build
  - Downgrade to JDK 8 where tools.jar exists
  - Not viable if project requires newer Java features

RECOMMENDED FIX:
----------------
Modify pom.xml to add a dependencyManagement section that:
1. Overrides the com.sun:tools dependency from compile-testing
2. Sets scope to "provided" (already included in JDK, doesn't need to be packaged)
3. Uses property-based version to match current JDK version

This approach:
- Maintains compatibility with existing code
- Doesn't require upgrading compile-testing
- Works with JDK 11+
- Minimal changes to build configuration
