MiniSGL Library - Fuzz Testing Notes
====================================

Library Purpose:
MiniSGL is a lightweight LLM (Large Language Model) serving library with distributed inference capabilities.

Key Functions to Fuzz:
----------------------

1. LLM.generate() - /app/minisgl/python/minisgl/llm/llm.py:77
   - Purpose: Generate text from prompts using LLM
   - Input: prompts (List[str]|List[List[int]]), sampling_params
   - Fuzz Priority: HIGH
   - Why: Core LLM generation function, handles text/token input

2. LLM._tokenize_one() - /app/minisgl/python/minisgl/llm/llm.py:42
   - Purpose: Tokenize text or process token lists
   - Input: prompt (List[int]|str)
   - Fuzz Priority: MEDIUM
   - Why: Tokenization is critical for LLM input

3. Scheduler.run_forever() - /app/minisgl/python/minisgl/scheduler.py
   - Purpose: Main scheduling loop for LLM inference
   - Input: None (uses pending_requests)
   - Fuzz Priority: HIGH
   - Why: Core scheduling logic for distributed inference

4. torch_utils functions - /app/minisgl/python/minisgl/utils/torch_utils.py
   - Purpose: PyTorch utility functions
   - Input: PyTorch tensors/models
   - Fuzz Priority: MEDIUM
   - Why: ML-specific operations

Fuzz Strategy:
-------------
- Very long prompts
- Empty prompt lists
- Invalid token IDs (out of range)
- Unicode text in prompts
- Special characters and escape sequences
- Invalid sampling parameters (negative temperatures, etc.)
- Mixed string and token list inputs
- Memory-intensive inputs
- Deep nesting in results

Oracles:
--------
- No crashes or unhandled exceptions
- Valid token outputs within expected ranges
- Results dictionary structure consistency
- Token IDs within valid vocabulary range
- Text generation should complete within reasonable time
- Handle empty results gracefully
