Black Library - Fuzz Testing Notes
===================================

Library Purpose:
Black is a Python code formatter that reformats Python code to follow a consistent style.

Key Functions to Fuzz:
----------------------

1. format_str() - /app/black/src/black/__init__.py:1177
   - Purpose: Main API for formatting Python code strings
   - Input: src_contents (str), mode (Mode), lines (Collection)
   - Fuzz Priority: HIGH
   - Why: Primary entry point, handles all Python code formatting

2. _format_str_once() - /app/black/src/black/__init__.py:1224
   - Purpose: Internal formatting function
   - Input: src_contents (str), mode (Mode), lines (Collection)
   - Fuzz Priority: HIGH
   - Why: Core formatting logic

3. lib2to3_parse() - /app/black/src/black/parsing.py:55
   - Purpose: Parse Python code using lib2to3
   - Input: src_txt (str), target_versions (Collection[TargetVersion])
   - Fuzz Priority: HIGH
   - Why: Parsing is critical, handles various Python syntax versions

4. parse_ast() - /app/black/src/black/parsing.py:137
   - Purpose: Parse Python code into AST
   - Input: src (str)
   - Fuzz Priority: MEDIUM
   - Why: AST parsing for validation

5. format_file_contents() - /app/black/src/black/__init__.py:1068
   - Purpose: Format file contents
   - Input: src_contents (str), fast (bool), mode (Mode)
   - Fuzz Priority: MEDIUM
   - Why: File-level formatting

Fuzz Strategy:
-------------
- Malformed Python code
- Invalid syntax
- Very long lines
- Complex nested structures
- Unicode in strings/comments
- Various Python syntax versions (2.7, 3.x)
- Edge cases: empty files, single character files
- Indentation errors
- Encoding issues

Oracles:
--------
- No crashes or unhandled exceptions
- InvalidInput exceptions are acceptable for invalid syntax
- Output should be valid Python syntax (parseable)
- Formatting should be idempotent (formatting twice = formatting once)
- AST equivalence check (formatted code should have same AST)
