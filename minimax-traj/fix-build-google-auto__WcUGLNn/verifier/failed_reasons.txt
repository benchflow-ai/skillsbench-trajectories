BUILD FAILURE ANALYSIS
======================

Repository: /home/travis/build/failed/google/auto

ROOT CAUSE:
-----------
The build fails with the following error:
"Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar"

This error occurs when building the auto-common module (and would affect all modules).

DETAILED ANALYSIS:
------------------
1. The project uses a multi-module Maven structure with build-pom.xml as the aggregator POM.

2. The auto-common module has a test dependency on 'com.google.testing.compile:compile-testing:0.7'

3. The 'compile-testing:0.7' library contains a system-scope dependency on 'com.sun:tools' that references ${toolsjar} property:
   ```xml
   <dependency>
     <groupId>com.sun</groupId>
     <artifactId>tools</artifactId>
     <version>${java.version}</version>
     <scope>system</scope>
     <systemPath>${toolsjar}</systemPath>
   </dependency>
   ```

4. The parent POM (auto-parent) defines the 'toolsjar' property via profiles:
   - default-profile: Sets toolsjar to ${java.home}/../lib/tools.jar
   - mac-profile: Sets toolsjar to ${java.home}/../Classes/classes.jar

5. The actual root cause: All module POMs (common, factory, service, value) reference parent version '3', but the build-pom.xml is building parent version '4-SNAPSHOT'. This version mismatch causes Maven to use the locally built 4-SNAPSHOT parent POM which defines the toolsjar property.

6. In Java 9+, the tools.jar file was removed from the JDK distribution. The build is running on Java 11, where tools.jar does not exist.

SOLUTION:
---------
Update the parent version in all module POMs from version '3' to version '4-SNAPSHOT' to match the current version in pom.xml. This will ensure consistent dependency resolution.

Affected files:
- common/pom.xml
- factory/pom.xml
- service/pom.xml
- value/pom.xml

Each needs to change:
  <parent>
    <version>3</version>
  </parent>
To:
  <parent>
    <version>4-SNAPSHOT</version>
  </parent>

ALTERNATIVE SOLUTION:
---------------------
If updating parent versions is not desired, an alternative would be to modify the parent POM to:
1. Remove or disable the profiles that set the toolsjar property for Java 9+
2. Or add JDK version activation conditions to only set toolsjar for JDK 8 and earlier

However, updating the parent version is the cleaner solution as it aligns the POM versions with the actual build.
