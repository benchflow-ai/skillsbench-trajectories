MiniSGL Library - Analysis for Fuzzing
=====================================

Library: minisgl (LLM inference engine)
Main Source: /app/minisgl/python/minisgl/

TIER 1 - Critical Functions (Input Processing & Parsing):
-------------------------------------------------------
1. parse_args() - Command-line argument parsing (server/args.py:54-236)
   - Fuzz with: crafted paths, invalid enum values, type confusion
   - Risks: path traversal, argument injection, config bypass
   - Targets: model_path, dtype, tensor_parallel_size, attention_backend

2. serialize_type()/deserialize_type() - Message serialization (message/utils.py:20-69)
   - Fuzz with: malformed msgpack, tensor type confusion, crafted binaries
   - Risks: buffer overflow, deserialization attacks
   - Priority: CRITICAL - handles network data and message passing

3. load_hf_weight() - Model weight loading (models/weight.py:78-105)
   - Fuzz with: malicious model files, corrupted safetensors, path traversal
   - Risks: arbitrary file access, memory corruption
   - Downloads from HuggingFace Hub or reads local files

4. TokenizeManager.tokenize() - Text tokenization (tokenizer/tokenize.py:16-33)
   - Fuzz with: malformed prompts, invalid UTF-8, malicious templates
   - Risks: buffer overflows, tokenizer corruption
   - Handles both string prompts and chat message templates

TIER 2 - High Priority (External Data & Communication):
------------------------------------------------------
5. API endpoints - HTTP request handling (server/api_server.py:214-277)
   - Fuzz with: JSON injection, oversized payloads, malformed requests
   - Risks: API injection, resource exhaustion
   - Targets: generate(), v1_completions()

6. validate_backend() - Backend validation (attention/__init__.py:50-61)
   - Fuzz with: crafted backend strings, comma-separated hybrids
   - Risks: validation bypass, regex errors
   - Parses comma-separated hybrid backends

7. cached_load_hf_config() - Config loading (utils/hf.py:17-20)
   - Fuzz with: malicious configs, JSON injection
   - Risks: HTTP injection, config corruption
   - Downloads and parses HuggingFace model configs

8. DetokenizeManager.detokenize() - Text decoding (tokenizer/detokenize.py:74-115)
   - Fuzz with: invalid token IDs, crafted sequences
   - Risks: buffer overflows, encoding errors
   - Converts token IDs to text incrementally

9. ZMQ queue operations - Message passing (utils/mp.py:24, 66)
   - Fuzz with: corrupted msgpack, oversized messages
   - Risks: protocol exploitation, memory corruption
   - Types: ZmqPushQueue, ZmqPullQueue, async variants

10. Scheduler._process_one_msg() - Message processing (scheduler/scheduler.py:116-139)
    - Fuzz with: crafted messages, malformed types
    - Risks: message processing errors
    - Handles UserMsg, ExitMsg, batched messages

TIER 3 - Medium Priority (Core APIs):
-----------------------------------
11. LLM.generate() - Main generation API (llm/llm.py:77-98)
    - Fuzz with: crafted prompts, extreme sampling parameters
    - Risks: prompt injection, resource exhaustion
    - User-facing API for text generation

12. ModelConfig.from_hf() - Config parsing (models/config.py:33-55)
    - Fuzz with: malformed HF configs, invalid parameters
    - Risks: config parsing errors
    - Parses HuggingFace model configuration

13. Engine.__init__() - Engine initialization (engine/engine.py:37-105)
    - Fuzz with: invalid configs, resource constraints
    - Risks: CUDA initialization failures
    - Loads model weights, allocates memory

14. launch_server() - Server launch (server/launch.py:40-113)
    - Fuzz with: crafted launch arguments
    - Risks: server misconfiguration
    - Parses command-line arguments

15. TokenizeMsg/DetokenizeMsg handling - Message types
    - Fuzz with: crafted message structures
    - Risks: type confusion, serialization errors
    - Contains: text strings, token IDs, incremental_output

KEY VULNERABILITY AREAS:
------------------------
- Command-line argument parsing (server/args.py)
- Message serialization/deserialization (message/utils.py)
- Model file loading (safetensors format)
- HTTP API request handling (JSON)
- Text tokenization and encoding
- ZMQ message passing protocol
- HuggingFace Hub interactions (HTTP + JSON)
- CUDA tensor operations

FUZZING STRATEGIES:
------------------
1. Command injection: crafted model paths with shell metacharacters
2. Path traversal: ../ in model_path or file paths
3. Deserialization attacks: malformed msgpack binaries
4. JSON injection: API endpoints with crafted JSON
5. Unicode edge cases: invalid UTF-8, normalization attacks
6. Resource exhaustion: oversized prompts, sequences, payloads
7. Model corruption: tampered safetensors, HF config manipulation
8. Type confusion: wrong tensor types in serialization
9. Template injection: chat message templates with special chars
10. Backend bypass: invalid attention_backend, cache_type values

INPUT SOURCES TO FUZZ:
----------------------
- sys.argv (command-line arguments)
- HTTP POST data (JSON requests to API)
- Text prompts (plain text and chat templates)
- Model paths (local paths and HuggingFace repo IDs)
- Serialized messages (msgpack via ZMQ)
- Model weight files (safetensors format)
- Configuration files (HuggingFace JSON configs)
- Sampling parameters (temperature, max_tokens, etc.)
