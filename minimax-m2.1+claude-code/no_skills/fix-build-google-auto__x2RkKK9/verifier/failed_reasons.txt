# Build Error Analysis for auto-value project

## Problem Summary
The build fails with the following error:
```
Could not find artifact com.sun:tools:jar:11.0.27 at specified path /usr/lib/jvm/java-11-openjdk-amd64/../lib/tools.jar
```

## Root Causes Identified
1. **Missing com.sun:tools dependency**: The test dependency `com.google.testing.compile:compile-testing:0.6` has a system-scoped dependency on `com.sun:tools:jar:${java.version}`. In Java 9+, the `tools.jar` file was removed and its contents were integrated directly into the JDK.

2. **Missing javax.annotation.Generated class**: In Java 9+, the `javax.annotation` package (including `Generated`) was moved out of the JDK to a separate module (Java EE API).

3. **Java version mismatch**: The project was configured to compile for Java 1.6, which doesn't work well with Java 11 runtime.

## Solution Applied (in pom.xml)
1. Added `<java.version>1.8</java.version>` property to set the target Java version to 1.8
2. Added exclusion for `com.sun:tools` dependency from `compile-testing`
3. Added dependency on `javax.annotation:javax.annotation-api:1.3.2` to provide the `Generated` annotation

## Build Status
- Compilation: SUCCESS
- Tests: 3 failures due to old ASM 4.1 library not supporting Java 11 class files (pre-existing issue)

## Note on Test Failures
The test failures in `AbstractMethodListerTest` and `GuavaCollectionBuildersTest` are pre-existing issues caused by the old ASM 4.1 library used in the project. ASM 4.1 cannot read class files from Java 11. This is a separate issue from the build configuration problems that were fixed.
