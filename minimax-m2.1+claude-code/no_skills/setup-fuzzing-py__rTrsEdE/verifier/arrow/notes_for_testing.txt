# Notes for Arrow Library Fuzzing

## Library Description
Arrow is a Python library for working with dates and times. It provides a user-friendly API for creating, formatting, and manipulating datetime objects.

## Key Functions for Fuzzing

### 1. arrow.get() - API Entry Point
- Location: arrow/api.py
- Function: get()
- Purpose: Parse and create Arrow datetime objects from various input formats
- Input: strings, timestamps, date objects, Arrow objects
- Fuzzing strategy: Provide various string formats, invalid inputs, edge cases

### 2. Arrow class methods
- Location: arrow/arrow.py
- Key methods:
  - __init__(): Constructor with timestamp, tzinfo, year/month/day/hour/minute/second/microsecond
  - fromtimestamp(): Create from Unix timestamp
  - strptime(): Parse strings with format
  - format(): Format Arrow object to string
  - replace(): Replace datetime components
  - span(): Get time span (year, month, week, day, hour, minute, second)
  - humanize(): Human-readable relative time
- Fuzzing strategy: Various timestamp values, timezone strings, format strings

### 3. Parser functions
- Location: arrow/parser.py
- Key functions:
  - parse_date(): Generic date parser
  - parse_token(): Parse individual date tokens
  - _parse_*(): Various format-specific parsers
- Fuzzing strategy: Various date string formats, locale variations

### 4. Factory methods
- Location: arrow/factory.py
- ArrowFactory.create(): Create Arrow instances
- Fuzzing strategy: Various input combinations

### 5. Formatter functions
- Location: arrow/formatter.py
- Format strings: RFC formats, cookie format, W3C format, etc.
- Fuzzing strategy: Various format specifiers

## Input Types to Test
1. String inputs: ISO 8601, RFC 2822, RFC 3339, custom formats
2. Integer/float: Unix timestamps (positive, negative, zero)
3. datetime objects: Python datetime objects
4. Arrow objects: Existing Arrow instances
5. Invalid inputs: Malformed strings, out-of-range values, None

## Edge Cases
- Invalid timezone strings
- Out-of-range dates (before epoch, far future)
- Leap year handling
- DST transitions
- Empty strings
- Unicode in date strings
- Very long strings
